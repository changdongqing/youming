## 三、应修订项

### S1. 第 13 节文件索引：quartz-config.yml 路径写错模块 🟠

第 463 行：

```
| Quartz 配置 | `pig-visual/pig-codegen/src/main/resources/quartz-config.yml` |
```

核验：`pig-visual/pig-codegen/src/main/resources/quartz-config.yml` **不存在**；实际在 `pig-visual/pig-quartz/src/main/resources/quartz-config.yml`。

文档第 4.4 节（正文）写的是对的（`pig-visual/pig-quartz/...`），仅索引表笔误。迁移执行者常按索引表定位文件，此处会扑空。

> ✅ **2026-07-08 源码复核**：本仓 `server/pig-visual/pig-quartz/src/main/resources/quartz-config.yml` 确实存在（含 `driverDelegateClass: org.quartz.impl.jdbcjobstore.StdJDBCDelegate`、`initialize-schema: never`），S1 修订有效。


### N1. 7.1 pgloader 配置与 04-5.2 Flyway 基线口径冲突 🟡

7.1 节 pgloader 配置：

```
WITH include drop, create tables, create indexes, reset sequences, ...
```

即 pgloader 自己建结构。但若按 04 文档 Flyway 接管结构（基线脚本 V20260706.01/02/03 建表），pgloader 再 `create tables` 会冲突。

**修订建议**：在 7.1 明确分支：

- 若**采用 Flyway**（推荐）：pgloader 用 `WITH data only`，仅迁数据，结构由 Flyway 基线脚本建。
- 若**不采用 Flyway**：pgloader 用 `create tables`（原配置），结构由 pgloader 建，后续手工维护。

并在 7.1 加一行交叉引用："与《04-Flyway集成设计》5.2 节的执行顺序见 N1（评审）"。避免迁移执行者两份文档口径不一造成困惑。

> ✅ **2026-07-08 youming 落地结论**：youming 为空库迁移（仅种子数据，无存量业务数据），**不使用 pgloader**，直接由 Flyway 基线脚本一次性建表 + INSERT 种子数据。pgloader 仅作为"未来有存量 MySQL 业务数据需迁移"时的备选方案记录。N1 在 youming 场景闭环。

### N2. 5.3 gen_field_type 的 AUTO_INCREMENT 决策前置核实 🟡

5.3 推荐 `gen_field_type` 改 `bigserial` + `setval(... 1634915190321451010)`。但未核实 `GenFieldType` 实体的 `@TableId` 策略：

- 若 `IdType.ASSIGN_ID`（应用雪花）→ PG 侧应 `bigint` 无序列，与 48 张业务表一致，**不需要 bigserial/setval**。
- 若 `IdType.AUTO`（DB 自增）→ 才需 `bigserial` + setval。

**修订建议**：5.3 加一句"P1 前核实 `GenFieldType` 实体主键策略；若 ASSIGN_ID 则同业务表用 bigint 无序列"。核实成本极低（读一个 entity），但能避免给字典表引入不必要的序列与 setval 维护负担。

> ✅ **2026-07-08 源码复核**：`server/pig-visual/pig-codegen/src/main/java/com/pig4cloud/pig/codegen/entity/GenFieldType.java:45` 确为 `@TableId(type = IdType.ASSIGN_ID)`。**结论：gen_field_type 用普通 bigint 无序列，不使用 bigserial/setval**。N2 闭环。

### N5. 3.1 隐式连接改 JOIN（可选）🟡

3.1 已提到 6 处 ANSI-89 隐式连接"建议改 JOIN ON（非必需）"。评审赞同并建议：把"非必需"在 P5 落地为"可选子项"，借迁移窗口统一代码风格。具体 6 处可在迁移时由脚本或人工一次性改写，回归覆盖即可。
