# 单体版开发服务器本机配置要求

> 适用对象：使用 `pig-boot` 单体模块进行本机开发调试的开发者。
> IDE：Visual Studio Code（不适用 IntelliJ IDEA）。
> 后端目录：`server/`，前端目录：`web/`。

## 一、架构说明

单体版通过 `pig-boot` 模块运行，**不依赖 Nacos、不依赖 Spring Cloud Gateway、不依赖 Sentinel**：

- 关闭 `spring.cloud.discovery`、`nacos.config/discovery`、`sentinel`。
- 直连 MySQL（业务库 `pig`）与 Redis。
- 服务端口 `9999`，统一上下文路径 `/admin`（即所有接口前缀为 `http://127.0.0.1:9999/admin`）。
- 激活 Profile：`dev`（`application-dev.yml`）。

单体版仅需启动 1 个后端进程 + 1 个前端进程，适合快速本地调试与功能验证。

## 二、本机配置要求

### 2.1 软件环境

| 软件 | 版本要求 | 说明 |
|------|---------|------|
| JDK | 17（必须） | 项目 `maven.compiler.source/target=17`；推荐 Temurin / Zulu 17 |
| Maven | 3.8+ | 用于编译 `pig-boot`；需激活 `boot` profile |
| Node.js | 18.x+（推荐 20 LTS） | 前端构建；Vite 8 对 Node 版本有要求 |
| npm | 随 Node 自带，或使用 pnpm/yarn | — |
| MySQL | 8.x | 字符集 utf8mb4；`lower_case_table_names=1` |
| Redis | 6.x / 7.x | 单体版默认使用 db `5` |
| Git | 2.20+ | — |
| Docker（可选） | — | 仅当用 `docker-compose-boot.yml` 一键起 MySQL/Redis 时需要 |

### 2.2 VSCode 必装扩展

| 扩展 | 用途 |
|------|------|
| **Extension Pack for Java**（vscjava） | Java 语言支持、调试、Maven 集成（含 Java Debugger + Maven for Java） |
| **Spring Boot Extension Pack** | Spring 配置提示、application.yml 智能补全 |
| **Vue - Official**（Volar） | Vue 3 SFC 支持 |
| **ESLint** / **Prettier** | 前端代码规范 |
| **TypeScript Vue Plugin** | TS + Vue 类型提示 |

> Java 扩展包会自动拉取 Red Hat Java 语言服务器；首次打开 `server/` 会下载依赖，请保持网络通畅。

### 2.3 硬件建议

- CPU 4 核及以上
- 内存 8 GB 及以上（JVM + Node + MySQL/Redis）
- 磁盘 10 GB 可用空间（Maven 依赖、npm 依赖）

## 三、数据库与缓存准备

### 3.1 初始化 MySQL

1. 创建数据库并导入 `server/db/` 下的 SQL：

   ```bash
   # 业务库
   mysql -uroot -p < server/db/pig.sql
   # Nacos 配置库（单体版不强制需要，但导入不影响运行）
   mysql -uroot -p < server/db/pig_config.sql
   ```

   `pig.sql` 会自动创建 `pig` 库及业务表；`pig_config.sql` 创建 `pig_config` 库。

2. 确认账号：默认使用 `root / root`（与 `application-dev.yml` 一致）。若本机 MySQL 密码不同，需修改配置（见 4.2）。

### 3.2 启动 Redis

```bash
# 本机直接启动
redis-server --daemonize yes
# 或 docker
docker run -d --name pig-redis -p 6379:6379 redis:7
```

### 3.3 （可选）一键拉起 MySQL + Redis

`server/docker-compose-boot.yml` 已提供 MySQL + Redis 容器（注意：该文件同时会构建 `pig-boot` 镜像，本机调试时通常只需 MySQL/Redis 部分）：

```bash
cd server
# 仅启动中间件，可手动执行 compose 中的 mysql / redis 服务
docker compose -f docker-compose-boot.yml up -d pig-mysql pig-redis
```

## 四、后端配置与启动（VSCode）

### 4.1 编译 pig-boot

单体模块需激活根 pom 的 `boot` profile（该 profile 只包含 `pig-boot` 一个模块）：

```bash
cd server
mvn clean install -Pboot -DskipTests
```

> 首次编译会下载大量依赖，耗时较长。若网络不佳，建议配置阿里云 Maven 镜像（`~/.m2/settings.xml`）。

### 4.2 修改本机数据源配置

`server/pig-boot/src/main/resources/application-dev.yml` 默认连接容器主机名 `pig-mysql` / `pig-redis`，本机调试需改为 `127.0.0.1`：

```yaml
spring:
  data:
    redis:
      host: 127.0.0.1   # 原为 pig-redis
      database: 5
  datasource:
    druid:
      username: root
      password: root     # 改为本机 MySQL 实际密码
      url: jdbc:mysql://127.0.0.1:3306/pig?characterEncoding=utf8&...   # 原为 pig-mysql
```

> 也可不改源文件，改用环境变量覆盖。但 `pig-boot` 的 dev 配置未对数据源做 `${MYSQL_HOST:...}` 占位，建议直接改 yml 或新增 `application-local.yml` 并以 `--spring.profiles.active=local` 启动。

### 4.3 VSCode 启动配置

在仓库根目录创建 `.vscode/launch.json`：

```json
{
  "version": "0.2.0",
  "configurations": [
    {
      "type": "java",
      "name": "PigBoot (单体)",
      "request": "launch",
      "mainClass": "com.pig4cloud.pig.PigBootApplication",
      "projectName": "pig-boot",
      "cwd": "${workspaceFolder}/server",
      "args": "--spring.profiles.active=dev",
      "vmArgs": "-Xms512m -Xmx1024m"
    }
  ]
}
```

启动步骤：

1. VSCode 打开仓库根目录 `youming/`。
2. 确认 Maven 扩展已识别 `server/` 为多模块项目（左下角状态栏 / Maven 面板可见 `pig-boot`）。
3. 按 `F5`（或运行配置下拉选 `PigBoot (单体)`），Java 调试器启动 `PigBootApplication`。
4. 控制台出现 `Started PigBootApplication ... in N seconds` 即启动成功。
5. 访问 `http://127.0.0.1:9999/admin/actuator/health` 验证（需放开 actuator，单体默认 `management.endpoints.access.default: none`，可用接口测试代替）。

> 断点调试：在任意 Java 方法行号左侧点击设置断点，`F5` 启动后命中即暂停，支持变量查看、表达式求值。

## 五、前端配置与启动（VSCode）

### 5.1 切换为单体模式

编辑 `web/.env`，将微服务标志改为 `false`：

```bash
# 是否是微服务架构（重要）—— 单体版必须改为 false
VITE_IS_MICRO=false
```

> 该标志决定前端请求路径前缀：
> - `true`（微服务）：验证码等走 `/auth/**`（经 gateway 路由到 pig-auth）。
> - `false`（单体）：走 `/admin/**`（直连 pig-boot 的 context-path）。

### 5.2 确认后端代理地址

`web/.env.development` 中：

```
VITE_PORT=8888
VITE_ADMIN_PROXY_PATH=http://127.0.0.1:9999
```

与单体后端端口 9999 一致，无需修改。

### 5.3 安装依赖并启动

```bash
cd web
npm install        # 或 pnpm install / yarn
npm run dev        # 即 vite --force，开发服务器
```

启动步骤（VSCode）：

1. VSCode 打开 `web/`（或在根目录通过终端 `cd web`）。
2. 在集成终端（`` Ctrl+` ``）执行上述 `npm install` 与 `npm run dev`。
3. Vite 启动后默认自动打开浏览器 `http://127.0.0.1:8888`。
4. 前端请求经 Vite 代理转发至 `http://127.0.0.1:9999`（单体后端）。

> 前端断点调试：VSCode 安装 Volar 后，可在 `.vue`/`.ts` 中使用浏览器 DevTools 调试；也可用 `Launch Chrome` 配置配合 sourcemap。

## 六、启动顺序总结

单体版启动顺序：

1. 启动 MySQL、Redis（本机或容器）。
2. 导入 `server/db/pig.sql`。
3. `mvn clean install -Pboot -DskipTests`（首次或依赖变更时）。
4. VSCode `F5` 启动 `PigBootApplication`，等待 9999 端口就绪。
5. `web/` 下 `npm install && npm run dev`，打开 `http://127.0.0.1:8888`。

## 七、默认账号

首次导入 `pig.sql` 后，默认登录账号：

- 用户名：`admin`
- 密码：`123456`

## 八、常见问题

| 现象 | 原因 / 处理 |
|------|------------|
| 启动报 `Unknown host pig-mysql` | 未改 `application-dev.yml` 的数据源主机名，改为 `127.0.0.1` |
| `npm run dev` 报 Node 版本不足 | 升级 Node 至 18+（推荐 20 LTS） |
| 前端登录验证码不显示 | 未将 `VITE_IS_MICRO` 改为 `false`，或后端 `/admin/code/image` 未就绪 |
| `mvn` 找不到 `pig-boot` 模块 | 未加 `-Pboot` profile；默认 profile 不包含该模块 |
| 端口 9999 被占用 | 关闭占用进程，或在 `application.yml` 改 `server.port` |
| Java 扩展识别不到项目 | 确认打开的是仓库根目录，Maven 扩展已安装并加载 `server/pom.xml` |
