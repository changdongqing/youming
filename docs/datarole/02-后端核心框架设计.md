# 02 — 后端核心框架设计

> `@DataScope` 注解、`DataScopeInnerInterceptor` 拦截器、`DataScopeProcessor` 处理器、`DataScopeContext` 线程开关、缓存策略

## 1. 模块定位与依赖关系

```
pig-common-data  （核心引擎，不依赖 security）
  ├── datascope/annotation/DataScope.java
  ├── datascope/interceptor/DataScopeInnerInterceptor.java
  ├── datascope/handler/DataScopeProcessor.java
  ├── datascope/handler/DataScopeHandler.java        (SPI 接口)
  ├── datascope/context/DataScopeContext.java
  ├── datascope/model/DataScopeType.java
  └── datascope/model/DataScopeRule.java

pig-common-core  （已有 UserContextHolder SPI，扩展接口）
  └── context/UserContext.java  ← 新增 getDeptIds() / getUserId()

pig-common-security  （适配层，无需改动 PigUser）
  └── context/PigUserContextAdapter.java  ← 实现 getDeptIds() / getUserId()

pig-upms-biz  （业务实现）
  ├── config/DataScopeConfiguration.java
  ├── service/impl/SysRoleDataScopeHandler.java     (实现 DataScopeHandler SPI)
  └── service/impl/DeptClosureService.java           (闭包表维护，可选)
```

**关键设计原则**：`pig-common-data` 是通用数据层，**不能反向依赖 `pig-common-security`**。数据权限引擎通过 `UserContextHolder` SPI（来自 `pig-common-core`）获取当前用户上下文，通过自定义 SPI `DataScopeHandler` 获取角色数据范围配置，由 `pig-upms-biz` 提供实现。

## 2. 数据范围枚举 `DataScopeType`

```java
package com.pig4cloud.pig.common.data.datascope.model;

import lombok.AllArgsConstructor;
import lombok.Getter;

/**
 * 数据范围类型。
 * <p>
 * 编码与数据库 sys_role.data_scope 列一致：
 * <ul>
 *   <li>1 - 全部数据：不附加过滤条件</li>
 *   <li>2 - 自定义数据：仅可见 sys_role_dept 指定的部门</li>
 *   <li>3 - 本部门数据：仅可见用户主部门</li>
 *   <li>4 - 本部门及以下：可见主部门及其所有子部门</li>
 *   <li>5 - 仅本人：仅可见当前用户创建的数据</li>
 * </ul>
 */
@Getter
@AllArgsConstructor
public enum DataScopeType {

    ALL("1", "全部数据"),
    CUSTOM("2", "自定义数据"),
    DEPT("3", "本部门数据"),
    DEPT_AND_CHILD("4", "本部门及以下"),
    SELF("5", "仅本人");

    /** 数据库存储编码 */
    private final String code;

    /** 描述 */
    private final String description;

    /**
     * 从数据库编码解析为枚举。
     * @param code data_scope 列值
     * @return 枚举值，未知编码默认返回 ALL（安全降级）
     */
    public static DataScopeType of(String code) {
        if (code == null) {
            return ALL;
        }
        for (DataScopeType type : values()) {
            if (type.code.equals(code)) {
                return type;
            }
        }
        return ALL;
    }
}
```

## 3. 解析结果模型 `DataScopeRule`

```java
package com.pig4cloud.pig.common.data.datascope.model;

import lombok.Builder;
import lombok.Getter;

import java.util.Set;

/**
 * 数据权限解析结果，由 {@code DataScopeProcessor} 产出，
 * 供拦截器构建 SQL 条件使用。
 */
@Getter
@Builder
public class DataScopeRule {

    /** 是否跳过数据权限（管理员 / 系统调用） */
    private final boolean skip;

    /** 可见部门 ID 集合（scope=CUSTOM/DEPT/DEPT_AND_CHILD 时有值） */
    private final Set<Long> visibleDeptIds;

    /** 是否限制为仅本人数据（scope=SELF 时为 true） */
    private final boolean selfOnly;

    /** 当前用户 ID（用于 create_by 关联，或用户级过滤） */
    private final Long userId;

    /** 当前用户名（用于 create_by = username 条件） */
    private final String username;

    /**
     * 判断该规则是否需要追加部门过滤条件。
     */
    public boolean hasDeptFilter() {
        return visibleDeptIds != null && !visibleDeptIds.isEmpty();
    }
}
```

## 4. `@DataScope` 注解

```java
package com.pig4cloud.pig.common.data.datascope.annotation;

import java.lang.annotation.*;

/**
 * 声明式数据权限：标注在 Mapper 方法或 Service 类上，
 * 由 {@code DataScopeInnerInterceptor} 解析并自动注入 SQL 过滤条件。
 *
 * <h3>使用示例</h3>
 * <pre>{@code
 * // Mapper 方法级标注
 * @DataScope(deptAlias = "ud", userAlias = "u")
 * @Select("SELECT u.* FROM sys_user u LEFT JOIN sys_user_dept ud ON u.user_id = ud.user_id WHERE u.del_flag = '0'")
 * List<UserVO> selectUserPage();
 *
 * // Service 类级标注（对该类所有 Mapper 调用生效）
 * @DataScope(deptAlias = "d")
 * public class SomeServiceImpl { ... }
 * }</pre>
 *
 * <h3>跳过数据权限</h3>
 * <pre>{@code
 * @DataScope(disabled = true)  // 该查询不过滤数据权限
 * List<SysUser> selectAllForExport();
 * }</pre>
 *
 * @author youming
 */
@Target({ElementType.METHOD, ElementType.TYPE})
@Retention(RetentionPolicy.RUNTIME)
@Documented
public @interface DataScope {

    /**
     * 部门表的别名。SQL 中部门字段的完整引用为 {@code {deptAlias}.{deptField}}。
     * <p>例如 deptAlias="ud", deptField="dept_id" → {@code ud.dept_id}
     */
    String deptAlias() default "d";

    /**
     * 用户/实体表的别名。用于"仅本人"场景的 create_by 字段引用。
     * <p>例如 userAlias="u" → {@code u.create_by}
     */
    String userAlias() default "u";

    /**
     * 部门字段名，默认 "dept_id"。
     */
    String deptField() default "dept_id";

    /**
     * 创建人字段名，默认 "create_by"。用于"仅本人"场景。
     */
    String createByField() default "create_by";

    /**
     * 是否禁用数据权限过滤。
     * <p>true 表示该查询不过滤数据权限（管理员导出、定时任务等场景）。
     */
    boolean disabled() default false;
}
```

## 5. `DataScopeContext` 线程开关

提供**编程式**跳过数据权限的能力，用于内部 Feign 调用、定时任务、数据同步等无用户上下文或需绕过权限的场景。

```java
package com.pig4cloud.pig.common.data.datascope.context;

/**
 * 数据权限线程上下文开关。
 *
 * <p>使用 try-with-resources 模式确保开关在作用域结束后自动恢复：
 * <pre>{@code
 * // 临时跳过数据权限（如管理员导出全量数据）
 * try (DataScopeContext ignored = DataScopeContext.disable()) {
 *     List<SysUser> allUsers = userMapper.selectAll();
 * } // 离开作用域后自动恢复过滤
 * }</pre>
 *
 * @author youming
 */
public final class DataScopeContext implements AutoCloseable {

    private static final ThreadLocal<Boolean> SKIP_HOLDER = ThreadLocal.withInitial(() -> false);

    private DataScopeContext() {
    }

    /**
     * 临时禁用数据权限过滤，返回 AutoCloseable 用于 try-with-resources。
     */
    public static DataScopeContext disable() {
        SKIP_HOLDER.set(true);
        return new DataScopeContext();
    }

    /**
     * 当前线程是否应跳过数据权限。
     */
    public static boolean isDisabled() {
        return SKIP_HOLDER.get();
    }

    /**
     * 恢复数据权限过滤（手动调用，通常由 try-with-resources 自动触发）。
     */
    public static void enable() {
        SKIP_HOLDER.remove();
    }

    @Override
    public void close() {
        enable();
    }
}
```

## 6. `DataScopeHandler` SPI 接口

此接口定义在 `pig-common-data` 中，由 `pig-upms-biz` 实现。解耦数据权限引擎与业务模块。

```java
package com.pig4cloud.pig.common.data.datascope.handler;

import com.pig4cloud.pig.common.data.datascope.model.DataScopeType;

import java.util.List;
import java.util.Set;

/**
 * 数据范围解析 SPI。
 *
 * <p>定义在 pig-common-data 中，由 pig-upms-biz 提供实现。
 * 引擎通过此接口获取角色数据范围配置和部门子树，
 * 避免反向依赖 upms 模块。
 *
 * @author youming
 */
public interface DataScopeHandler {

    /**
     * 查询指定角色集合的数据范围配置。
     *
     * <p>多角色时由调用方负责合并取最宽范围。
     *
     * @param roleIds 角色ID列表
     * @return 每个角色对应的数据范围类型，顺序与入参一致
     */
    List<DataScopeType> getDataScopeTypes(List<Long> roleIds);

    /**
     * 查询角色自定义数据范围关联的部门 ID 集合。
     * <p>仅当角色 data_scope = '2'(CUSTOM) 时此方法返回的集合才有意义。
     *
     * @param roleIds 角色ID列表
     * @return 合并后的部门 ID 集合
     */
    Set<Long> getCustomDeptIds(List<Long> roleIds);

    /**
     * 查询指定部门的全部子部门 ID（含自身）。
     * <p>用于 DEPT_AND_CHILD 场景。
     *
     * @param deptId 部门ID
     * @return 该部门及其所有子部门的 ID 集合
     */
    Set<Long> getDeptAndChildren(Long deptId);
}
```

## 7. `DataScopeProcessor` 处理器

核心逻辑：根据当前用户上下文 + 角色数据范围配置，计算最终的 `DataScopeRule`。

```java
package com.pig4cloud.pig.common.data.datascope.handler;

import cn.hutool.core.collection.CollUtil;
import com.pig4cloud.pig.common.core.context.UserContext;
import com.pig4cloud.pig.common.core.context.UserContextHolder;
import com.pig4cloud.pig.common.data.datascope.context.DataScopeContext;
import com.pig4cloud.pig.common.data.datascope.model.DataScopeRule;
import com.pig4cloud.pig.common.data.datascope.model.DataScopeType;
import lombok.RequiredArgsConstructor;
import lombok.extern.slf4j.Slf4j;

import java.util.*;
import java.util.stream.Collectors;

/**
 * 数据权限处理器：解析当前用户的数据范围规则。
 *
 * <h3>多角色取最宽范围规则</h3>
 * <ol>
 *   <li>若任一角色为 ALL → 最终为 ALL（短路，不附加任何条件）</li>
 *   <li>收集所有 CUSTOM 角色的自定义部门 ID → customDeptIds</li>
 *   <li>收集所有 DEPT 角色标记 → 加入用户主部门</li>
 *   <li>收集所有 DEPT_AND_CHILD 角色标记 → 加入用户主部门及子部门</li>
 *   <li>收集所有 SELF 角色标记 → 追加 create_by = username 条件</li>
 *   <li>合并所有部门 ID 为 visibleDeptIds，selfOnly 标记是否需要追加本人条件</li>
 * </ol>
 *
 * @author youming
 */
@Slf4j
@RequiredArgsConstructor
public class DataScopeProcessor {

    private final UserContextHolder userContextHolder;
    private final DataScopeHandler dataScopeHandler;

    /**
     * 解析当前用户的数据范围规则。
     *
     * @return 数据范围规则；若应跳过过滤则返回 skip=true 的规则
     */
    public DataScopeRule resolve() {
        // 1. 线程开关检查（编程式跳过）
        if (DataScopeContext.isDisabled()) {
            return DataScopeRule.builder().skip(true).build();
        }

        // 2. 获取用户上下文
        UserContext userContext = userContextHolder.get();
        if (userContext == null) {
            // 未登录（内部 Feign 调用 / 定时任务）→ 放行
            log.debug("[DataScope] No user context, skip data scope filtering");
            return DataScopeRule.builder().skip(true).build();
        }

        List<Long> roleIds = userContext.getRoleIds();
        if (CollUtil.isEmpty(roleIds)) {
            // 无角色 → 无数据（安全降级：返回空集）
            log.debug("[DataScope] User {} has no roles, deny all data", userContext.getUsername());
            return DataScopeRule.builder()
                    .skip(false)
                    .visibleDeptIds(Collections.emptySet())
                    .selfOnly(false)
                    .userId(userContext.getUserId())
                    .username(userContext.getUsername())
                    .build();
        }

        // 3. 查询各角色的数据范围类型
        List<DataScopeType> scopeTypes = dataScopeHandler.getDataScopeTypes(roleIds);

        // 4. 短路：任一角色为 ALL → 全部数据
        if (scopeTypes.contains(DataScopeType.ALL)) {
            return DataScopeRule.builder().skip(true).build();
        }

        // 5. 合并多角色范围
        Set<Long> visibleDeptIds = new HashSet<>();
        boolean selfOnly = false;
        Long userDeptId = userContext.getDeptId();

        // 5a. CUSTOM：收集自定义部门
        Set<Long> customDeptIds = dataScopeHandler.getCustomDeptIds(roleIds);
        visibleDeptIds.addAll(customDeptIds);

        // 5b. DEPT / DEPT_AND_CHILD：加入用户部门信息
        boolean needDeptAndChild = scopeTypes.contains(DataScopeType.DEPT_AND_CHILD);
        boolean needDept = scopeTypes.contains(DataScopeType.DEPT);

        if (needDeptAndChild && userDeptId != null) {
            visibleDeptIds.addAll(dataScopeHandler.getDeptAndChildren(userDeptId));
        } else if (needDept && userDeptId != null) {
            visibleDeptIds.add(userDeptId);
        }

        // 5c. SELF：标记需要追加本人条件
        if (scopeTypes.contains(DataScopeType.SELF)) {
            selfOnly = true;
        }

        return DataScopeRule.builder()
                .skip(false)
                .visibleDeptIds(visibleDeptIds)
                .selfOnly(selfOnly)
                .userId(userContext.getUserId())
                .username(userContext.getUsername())
                .build();
    }
}
```

## 8. `DataScopeInnerInterceptor` 拦截器

MyBatis-Plus `InnerInterceptor` 实现，在查询执行前改写 SQL。

```java
package com.pig4cloud.pig.common.data.datascope.interceptor;

import cn.hutool.core.collection.CollUtil;
import com.pig4cloud.pig.common.data.datascope.annotation.DataScope;
import com.pig4cloud.pig.common.data.datascope.handler.DataScopeProcessor;
import com.pig4cloud.pig.common.data.datascope.model.DataScopeRule;
import lombok.extern.slf4j.Slf4j;
import net.sf.jsqlparser.expression.Expression;
import net.sf.jsqlparser.expression.operators.conditional.AndExpression;
import net.sf.jsqlparser.expression.operators.conditional.OrExpression;
import net.sf.jsqlparser.expression.operators.relational.ExpressionList;
import net.sf.jsqlparser.expression.operators.relational.InExpression;
import net.sf.jsqlparser.expression.operators.relational.ParenthesedExpressionList;
import net.sf.jsqlparser.expression.LongValue;
import net.sf.jsqlparser.expression.operators.relational.EqualsTo;
import net.sf.jsqlparser.schema.Column;
import net.sf.jsqlparser.statement.select.PlainSelect;
import net.sf.jsqlparser.statement.select.Select;
import org.apache.ibatis.executor.Executor;
import org.apache.ibatis.mapping.BoundSql;
import org.apache.ibatis.mapping.MappedStatement;
import org.apache.ibatis.session.ResultHandler;
import org.apache.ibatis.session.RowBounds;

import java.sql.SQLException;
import java.util.Set;

/**
 * MyBatis-Plus 内拦截器：数据权限 SQL 条件注入。
 *
 * <h3>执行流程</h3>
 * <ol>
 *   <li>检查 MappedStatement 是否标注了 @DataScope（Mapper 方法级或类级）</li>
 *   <li>调用 DataScopeProcessor 解析当前用户的数据范围规则</li>
 *   <li>使用 JSqlParser 解析原 SQL，将过滤条件注入 WHERE 子句</li>
 * </ol>
 *
 * <p>仅对标注了 @DataScope 的查询生效，无注解的查询直接放行。
 *
 * @author youming
 */
@Slf4j
public class DataScopeInnerInterceptor implements InnerInterceptor {

    private final DataScopeProcessor dataScopeProcessor;
    private final DataScopeAnnotationResolver annotationResolver;

    public DataScopeInnerInterceptor(DataScopeProcessor processor,
                                      DataScopeAnnotationResolver annotationResolver) {
        this.dataScopeProcessor = processor;
        this.annotationResolver = annotationResolver;
    }

    @Override
    public void beforeQuery(Executor executor, MappedStatement ms, Object parameter,
                            RowBounds rowBounds, ResultHandler resultHandler, BoundSql boundSql) throws SQLException {

        // 1. 检查是否标注了 @DataScope
        DataScope dataScope = annotationResolver.resolve(ms);
        if (dataScope == null || dataScope.disabled()) {
            return; // 无注解或显式禁用 → 放行
        }

        // 2. 解析数据范围规则
        DataScopeRule rule = dataScopeProcessor.resolve();
        if (rule.isSkip()) {
            return; // 管理员 / 系统调用 → 放行
        }

        // 3. 构建 SQL 条件并注入
        Expression scopeExpression = buildExpression(dataScope, rule);
        if (scopeExpression == null) {
            // 无任何可见数据 → 注入 1=0（返回空结果集）
            scopeExpression = new EqualsTo(new LongValue(1), new LongValue(0));
        }

        // 4. JSqlParser 改写 SQL
        injectCondition(boundSql, ms, scopeExpression);
    }

    /**
     * 根据数据范围规则构建 SQL WHERE 条件表达式。
     */
    private Expression buildExpression(DataScope dataScope, DataScopeRule rule) {
        Expression result = null;

        // 部门过滤条件
        if (rule.hasDeptFilter()) {
            String deptColumn = dataScope.deptAlias() + "." + dataScope.deptField();
            InExpression deptIn = buildInExpression(deptColumn, rule.getVisibleDeptIds());
            result = deptIn;
        }

        // 本人过滤条件
        if (rule.isSelfOnly()) {
            String createByColumn = dataScope.userAlias() + "." + dataScope.createByField();
            EqualsTo selfCond = new EqualsTo(new Column(createByColumn),
                    new StringValue(rule.getUsername()));

            if (result != null) {
                // 部门条件 OR 本人条件（多角色取并集）
                result = new OrExpression(result, selfCond);
            } else {
                result = selfCond;
            }
        }

        return result;
    }

    /**
     * 构建 IN 表达式：column IN (val1, val2, ...)
     */
    private InExpression buildInExpression(String columnName, Set<Long> values) {
        ParenthesedExpressionList<Expression> valueList = new ParenthesedExpressionList<>();
        values.forEach(val -> valueList.add(new LongValue(val)));
        return new InExpression(new Column(columnName), valueList);
    }

    /**
     * 使用 JSqlParser 将条件注入到 SQL 的 WHERE 子句。
     *
     * <p>改写逻辑：
     * <pre>
     *   原 SQL: SELECT ... FROM ... WHERE [original_conditions]
     *   改写后: SELECT ... FROM ... WHERE [original_conditions] AND [scope_condition]
     *   无原条件: SELECT ... FROM ... WHERE [scope_condition]
     * </pre>
     */
    private void injectCondition(BoundSql boundSql, MappedStatement ms, Expression scopeExpression) {
        // 使用 MyBatis-Plus 提供的 JsqlParserUtil 解析并改写
        // 实际实现借助 MP 的 PluginUtils / JsqlParser 工具方法
        String originalSql = boundSql.getSql();
        Statement statement = CCJSqlParserUtil.parse(originalSql);

        if (statement instanceof Select select) {
            PlainSelect plainSelect = select.getPlainSelect();
            Expression where = plainSelect.getWhere();

            if (where == null) {
                plainSelect.setWhere(scopeExpression);
            } else {
                plainSelect.setWhere(new AndExpression(where, scopeExpression));
            }

            // 将改写后的 SQL 写回 BoundSql
            String newSql = select.toString();
            PluginUtils.updateBoundSql(ms, boundSql, newSql);
        }
    }
}
```

> **注意**：上述代码中的 JSqlParser API 调用基于 JSqlParser 4.9（MyBatis-Plus 3.5.9 内置版本）。实际实现时需根据具体版本微调 API。`PluginUtils.updateBoundSql` 是 MyBatis-Plus 提供的工具方法，用于回写改写后的 SQL。`StringValue` 需从 `net.sf.jsqlparser.expression` 导入。

## 9. `DataScopeAnnotationResolver` 注解解析器

负责从 `MappedStatement` 中解析 `@DataScope` 注解（支持方法级和类级）。

```java
package com.pig4cloud.pig.common.data.datascope.interceptor;

import com.pig4cloud.pig.common.data.datascope.annotation.DataScope;
import org.apache.ibatis.mapping.MappedStatement;
import org.apache.ibatis.reflection.MetaObject;
import org.apache.ibatis.session.Configuration;

import java.lang.reflect.Method;
import java.util.Map;
import java.util.concurrent.ConcurrentHashMap;

/**
 * @DataScope 注解解析器。
 *
 * <p>从 MappedStatement 对应的 Mapper 方法上解析注解，带缓存。
 *
 * @author youming
 */
public class DataScopeAnnotationResolver {

    /** 缓存：MappedStatement ID → @DataScope（null 表示无注解） */
    private final Map<String, DataScope> cache = new ConcurrentHashMap<>();

    /**
     * 解析 MappedStatement 上的 @DataScope 注解。
     *
     * @param ms MyBatis MappedStatement
     * @return 注解实例，无注解时返回 null
     */
    public DataScope resolve(MappedStatement ms) {
        return cache.computeIfAbsent(ms.getId(), this::doResolve);
    }

    private DataScope doResolve(String mappedStatementId) {
        try {
            // mappedStatementId 格式: com.xxx.Mapper.methodName
            int lastDot = mappedStatementId.lastIndexOf('.');
            String className = mappedStatementId.substring(0, lastDot);
            String methodName = mappedStatementId.substring(lastDot + 1);

            Class<?> mapperClass = Class.forName(className);

            // 优先查找方法级注解
            for (Method method : mapperClass.getMethods()) {
                if (method.getName().equals(methodName) && method.isAnnotationPresent(DataScope.class)) {
                    return method.getAnnotation(DataScope.class);
                }
            }

            // 回退到类级注解
            if (mapperClass.isAnnotationPresent(DataScope.class)) {
                return mapperClass.getAnnotation(DataScope.class);
            }
        } catch (ClassNotFoundException e) {
            // 非 Mapper 接口（如 XML 定义），忽略
        }
        return null;
    }
}
```

### 10.1 修改 `MybatisPlusConfiguration`

```java
// pig-common-data/.../mybatis/MybatisPlusConfiguration.java

@Bean
public MybatisPlusInterceptor mybatisPlusInterceptor(
        ObjectProvider<DataScopeInnerInterceptor> dataScopeInterceptorProvider) {

    MybatisPlusInterceptor interceptor = new MybatisPlusInterceptor();

    // 1. 分页支持（已有，不变）
    PaginationInnerInterceptor paginationInnerInterceptor = new PaginationInnerInterceptor(DbType.POSTGRE_SQL);
    paginationInnerInterceptor.setMaxLimit(1000L);
    interceptor.addInnerInterceptor(paginationInnerInterceptor);

    // 2. 数据权限拦截器（新增）
    //    使用 ObjectProvider 实现可选注入：
    //    - pig-upms-biz 等业务模块提供 DataScopeInnerInterceptor Bean 时自动启用
    //    - 纯 common-data 无业务实现时不报错
    dataScopeInterceptorProvider.ifAvailable(interceptor::addInnerInterceptor);

    // 3. 乐观锁（已有，不变）
    interceptor.addInnerInterceptor(new OptimisticLockerInnerInterceptor());

    return interceptor;
}
```

### 10.3 拦截器顺序说明

```
请求 → PaginationInnerInterceptor → DataScopeInnerInterceptor → OptimisticLocker → DB
```

| 顺序 | 拦截器 | 理由 |
|------|--------|------|
| 1 | Pagination | 分页计数需要先改写 SQL（count 查询） |
| 2 | **DataScope** | 在分页之后注入数据权限条件，确保 count 也带权限过滤 |
| 3 | OptimisticLocker | 乐观锁仅影响 UPDATE，与数据权限无冲突 |

> **重要**：MyBatis-Plus 的 `InnerInterceptor` 链按注册顺序执行 `beforeQuery`。数据权限必须在分页之前或之后注入，确保分页 count 查询也包含数据权限条件。MyBatis-Plus 3.5.x 的分页拦截器会自动对 count SQL 应用后续拦截器的改写，因此 DataScope 放在 Pagination 之后是安全的。

## 12. 部门闭包表维护（可选方案）

当部门量增长到 500+ 时，启用闭包表替代递归 CTE。

### 12.1 DeptClosureService

```java
package com.pig4cloud.pig.admin.service.impl;

import com.pig4cloud.pig.admin.api.entity.SysDeptClosure;
import com.pig4cloud.pig.admin.mapper.SysDeptClosureMapper;
import lombok.RequiredArgsConstructor;
import org.springframework.stereotype.Service;
import org.springframework.transaction.annotation.Transactional;

import java.util.List;

/**
 * 部门闭包表维护服务。
 *
 * <p>在部门增删改时同步维护 sys_dept_closure 表，
 * 确保祖先-后代关系一致。
 *
 * @author youming
 */
@Service
@RequiredArgsConstructor
public class DeptClosureService {

    private final SysDeptClosureMapper closureMapper;

    /**
     * 新增部门时维护闭包表。
     *
     * @param deptId 新部门 ID
     * @param parentId 父部门 ID
     */
    @Transactional(rollbackFor = Exception.class)
    public void onDeptCreated(Long deptId, Long parentId) {
        // 1. 自身到自身
        closureMapper.insert(new SysDeptClosure(deptId, deptId, 0));

        if (parentId != null && parentId > 0) {
            // 2. 父部门的所有祖先 → 新部门
            List<SysDeptClosure> ancestors = closureMapper
                    .selectList(Wrappers.<SysDeptClosure>lambdaQuery()
                            .eq(SysDeptClosure::getDescendant, parentId));

            List<SysDeptClosure> newRelations = ancestors.stream()
                    .map(a -> new SysDeptClosure(a.getAncestor(), deptId, a.getDepth() + 1))
                    .toList();
            closureMapper.insertBatch(newRelations);
        }
    }

    /**
     * 删除部门时清理闭包表。
     *
     * @param deptId 被删除的部门 ID
     */
    @Transactional(rollbackFor = Exception.class)
    public void onDeptDeleted(Long deptId) {
        // 删除所有以 deptId 为后代的记录（含自身）
        closureMapper.delete(Wrappers.<SysDeptClosure>lambdaQuery()
                .eq(SysDeptClosure::getDescendant, deptId));
    }

    /**
     * 移动部门时重建闭包关系。
     *
     * @param deptId 被移动的部门 ID
     * @param newParentId 新父部门 ID
     */
    @Transactional(rollbackFor = Exception.class)
    public void onDeptMoved(Long deptId, Long newParentId) {
        // 1. 删除旧关系：deptId 子树 与 deptId 旧祖先子树 的交叉
        //    即删除 ancestor 不在 deptId 子树中、descendant 在 deptId 子树中的记录
        closureMapper.deleteCrossReferences(deptId);

        // 2. 插入新关系：新父部门的祖先 → deptId 子树
        List<SysDeptClosure> newParentAncestors = closureMapper
                .selectList(Wrappers.<SysDeptClosure>lambdaQuery()
                        .eq(SysDeptClosure::getDescendant, newParentId));
        List<SysDeptClosure> deptSubtree = closureMapper
                .selectList(Wrappers.<SysDeptClosure>lambdaQuery()
                        .eq(SysDeptClosure::getAncestor, deptId));

        for (SysDeptClosure ancestor : newParentAncestors) {
            for (SysDeptClosure descendant : deptSubtree) {
                int depth = ancestor.getDepth() + descendant.getDepth() + 1;
                closureMapper.insert(new SysDeptClosure(
                        ancestor.getAncestor(), descendant.getDescendant(), depth));
            }
        }
    }

    /**
     * 查询部门及其所有子部门（使用闭包表）。
     */
    public Set<Long> getDeptAndChildren(Long deptId) {
        return closureMapper.selectList(Wrappers.<SysDeptClosure>lambdaQuery()
                        .eq(SysDeptClosure::getAncestor, deptId))
                .stream()
                .map(SysDeptClosure::getDescendant)
                .collect(Collectors.toSet());
    }
}
```

### 12.2 闭包表初始化

```sql
-- 初始化闭包表数据（执行一次，将现有 parent_id 树转换为闭包关系）
INSERT INTO sys_dept_closure (ancestor, descendant, depth)
WITH RECURSIVE dept_path AS (
    -- 自身到自身
    SELECT dept_id AS ancestor, dept_id AS descendant, 0 AS depth
    FROM sys_dept WHERE del_flag = '0'
    UNION ALL
    -- 父→子
    SELECT dp.ancestor, d.dept_id, dp.depth + 1
    FROM dept_path dp
    INNER JOIN sys_dept d ON d.parent_id = dp.descendant
    WHERE d.del_flag = '0'
)
SELECT * FROM dept_path;
```

## 13. 异常处理与降级策略

| 场景 | 行为 | 理由 |
|------|------|------|
| `UserContextHolder.get()` 返回 null | 跳过过滤（放行） | 内部 Feign 调用/定时任务无用户上下文 |
| 用户无角色 | 返回空集（`1=0`） | 安全降级：无权限则不可见 |
| `DataScopeHandler` 查询异常 | 记录日志 + 返回空集 | 安全降级：宁可不可见，不可越权 |
| JSqlParser 解析失败 | 记录日志 + 放行原 SQL | 避免阻断业务，但需告警 |
| `DataScopeContext.isDisabled()` | 跳过过滤 | 编程式显式跳过 |
| `@DataScope(disabled = true)` | 跳过过滤 | 注解式显式跳过 |

> **安全原则**：当不确定是否应该过滤时，**默认放行**（不阻断业务），但记录 WARN 日志。数据权限是"锦上添花"的安全增强，不应成为系统可用性的单点故障。对于高安全场景，可通过配置切换为"默认拒绝"模式。
