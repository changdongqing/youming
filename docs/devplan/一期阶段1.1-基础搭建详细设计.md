## 1. 阶段目标

搭建 `pig-rm`（研发管理）模块的 Maven 工程、启动类、基础配置，注册到 Nacos，配置网关路由，完成 Flyway 空迁移占位。此阶段结束后：

- `pig-rm-biz` 可独立启动（微服务模式，端口 4004）并注册到 Nacos；
- `pig-boot` 单体模式可聚合 `pig-rm-biz`；
- 网关 `/admin/rm/**` 路由可达，请求能转发到 `pig-rm-biz` 的健康检查端点；
- `sys_menu` 中已有"研发管理"一级菜单（前端可见空菜单骨架）；
- Flyway V18 空占位脚本已就位。

## 2. 工程结构

参照 `pig-ontology` 的单模块布局（`api` 包内嵌于 `-biz`，不拆独立 `-api` jar）。

```
server/pig-rm/
├── pom.xml                                    # 父 POM，packaging=pom
└── pig-rm-biz/
    ├── pom.xml                                # 业务模块 POM，packaging=jar
    └── src/main/
        ├── java/com/pig4cloud/pig/rm/
        │   ├── PigRmApplication.java          # 启动类
        │   ├── api/                            # 对外 API（后续阶段填充）
        │   │   ├── dto/
        │   │   ├── vo/
        │   │   └── entity/
        │   ├── controller/                     # 控制器（后续阶段填充）
        │   ├── service/
        │   ├── mapper/
        │   └── config/                         # 模块配置
        └── resources/
            └── application.yml
```

> 与 `pig-ontology` 一致：无独立 `pig-rm-api` 子模块；`api` 包（entity/dto/vo）内嵌在 `pig-rm-biz` 中。后续如需被其他服务 Feign 调用，再按需拆分。

## 3. 后端工程详细设计

### 3.1 父 POM — `server/pig-rm/pom.xml`

```xml
<?xml version="1.0" encoding="UTF-8"?>

         xsi:schemaLocation="http://maven.apache.org/POM/4.0.0 https://maven.apache.org/xsd/maven-4.0.0.xsd">
    <modelVersion>4.0.0</modelVersion>

    <!-- 继承 pig 根 POM -->
    <parent>
        <groupId>com.pig4cloud</groupId>
        <artifactId>pig</artifactId>
        <version>4.0.0</version>
    </parent>

    <artifactId>pig-rm</artifactId>
    <packaging>pom</packaging>
    <description>研发管理业务模块</description>
```

### 3.3 启动类 — `PigRmApplication.java`

```java
package com.pig4cloud.pig.rm;

import com.pig4cloud.pig.common.security.annotation.EnablePigResourceServer;
import com.pig4cloud.pig.common.swagger.annotation.EnableOpenApi;
import org.springframework.boot.SpringApplication;
import org.springframework.boot.autoconfigure.SpringBootApplication;
import org.springframework.cloud.client.discovery.EnableDiscoveryClient;
import org.springframework.scheduling.annotation.EnableScheduling;

/**
 * 研发管理业务模块启动类
 *
 * @author youming
 * @date 2026-07-29
 */
@EnableOpenApi("rm")
@EnablePigResourceServer
@EnableDiscoveryClient
@EnableScheduling
@SpringBootApplication
public class PigRmApplication {

    public static void main(String[] args) {
        SpringApplication.run(PigRmApplication.class, args);
    }
}
```

**注意**：参照 ontology，不使用 `@ComponentScan`/`@MapperScan`，依赖默认基础包 `com.pig4cloud.pig` 扫描（单体 `PigBootApplication` 也扫描此包）。修正 ontology 中存在的重复 import 问题。

### 3.4 应用配置 — `application.yml`

```yaml
server:
  port: 4004

spring:
  application:
    name: @artifactId@
  cloud:
    nacos:
      username: @nacos.username@
      password: @nacos.password@
      discovery:
        server-addr: ${NACOS_HOST:pig-register}:${NACOS_PORT:8848}
      config:
        server-addr: ${spring.cloud.nacos.discovery.server-addr}
    # 禁用 Spring Cloud Gateway server webflux（本服务为 WebMVC）
    gateway:
      server:
        webflux:
          redis:
            enabled: false
          enabled: false
  config:
    import:
      - optional:nacos:application-@profiles.active@.yml
      - optional:nacos:${spring.application.name}-@profiles.active@.yml
```

**端口分配**：4004（ontology 为 4003，upms 为 4000）。

**Nacos 配置**：本机环境 `NACOS_HOST` 默认 `pig-register`（容器 `devops-nacos`），如直连本机可设 `NACOS_HOST=127.0.0.1`。

数据源由 Nacos 共享配置 `application-dev.yml` 统一管理（复用 pig 全局配置），连接 `mingwanwudb`：

```yaml
spring:
```

## 4. 网关路由配置

在 `pig-gateway` 的 Nacos 配置（`pig-gateway-dev.yml`）中追加路由规则：

```yaml
spring:
  cloud:
    gateway:
      routes:
        # ... 已有路由 ...
        - id: pig-rm
          uri: lb://pig-rm-biz
          predicates:
            - Path=/admin/rm/**
          filters:
            - StripPrefix=1
```

**路由说明**：

| 外部请求路径 | StripPrefix=1 后 | 转发到 |
| --- | --- | --- |
| `/admin/rm/requirement/page` | `/rm/requirement/page` | `pig-rm-biz`（4004） |
| `/admin/rm/dev-task/page` | `/rm/dev-task/page` | `pig-rm-biz` |

> Controller 中方法路径写 `/rm/xxx`（不含 `/admin` 前缀），与 ontology 的 `/ont/xxx` 模式一致。

## 7. pig-boot 单体聚合

在 `pig-boot` 的 POM 中追加 `pig-rm-biz` 依赖（profile=boot）：

```xml
<!-- 在 pig-boot pom.xml 的 boot profile dependencies 中追加 -->
<dependency>
    <groupId>com.pig4cloud</groupId>
    <artifactId>pig-rm-biz</artifactId>
    <version>${project.version}</version>
</dependency>
```

单体模式 `PigBootApplication` 默认扫描 `com.pig4cloud.pig` 包，自动发现 `pig-rm` 的 Controller/Service/Mapper，无需额外配置。context-path `/admin` 使得路径统一为 `/admin/rm/xxx`。
