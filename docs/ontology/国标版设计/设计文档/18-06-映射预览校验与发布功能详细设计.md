# 映射预览、校验与发布功能详细设计

> 模块：18 数据源映射  
> 功能编号：18-06  
> 前置：09 校验、14 版本、18-02～18-05  
> 设计日期：2026-07-14

## 1. 目标

在映射进入生产执行前完成配置静态校验、源元数据校验、抽样预览、目标Schema校验、敏感字段识别和发布门禁，避免错误配置通过全量同步污染实例数据。

## 2. 原则

- 预览默认只读，不写实例事实表和Outbox；
- 校验结果必须绑定配置revision、configHash、本体版本和元数据hash；
- WARNING可由有权限用户确认，VIOLATION阻断发布；
- 抽样通过不等于全量无错误，生产作业仍需记录级校验；
- 预览结果不持久化原始整行数据；
- 发布必须重新检查校验以来的所有依赖漂移。

## 3. 校验层次

| 层次 | 内容 | 失败级别 |
|---|---|---|
| L1 配置结构 | 必填、状态、唯一编码、JSON Schema | VIOLATION |
| L2 数据源元数据 | 对象/列/PK/FK、白名单、hash | VIOLATION/WARNING |
| L3 目标Schema | 实体类型、属性domain/range、单位、枚举 | VIOLATION |
| L4 本体版本 | current version、constraint、workspace revision | VIOLATION |
| L5 执行计划 | 模板、转换器、过滤DSL、排序依赖 | VIOLATION |
| L6 抽样数据 | IRI、类型转换、空值、重复键、关系缺失 | VIOLATION/WARNING |
| L7 安全合规 | 敏感列、凭证、字段策略、禁止列 | VIOLATION/WARNING |
| L8 增量能力 | 游标、删除检测、乱序风险 | VIOLATION/WARNING |

## 4. 校验报告表

```sql
CREATE TABLE ont_mapping_validation_report (
  id bigint NOT NULL,
  mapping_version_id bigint NOT NULL,
  report_status varchar(16) NOT NULL DEFAULT 'RUNNING',
  trigger_type varchar(16) NOT NULL,
  config_revision bigint NOT NULL,
  candidate_config_hash varchar(64) NOT NULL,
  ontology_version_id bigint NOT NULL,
  workspace_revision bigint NOT NULL,
  metadata_hash_summary varchar(64) NOT NULL,
  sample_size integer NOT NULL DEFAULT 0,
  violation_count integer NOT NULL DEFAULT 0,
  warning_count integer NOT NULL DEFAULT 0,
  info_count integer NOT NULL DEFAULT 0,
  summary_json jsonb NOT NULL DEFAULT '{}'::jsonb,
  started_at timestamp NOT NULL DEFAULT now(),
  completed_at timestamp DEFAULT NULL,
  requested_by varchar(64) NOT NULL,
  trace_id varchar(64) DEFAULT NULL,
  create_by varchar(64) DEFAULT ' ',
  create_time timestamp NOT NULL DEFAULT now(),
  update_by varchar(64) DEFAULT ' ',
  update_time timestamp DEFAULT NULL,
  del_flag char(1) NOT NULL DEFAULT '0',
  PRIMARY KEY (id),
  CONSTRAINT fk_ont_map_val_version FOREIGN KEY (mapping_version_id)
    REFERENCES ont_mapping_version(id) ON DELETE RESTRICT,
  CONSTRAINT fk_ont_map_val_ontology_version FOREIGN KEY (ontology_version_id)
    REFERENCES ont_ontology_version(id) ON DELETE RESTRICT,
  CONSTRAINT ck_ont_map_val_status
    CHECK (report_status IN ('RUNNING','PASSED','FAILED','CANCELLED')),
  CONSTRAINT ck_ont_map_val_trigger
    CHECK (trigger_type IN ('MANUAL','PUBLISH_RECHECK','SYSTEM')),
  CONSTRAINT ck_ont_map_val_counts
    CHECK (sample_size >= 0 AND violation_count >= 0 AND warning_count >= 0 AND info_count >= 0),
  CONSTRAINT ck_ont_map_val_del CHECK (del_flag IN ('0','1'))
);

CREATE INDEX idx_ont_map_val_version_time
  ON ont_mapping_validation_report(mapping_version_id, create_time DESC)
  WHERE del_flag = '0';
```

## 5. 校验问题表

```sql
CREATE TABLE ont_mapping_validation_issue (
  id bigint NOT NULL,
  report_id bigint NOT NULL,
  severity varchar(16) NOT NULL,
  issue_code varchar(64) NOT NULL,
  scope_type varchar(24) NOT NULL,
  scope_ref varchar(128) DEFAULT NULL,
  message varchar(512) NOT NULL,
  suggestion varchar(512) DEFAULT NULL,
  source_record_key_hash varchar(64) DEFAULT NULL,
  sample_context jsonb DEFAULT NULL,
  acknowledged char(1) NOT NULL DEFAULT '0',
  acknowledged_by varchar(64) DEFAULT NULL,
  acknowledged_at timestamp DEFAULT NULL,
  sort_order integer NOT NULL DEFAULT 0,
  create_by varchar(64) DEFAULT 'system',
  create_time timestamp NOT NULL DEFAULT now(),
  update_by varchar(64) DEFAULT 'system',
  update_time timestamp DEFAULT NULL,
  del_flag char(1) NOT NULL DEFAULT '0',
  PRIMARY KEY (id),
  CONSTRAINT fk_ont_map_issue_report FOREIGN KEY (report_id)
    REFERENCES ont_mapping_validation_report(id) ON DELETE CASCADE,
  CONSTRAINT ck_ont_map_issue_severity CHECK (severity IN ('VIOLATION','WARNING','INFO')),
  CONSTRAINT ck_ont_map_issue_scope
    CHECK (scope_type IN ('PROJECT','VERSION','SOURCE','ENTITY','FIELD','RELATION','RECORD')),
  CONSTRAINT ck_ont_map_issue_ack CHECK (acknowledged IN ('0','1')),
  CONSTRAINT ck_ont_map_issue_del CHECK (del_flag IN ('0','1'))
);

CREATE INDEX idx_ont_map_issue_report_severity
  ON ont_mapping_validation_issue(report_id, severity, sort_order)
  WHERE del_flag = '0';

ALTER TABLE ont_mapping_version
  ADD CONSTRAINT fk_ont_map_version_validation_report
  FOREIGN KEY (validation_report_id)
  REFERENCES ont_mapping_validation_report(id) ON DELETE SET NULL;
```

`sample_context`只允许脱敏、截断后的字段：列名、类型、值长度、值哈希、是否为空、转换结果类型。禁止保存password、salt、token、完整手机号、完整邮箱和整行JSON。

## 6. 预览请求与结果

```java
public record MappingPreviewRequest(
    Long mappingVersionId,
    List<String> entityMappingCodes,
    Integer sampleSize,
    PreviewSampleMode sampleMode,
    Map<String, String> startKeys
) {}
```

样本模式：

- `FIRST_N`：按主键升序前N条，确定性最强；
- `KEYS`：用户提交指定记录键；
- `RANDOM`：V1不实现，数据库随机排序成本高且不可重放。

结果：

```json
{
  "reportId": 1,
  "entityResults": [{
    "mappingCode":"USER_ACCOUNT",
    "sourceRecordKeyHash":"...",
    "generatedIri":".../user-account/1",
    "label":"管理员（admin）",
    "action":"WOULD_CREATE",
    "values":[
      {"propertyId":954002,"resultType":"STRING","maskedPreview":"ad***"}
    ],
    "issues":[]
  }],
  "relationResults": [],
  "truncated": false
}
```

对于敏感目标属性，预览仅返回脱敏值；普通列默认最大展示128字符。

## 8. 禁止字段和敏感字段

首期内置名称规则仅作为安全兜底，不替代显式策略：

```text
password, passwd, salt, secret, token, private_key,
access_key, refresh_token, credential
```

匹配规则：忽略大小写，按下划线/驼峰分词后精确词匹配，避免`password_expire_flag`被完全禁止时丢失合理状态字段。建议分类：

- `password/salt/secret/token/private_key`：默认VIOLATION，禁止映射；
- `phone/email/openid/id_card`：WARNING或根据数据属性安全级别要求加密；
- `password_expire_flag/password_modify_time`：非凭证明文，但组织账号首期不映射，INFO/WARNING。

发布时禁止列即使目标属性标为敏感也不能通过确认放行。

## 9. 抽样唯一性

- 主键/唯一键由元数据证明时无需仅依赖样本；
- 视图自选键需要样本和受限COUNT检查；
- V1可执行：

```sql
SELECT key_cols, count(*)
FROM allowed_view
GROUP BY key_cols
HAVING count(*) > 1
LIMIT 1
```

该SQL由Connector根据受控列生成，必须设置statement timeout。大视图超时则发布阻断，不能把“未发现重复”当作唯一证明。

## 10. SHACL预校验

预览将样本转换为临时RDF模型或调用模块09实例级校验器：

- 不写数据库；
- 包含样本实例及样本内可解析关系；
- 校验数据类型、必填、枚举、单位、domain/range、功能性；
- 对依赖全图唯一性的规则，查询现有关系库并模拟本批次增量；
- 报告明确`SAMPLE_ONLY`，不得标成全量通过。

## 11. 增量和删除能力校验

### 11.1 增量

- incrementalColumn存在；
- 类型为TIMESTAMP或NUMERIC；
- keyColumns用于同值游标稳定排序；
- 源更新时间允许NULL时，NULL记录只能由首次FULL摄入；
- 目标数据库时区明确；
- 无更新时间列则INCREMENTAL不可发布为计划运行类型。

### 11.2 删除

- 有软删除列：可按值检测，但Filter DSL不得提前排除全部删除值；否则为VIOLATION；
- FULL作业：可通过seen set/miss count检测物理删除；
- INCREMENTAL无CDC且无软删除列：物理删除不可检测，产生WARNING；
- JOIN_TABLE删除同理；
- deleteStrategy=SOFT_DELETE且不可检测时至少WARNING，高风险确认；
- BLOCK_AND_REVIEW不降低检测要求。

## 12. 发布门禁

发布必须满足：

1. 版本状态VALIDATED；
2. 报告PASSED且violationCount=0；
3. 所有必须确认的WARNING已acknowledged；
4. config revision/hash与报告一致；
5. Ontology版本、workspace revision与报告一致；
6. 元数据依赖hash未发生阻断性漂移；
7. 所有数据源ACTIVE且测试对应当前revision；
8. 至少一个启用实体映射；
9. 映射编译成功；
10. 当前用户拥有工程PUBLISH ACL和`ontology_mapping_publish`；
11. 高风险变化已二次确认/审批；
12. 发布事务按18-03执行。

## 13. WARNING确认

- 只有`ontology_mapping_publish`权限且拥有工程PUBLISH ACL的用户可确认；
- 确认写issue的ack字段和审计；
- 配置或依赖变化使旧确认失效；
- 禁止批量“全部忽略”而不展示问题；
- VIOLATION没有确认接口。

典型可确认WARNING：

- INCREMENTAL无法发现物理删除；
- label可能为空；
- 源列长度大于目标UI建议；
- 视图依赖无法获得FK元数据但键已显式配置。

## 14. API

> 所有路径前缀为 `/ontology/data-mapping`。

| 方法 | 路径 | 权限 |
|---|---|---|
| POST | `/versions/{id}/preview` | ontology_mapping_validate |
| POST | `/versions/{id}/validate` | ontology_mapping_validate |
| GET | `/validation-reports/{id}` | ontology_mapping_view |
| GET | `/validation-reports/{id}/issues` | ontology_mapping_view |
| POST | `/validation-issues/{id}/acknowledge` | ontology_mapping_publish |
| POST | `/versions/{id}/publish` | ontology_mapping_publish |
| POST | `/versions/{id}/publish/prepare` | ontology_mapping_publish，返回风险摘要 |

预览和校验为异步任务时可复用作业框架，但报告事实仍写本模块报告表。V1样本上限100且超时15秒，可同步返回；超过阈值应拒绝而非后台无限运行。

## 17. 测试与验收

- 配置revision变化后旧报告无法发布；
- 本体版本或元数据漂移使报告过期；
- 禁止字段不能通过WARNING确认绕过；
- 敏感值预览只返回脱敏结果；
- 抽样不写实例、来源绑定和Outbox；
- 视图唯一性检查超时按失败关闭；
- VIOLATION阻断，WARNING需逐项确认；
- 工作区存在未发布Schema变化时生产发布失败；
- 发布Prepare准确显示IRI、主键、删除策略等高风险变化；
- 报告和日志不保存原始整行。
