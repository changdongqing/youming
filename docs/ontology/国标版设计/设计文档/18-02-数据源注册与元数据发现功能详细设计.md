# 数据源注册与元数据发现功能详细设计

> 模块：18 数据源映射  
> 功能编号：18-02  
> V1连接器：PostgreSQL JDBC  
> 设计日期：2026-07-14

## 1. 目标

提供受控的数据源注册、凭证加密、连接测试、元数据发现和只读数据扫描能力，为映射设计器和同步作业提供统一Connector SPI。

## 2. 设计边界

### 2.1 包含

- PostgreSQL JDBC连接；
- 主机/端口/数据库或完整JDBC URL配置；
- AES-GCM凭证加密，密钥不可用时失败关闭；
- Schema、表、视图、列、主键、唯一键和外键发现；
- 元数据缓存和指纹；
- 只读、超时、分页、白名单扫描；
- 连接池按需创建、空闲回收和凭证变更失效。

### 2.2 不包含

- 任意SQL控制台；
- DDL/DML写入源库；
- 存储过程；
- 跨数据库联邦查询；
- V1中的MySQL/Oracle等实现；
- 将凭证返回前端或写入日志。

## 3. 为什么不直接复用代码生成数据源表

`gen_datasource_conf`属于可选的`pig-codegen`业务模块，Ontology在`pig-boot`中可用但不应依赖代码生成模块是否安装。直接复用会产生：

- 模块依赖反转；
- 删除/权限语义不一致；
- 凭证生命周期由代码生成页面控制；
- Ontology无法增加Schema白名单、只读策略和安全级别。

V1建立`ont_data_source`，底层连接创建可复用`pig-common-datasource`依赖或Spring Boot JDBC/Hikari能力。后续若建设公共数据源中心，再通过迁移和适配器合并，不在V1耦合`gen_datasource_conf`。

`ConnectorRegistry`按`sourceType/databaseType`选择实现。V1唯一实现：

```text

```

## 5. 数据源表

```sql
CREATE TABLE ont_data_source (
  id bigint NOT NULL,
  source_code varchar(64) NOT NULL,
  source_name varchar(128) NOT NULL,
  source_type varchar(16) NOT NULL DEFAULT 'JDBC',
  database_type varchar(32) NOT NULL DEFAULT 'POSTGRESQL',
  connection_mode varchar(16) NOT NULL DEFAULT 'HOST',
  connection_config jsonb NOT NULL,
  credential_ciphertext bytea NOT NULL,
  credential_iv bytea NOT NULL,
  credential_key_id varchar(64) NOT NULL,
  allowed_schemas jsonb NOT NULL DEFAULT '[]'::jsonb,
  allowed_objects jsonb NOT NULL DEFAULT '[]'::jsonb,
  status varchar(16) NOT NULL DEFAULT 'DRAFT',
  revision bigint NOT NULL DEFAULT 0,
  last_test_status varchar(16) DEFAULT NULL,
  last_test_revision bigint DEFAULT NULL,
  last_test_at timestamp DEFAULT NULL,
  last_test_latency_ms bigint DEFAULT NULL,
  last_test_error_code varchar(64) DEFAULT NULL,
  metadata_refreshed_at timestamp DEFAULT NULL,
  security_level_code varchar(32) NOT NULL DEFAULT 'RESTRICTED',
  remarks varchar(255) DEFAULT NULL,
  create_by varchar(64) DEFAULT ' ',
  create_time timestamp NOT NULL DEFAULT now(),
  update_by varchar(64) DEFAULT ' ',
  update_time timestamp DEFAULT NULL,
  del_flag char(1) NOT NULL DEFAULT '0',
  PRIMARY KEY (id),
  CONSTRAINT fk_ont_ds_security_level FOREIGN KEY (security_level_code)
    REFERENCES ont_security_level(level_code) ON DELETE RESTRICT,
  CONSTRAINT ck_ont_ds_source_type CHECK (source_type IN ('JDBC')),
  CONSTRAINT ck_ont_ds_database_type CHECK (database_type IN ('POSTGRESQL')),
  CONSTRAINT ck_ont_ds_connection_mode CHECK (connection_mode IN ('HOST','JDBC_URL')),
  CONSTRAINT ck_ont_ds_status CHECK (status IN ('DRAFT','ACTIVE','DISABLED')),
  CONSTRAINT ck_ont_ds_test CHECK (last_test_status IS NULL OR last_test_status IN ('SUCCESS','FAILED')),
  CONSTRAINT ck_ont_ds_test_revision CHECK (last_test_revision IS NULL OR last_test_revision >= 0),
  CONSTRAINT ck_ont_ds_revision CHECK (revision >= 0),
  CONSTRAINT ck_ont_ds_del CHECK (del_flag IN ('0','1'))
);

CREATE UNIQUE INDEX uk_ont_ds_code
  ON ont_data_source(source_code) WHERE del_flag = '0';
CREATE INDEX idx_ont_ds_status
  ON ont_data_source(status, source_type, database_type) WHERE del_flag = '0';
```

### 5.1 connection_config

HOST模式：

```json
{
  "host": "127.0.0.1",
  "port": 5432,
  "database": "youmingdb",
  "sslMode": "disable",
  "connectTimeoutSeconds": 5,
  "socketTimeoutSeconds": 30,
  "queryTimeoutSeconds": 30,
  "fetchSize": 500
}
```

JDBC_URL模式：

```json
{
  "jdbcUrl": "jdbc:postgresql://host:5432/db?sslmode=require",
  "queryTimeoutSeconds": 30,
  "fetchSize": 500
}
```

`connection_config`不得包含username、password、token、私钥。完整JDBC URL需解析并拒绝`user/password`参数。

### 5.2 凭证载荷

加密前：

```json
{
  "username": "ontology_reader",
  "password": "..."
}
```

不保存可逆凭证摘要，不提供“查看密码”。更新凭证时前端只提交新值，详情接口返回：

```json
{
  "credentialConfigured": true,
  "credentialKeyId": "仅管理员可见的非敏感keyId",
  "usernameMasked": "ont***der"
}
```

## 6. 凭证加密

新增：

```java
public interface DataSourceCredentialCryptoService {
    EncryptedCredential encrypt(Long sourceId, DataSourceCredential credential);
    DataSourceCredential decrypt(Long sourceId, EncryptedCredential encrypted);
}
```

实现复用模块36`KeyProvider`和AES-256-GCM算法，AAD绑定：

```text
ontology-data-source:{sourceId}:{sourceCode}:{revision}
```

修改连接配置或凭证时：

1. 先生成新revision；
2. 使用新revision加密；
3. 同事务更新密文、IV、keyId和revision；
4. 连接池缓存按sourceId失效；
5. 状态改为DRAFT，必须重新测试；
6. 解密失败拒绝连接，禁止回退明文。

不能直接复用`SensitiveValueCryptoService`的实例值AAD，因为其AAD固定为ontologyId/instanceId/dataPropertyId；应复用底层KeyProvider并建立数据源专用服务。

## 7. 元数据缓存表

```sql
CREATE TABLE ont_data_source_metadata (
  id bigint NOT NULL,
  source_id bigint NOT NULL,
  schema_name varchar(128) NOT NULL,
  object_name varchar(128) NOT NULL,
  object_type varchar(16) NOT NULL,
  metadata_json jsonb NOT NULL,
  metadata_hash varchar(64) NOT NULL,
  source_revision bigint NOT NULL,
  refreshed_at timestamp NOT NULL DEFAULT now(),
  expires_at timestamp NOT NULL,
  create_by varchar(64) DEFAULT 'system',
  create_time timestamp NOT NULL DEFAULT now(),
  update_by varchar(64) DEFAULT 'system',
  update_time timestamp DEFAULT NULL,
  del_flag char(1) NOT NULL DEFAULT '0',
  PRIMARY KEY (id),
  CONSTRAINT fk_ont_ds_meta_source FOREIGN KEY (source_id)
    REFERENCES ont_data_source(id) ON DELETE CASCADE,
  CONSTRAINT ck_ont_ds_meta_type CHECK (object_type IN ('TABLE','VIEW')),
  CONSTRAINT ck_ont_ds_meta_del CHECK (del_flag IN ('0','1'))
);

CREATE UNIQUE INDEX uk_ont_ds_meta_object
  ON ont_data_source_metadata(source_id, schema_name, object_name)
  WHERE del_flag = '0';
CREATE INDEX idx_ont_ds_meta_expire
  ON ont_data_source_metadata(source_id, expires_at)
  WHERE del_flag = '0';
```

`metadata_json`规范结构：

```json
{
  "columns": [
    {"name":"user_id","jdbcType":"BIGINT","nullable":false,"ordinal":1},
    {"name":"username","jdbcType":"VARCHAR","size":64,"nullable":true,"ordinal":2}
  ],
  "primaryKey": ["user_id"],
  "uniqueKeys": [],
  "foreignKeys": [
    {"name":"fk_x","columns":["dept_id"],"targetSchema":"public","targetObject":"sys_dept","targetColumns":["dept_id"]}
  ]
}
```

元数据哈希由规范化JSON计算，列顺序按ordinal，键集合按名称排序。发布映射时保存所依赖对象的`metadata_hash`；执行前发现漂移时按18-06规则阻断或警告。

## 8. SQL安全

### 8.1 标识符

- Schema、表、列必须来自当前元数据快照；
- 使用PostgreSQL双引号转义标识符；
- 不接受用户提交的拼接标识符；
- 对象必须同时通过`allowed_schemas/allowed_objects`白名单；
- 默认拒绝`pg_catalog`、`information_schema`和以`pg_`开头的系统对象。

### 8.2 过滤条件

V1使用结构化DSL：

```json
{
  "op": "AND",
  "items": [
    {"column":"del_flag","operator":"EQ","value":"0"},
    {"column":"update_time","operator":"GTE_CURSOR","cursorField":"updatedAt"}
  ]
}
```

允许操作符：

```text
EQ, NE, GT, GTE, LT, LTE, IN, IS_NULL, IS_NOT_NULL,
STARTS_WITH, ENDS_WITH, CONTAINS, GTE_CURSOR
```

值全部使用PreparedStatement参数。禁止RAW、SUBQUERY、FUNCTION、UNION和注释符。

### 8.3 只读连接

每次扫描：

```text
connection.setReadOnly(true)
BEGIN READ ONLY
SET LOCAL statement_timeout = ...
SET LOCAL lock_timeout = ...
```

数据库账号也必须是只读账号。应用层只读不能替代数据库权限。

## 9. 连接池

- 每个数据源按需创建独立小池，默认最大2连接；
- 缓存键为`sourceId + revision`；
- 空闲10分钟关闭；
- 配置修改、停用、删除立即关闭旧池；
- 连接测试使用临时连接或池中连接，但不扩大池；
- 不把动态源注册进全局业务`DynamicRoutingDataSource`，避免`@DS`上下文泄漏；
- 关闭失败记录WARN，不阻塞配置事务完成。

## 10. 元数据发现流程

```text
鉴权
 → 读取数据源（不返回密文）
 → 解密凭证
 → 获取Connector
 → 建立只读连接
 → DatabaseMetaData读取Schema/Object/Column/PK/FK
 → 白名单过滤
 → 规范化元数据
 → 计算hash
 → upsert缓存
 → 更新metadata_refreshed_at
 → 写审计日志
```

一次刷新默认最多500个对象。超过上限要求按Schema或对象名过滤，防止无界扫描。

## 12. 状态规则

- 新建：DRAFT；
- 测试成功不自动ACTIVE，用户显式启用；
- 启用要求`last_test_status=SUCCESS`且`last_test_revision=revision`；
- 修改连接、凭证、白名单：DRAFT并清空测试状态；
- DISABLED禁止新作业，运行中作业在下一页读取前停止为FAILED或CANCELLED，错误码`ONT-DS-021`；
- 数据源不能在Worker中自动启用。

## 13. 数据访问审计

必须审计：

- 新增、修改、停用、删除；
- 连接测试；
- 元数据刷新；
- 读取Schema/对象列表；
- 解密失败；
- Worker建立连接和扫描开始/结束摘要。

审计`actionSummary`不包含密码、完整JDBC URL参数或源列样例值。

## 16. 测试与验收

- Testcontainers PostgreSQL连接测试成功；
- 错误密码不泄漏原始异常详情；
- URL含password参数被拒绝；
- 元数据能识别`sys_user`主键和`sys_user_post`复合主键；
- 系统Schema默认不可见；
- 白名单之外对象无法扫描；
- Filter DSL全部使用参数化SQL；
- 数据源修改后旧连接池关闭、状态回DRAFT；
- 凭证密文不可在Controller JSON、日志、异常和审计中出现；
- 同一sourceId/revision并发获取只创建一个池；
- Metadata hash对相同结构稳定，对列类型/主键变化敏感；
- 只读账号无法执行写语句，Connector本身不暴露写方法。
