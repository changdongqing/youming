# 运行时实例摄入与来源绑定功能详细设计

> 模块：18 数据源映射  
> 功能编号：18-01  
> 前置：08 实体实例、09 校验、14 版本演化、26 EDA、36 安全  
> 设计日期：2026-07-14

## 1. 目标与边界

本功能提供面向内部模块的统一程序化实例写入入口，将映射记录转换为可校验、可幂等、可追溯的Ontology实例、数据属性值和对象属性断言。

本功能不负责连接源数据库、不解析映射配置、不调度作业，也不向外部客户端开放任意批量写接口。

## 2. 核心原则

1. **单一写入规则**：数据源映射、未来IoT、规则和API导入统一复用摄入服务。
2. **稳定外部身份**：来源绑定是幂等事实，不以可变label、IRI模板或值内容代替。
3. **关系库事实源**：继续使用`ont_entity_instance`及值/关系表，不引入Triplestore双写。
4. **事务内事件**：实例变更与Outbox事件同事务提交。
5. **失败关闭**：工作区锁、版本漂移、安全策略、Schema校验任一失败均拒绝写入。
6. **来源所有权**：来源生成值和关系有明确所有者，避免全量同步删除人工数据。

## 3. 服务接口

```java
public interface OntologyInstanceIngestionService {

    IngestionResult upsertEntity(EntityIngestionCommand command);

    RelationIngestionResult upsertRelation(RelationIngestionCommand command);

    DeactivationResult deactivateEntity(SourceIdentity sourceIdentity,
                                         DeleteStrategy strategy,
                                         IngestionContext context);

    BatchIngestionResult ingestBatch(List<EntityIngestionCommand> commands,
                                     IngestionContext context);
}
```

该接口为Java内部SPI。若未来Ontology独立微服务，再增加仅供服务间调用的受保护Internal Controller；V1不创建公网批量写API。

`ingestBatch`的`List`入参仅适用于小批次（如重试作业的≤1000条）。大批量同步作业（万级记录）**不应**将全部记录加载到`List`后传入，而应由调用方（`MappingJobWorker`）按页读取、逐条或小批次调用`upsertEntity`。后续如需流式摄入，可在此接口增加`Stream<EntityIngestionCommand>`重载，但V1不强制实现。


### 3.2 SourceIdentity

```java
public record SourceIdentity(
    Long sourceId,
    Long mappingProjectId,
    Long mappingVersionId,
    String entityMappingCode,
    String sourceObject,
    String sourceRecordKey
) {}
```

`sourceRecordKey`是规范化复合键字符串，不保存未经转义的任意JSON。规范格式：

```text
column1=base64url(value1)&column2=base64url(value2)
```

列名按映射定义顺序排序。另存SHA-256摘要用于索引和日志。

### 3.4 IngestionContext

包含：

- 作业ID、记录ID；
- 请求人和授权上下文摘要；
- 映射版本配置哈希；
- 追踪ID；
- 执行时间；
- 是否预览；
- 是否允许受控人工覆盖。

预览上下文不得进入持久化写分支。

## 4. 来源绑定表

```sql

  id bigint NOT NULL,
  source_id bigint NOT NULL,
  mapping_project_id bigint NOT NULL,
  current_mapping_version_id bigint NOT NULL,
  entity_mapping_code varchar(64) NOT NULL,
  source_object varchar(256) NOT NULL,
  source_record_key varchar(1024) NOT NULL,
  source_record_key_hash varchar(64) NOT NULL,
  instance_id bigint NOT NULL,
  source_updated_at timestamp DEFAULT NULL,
  content_hash varchar(64) DEFAULT NULL,
  first_seen_job_id bigint DEFAULT NULL,
  last_seen_job_id bigint DEFAULT NULL,
  first_seen_at timestamp NOT NULL DEFAULT now(),
  last_seen_at timestamp NOT NULL DEFAULT now(),
  binding_status varchar(16) NOT NULL DEFAULT 'ACTIVE',
  miss_count integer NOT NULL DEFAULT 0,
  create_by varchar(64) DEFAULT 'system',
  create_time timestamp NOT NULL DEFAULT now(),
  update_by varchar(64) DEFAULT 'system',
  update_time timestamp DEFAULT NULL,
  del_flag char(1) NOT NULL DEFAULT '0',
  PRIMARY KEY (id),
  CONSTRAINT fk_ont_binding_source FOREIGN KEY (source_id)
    REFERENCES ont_data_source(id) ON DELETE RESTRICT,

    REFERENCES ont_entity_instance(id) ON DELETE RESTRICT,

    CHECK (binding_status IN ('ACTIVE','INACTIVE','MISSING','CONFLICT')),
  CONSTRAINT ck_ont_binding_del CHECK (del_flag IN ('0','1'))

CREATE UNIQUE INDEX uk_ont_binding_identity
  ON ont_source_instance_binding
  (mapping_project_id, entity_mapping_code, source_record_key_hash)
  WHERE del_flag = '0';

CREATE UNIQUE INDEX uk_ont_binding_instance_mapping
  ON ont_source_instance_binding (mapping_project_id, entity_mapping_code, instance_id)
  WHERE del_flag = '0';

  ON ont_source_instance_binding (mapping_project_id, last_seen_job_id, binding_status)
  WHERE del_flag = '0';
```

唯一索引使用哈希控制索引长度，但插入或查询命中后必须再次比较完整`source_record_key`，理论哈希碰撞视为`ONT-ING-009`并失败关闭。

## 7. 实例表改造

V22需删除并重建V10的来源约束，具体名称以数据库实际约束为准：

```sql
ALTER TABLE ont_entity_instance
  DROP CONSTRAINT IF EXISTS ck_ont_entity_instance_source_type,
  DROP CONSTRAINT IF EXISTS ck_ont_entity_instance_source_builtin;

ALTER TABLE ont_entity_instance
  ADD CONSTRAINT ck_ont_entity_instance_source_type
    CHECK (source_type IN (
      'APPENDIX_D','EXTENSION','MANUAL','DATA_MAPPING',
      'IOT','RULE','IMPORT','API'
    )),
  ADD CONSTRAINT ck_ont_entity_instance_source_builtin
    CHECK (
      (source_type = 'APPENDIX_D' AND is_builtin = '1') OR
      (source_type <> 'APPENDIX_D' AND is_builtin = '0')
    );
```

历史`EXTENSION`实例不迁移为`MANUAL`，保持向后兼容。新页面人工创建可继续使用`EXTENSION`，后续统一语义时另发迁移。

## 8. Upsert算法

### 8.1 实体摄入

```text
1. 校验映射版本、本体版本、工作区和授权上下文
2. 规范化SourceIdentity并计算keyHash
3. 查询来源绑定；不存在时尝试插入占位绑定
4. 并发ON CONFLICT后重新读取并锁定绑定行
5. 若绑定不存在：
   5.1 校验IRI唯一性
   5.2 创建source_type=DATA_MAPPING实例
   5.3 回填绑定instance_id
6. 若绑定存在：
   6.1 校验实例仍存在且ontology/type一致
   6.2 contentHash相同且sourceUpdatedAt未前进 → SKIPPED_UNCHANGED
   6.3 否则更新允许变更的label/type治理字段
7. 按fieldMappingCode合并来源拥有的数据值
8. 更新绑定contentHash、lastSeenJobId、lastSeenAt、status
9. 写Outbox事件
10. 提交事务
```

来源绑定创建需要避免先有外键后无实例的问题。实现可选择：

- 先分配实例ID和绑定ID，在同一事务插入实例后插入绑定；
- 不允许绑定表出现`instance_id=NULL`占位记录。

并发通过`uk_ont_binding_identity`兜底；冲突事务捕获唯一键异常后重新查询绑定，不通过“先查再插”假设实现幂等。

### 8.2 类型变化

默认不允许已绑定实例更换`rdf_type_id`。映射版本改变目标类型时：

- 若新旧类型相同或新类型是旧类型的更具体兼容子类，可在发布校验明确允许；
- 其他情况返回`ONT-ING-013 TYPE_CHANGE_REQUIRES_MIGRATION`；
- 必须通过模块14实例迁移或新建映射工程，不在普通同步中静默改类型。

### 8.3 IRI变化

来源绑定已存在时，默认保持原实例IRI。映射版本的IRI模板变化不会自动改写历史IRI。

需要IRI迁移时由专门迁移计划执行，并检查所有对象关系、序列化和外部引用。发布校验应将IRI模板变化标为高风险。

## 9. 属性所有权和冲突

| 策略 | 同步行为 | 人工编辑行为 |
|---|---|---|
| `SOURCE_WINS` | 源值覆盖映射拥有的旧值 | 普通实例接口拒绝修改；管理员受控覆盖后下次同步仍覆盖 |
| `MANUAL_WINS` | 无人工覆盖时更新；已覆盖则保持人工值并标记`OVERRIDDEN` | 允许有权限用户覆盖 |
| `REJECT_CONFLICT` | 检测到值与现值不同则记录失败，不覆盖 | 允许修改，但后续同步进入冲突 |

映射只能删除带本映射来源记录的值，不能按`data_property_id`整体删除所有值。一个数据属性若允许多值，不同来源可以各自拥有独立值。

手工实例接口修改带来源的值时必须调用`MappedValueWriteGuard`：

```java
public interface MappedValueWriteGuard {
    void assertWritable(Long dataValueId, SecuritySubject subject, boolean forceOverride);
}
```

## 10. 删除与失活

`deactivateEntity`策略：

- `IGNORE`：仅更新绑定`MISSING`；
- `MARK_INACTIVE`：写目标本体配置的状态数据属性，不存在状态属性则只标记绑定；
- `SOFT_DELETE`：仅当实例没有非本映射来源值/关系、没有受保护引用时软删除；
- `BLOCK_AND_REVIEW`：绑定进入`CONFLICT`并创建作业错误。

V1不在`ont_entity_instance`新增通用active字段，避免把业务状态硬编码进核心实例表。`MARK_INACTIVE`需要实体映射配置目标状态属性和失活值。

## 11. 校验顺序

1. 工作区可写；
2. 映射版本与本体版本兼容；
3. 来源身份完整；
4. 命名空间和实体类型同工程；
5. IRI格式与唯一性；
6. 数据属性适用性、类型、值域、单位、基数和唯一性；
7. 安全策略与敏感值加密；
8. 对象关系域/值域和功能性；
9. 轻量增量SHACL检查；
10. 持久化和事件。

大批次不对每条记录执行全图SHACL；只运行受影响实例的增量校验。作业结束后可按配置触发模块09异步范围校验。

## 12. 事件

实体事务可发布：

| 事件 | 条件 |
|---|---|
| `INSTANCE_INGESTED` | 新建映射实例 |
| `INSTANCE_UPDATED_FROM_SOURCE` | 值、label或来源状态变化 |
| `INSTANCE_SOURCE_UNCHANGED` | 默认不发布，仅记指标 |
| `INSTANCE_DEACTIVATED_FROM_SOURCE` | 执行失活/软删除 |
| `MAPPING_VALUE_OVERRIDDEN` | 发生受控人工覆盖 |

Payload只包含实例ID、ontologyId、entityTypeId、mappingProjectId、mappingVersionId、jobId、变更字段ID集合和摘要，不包含字面量明文。

## 14. 测试

1. 同一来源身份并发摄入100次只生成一个实例；
2. 内容哈希不变返回SKIPPED，不重复更新值和事件；
3. SOURCE_WINS仅覆盖本字段映射拥有的值；
4. 不删除人工值或其他映射来源值；
5. MANUAL_WINS人工覆盖后同步保持人工值；
6. REJECT_CONFLICT产生可重试错误且事务不部分提交；
7. IRI模板变化不自动改已有IRI；
8. 工作区MIGRATING时拒绝写入；
9. 本体版本漂移时拒绝生产写入；
10. 敏感值加密失败时不回退明文；
11. 实例、来源绑定、值来源和Outbox同事务回滚；
12. 哈希命中后完整键不相等时失败关闭；
13. 软删除不会删除被人工关系或其他来源引用的实例。

## 15. 验收标准

- 映射Worker不直接操作三张实例事实表；
- 重复执行和故障重试不产生重复实例；
- 每个映射实例都能反查来源记录和最近作业；
- 每个映射拥有的值/关系都能反查字段/关系映射；
- 人工数据与来源数据边界清晰；
- 任何错误日志和事件不包含源记录敏感明文；
- 后续模块19/20可以复用该服务而无需复制实例校验逻辑。
