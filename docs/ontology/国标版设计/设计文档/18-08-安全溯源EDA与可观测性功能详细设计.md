# 安全、溯源、EDA与可观测性功能详细设计

> 模块：18 数据源映射  
> 功能编号：18-08  
> 前置：26 EDA、36 安全与合规  
> 设计日期：2026-07-14

## 1. 目标

规定数据源映射在凭证、权限、敏感值、异步授权、审计、事件和运行指标方面的横切要求，确保映射不是绕过模块36的数据旁路，也不会把原始业务数据复制到日志和事件系统。

## 2. 威胁模型

| 威胁 | 对策 |
|---|---|
| 数据源密码泄漏 | AES-GCM加密、永不回显、日志过滤、密钥失效失败关闭 |
| 利用映射执行任意SQL | 元数据白名单、结构化DSL、参数化SQL、只读连接 |
| 越权映射高敏字段 | 工程ACL、资源策略、字段安全级别和INGEST动作 |
| 异步Worker以SYSTEM绕过权限 | 作业授权快照+已发布映射授权，不提供通用系统明文权限 |
| 预览/错误记录泄漏源数据 | 脱敏投影、值哈希、长度限制、不保存整行 |
| 事件载荷传播敏感数据 | 只发ID/摘要/计数，发布前载荷最小化检查 |
| 删除策略误删大量实例 | 高风险发布确认、连续FULL未见、审批和审计 |
| 映射配置被篡改 | 不可变发布快照、hash、乐观锁、发布事件 |

## 3. 权限模型

### 3.1 两层授权

1. pig菜单/按钮权限：控制功能入口；
2. Ontology工程ACL和数据策略：控制具体工程、实体类型、数据属性和对象属性。

用户拥有`ontology_mapping_execute`并不表示可向所有Ontology工程写入。

### 3.2 权限矩阵

| 操作 | 按钮权限 | 工程ACL | 其他 |
|---|---|---|---|
| 查看映射 | ontology_mapping_view | VIEW | 数据源详情按安全级别投影 |
| 管理数据源 | ontology_mapping_source_manage | ADMIN或映射管理员 | 凭证永不回显 |
| 编辑映射 | ontology_mapping_edit | EDIT | 仅DRAFT |
| 预览/校验 | ontology_mapping_validate | EDIT | 对目标资源执行VIEW/INGEST预判 |
| 发布 | ontology_mapping_publish | PUBLISH | 高风险变化二次确认/审批 |
| 执行 | ontology_mapping_execute | EDIT或显式执行授权 | 仅PUBLISHED |
| 重试 | ontology_mapping_retry | EDIT | 原版本仍兼容 |
| 查看作业错误 | ontology_mapping_job_view | VIEW | 敏感上下文脱敏 |
| 强制删除/游标重置 | ontology_mapping_admin | ADMIN | 高风险审批 |

## 4. 扩展模块36动作与资源

V22扩展`DataAction`：

```java
public enum DataAction {
    VIEW, EDIT, EXPORT, SPARQL, INGEST
}
```

并更新数据库约束：

```sql
ALTER TABLE ont_data_policy_rule
  DROP CONSTRAINT IF EXISTS ck_ont_policy_action;
ALTER TABLE ont_data_policy_rule
  ADD CONSTRAINT ck_ont_policy_action
  CHECK (action IN ('VIEW','EDIT','EXPORT','SPARQL','INGEST'));
```

增加安全资源类型常量：

```text
DATA_SOURCE
MAPPING_PROJECT
MAPPING_VERSION
MAPPING_JOB
ENTITY_INSTANCE（现有注释已使用，常量需补齐）
```

INGEST策略主要作用于目标实体类型、数据属性和对象属性：

- DENY：字段/关系不得发布或执行；
- MASK不适用于写入决策，INGEST遇到MASK按DENY处理，避免将脱敏值当真实数据写入；
- ALLOW：继续执行，并根据目标安全级别决定静态加密。

## 5. 数据源凭证安全

遵循18-02：

- 凭证加密服务复用模块36 KeyProvider，不复用实例值AAD；
- 密文、IV、keyId存库；
- API永不返回密文；
- 数据源修改后旧池立即失效；
- 密钥不可用或解密失败时拒绝连接；
- 连接测试异常转换为稳定错误码，不返回驱动原始URL；
- 备份包含密文，不包含应用主密钥；
- 凭证轮换只影响后续连接，不修改历史作业。

## 6. 异步授权上下文

### 6.1 手工作业

创建作业时：

1. 解析当前SecuritySubject；
2. 校验工程ACL和按钮权限；
3. 对映射涉及的实体类型、数据属性、对象属性批量执行INGEST决策；
4. 生成授权摘要：主体ID、角色/部门ID哈希、策略revision、资源集合hash、有效期；
5. 写入`authorization_snapshot`，不保存访问令牌；
6. Worker启动时确认策略revision未发生高风险变化。若变化则重新决策，失败关闭。

### 6.2 计划作业

- 映射工程配置USER或ROLE执行主体；
- 发布/启用调度时校验主体权限；
- 每次创建计划作业重新解析主体当前权限；
- 用户被禁用、角色被删除或权限收回时不创建作业；
- 不能配置`SYSTEM`作为执行主体；
- Worker不是以该用户登录，而是按已验证的最小资源授权执行。

### 6.3 授权快照结构

```json
{
  "subjectType":"USER",
  "subjectId":1,
  "subjectName":"admin",
  "policyRevision":"...",
  "resourceDigest":"...",
  "authorizedAt":"2026-07-14T10:00:00Z",
  "expiresAt":"2026-07-14T12:00:00Z"
}
```

不得保存角色名称明细、JWT、密码或完整策略内容。

## 7. 敏感目标值

目标数据属性安全级别决定持久化：

- PUBLIC/INTERNAL：按普通值写入；
- CONFIDENTIAL/RESTRICTED：按模块36规则写`encrypted_value/key_id/iv`，`literal_value`不得保留明文；
- 加密AAD仍绑定ontologyId/instanceId/dataPropertyId；
- 内容哈希和provenance的valueHash使用HMAC或加盐摘要，避免低熵值字典攻击；若当前只提供SHA-256，手机号等低熵值不得保存裸hash，可仅保存密文hash或不保存值hash；
- 预览通过统一输出投影服务返回MASK/DENY结果；
- SPARQL、导出和可视化继续由模块36控制，不因来源是映射而例外。

## 8. 来源溯源

来源绑定、值provenance、关系provenance由18-01定义。额外原则：

- provenance属于治理元数据，默认不序列化进业务RDF；
- SPARQL需要查询来源时使用单独受控系统图/管理API，V1先提供管理API；
- sourceRecordKey仅在管理员详情中脱敏展示；
- sourceUpdatedAt、mappingVersion、jobId可公开到INTERNAL级别；
- 删除作业明细不删除来源绑定和当前provenance；
- 来源记录被遗忘/合规删除时，按安全审批流程处理绑定和实例数据。

## 9. 数据访问审计

必须审计：

- 数据源新增、修改、测试、启停、元数据刷新；
- 映射工程/版本新增、编辑、校验、WARNING确认、发布、停用；
- FULL/INCREMENTAL/RETRY作业创建、取消、恢复、游标重置；
- 强制人工覆盖来源值；
- 高风险删除策略执行；
- 作业错误详情查看；
- 凭证解密失败和策略拒绝。

审计链使用模块36`DataAccessAuditService`，resourceRef使用ID组合，不写源记录明文：

```text
mappingProject:100/version:5/job:900
```

## 10. 高风险审批

V1接入`ont_operation_approval_request`并新增以下操作类型：

```text
MAPPING_PUBLISH_IRI_CHANGE
MAPPING_ENABLE_SOFT_DELETE
MAPPING_RESET_CURSOR
MAPPING_FORCE_DELETE_INSTANCE
MAPPING_CREDENTIAL_ROTATE
```

V1强制审批：

- 已有ACTIVE绑定时修改IRI策略；
- 启用SOFT_DELETE并预计影响超过阈值；
- 强制重置增量游标到更早/更晚位置；
- 批量删除映射实例；
- RESTRICTED数据源凭证轮换可按部署策略开启审批。

审批payload只保存摘要；执行时重新计算摘要并与审批请求比较，防止批准后参数被替换。

## 11. EDA事件契约

### 11.1 事件类型

```text
MAPPING_VERSION_PUBLISHED
MAPPING_PROJECT_DISABLED
MAPPING_JOB_STARTED
MAPPING_JOB_COMPLETED
MAPPING_JOB_FAILED
MAPPING_JOB_CANCELLED
INSTANCE_INGESTED
INSTANCE_UPDATED_FROM_SOURCE
INSTANCE_DEACTIVATED_FROM_SOURCE
MAPPING_VALUE_OVERRIDDEN
RELATION_INGESTED
RELATION_UPDATED_FROM_SOURCE
RELATION_SOURCE_REMOVED
MAPPING_RELATION_PENDING
MAPPING_RELATION_RESOLVED
MAPPING_RELATION_UNRESOLVED
MAPPING_SECURITY_DENIED
MAPPING_RECORD_REJECTED
```

### 11.2 Payload规则

统一Envelope沿用模块26。映射Payload允许：

- ontologyId、mappingProjectId、mappingVersionId、jobId；
- instanceId/entityTypeId/propertyIds；
- sourceId但不含连接信息；
- 计数、耗时、状态、错误码；
- sourceRecordKeyHash，不含完整key；
- traceId。

禁止：

- 原始行JSON；
- 字面量明文；
- 手机、邮箱、OpenID；
- JDBC URL、用户名、密码；
- SQL和PreparedStatement参数；
- 授权快照全文。

### 11.3 发布频率

- 实例变化事件可逐实例发布，但大批次需压测；
- 作业进度默认每分钟或每10%聚合发布；
- UNCHANGED不发布；
- 记录失败默认只聚合作业错误码计数，不逐条发事件；
- 高频源接入应由模块19/21处理，不能用模块18扫描事件冒充遥测流。

## 12. 事件处理器

首期消费者：

- SPARQL/可视化缓存失效；
- 安全审计指标；
- 可观测统计；
- 后续告警模块可消费有业务意义的实例变化，但不能依赖原始值明文事件。

事件消费至少一次，消费者按eventId幂等。映射重试可能产生新的变更事件，payload应含jobId和contentHash用于业务去重。

Micrometer：

```text
ontology.mapping.datasource.test.total{result,databaseType}
ontology.mapping.datasource.connection.active{sourceId}
ontology.mapping.metadata.refresh.duration
ontology.mapping.job.total{runType,status}
ontology.mapping.job.duration{runType}
ontology.mapping.record.total{mappingCode,action,status}
ontology.mapping.record.error.total{errorCode}
ontology.mapping.ingestion.duration{action}
ontology.mapping.pending.relation.count{status}
ontology.mapping.cursor.lag.seconds{mappingProjectId,mappingCode}
ontology.mapping.security.denied.total{resourceType}

```

注意高基数：

- 不以jobId、instanceId、sourceRecordKey作为指标label；
- mappingProjectId/mappingCode数量可控但仍需配置上限；
- 详细ID放日志和trace。

## 14. 日志与Trace

日志统一字段：

```text
traceId, jobId, mappingProjectId, mappingVersionId,
sourceId, mappingCode, phase, errorCode, durationMs
```

源记录只记录`sourceRecordKeyHash`。异常栈仅内部日志可见，先经过JDBC URL/credential过滤器。

Trace跨度：

```text
mapping.job
  mapping.entity.scan
    datasource.read.page
    mapping.transform.batch
    ontology.ingest.record
    outbox.append
  mapping.relation.scan
  mapping.delete.detect
```

不在span attribute写字面量值和SQL参数。

## 15. 数据保留

- 凭证：随数据源逻辑删除保留到审批清理，不出审计；
- 验证报告：至少180天；
- 作业主记录：至少1年或按合规要求；
- 失败明细：默认30天；
- 来源绑定/provenance：与实例生命周期一致；
- 审计日志：按模块36策略，不由映射清理任务删除；
- EDA Stream按模块26保留策略，不用于长期审计事实。

## 17. 测试与验收

1. 无按钮权限或无工程ACL均拒绝；
2. INGEST=DENY的属性无法发布映射；
3. INGEST=MASK按DENY处理，不写脱敏假值；
4. 计划任务主体失效后不创建作业；
5. Worker不能使用SYSTEM绕过策略；
6. 凭证、URL参数、源整行不出现在日志/事件/API；
7. CONFIDENTIAL手机号、邮箱以密文存储并在预览脱敏；
8. 高风险操作审批摘要不匹配时拒绝执行；
9. EDA与实例事务一致；
10. 指标不存在源记录键等高基数label；
11. 审计链包含映射发布、执行、取消和强制覆盖；
12. 安全模块不可用时生产映射失败关闭。
