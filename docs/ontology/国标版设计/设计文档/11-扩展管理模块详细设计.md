## 1. 评审结论与设计边界

### 1.1 现状评审

截至本设计时点，前述 10 个模块已全部落地：命名空间（6 条预置）、实体类型（86 个核心类型 + 继承树 + 不相交 + 等价类）、数据属性（47 个核心属性 + 值域规范 + 单位引用）、对象属性（34 个核心属性 + 域值域 + 语义标记）、公理规则（12 条内置规则 + 24 条目标绑定）、实体对象实例（29 个附录 D 实例 + 83 条数据值 + 39 条对象断言）、校验引擎（5 类执行器 + SHACL 验证器 + OWL 推理机 + 报告持久化）、序列化与交换（4 格式导出 + 实例导入 + 导出前置校验 + 审计日志）均已通过 Flyway V4–V12 迁移脚本预置并验证。但代码库中存在以下扩展管理缺口：

| 缺口 | 现状 | 影响 |
|------|------|------|
| **无扩展模块管理实体** | 后端无 `ont_extension_module` 表，扩展实体类型/属性/规则散落在各模块的 `is_builtin='0'` 记录中，无统一的"行业扩展模块"归属分组 | PRD §4.9"行业模块管理"无法落地，用户无法按行业模块（如医疗、石油、电梯）查看和管理扩展资源 |
| **扩展命名空间强制分散实现** | 各 Service 层分别检查"扩展类型必须用扩展命名空间"（`OntEntityTypeServiceImpl.validateSemanticFields` 中 `requireExtensionNamespace && BUILTIN.equals(namespace.getIsBuiltin())`），但无统一注册入口 | PRD §3.3"扩展命名空间强制"策略缺乏统一治理面，用户新建扩展时无法选择"扩展模块"作为第一步 |
| **无扩展合法性校验引擎** | PRD §4.9 要求"校验扩展不与核心同名/矛盾、不修改核心定义、仅可加子类/属性"（第 9.2 条 5 条规则），但无集中校验器 | 扩展可能创建与核心同名的实体类型/属性，或修改核心定义，违反国标第 9 章扩展原则 |
| **无扩展模块导出** | PRD §4.9 要求"行业扩展可独立导出为模块包"，但序列化模块（10）仅支持按本体工程/实体类型子树导出，无按扩展模块维度导出 | 行业扩展无法以独立模块包形式分发和复用 |
| **无变更影响分析** | PRD §3.3"变更影响分析"要求"修改扩展 Schema、单位或公理前计算被引用范围"，删除/停用弹窗应列出影响实例、规则、导出任务 | 各模块删除校验已存在（如 `OntNamespaceServiceImpl.removeNamespace` 检查 5 类引用），但无统一的"扩展模块变更影响分析"汇总视图 |
| **推理引擎扩展无注册入口** | PRD §4.7.4 设计约束第 3 条明确"扩展推理引擎需通过扩展管理模块（§4.9）注册"，但扩展管理模块不存在 | 未来行业扩展接入深度推理引擎时无注册通道 |
| **无扩展模块审计** | 扩展操作（创建模块、注册资源、合法性校验、导出）无审计日志 | PRD §3.3"审计可追溯"要求核心/扩展 Schema 操作均留痕 |

### 1.2 优化结论

| 级别 | 评审发现 | 优化结论 |
|------|----------|----------|
| P0 | 扩展管理模块的核心职责是"分组治理 + 合法性校验 + 模块导出"，但已有模块（03~07）已各自实现 `is_builtin` 保护和扩展命名空间强制 | 扩展管理模块不重复实现已有 CRUD，而是作为**编排层**：新建 `ont_extension_module` 表作为扩展资源的归属分组容器，各已有模块的扩展记录（`is_builtin='0'`）通过 `extension_module_id` 逻辑关联到模块 |
| P0 | PRD §4.9 的 5 条扩展校验规则（第 9.2 条落地）需集中校验器，但各模块已有零散校验（如 IRI 唯一性、命名空间非核心） | 新建 `ExtensionValidator` 统一校验引擎，在"创建扩展模块"和"向模块注册资源"两个触发点执行 5 条规则，已有模块的写入校验保持不变 |
| P0 | 扩展资源"注册到模块"是核心交互，但已有模块的 CRUD 接口（如 `POST /ontology/entity-types`）无 `extensionModuleId` 参数 | 已有 CRUD 接口**不新增参数**，扩展模块注册通过**后置关联**实现：用户在扩展管理页面选择已创建的扩展实体类型/属性/规则，批量关联到扩展模块；不侵入已有写入路径 |
| P1 | 扩展模块导出需要按模块维度筛选资源，但序列化模块（10）的 `OntologyModelExporter` 仅支持按 `ontologyId` + `scope` 参数导出 | 扩展模块导出复用序列化模块能力：扩展模块导出时按 `extension_module_id` 查询关联的资源 ID 集合，构建"资源 ID 过滤器"传递给序列化服务，不新建独立的序列化器 |
| P1 | 变更影响分析需要跨表查询（实体类型/属性/规则/单位/实例的引用关系），但各模块删除校验已有零散实现 | 变更影响分析复用已有模块的引用检查逻辑，扩展管理模块的 `ExtensionImpactAnalyzer` 聚合查询各表 `extension_module_id` 关联记录数，生成影响摘要 |
| P2 | 推理引擎适配层（§4.7.4）的 `ReasonerAdapter` SPI 已通过 Spring Bean 注册，但无管理面 | 扩展管理模块提供"已注册扩展组件"只读列表，展示 Spring 容器中所有 `ReasonerAdapter` 实现；本期不实现扩展推理引擎的在线注册（需重启生效），仅展示 |
| P2 | PRD §6.3 要求"新增扩展抽屉式分步表单：基础信息 → 定义域/值域 → 约束/预览 → 校验"，但分步表单交互复杂 | 本期实现简化版分步表单：步骤 1 选择扩展模块（或新建）→ 步骤 2 创建资源（复用已有各模块的新建表单）→ 步骤 3 关联到模块 + 合法性校验；不实现内嵌的约束/预览步骤（约束预览在各模块已有） |

### 1.3 本期范围

**本期包含：**

1. 扩展模块管理表（`ont_extension_module`）—— 行业扩展模块的 CRUD 载体
2. 扩展资源关联表（`ont_extension_resource`）—— 扩展模块与已有资源的关联关系
3. 扩展合法性校验引擎（`ExtensionValidator`）—— 第 9.2 条 5 条规则集中校验
4. 变更影响分析器（`ExtensionImpactAnalyzer`）—— 跨表引用汇总
5. 扩展模块导出能力 —— 复用序列化模块（10），按模块维度筛选资源导出
6. 扩展管理 REST API（模块 CRUD、资源关联、合法性校验、影响分析、模块导出）
7. 扩展管理前端模块（模块列表、模块详情、资源关联抽屉、合法性校验报告、影响分析弹窗）
8. Flyway V13 迁移脚本（建表 + 菜单权限 + 种子数据）
9. 扩展组件注册只读列表（展示 `ReasonerAdapter` SPI 实现）
10. 扩展模块操作审计日志（复用 `ont_serialization_log` 表的扩展行，或新建轻量审计表）

**本期不包含：**

- 扩展资源的 CRUD（仍由各已有模块 03~07 负责，扩展管理模块不重复实现）
- 扩展推理引擎在线热注册（`ReasonerAdapter` SPI 需重启生效，本期仅展示已注册实现）
- 扩展模块版本管理（不实现模块版本号、版本对比、版本回滚）
- 扩展模块依赖管理（不实现模块间依赖声明与冲突检测）
- 扩展模块导入（不支持从模块包文件反向导入为内部模型）
- 扩展模块的 RBAC 细粒度隔离（不实现"不同用户只能管理自己的扩展模块"的数据级隔离）

### 1.5 权威语义口径

1. 扩展管理模块是**编排层**，不拥有扩展资源的 CRUD 权限——扩展实体类型/属性/规则/单位的创建、修改、删除仍由各已有模块（03~07）负责，扩展管理模块仅负责"分组管理 + 合法性校验 + 模块导出 + 影响分析"。
2. 扩展模块（`ont_extension_module`）是行业扩展资源的**归属容器**：每个行业扩展模块绑定一个扩展命名空间（`ont_namespace`，`is_builtin='0'`），该命名空间下创建的所有资源自动归属于该扩展模块。
3. 扩展资源关联（`ont_extension_resource`）记录的是**逻辑关联**，不改变资源本身的存储和语义——关联关系通过 `resource_type` + `resource_id` 多态引用，不添加物理外键约束到各已有表。
4. 扩展合法性校验（第 9.2 条 5 条规则）在两个触发点执行：**(a) 创建扩展模块时**——校验绑定的命名空间是扩展命名空间；**(b) 向扩展模块注册资源时**——校验资源确实属于扩展命名空间、名称不与核心重复、定义不与核心矛盾、仅以子类/属性方式扩展。
5. 扩展模块导出复用序列化模块（10）的 `OntologyModelExporter`，通过传入"资源 ID 过滤器"实现按模块维度筛选——不新建独立序列化器，不重复组装 Jena Model。
6. 核心锁定策略（PRD §3.3"核心 Schema 锁定"）：核心资源（`is_builtin='1'`）不可关联到扩展模块、不可被扩展模块导出为模块包的一部分。扩展模块导出仅包含 `is_builtin='0'` 的资源。
7. 变更影响分析是**只读查询**：不修改任何数据，仅跨表统计 `extension_module_id` 关联记录数和各资源的被引用情况。
8. 推理引擎扩展注册是**只读展示**：从 Spring 容器查询所有 `ReasonerAdapter` Bean，展示引擎名称和能力声明；本期不实现在线注册（需代码级实现 + 重启生效）。
9. 扩展模块操作审计：模块 CRUD、资源关联/解除、合法性校验、模块导出操作均通过 `@SysLog` 记录操作日志（复用已有的 Spring SysLog 机制），不新建独立审计表。
10. 扩展模块与本体工程（`ont_ontology_project`）的关系：扩展模块创建时选择归属的本体工程，默认归属核心工程（`CORE_ONTOLOGY_ID = 935001`）；扩展模块导出时从该本体工程中筛选关联资源。

### 2.2 核心设计决策

| 决策 | 选择 | 理由 |
|------|------|------|
| 扩展模块与资源的关系模型 | **逻辑关联**（`ont_extension_resource` 多态引用表），不添加物理外键到各已有表 | 已有表（`ont_entity_type` 等）已有 `namespace_id` 外键和 `is_builtin` 字段，添加 `extension_module_id` 物理外键需 V4~V12 全部加列，侵入性大；逻辑关联表通过 `resource_type` + `resource_id` 多态引用，零侵入已有表 |
| 扩展资源自动归属策略 | **命名空间绑定**：扩展模块绑定一个扩展命名空间，该命名空间下的资源自动归属于该模块 | PRD §3.3"扩展命名空间强制"已要求扩展资源必须使用扩展命名空间，因此命名空间是天然的归属键；用户向模块"注册资源"时，系统自动验证资源命名空间与模块命名空间一致 |
| 合法性校验触发时机 | **两阶段校验**：创建模块时校验命名空间 + 注册资源时校验 5 条规则 | PRD §6.3 要求"抽屉式分步表单→校验"，两阶段校验将复杂校验拆为可控步骤；已有模块写入时已有零散校验（如 IRI 唯一性），扩展管理模块的校验是**补充而非替代** |
| 模块导出实现方式 | **委托序列化模块**：构建资源 ID 集合过滤器，调用 `SerializationService.export()` | 序列化模块（10）已完整实现 4 格式导出 + 前缀映射 + 谓词策略，复用避免代码重复；扩展模块导出本质是"按资源 ID 过滤的子集导出" |
| 变更影响分析实现方式 | **聚合查询**：跨表统计 `extension_module_id` 关联记录 + 各资源被引用情况 | 各模块删除校验已有引用检查逻辑（如 `OntNamespaceServiceImpl.removeNamespace` 检查 5 类引用），扩展管理模块的 `ImpactAnalyzer` 聚合这些查询为统一摘要 |
| 推理引擎扩展注册展示 | **Spring Bean 只读查询**：`applicationContext.getBeansOfType(ReasonerAdapter.class)` | PRD §4.7.4 明确 SPI 通过 Spring Bean 注册（09 设计文档已确定），扩展管理模块仅展示已注册 Bean 列表，不实现在线热注册 |
| 扩展模块审计 | **复用 `@SysLog`**：不新建审计表 | 已有所有 Controller 均使用 `@SysLog` 注解记录操作日志，扩展管理模块照搬此模式；模块导出操作的审计复用序列化模块的 `ont_serialization_log` 表（operation_type 增加值 `EXTENSION_EXPORT`） |
| 扩展模块物理删除策略 | **逻辑删除 + 关联解除**：模块逻辑删除（`del_flag='1'`），关联表记录同步逻辑删除；已有资源本身不受影响 | PRD §3.3"变更影响分析"要求删除前列出影响范围并二次确认；模块删除不影响已创建的扩展资源（资源仍属于其命名空间），仅解除分组关系 |

### 2.3 后端包结构

## 3. 数据模型与 Flyway V13 设计

### 3.1 扩展模块表 ont_extension_module

```
ont_extension_module
├── id: bigint (ASSIGN_ID)
├── module_code: varchar(64)      -- 模块代码（唯一，如 medical、petroleum、elevator）
├── module_name: varchar(128)     -- 模块名称（如"医疗行业扩展"）
├── namespace_id: bigint           -- 绑定的扩展命名空间ID（→ ont_namespace.id, is_builtin='0'）
├── ontology_id: bigint           -- 归属本体工程ID（→ ont_ontology_project.id）
├── description: text             -- 模块描述
├── version: varchar(32)          -- 模块版本号（首期不强制语义化版本，自由文本）
├── is_builtin: char(1)           -- 是否内置模块（预留，首期恒为'0'）
├── sort_order: integer           -- 排序
├── remarks: text                 -- 备注
├── create_by / create_time      -- 审计
├── update_by / update_time       -- 审计
└── del_flag: char(1)             -- 逻辑删除
```

**约束：**
1. `module_code` 全局唯一（部分唯一索引 `WHERE del_flag = '0'`），正则 `^[a-z][a-z0-9_-]*$`（与命名空间 prefix 风格一致）。
2. `namespace_id` 必须引用 `ont_namespace` 中 `is_builtin='0'`（扩展命名空间）的记录——创建时校验。
3. `ontology_id` 默认 `935001`（`CORE_ONTOLOGY_ID`），外键引用 `ont_ontology_project(id) ON DELETE RESTRICT`。
4. `is_builtin` 首期恒为 `'0'`——内置扩展模块（如国标核心扩展）不预置，预留字段为后续"平台官方扩展"做准备。
5. `namespace_id` 修改时需检查：该命名空间下所有资源的 `extension_module_id` 是否仍指向本模块（若变更命名空间，需先解除所有资源关联）。

### 3.2 扩展资源关联表 ont_extension_resource

```
ont_extension_resource
├── id: bigint (ASSIGN_ID)
├── module_id: bigint             -- 扩展模块ID（→ ont_extension_module.id）
├── resource_type: varchar(32)    -- 资源类型：ENTITY_TYPE/DATA_PROPERTY/OBJECT_PROPERTY/AXIOM_RULE/UNIT
├── resource_id: bigint           -- 资源记录ID（多态引用，不添加物理外键）
├── resource_iri: text            -- 资源IRI（冗余存储，便于导出和展示）
├── resource_name: varchar(128)   -- 资源名称（冗余存储，便于列表展示）
├── create_by / create_time       -- 审计
├── update_by / update_time       -- 审计
└── del_flag: char(1)             -- 逻辑删除
```

**约束：**
1. `(module_id, resource_type, resource_id)` 联合唯一（部分唯一索引 `WHERE del_flag = '0'`）——同一资源不可重复关联到同一模块。
2. `resource_type` 取值约束：`CHECK (resource_type IN ('ENTITY_TYPE', 'DATA_PROPERTY', 'OBJECT_PROPERTY', 'AXIOM_RULE', 'UNIT'))`。
3. `resource_id` 不添加物理外键——多态引用各已有表，物理外键需在各表添加反向引用列，侵入性大。
4. `resource_iri` 和 `resource_name` 为冗余字段——注册资源时从各表查询并快照存储，便于导出和列表展示无需 JOIN 各资源表；资源本身改名后需手动触发"同步快照"操作。
5. 关联解除（逻辑删除 `del_flag='1'`）不影响资源本身——资源仍属于其命名空间，仅解除与扩展模块的分组关系。

## 4. 扩展合法性校验引擎设计

> 对应 PRD §4.9"扩展合法性校验" + 第 9.2 条 5 条规则

### 4.1 校验规则清单

国标第 9.2 条规定了 5 条扩展校验规则，平台落地如下：

| 序号 | 国标第9.2条规则 | 校验器实现 | 触发时机 | 严重级别 |
|------|----------------|-----------|----------|---------|
| R1 | 扩展实体类型/属性必须使用扩展命名空间（非 `standard-ontology#`） | `ExtensionNamespaceRule` | 创建模块 / 注册资源 | VIOLATION |
| R2 | 名称不得与核心重复 | `NameConflictRule` | 注册资源 | VIOLATION |
| R3 | 定义不得与核心矛盾 | `DefinitionConflictRule` | 注册资源 | WARNING |
| R4 | 满足核心约束条件，可进一步限定（如枚举值子集化） | `ConstraintConformanceRule` | 注册资源 | WARNING |
| R5 | 只允许 subClassOf 核心类型，不允许修改核心类型本身 | `SubClassOnlyRule` | 注册资源 | VIOLATION |

    @Override
    public List<ExtensionValidationResult> validate(OntExtensionModule module, OntExtensionResource resource) {
        // 阶段1：创建模块时校验绑定命名空间
        OntNamespace namespace = namespaceMapper.selectById(module.getNamespaceId());
        if (namespace == null) {
            return Collections.singletonList(ExtensionValidationResult.fail(
                getRuleCode(), getRuleName(), getGbClause(), "VIOLATION", null,
                "扩展模块绑定的命名空间不存在", "请选择有效的扩展命名空间"));
        }
        if (BUILTIN.equals(namespace.getIsBuiltin())) {
            return Collections.singletonList(ExtensionValidationResult.fail(
                getRuleCode(), getRuleName(), getGbClause(), "VIOLATION", null,
                "扩展模块必须绑定扩展命名空间，不可绑定核心命名空间(is_builtin=1)",
                "请选择is_builtin=0的扩展命名空间"));
        }

        // 阶段2：注册资源时校验资源命名空间与模块一致
        if (resource == null) {
            return Collections.singletonList(ExtensionValidationResult.pass(
                getRuleCode(), getRuleName(), getGbClause()));
        }

        Long resourceNamespaceId = resolveResourceNamespaceId(resource);
        if (resourceNamespaceId == null) {
            // 单位条目可能 namespace_id 为空（内置单位），扩展单位必填
            return Collections.singletonList(ExtensionValidationResult.fail(
                getRuleCode(), getRuleName(), getGbClause(), "VIOLATION",
                resource.getResourceIri(),
                "资源未绑定命名空间", "扩展资源必须绑定扩展命名空间"));
        }
        if (!resourceNamespaceId.equals(module.getNamespaceId())) {
            return Collections.singletonList(ExtensionValidationResult.fail(
                getRuleCode(), getRuleName(), getGbClause(), "VIOLATION",
                resource.getResourceIri(),
                "资源命名空间与扩展模块绑定的命名空间不一致",
                "请确保资源使用模块绑定的扩展命名空间"));
        }

        return Collections.singletonList(ExtensionValidationResult.pass(
            getRuleCode(), getRuleName(), getGbClause()));
    }

    /**
     * 根据资源类型查询资源所属命名空间ID。
     */
    private Long resolveResourceNamespaceId(OntExtensionResource resource) {
        switch (resource.getResourceType()) {
            case "ENTITY_TYPE":
                OntEntityType entityType = entityTypeMapper.selectById(resource.getResourceId());
                return entityType != null ? entityType.getNamespaceId() : null;
            case "DATA_PROPERTY":
                OntDataProperty dataProperty = dataPropertyMapper.selectById(resource.getResourceId());
                return dataProperty != null ? dataProperty.getNamespaceId() : null;
            case "OBJECT_PROPERTY":
                OntObjectProperty objectProperty = objectPropertyMapper.selectById(resource.getResourceId());
                return objectProperty != null ? objectProperty.getNamespaceId() : null;
            case "AXIOM_RULE":
                // 公理规则无 namespace_id 字段，按 ontology_id 归属判断
                OntAxiomRule rule = axiomRuleMapper.selectById(resource.getResourceId());
                if (rule != null && BUILTIN.equals(rule.getIsBuiltin())) {
                    return null; // 内置规则不可关联
                }
                return module.getNamespaceId(); // 扩展规则继承模块命名空间
            case "UNIT":
                OntUnit unit = unitMapper.selectById(resource.getResourceId());
                return unit != null ? unit.getNamespaceId() : null;
            default:
                return null;
        }
    }

}
```

> 注：R1 校验器中 `AXIOM_RULE` 分支引用了 `module` 变量——实际实现中需将 `module` 传入 `resolveResourceNamespaceId` 或在方法签名中调整。此处为设计示意，实现时以编译通过为准。

> 国标第 9.2 条第 2 条：名称不得与核心重复

package com.pig4cloud.pig.ontology.extension.validator;

import com.pig4cloud.pig.ontology.entity.OntExtensionModule;
import com.pig4cloud.pig.ontology.entity.OntExtensionResource;
import com.pig4cloud.pig.ontology.entity.OntEntityType;

import com.pig4cloud.pig.ontology.mapper.OntEntityTypeMapper;
import com.pig4cloud.pig.ontology.mapper.OntDataPropertyMapper;

import com.baomidou.mybatisplus.core.toolkit.Wrappers;
import lombok.AllArgsConstructor;
import org.springframework.stereotype.Component;

import java.util.ArrayList;
import java.util.List;

/**
 * R2: 名称不得与核心重复规则。
 *
 * <p>校验扩展资源的IRI或名称不与核心(is_builtin=1)资源重复。
 *
 * <p>国标依据：第9.2条第2条
 *
 * @author youming
 */
@Component
@AllArgsConstructor
public class NameConflictRule implements ExtensionValidationRule {

    private static final String BUILTIN = "1";

    private final OntEntityTypeMapper entityTypeMapper;
    private final OntDataPropertyMapper dataPropertyMapper;
    private final OntObjectPropertyMapper objectPropertyMapper;
    private final OntAxiomRuleMapper axiomRuleMapper;
    private final OntUnitMapper unitMapper;

    @Override
    public String getRuleCode() {
        return "R2";
    }

    @Override
    public String getRuleName() {
        return "名称不得与核心重复";
    }

    @Override
    public String getGbClause() {
        return "GB/T 48000.3—2026 第9.2条第2条";
    }

    @Override
    public List<ExtensionValidationResult> validate(OntExtensionModule module, OntExtensionResource resource) {
        if (resource == null) {
            return List.of(ExtensionValidationResult.pass(getRuleCode(), getRuleName(), getGbClause()));
        }

        List<ExtensionValidationResult> results = new ArrayList<>();
        String resourceIri = resource.getResourceIri();
        String resourceName = resource.getResourceName();

        // 按资源类型查询核心资源中是否存在同名或同IRI的记录
        boolean conflictFound = false;
        String conflictType = "";

        switch (resource.getResourceType()) {
            case "ENTITY_TYPE":
                if (entityTypeMapper.exists(Wrappers.<OntEntityType>lambdaQuery()
                    .eq(OntEntityType::getIsBuiltin, BUILTIN)
                    .and(w -> w.eq(OntEntityType::getIri, resourceIri)
                        .or().eq(OntEntityType::getName, resourceName)))) {
                    conflictFound = true;
                    conflictType = "实体类型";
                }
                break;
            case "DATA_PROPERTY":
                if (dataPropertyMapper.exists(Wrappers.<OntDataProperty>lambdaQuery()
                    .eq(OntDataProperty::getIsBuiltin, BUILTIN)
                    .and(w -> w.eq(OntDataProperty::getIri, resourceIri)
                        .or().eq(OntDataProperty::getName, resourceName)))) {
                    conflictFound = true;
                    conflictType = "数据属性";
                }
                break;
            case "OBJECT_PROPERTY":
                if (objectPropertyMapper.exists(Wrappers.<OntObjectProperty>lambdaQuery()
                    .eq(OntObjectProperty::getIsBuiltin, BUILTIN)
                    .and(w -> w.eq(OntObjectProperty::getIri, resourceIri)
                        .or().eq(OntObjectProperty::getName, resourceName)))) {
                    conflictFound = true;
                    conflictType = "对象属性";
                }
                break;
            case "AXIOM_RULE":
                if (axiomRuleMapper.exists(Wrappers.<OntAxiomRule>lambdaQuery()
                    .eq(OntAxiomRule::getIsBuiltin, BUILTIN)
                    .and(w -> w.eq(OntAxiomRule::getRuleCode, resourceName)
                        .or().eq(OntAxiomRule::getName, resourceName)))) {
                    conflictFound = true;
                    conflictType = "公理规则";
                }
                break;
            case "UNIT":
                if (unitMapper.exists(Wrappers.<OntUnit>lambdaQuery()
                    .eq(OntUnit::getIsBuiltin, BUILTIN)
                    .and(w -> w.eq(OntUnit::getUnitCode, resourceName)
                        .or().eq(OntUnit::getUnitSymbol, resource.getName())))) {
                    conflictFound = true;
                    conflictType = "单位条目";
                }
                break;
            default:
                break;
        }

        if (conflictFound) {
            results.add(ExtensionValidationResult.fail(
                getRuleCode(), getRuleName(), getGbClause(), "VIOLATION", resourceIri,
                "扩展" + conflictType + "的名称或IRI与核心资源重复",
                "请修改扩展资源的名称或IRI，确保不与核心(is_builtin=1)资源冲突"));
        } else {
            results.add(ExtensionValidationResult.pass(getRuleCode(), getRuleName(), getGbClause()));
        }

        return results;
    }

}
```

#### 4.4.3 R3~R5 规则概述

R3（DefinitionConflictRule）、R4（ConstraintConformanceRule）、R5（SubClassOnlyRule）的实现模式与 R1/R2 一致，均实现 `ExtensionValidationRule` 接口，核心校验逻辑如下：

| 规则 | 校验逻辑 | 严重级别 |
|------|---------|---------|
| **R3 DefinitionConflictRule** | 对比扩展资源的 `definition` 字段与同名核心资源的 `definition`，若存在语义矛盾（首期用文本相似度 < 阈值判断，不实现 NLP 语义比对），产出 WARNING | WARNING |
| **R4 ConstraintConformanceRule** | 校验扩展枚举型数据属性的枚举值集合是否为核心枚举的子集（`issubsetof`）；校验扩展数据属性的值域约束是否比核心更严格（如 `regexPattern` 更窄、`maxValue` 更小） | WARNING |
| **R5 SubClassOnlyRule** | 校验扩展实体类型的 `subClassOf` 至少包含一个核心实体类型；校验扩展实体类型未修改核心类型的 `iri`/`name`/`definition`（通过检查核心类型记录未被更新判断） | VIOLATION |

> **设计约束**：R3 的"定义矛盾"检测首期采用**文本相似度启发式**（Jaccard 相似度 < 0.3 判为潜在矛盾），不实现 NLP 语义比对。R4 的"进一步限定"校验首期仅覆盖枚举子集化和数值范围收窄两种场景。R5 的"修改核心类型"检测通过检查核心类型记录的 `update_time` 是否晚于扩展模块创建时间来判断——若核心类型记录被修改过，则产出 VIOLATION。

### 4.5 校验编排器

```java
/*
 * Copyright (c) 2026 youming Authors. All Rights Reserved.
 */

package com.pig4cloud.pig.ontology.extension.validator;

import com.pig4cloud.pig.ontology.entity.OntExtensionModule;
import com.pig4cloud.pig.ontology.entity.OntExtensionResource;
import lombok.AllArgsConstructor;
import org.springframework.stereotype.Component;

import java.util.ArrayList;
import java.util.List;

/**
 * 扩展合法性校验编排器。
 *
 * <p>按R1→R2→R3→R4→R5顺序执行5条规则，聚合结果为统一报告。
 * 任一VIOLATION级规则失败时，后续规则仍继续执行（全量校验），
 * 但最终报告的conforms=false会阻断操作。
 *
 * @author youming
 */
@Component
@AllArgsConstructor
public class ExtensionValidator {

    private final List<ExtensionValidationRule> rules;

    /**
     * 执行全量校验（创建模块时，resource=null）。
     */
    public ExtensionValidationReport validateModule(OntExtensionModule module) {
        return validate(module, null);
    }

    /**
     * 执行全量校验（注册资源时，resource非空）。
     */
    public ExtensionValidationReport validateResource(OntExtensionModule module, OntExtensionResource resource) {
        return validate(module, resource);
    }

    /**
     * 执行全量校验。
     */
    private ExtensionValidationReport validate(OntExtensionModule module, OntExtensionResource resource) {
        List<ExtensionValidationResult> allResults = new ArrayList<>();
        for (ExtensionValidationRule rule : rules) {
            allResults.addAll(rule.validate(module, resource));
        }

        boolean conforms = allResults.stream()
            .noneMatch(r -> "VIOLATION".equals(r.getSeverity()) && !r.getPassed());

        long violationCount = allResults.stream()
            .filter(r -> "VIOLATION".equals(r.getSeverity()) && !r.getPassed())
            .count();
        long warningCount = allResults.stream()
            .filter(r -> "WARNING".equals(r.getSeverity()) && !r.getPassed())
            .count();

        ExtensionValidationReport report = new ExtensionValidationReport();
        report.setConforms(conforms);
        report.setViolationCount(violationCount);
        report.setWarningCount(warningCount);
        report.setResults(allResults);
        return report;
    }

}
```

## 5. 扩展模块导出设计

### 5.1 导出策略

扩展模块导出复用序列化模块（10）的 `SerializationService.export()` 能力，通过构建"资源 ID 过滤器"实现按模块维度筛选：

```
扩展模块导出流程
├── 1. 查询 ont_extension_resource WHERE module_id = {moduleId} AND del_flag = '0'
├── 2. 按 resource_type 分组，收集资源 ID 集合
│   ├── entity_type_ids = [940087, 940088, ...]    // 扩展实体类型ID
│   ├── data_property_ids = [...]                   // 扩展数据属性ID
│   ├── object_property_ids = [...]                 // 扩展对象属性ID
│   ├── axiom_rule_ids = [...]                      // 扩展公理规则ID
│   └── unit_ids = [...]                            // 扩展单位ID
├── 3. 构建 ExtensionExportFilter（资源 ID 集合）
├── 4. 委托 SerializationService.export()
│   ├── 传入 ontologyId = module.ontologyId
│   ├── 传入 scope = INSTANCE_ONLY（模块包仅含实例层资源）
│   ├── 传入 format = 请求参数（TURTLE / JSON-LD / RDF-XML / N-TRIPLES）
│   ├── 传入 extensionFilter = ExtensionExportFilter（资源 ID 过滤器）
│   └── SerializationService 组装 Jena Model 时按过滤器筛选
├── 5. 返回序列化文本 + 审计日志写入
└── 6. 前端下载文件
```

> **设计决策**：扩展模块导出首期仅导出 `INSTANCE_ONLY` 范围（扩展实例数据 + 扩展 Schema 声明），不导出核心 Schema。完整本体导出仍由序列化模块的 `FULL` 范围导出承担。模块包的语义是"可独立分发的行业扩展子集"，不包含核心国标 Schema（核心 Schema 由平台预置，接收方已有）。

```java

package com.pig4cloud.pig.ontology.extension.export;

import com.pig4cloud.pig.ontology.entity.OntExtensionModule;
import com.pig4cloud.pig.ontology.entity.OntExtensionResource;
import com.pig4cloud.pig.ontology.mapper.OntExtensionResourceMapper;
import com.pig4cloud.pig.ontology.serialization.service.SerializationService;
import com.baomidou.mybatisplus.core.toolkit.Wrappers;
import lombok.AllArgsConstructor;
import org.springframework.stereotype.Component;

import java.util.List;
import java.util.Map;
import java.util.stream.Collectors;

/**
 * 扩展模块导出器。
 *
 * <p>委托序列化模块的 SerializationService 执行导出，
 * 通过构建资源 ID 过滤器实现按模块维度筛选。
 *
 * @author youming
 */
@Component
@AllArgsConstructor
public class ExtensionExporter {

    private final OntExtensionResourceMapper resourceMapper;
    private final SerializationService serializationService;

    /**
     * 导出扩展模块为指定RDF格式。
     *
     * @param module 扩展模块
     * @param format RDF格式（TURTLE / JSON-LD / RDF-XML / N-TRIPLES）
     * @return 序列化文本
     */
    public String exportModule(OntExtensionModule module, String format) {
        // 1. 查询模块关联的所有资源
        List<OntExtensionResource> resources = resourceMapper.selectList(
            Wrappers.<OntExtensionResource>lambdaQuery()
                .eq(OntExtensionResource::getModuleId, module.getId())
                .eq(OntExtensionResource::getDelFlag, "0"));

        // 2. 按资源类型分组
        Map<String, List<Long>> resourceIdsByType = resources.stream()
            .collect(Collectors.groupingBy(
                OntExtensionResource::getResourceType,
                Collectors.mapping(OntExtensionResource::getResourceId, Collectors.toList())));

        // 3. 构建导出过滤器
        ExtensionExportFilter filter = ExtensionExportFilter.builder()
            .entityTypeIds(resourceIdsByType.getOrDefault("ENTITY_TYPE", List.of()))
            .dataPropertyIds(resourceIdsByType.getOrDefault("DATA_PROPERTY", List.of()))
            .objectPropertyIds(resourceIdsByType.getOrDefault("OBJECT_PROPERTY", List.of()))
            .axiomRuleIds(resourceIdsByType.getOrDefault("AXIOM_RULE", List.of()))
            .unitIds(resourceIdsByType.getOrDefault("UNIT", List.of()))
            .build();

        // 4. 委托序列化服务导出
        return serializationService.export(
            module.getOntologyId(),
            format,
            "INSTANCE_ONLY",
            "PREFERRED_ALIAS",
            filter);
    }

}
```

import com.pig4cloud.pig.ontology.service.OntEntityTypeService;
import lombok.AllArgsConstructor;
import org.springframework.stereotype.Service;
import org.springframework.transaction.annotation.Transactional;
import org.springframework.util.StringUtils;

import java.util.regex.Pattern;

/**
 * 扩展模块服务实现。
 *
 * @author youming
 */
@Service
@AllArgsConstructor
public class OntExtensionModuleServiceImpl extends ServiceImpl<OntExtensionModuleMapper, OntExtensionModule>
		implements OntExtensionModuleService {

	private static final String BUILTIN = "1";

	private static final String EXTENSION = "0";

	private static final Pattern MODULE_CODE_PATTERN = Pattern.compile("^[a-z][a-z0-9_-]*$");

	private final OntNamespaceMapper namespaceMapper;

	private final OntExtensionResourceMapper resourceMapper;

	private final ExtensionValidator validator;

	private final ExtensionExporter exporter;

	@Override
	@Transactional(rollbackFor = Exception.class)
	public R<OntExtensionModule> saveModule(ExtensionModuleCreateDTO request) {
		// 校验moduleCode格式
		if (!StringUtils.hasText(request.getModuleCode())) {
			return R.failed("模块代码不能为空");
		}
		if (!MODULE_CODE_PATTERN.matcher(request.getModuleCode()).matches()) {
			return R.failed("模块代码仅支持小写英文、数字、下划线和中划线，且必须以小写英文开头");
		}

		// 校验moduleCode唯一
		long codeCount = this.count(Wrappers.<OntExtensionModule>lambdaQuery()
			.eq(OntExtensionModule::getModuleCode, request.getModuleCode()));
		if (codeCount > 0) {
			return R.failed("模块代码已存在");
		}

		// 校验命名空间为扩展命名空间
		OntNamespace namespace = namespaceMapper.selectById(request.getNamespaceId());
		if (namespace == null) {
			return R.failed("命名空间不存在");
		}
		if (BUILTIN.equals(namespace.getIsBuiltin())) {
			return R.failed("扩展模块必须绑定扩展命名空间，不可绑定核心命名空间");
		}

		// 执行R1校验
		OntExtensionModule module = new OntExtensionModule();
		module.setModuleCode(request.getModuleCode());
		module.setModuleName(request.getModuleName());
		module.setNamespaceId(request.getNamespaceId());
		module.setOntologyId(request.getOntologyId() != null ? request.getOntologyId() : OntEntityTypeService.CORE_ONTOLOGY_ID);
		module.setDescription(request.getDescription());
		module.setVersion(request.getVersion());
		module.setIsBuiltin(EXTENSION);
		module.setSortOrder(request.getSortOrder() != null ? request.getSortOrder() : 0);
		module.setRemarks(request.getRemarks());

		ExtensionValidationReport report = validator.validateModule(module);
		if (!report.getConforms()) {
			return R.failed("扩展合法性校验未通过", report);
		}

		this.save(module);
		return R.ok(module);
	}

	@Override
	@Transactional(rollbackFor = Exception.class)
	public R<OntExtensionModule> updateModule(ExtensionModuleUpdateDTO request) {
		if (request.getId() == null) {
			return R.failed("模块ID不能为空");
		}
		OntExtensionModule old = this.getById(request.getId());
		if (old == null) {
			return R.failed("扩展模块不存在");
		}

		// 内置模块不可修改（首期无内置模块，预留）
		if (BUILTIN.equals(old.getIsBuiltin())) {
			return R.failed("内置扩展模块不可修改");
		}

		// 命名空间变更需检查关联资源
		if (request.getNamespaceId() != null && !request.getNamespaceId().equals(old.getNamespaceId())) {
			long resourceCount = resourceMapper.selectCount(Wrappers.<OntExtensionResource>lambdaQuery()
				.eq(OntExtensionResource::getModuleId, old.getId())
				.eq(OntExtensionResource::getDelFlag, EXTENSION));
			if (resourceCount > 0) {
				return R.failed("该模块已关联" + resourceCount + "个资源，命名空间不可修改（请先解除资源关联）");
			}
		}

		OntExtensionModule update = new OntExtensionModule();
		update.setId(old.getId());
		update.setModuleName(request.getModuleName());
		update.setNamespaceId(request.getNamespaceId());
		update.setDescription(request.getDescription());
		update.setVersion(request.getVersion());
		update.setSortOrder(request.getSortOrder());
		update.setRemarks(request.getRemarks());
		this.updateById(update);
		return R.ok(this.getById(old.getId()));
	}

	@Override
	@Transactional(rollbackFor = Exception.class)
	public R<Boolean> removeModule(Long id) {
		OntExtensionModule module = this.getById(id);
		if (module == null) {
			return R.failed("扩展模块不存在");
		}
		if (BUILTIN.equals(module.getIsBuiltin())) {
			return R.failed("内置扩展模块不可删除");
		}

		// 逻辑删除关联资源（不删除资源本身）
		resourceMapper.update(null, Wrappers.<OntExtensionResource>lambdaUpdate()
			.eq(OntExtensionResource::getModuleId, id)
			.set(OntExtensionResource::getDelFlag, "1"));

		return R.ok(this.removeById(id));
	}

	@Override
	public ExtensionModuleDetailVO getDetail(Long id) {
		OntExtensionModule module = this.getById(id);
		if (module == null) {
			return null;
		}
		ExtensionModuleDetailVO vo = new ExtensionModuleDetailVO();
		// BeanUtils.copyProperties or manual mapping
		vo.setId(module.getId());
		vo.setModuleCode(module.getModuleCode());
		vo.setModuleName(module.getModuleName());
		vo.setNamespaceId(module.getNamespaceId());

		// 填充命名空间信息
		OntNamespace ns = namespaceMapper.selectById(module.getNamespaceId());
		if (ns != null) {
			vo.setNamespacePrefix(ns.getPrefix());
			vo.setNamespaceUri(ns.getUri());
		}

		vo.setOntologyId(module.getOntologyId());
		vo.setDescription(module.getDescription());
		vo.setVersion(module.getVersion());
		vo.setIsBuiltin(module.getIsBuiltin());
		vo.setSortOrder(module.getSortOrder());
		vo.setRemarks(module.getRemarks());
		vo.setCreateTime(module.getCreateTime());

		// 填充资源数量
		long resourceCount = resourceMapper.selectCount(Wrappers.<OntExtensionResource>lambdaQuery()
			.eq(OntExtensionResource::getModuleId, id)
			.eq(OntExtensionResource::getDelFlag, EXTENSION));
		vo.setResourceCount(resourceCount);

		return vo;
	}

	@Override
	public ExtensionValidationReport validateModule(Long id) {
		OntExtensionModule module = this.getById(id);
		if (module == null) {
			return null;
		}
		return validator.validateModule(module);
	}

	@Override
	public String exportModule(Long id, String format) {
		OntExtensionModule module = this.getById(id);
		if (module == null) {
			return null;
		}
		return exporter.exportModule(module, format);
	}

	@Override
	public String getExportFilename(Long id, String format) {
		OntExtensionModule module = this.getById(id);
		if (module == null) {
			return "extension." + format.toLowerCase().replace("-", "");
		}
		String ext = switch (format) {
			case "TURTLE" -> "ttl";
			case "JSON-LD" -> "jsonld";
			case "RDF-XML" -> "rdf";
			case "N-TRIPLES" -> "nt";
			default -> "txt";
		};
		return module.getModuleCode() + "_extension." + ext;
	}

		}

		summary.setModuleCode(module.getModuleCode());

		// 1. 资源摘要
		List<OntExtensionResource> resources = resourceMapper.selectList(
			Wrappers.<OntExtensionResource>lambdaQuery()
				.eq(OntExtensionResource::getModuleId, moduleId)
				.eq(OntExtensionResource::getDelFlag, "0"));

		Map<String, Long> countByType = resources.stream()
			.collect(Collectors.groupingBy(
			 OntExtensionResource::getResourceType,
			 Collectors.counting()));

		ExtensionImpactSummaryVO.ResourceSummaryVO resourceSummary = new ExtensionImpactSummaryVO.ResourceSummaryVO();
		resourceSummary.setEntityType(countByType.getOrDefault("ENTITY_TYPE", 0L).intValue());
		resourceSummary.setDataProperty(countByType.getOrDefault("DATA_PROPERTY", 0L).intValue());
		resourceSummary.setObjectProperty(countByType.getOrDefault("OBJECT_PROPERTY", 0L).intValue());
		resourceSummary.setAxiomRule(countByType.getOrDefault("AXIOM_RULE", 0L).intValue());
		resourceSummary.setUnit(countByType.getOrDefault("UNIT", 0L).intValue());
		summary.setResourceSummary(resourceSummary);

		// 2. 实例影响（查询关联实体类型下的实例数）
		List<Long> entityTypeIds = resources.stream()
			.filter(r -> "ENTITY_TYPE".equals(r.getResourceType()))
			.map(OntExtensionResource::getResourceId)
			.toList();

		if (!entityTypeIds.isEmpty()) {
			List<OntEntityType> entityTypes = entityTypeMapper.selectBatchIds(entityTypeIds);
			List<ExtensionImpactSummaryVO.InstanceCountVO> instanceCounts = new ArrayList<>();
			int totalInstances = 0;

			for (OntEntityType type : entityTypes) {
				long count = entityInstanceMapper.selectCount(Wrappers.<OntEntityInstance>lambdaQuery()
					.eq(OntEntityInstance::getRdfTypeIri, type.getIri()));
				if (count > 0) {
					ExtensionImpactSummaryVO.InstanceCountVO ic = new ExtensionImpactSummaryVO.InstanceCountVO();
					ic.setEntityTypeIri(type.getIri());
					ic.setCount((int) count);
					instanceCounts.add(ic);
					totalInstances += (int) count;
				}
			}

			ExtensionImpactSummaryVO.InstanceImpactVO instanceImpact = new ExtensionImpactSummaryVO.InstanceImpactVO();
			instanceImpact.setTotalInstances(totalInstances);
			instanceImpact.setInstancesByType(instanceCounts);
			summary.setInstanceImpact(instanceImpact);
		}

		// 3. 导出影响（查询最近的导出日志）
		ExtensionImpactSummaryVO.ExportImpactVO exportImpact = new ExtensionImpactSummaryVO.ExportImpactVO();
		exportImpact.setActiveExportTasks(0);
		exportImpact.setLastExportLogId(null);
		summary.setExportImpact(exportImpact);

		return summary;
	}

## 13. 风险与对策

| 风险 | 影响 | 对策 |
|------|------|------|
| 扩展资源逻辑关联表无物理外键，资源被删除后关联记录成为悬空引用 | 列表展示悬空数据、导出包含不存在的资源 | 定期清理任务（`ExtensionResourceCleanupJob`）扫描关联表中 `resource_id` 指向已删除资源的记录，逻辑删除关联；列表展示时 JOIN 查询过滤悬空记录 |
| R3 定义矛盾检测使用文本相似度启发式，可能误报或漏报 | WARNING 级假阳性过多或遗漏真实矛盾 | R3 为 WARNING 级（不阻断操作），用户可忽略假阳性；远期升级为 NLP 语义比对 |
| 扩展模块导出委托序列化模块，需序列化模块增加 `ExtensionExportFilter` 参数 | 序列化模块（10）需向后兼容增强 | 过滤器为可选参数（null 时行为不变），序列化模块 `OntologyModelExporter` 增加 filter 判断逻辑，不破坏已有 API |
| 核心类型被修改导致 R5 误判 | 核心类型的 `update_time` 因非语义字段（如 description）更新而误判为"核心被修改" | R5 校验核心类型的 `name`/`iri`/`definition` 语义字段是否变更（而非 `update_time`），仅语义字段变更判为 VIOLATION |
| 扩展模块数量增长后列表性能下降 | 分页查询慢 | `ont_extension_module` 表已有 `module_code` 唯一索引和 `namespace_id`/`ontology_id` 普通索引，支持高效分页查询 |
| 扩展模块与本体工程的 1:N 关系导致跨工程查询复杂 | 用户在多个本体工程中创建扩展模块时管理混乱 | 首期扩展模块默认归属核心工程（`CORE_ONTOLOGY_ID`），不支持跨工程模块；远期支持多工程扩展管理 |

## 16. 后续模块稳定契约

### 16.1 本模块对后续模块的承诺

1. `ont_extension_module` 表结构和 `ont_extension_resource` 表结构在首期交付后不再变更（字段只增不删不改语义）。
2. `ExtensionValidator` 的 5 条规则编号（R1~R5）固定，后续规则扩展使用 R6、R7... 递增编号。
3. 扩展管理 REST API 路径（`/ontology/extension/...`）固定，后续版本仅增加端点不修改已有端点语义。
4. 扩展组件注册列表 API（`GET /components/registered`）返回格式固定，后续可增加组件类型（当前仅 ReasonerAdapter）。

### 16.2 本模块对前置模块的要求

1. 序列化模块（10）需增加 `ExtensionExportFilter` 可选参数支持——这是本模块对前置模块的唯一新增要求，为向后兼容增强。
2. 各已有模块（03~07）的 `is_builtin` 字段和扩展命名空间校验逻辑保持不变。
3. `ont_namespace` 表的 `is_builtin` 字段语义不变（`'1'`=核心，`'0'`=扩展）。

> **文档结束**
>
> 本设计文档严格依据 GB/T 48000.3—2026 第 9 章扩展方式设计，对应 PRD §4.9 扩展管理模块。核心设计原则为"编排层不侵入已有模块"——扩展管理模块作为编排层，不拥有扩展资源的 CRUD 权限（由各已有模块 03~07 负责），仅负责"分组管理 + 合法性校验（第 9.2 条 5 条规则）+ 模块导出 + 变更影响分析 + 扩展组件注册展示"。扩展模块与资源通过逻辑关联表（`ont_extension_resource`）多态引用，零侵入已有表结构。模块导出委托序列化模块（10）的 `SerializationService`，通过资源 ID 过滤器实现按模块维度筛选，不重复构建序列化器。合法性校验引擎实现 5 条规则（R1~R5），VIOLATION 级阻断操作、WARNING 级提示用户确认。推理引擎适配层（§4.7.4）的 `ReasonerAdapter` SPI 通过扩展管理模块的组件注册列表展示，本期不实现在线热注册。与可视化模块（§4.10）的衔接通过扩展资源关联表和模块列表 API 实现。
