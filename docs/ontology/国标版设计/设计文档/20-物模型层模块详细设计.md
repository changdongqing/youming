## 1. 评审结论

物模型层是 IoT 数据进入本体语义层的强制契约层。没有物模型，MQTT 遥测数据只是无语义的裸数据（`{deviceId, temperature, status}`），无法确定属性含义、单位、读写方向和值域。本模块在模块18 数据源映射已完成、`OntologyInstanceIngestionService` 已预留 `IOT` 来源类型的基础上，建设物模型本体定义与本体映射契约，不建设 MQTT 接入和时序存储（属模块19/21）。

| 级别 | 问题 | 设计结论 |
|---|---|---|
| P0 | IoT 属性与标准数字化属性语义不同，不能混用模块05核心数据属性 | 建立独立物模型扩展命名空间，物模型属性作为扩展数据属性，domain 指向物模型实体类型 |
| P0 | 物模型必须与本体实体类型/属性双向映射，否则 IoT 数据无法语义化 | 建设物模型→本体映射配置表，复用模块18映射引擎的 IRI 模板和转换器能力 |
| P0 | 物模型版本必须与本体版本兼容绑定，否则 Schema 漂移产生错误实例 | 物模型版本绑定本体已发布版本，复用模块14版本兼容机制 |
| P0 | 设备实例来源必须可溯源 | 复用 `OntologyInstanceIngestionService`，source_type 使用 `IOT`，来源绑定记录设备来源 |
| P1 | 物模型属性含测点单位，不能脱离单位字典 | 复用模块02单位字典，数据属性 `unit_category_id` + `unit_ref_mode` 绑定单位 |
| P1 | 物模型事件 ≠ 校验违规事件，不能塞进模块09校验引擎 | 物模型事件作为独立实体类型建模，事件实例通过 IngestionService 写入，不通过 SHACL 校验 |
| P1 | 下行控制涉及安全联锁，不能在物模型层直接执行 | 物模型定义 Service 语义契约（输入/输出参数），执行层属模块24服务触发，本模块不建设控制链路 |

## 2. 范围

### 2.1 V1 包含

- 物模型扩展本体定义：Product、DeviceModel、Property、Service、Event、Parameter、DataType、EnumEntry 等实体类型及其数据属性、对象属性；
- 物模型版本管理：物模型版本快照、与本体版本兼容绑定；
- 物模型→本体映射配置：物模型属性到本体数据属性的映射规则、IRI 模板、转换器；
- 设备实例语义化入口：设备实例通过 IngestionService 以 `IOT` 来源写入本体，最新状态更新实例属性值；
- 物模型元数据管理前端控制台；
- 物模型映射预览与静态校验。

### 2.2 V1 不包含

- MQTT/Kafka/HTTP 协议接入与遥测消费（属模块19 IoT接入层）；
- 时序数据存储与历史查询（属模块21 时序数据层）；
- 告警规则与通知（属模块23 告警规则模块）；
- 下行控制命令下发与安全联锁执行（属模块24 服务触发层）；
- 设备数字孪生三维可视化（属模块33 数字孪生）；
- 边缘计算与云边协同（属模块35 边缘计算层）；
- BACnet/Modbus/OPC UA 工业协议适配（属模块30 IBMS子系统适配层）；
- 自动实体消歧与模糊匹配（属模块15 本体对齐）。

## 3. 核心术语

| 术语 | 定义 |
|---|---|
| 产品 `Product` | IoT 平台中设备型号的抽象，定义一类设备的物模型契约（对应阿里云 Product / 华为 Product） |
| 设备模型 `DeviceModel` | 物模型的版本化定义容器，一个产品可有多个版本的物模型 |
| 物模型属性 `ThingProperty` | 设备能力描述中的属性项（如温度、电压、开关状态），有数据类型、单位、读写方向 |
| 物模型服务 `ThingService` | 设备可被调用的功能（如召唤电梯、锁梯、调节温度），含输入/输出参数 |
| 物模型事件 `ThingEvent` | 设备主动上报的事件（如困人、超载、故障），有事件类型和参数 |
| 参数 `ThingParameter` | 服务或事件的输入/输出参数定义 |
| 访问模式 `AccessMode` | 属性读写方向：READ_ONLY / WRITE_ONLY / READ_WRITE |
| 物模型版本 `ThingModelVersion` | 物模型配置的不可变发布快照，绑定本体版本 |
| 设备实例 `DeviceInstance` | 物理设备的本体实例，source_type 为 IOT |
| 物模型映射 `ThingModelMapping` | 物模型属性到本体数据属性的语义映射规则 |

## 6. 物模型版本状态机

### 6.1 物模型版本状态

```text
DRAFT ──publish──→ PUBLISHED ──deprecate──→ DEPRECATED
  │                    │
  │                    ├── newVersion ──→ DRAFT（新版本）
  │                    └── rollback（恢复到前一版本）
  └── discard ──→ (删除)
```

| 状态 | 含义 | 允许操作 |
|---|---|---|
| DRAFT | 编辑中，可修改属性/服务/事件定义 | 编辑、预览、发布、废弃 |
| PUBLISHED | 已发布，不可修改，设备实例可引用 | 废弃、创建新版本 |
| DEPRECATED | 已废弃，不阻止已有引用但不可新建设备引用 | — |

### 6.2 物模型版本与本体版本绑定规则

| 物模型版本操作 | 本体版本约束 | 校验逻辑 |
|---|---|---|
| 发布物模型版本 | 必须绑定一个 `PUBLISHED` 状态的本体版本 | 复用 `WorkspaceStatusGuard` 检查本体版本为 PUBLISHED |
| 本体版本 BREAKING 变更 | 关联的物模型版本标记为需复核 | 物模型版本状态不变，但标记 `compatibility_review_required=1` |
| 物模型版本发布预检 | 执行本体版本兼容性检查 | 复用 `OntologyCompatibilityClassifier` 判定 BREAKING |

### 6.3 设备实例引用物模型版本规则

- 设备实例（943010）通过 `usesThingModelVersion`（963011）引用一个 `PUBLISHED` 状态的物模型版本；
- 引用 `DRAFT` 或 `DEPRECATED` 版本的设备实例写入被拒绝（IngestionService 校验）；
- 物模型版本废弃后，已有设备实例不被强制迁移，但新设备不可引用。

## 8. 表结构DDL

### 8.1 ont_thing_model_version

```sql
CREATE TABLE ont_thing_model_version (
    id                   BIGSERIAL PRIMARY KEY,
    product_id           BIGINT NOT NULL,           -- 产品实体实例ID（ont_entity_instance.id）
    version_number       VARCHAR(32) NOT NULL,      -- SemVer: 1.0.0
    prior_version_id     BIGINT,                    -- 前一版本自引用
    release_status       VARCHAR(16) NOT NULL DEFAULT 'DRAFT'
                         CHECK (release_status IN ('DRAFT','PUBLISHED','DEPRECATED')),
    ontology_version_id  BIGINT NOT NULL,           -- 绑定的本体版本ID（ont_ontology_version.id）
    compatibility_review_required CHAR(1) NOT NULL DEFAULT '0',
    snapshot             JSONB NOT NULL,             -- 物模型全量快照（属性/服务/事件/参数/枚举）
    snapshot_hash        VARCHAR(64) NOT NULL,       -- SHA-256
    diff_summary         JSONB,                      -- 与前一版本的diff
    description          TEXT,
    published_at         TIMESTAMP,
    deprecated_at        TIMESTAMP,
    create_by            VARCHAR(64),
    create_time          TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    update_by            VARCHAR(64),
    update_time          TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    del_flag             CHAR(1) DEFAULT '0',
    UNIQUE (product_id, version_number, del_flag),
    FOREIGN KEY (ontology_version_id) REFERENCES ont_ontology_version(id)
);

CREATE INDEX idx_thing_model_version_product ON ont_thing_model_version(product_id)
    WHERE del_flag='0';
```

## 10. 物模型映射预览与校验

### 10.1 静态校验项

| 序号 | 校验项 | 级别 | 说明 |
|---|---|---|---|
| 1 | 物模型属性编码唯一性 | VIOLATION | 同一版本内 propertyCode 不得重复 |
| 2 | 映射目标数据属性存在性 | VIOLATION | target_data_property_id 必须存在于已发布本体版本 |
| 3 | 映射目标实体类型存在性 | VIOLATION | target_entity_type_id 必须存在于已发布本体版本 |
| 4 | IRI模板语法 | VIOLATION | 复用模块18 IriTemplateCompiler 校验 |
| 5 | 转换器合法性 | VIOLATION | transformer_code 必须在 TransformerRegistry 已注册 |
| 6 | 数据类型兼容 | WARNING | 物模型 propertyBaseType 与本体 base_type 兼容性（int→NUMERIC, string→TEXT, bool→BOOLEAN） |
| 7 | 单位维度兼容 | WARNING | 物模型单位与本体数据属性单位维度一致（温度≠电压） |
| 8 | 枚举值子集 | WARNING | 物模型枚举值必须为本体数据属性枚举的子集（复用R4规则） |
| 9 | 读写方向一致 | WARNING | 物模型 READ_ONLY 属性不应映射到需写入的本体属性 |
| 10 | 必填属性覆盖 | WARNING | 物模型 isRequired=1 的属性应有映射配置 |
| 11 | 服务映射完整性 | VIOLATION | 服务映射的输入参数应有对应本体属性或参数实体 |
| 12 | 事件映射完整性 | VIOLATION | 事件映射的事件类型应有对应本体属性值 |
| 13 | 本体版本已发布 | VIOLATION | 绑定的本体版本必须为 PUBLISHED |

### 10.2 抽样预览流程

```text
1. 读取物模型版本快照，加载属性/服务/事件定义
2. 对每个已配置映射的属性：
   a. 构造模拟源值（根据 propertyBaseType 生成样例）
   b. 执行转换器（transformer_code + transformer_config）
   c. 生成IRI（iri_template + 模拟设备编码）
   d. 检查数据类型兼容、单位兼容
3. 生成预览结果：
   - 模拟IRI
   - 转换后的值
   - 目标本体属性
   - 兼容性警告
   - 预计成功/失败计数
```

## 11. 设备实例摄入流程

### 11.1 设备最新状态摄入

```text
模块19 IoT接入层接收到 MQTT 消息
  → 解析为 {deviceCode, propertyCode: value} 映射
  → 调用 ThingModelIngestionAdapter.ingestDeviceState(versionId, deviceCode, propertyValues, sourceId, messageId)
  → 适配器执行：
    1. 查询物模型版本快照，验证版本为 PUBLISHED
    2. 查询设备实例（通过 deviceCode + sourceId 定位 ont_source_instance_binding）
    3. 对每个 propertyCode：
       a. 查询 ont_thing_model_property_mapping 获取映射配置
       b. 执行转换器（transformer_code）
       c. 执行单位转换（unit_conversion_code）
       d. 构造 ValueIngestionItem（ownership_policy, null_strategy）
    4. 构造 EntityIngestionCommand：
       - entityTypeId = 943010 (DeviceInstance)
       - sourceType = IOT
       - SourceIdentity(sourceId, mappingProjectId=null, mappingVersionId=thingModelVersionId,
                        entityMappingCode=deviceCode, sourceObject=deviceCode,
                        sourceRecordKey=deviceCode)
       - values = List<ValueIngestionItem>
       - contentHash = SHA-256(propertyValues)
    5. 调用 OntologyInstanceIngestionService.upsertEntity(command)
    6. IngestionService 内部执行：
       - 版本守卫（WorkspaceStatusGuard）
       - 幂等检查（content_hash + source_binding）
       - 属性所有权冲突策略
       - SHACL校验
       - 来源绑定 upsert
       - 事件发布（INSTANCE_INGESTED / INSTANCE_UPDATED_FROM_SOURCE）
```

### 11.2 设备事件摄入

```text
模块19 解析设备事件消息
  → 调用 ThingModelIngestionAdapter.ingestDeviceEvent(versionId, deviceCode, eventCode, eventParams, sourceId, messageId)
  → 适配器执行：
    1. 查询 ont_thing_model_event_mapping 获取事件映射
    2. 构造事件实例 EntityIngestionCommand：
       - entityTypeId = 映射的目标事件实体类型
       - IRI = iri_template（含 messageId 保证唯一性）
       - values = 事件参数映射后的值
    3. 构造设备→事件关系 RelationIngestionCommand
    4. 调用 IngestionService.upsertEntity + upsertRelation
```

### 11.3 幂等控制

| 幂等键 | 构成 | 作用 |
|---|---|---|
| 设备状态幂等 | `sourceId + deviceCode + contentHash` | 相同设备状态重复消息不重复写入 |
| 设备事件幂等 | `sourceId + deviceCode + messageId` | 相同事件消息不重复创建事件实例 |
| 设备实例幂等 | `(sourceId, entityMappingCode=deviceCode, sourceRecordKey=deviceCode)` | 同一设备不重复创建实例 |

## 12. 事件

| 事件 | 触发条件 | 载荷 |
|---|---|---|
| `THING_MODEL_VERSION_PUBLISHED` | 物模型版本发布 | versionId, productId, versionNumber, ontologyVersionId |
| `THING_MODEL_VERSION_DEPRECATED` | 物模型版本废弃 | versionId, productId, versionNumber |
| `DEVICE_STATE_INGESTED` | 设备最新状态写入完成 | deviceCode, versionId, instanceIri, updatedPropertyCount |
| `DEVICE_EVENT_INGESTED` | 设备事件实例创建完成 | deviceCode, versionId, eventCode, eventInstanceIri |
| `THING_MODEL_MAPPING_VALIDATION_FAILED` | 映射校验失败 | versionId, issues |
| `DEVICE_INGESTION_REJECTED` | 设备摄入被拒绝 | deviceCode, versionId, reason, messageId |

事件载荷遵循数据最小化原则，不包含设备密钥、未脱敏敏感值。

## 19. 测试与验收

### 19.1 功能验收

1. 能创建产品并定义属性/服务/事件/参数；
2. 能发布物模型版本并绑定已发布本体版本；
3. 能配置物模型属性到本体数据属性的映射；
4. 能配置物模型服务到本体语义实体的映射；
5. 能配置物模型事件到本体事件实体类型的映射；
6. 映射静态校验能检出 VIOLATION 和 WARNING；
7. 映射预览能生成模拟IRI和转换值；
8. 设备实例能通过 IngestionService 以 IOT 来源写入；
9. 重复设备状态消息不产生重复写入（幂等）；
10. 物模型版本废弃后新设备不可引用，已有设备不受影响；
11. 本体版本 BREAKING 变更后物模型版本标记需复核；
12. 设备密钥不以明文出现在数据库、日志和事件载荷中。

### 19.2 语义验收

通过 SPARQL 能查询：

- 某产品定义了哪些物模型属性；
- 某物模型属性映射到哪个本体数据属性；
- 某设备实例属于哪个产品、使用哪个物模型版本；
- 某设备实例的最新状态属性值；
- 某设备实例上报过哪些事件；
- 某物模型版本绑定了哪个本体版本。

### 19.3 一致性验收

- 物模型扩展本体通过模块11扩展合法性5条规则校验（R1命名空间、R2名称不重复、R3定义不矛盾、R4枚举子集、R5子类扩展）；
- 物模型版本快照 hash 与重新构建的 hash 一致；
- 物模型映射配置变更后重新发布版本，旧版本不受影响。
