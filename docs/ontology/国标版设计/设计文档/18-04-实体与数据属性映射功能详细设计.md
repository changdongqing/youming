# 实体与数据属性映射功能详细设计

> 模块：18 数据源映射  
> 功能编号：18-04  
> 前置：03～05、08、18-02、18-03  
> 设计日期：2026-07-14

## 1. 目标

配置并编译“源对象记录 → 本体实体实例”和“源列 → 数据属性值”的确定性映射，包括稳定身份、IRI、标签、类型转换、空值、多值、单位和所有权策略。

## 2. 核心约束

- 实体映射必须指定稳定主键；
- IRI必须由命名空间和稳定键确定，不可使用随机值或当前时间；
- 字段映射只能引用实体类型适用的数据属性；
- V1源表达式仅允许单列，不允许任意SQL；
- 转换器必须确定、无外部副作用、可重放；
- 敏感字段映射必须通过模块36策略；
- 映射删除只影响本映射拥有的数据值。

## 3. 实体映射表

```sql
CREATE TABLE ont_entity_mapping (
  id bigint NOT NULL,
  mapping_version_id bigint NOT NULL,
  mapping_code varchar(64) NOT NULL,
  mapping_name varchar(128) NOT NULL,
  source_id bigint NOT NULL,
  source_schema varchar(128) NOT NULL,
  source_object varchar(128) NOT NULL,
  source_object_type varchar(16) NOT NULL DEFAULT 'TABLE',
  target_entity_type_id bigint NOT NULL,
  target_namespace_id bigint NOT NULL,
  key_columns jsonb NOT NULL,
  iri_template varchar(512) NOT NULL,
  label_template varchar(512) DEFAULT NULL,
  filter_dsl jsonb DEFAULT NULL,
  incremental_column varchar(128) DEFAULT NULL,
  incremental_type varchar(16) DEFAULT NULL,
  source_delete_flag_column varchar(128) DEFAULT NULL,
  source_delete_values jsonb DEFAULT NULL,
  delete_strategy varchar(24) NOT NULL DEFAULT 'MARK_INACTIVE',
  inactive_property_id bigint DEFAULT NULL,
  inactive_literal_value varchar(255) DEFAULT NULL,
  conflict_policy varchar(24) NOT NULL DEFAULT 'SOURCE_WINS',

  update_by varchar(64) DEFAULT ' ',

  PRIMARY KEY (id),
  CONSTRAINT fk_ont_entity_map_version FOREIGN KEY (mapping_version_id)
    REFERENCES ont_mapping_version(id) ON DELETE CASCADE,
  CONSTRAINT fk_ont_entity_map_source FOREIGN KEY (source_id)
    REFERENCES ont_data_source(id) ON DELETE RESTRICT,
  CONSTRAINT fk_ont_entity_map_type FOREIGN KEY (target_entity_type_id)
    REFERENCES ont_entity_type(id) ON DELETE RESTRICT,
  CONSTRAINT fk_ont_entity_map_namespace FOREIGN KEY (target_namespace_id)
    REFERENCES ont_namespace(id) ON DELETE RESTRICT,
  CONSTRAINT fk_ont_entity_map_inactive_prop FOREIGN KEY (inactive_property_id)
    REFERENCES ont_data_property(id) ON DELETE RESTRICT,
  CONSTRAINT ck_ont_entity_map_object_type CHECK (source_object_type IN ('TABLE','VIEW')),
  CONSTRAINT ck_ont_entity_map_inc_type
    CHECK (incremental_type IS NULL OR incremental_type IN ('TIMESTAMP','NUMERIC')),
  CONSTRAINT ck_ont_entity_map_delete
    CHECK (delete_strategy IN ('IGNORE','MARK_INACTIVE','SOFT_DELETE','BLOCK_AND_REVIEW')),
  CONSTRAINT ck_ont_entity_map_conflict
    CHECK (conflict_policy IN ('SOURCE_WINS','MANUAL_WINS','REJECT_CONFLICT')),
  CONSTRAINT ck_ont_entity_map_enabled CHECK (enabled IN ('0','1')),
  CONSTRAINT ck_ont_entity_map_order CHECK (sync_order >= 0),
  CONSTRAINT ck_ont_entity_map_revision CHECK (revision >= 0),
  CONSTRAINT ck_ont_entity_map_del CHECK (del_flag IN ('0','1'))
);

CREATE UNIQUE INDEX uk_ont_entity_map_code
  ON ont_entity_mapping(mapping_version_id, mapping_code)
  WHERE del_flag = '0';
CREATE INDEX idx_ont_entity_map_source
  ON ont_entity_mapping(source_id, source_schema, source_object)
  WHERE del_flag = '0';
CREATE INDEX idx_ont_entity_map_order
  ON ont_entity_mapping(mapping_version_id, sync_order)
  WHERE del_flag = '0' AND enabled = '1';
```

### 3.1 key_columns

```json
[
  {"column":"user_id","order":1,"normalizer":"LONG"}
]
```

复合键：

```json
[
  {"column":"user_id","order":1,"normalizer":"LONG"},
  {"column":"tenant_id","order":2,"normalizer":"TRIM_STRING"}
]
```

要求：

- 列存在、不可为空或配置明确空键拒绝；
- 默认必须等于主键或唯一键；
- 使用非唯一键时发布失败；
- 视图无PK时允许用户选择经预览唯一性验证的列组，但发布报告标记高风险；
- normalizer只允许内置稳定规范化器。

## 4. IRI模板

V1语法：

```text
user-account/{user_id|url}
organization/{dept_id|url}
position/{post_id|url}
```

最终IRI：

```text
namespace.uri + renderedLocalName
```

支持过滤器：

- `url`：UTF-8 percent encoding；
- `lower`：Locale.ROOT小写；
- `upper`：Locale.ROOT大写；
- `trim`；
- `number`：规范十进制；
- `date:yyyyMMdd`：输入需为日期类型。

禁止：

- `now/random/uuid`；
- 网络查询；
- 脚本；
- 未在keyColumns中的字段参与身份模板，除非发布时明确标记为高风险并仍保证稳定性。V1直接限制IRI模板变量必须是keyColumns。

生成后本地名必须满足命名空间模块允许的IRI规则，长度不超过128。完整IRI不超过512。

### 4.1 模板变化

- PUBLISHED版本之间IRI模板变化分类为`MAJOR_HIGH_RISK`；
- 已有来源绑定保持原IRI，不自动迁移；
- 新记录使用新模板会造成同工程内新旧IRI风格并存，因此默认发布阻断；
- 只有映射工程尚无ACTIVE来源绑定时允许直接修改；否则要求专门IRI迁移计划。

## 5. 标签模板

语法与IRI模板相似，但可引用任意已选择源列：

```text
{name}（{username}）
```

- 缺失变量按`labelNullPolicy`处理，V1固定为空字符串并清理重复分隔符较复杂，故建议字段映射指定label源；
- 设计实现采用简单模板：任一变量为空时允许渲染为空，不自动理解中文标点；
- 最终label为空时回退到`iriLocalName`；
- label最大255，超长按错误处理，默认不截断以免丢语义；可显式使用`TRUNCATE`转换器。

## 6. 字段映射表

```sql
CREATE TABLE ont_field_mapping (
  id bigint NOT NULL,
  entity_mapping_id bigint NOT NULL,
  mapping_code varchar(64) NOT NULL,
  mapping_name varchar(128) NOT NULL,
  source_kind varchar(16) NOT NULL DEFAULT 'COLUMN',
  source_column varchar(128) DEFAULT NULL,
  constant_value text DEFAULT NULL,
  target_data_property_id bigint NOT NULL,
  transform_type varchar(32) NOT NULL DEFAULT 'IDENTITY',
  transform_config jsonb DEFAULT NULL,
  null_policy varchar(24) NOT NULL DEFAULT 'SKIP_VALUE',
  default_literal_value text DEFAULT NULL,
  error_policy varchar(16) NOT NULL DEFAULT 'REJECT_RECORD',
  ownership_policy varchar(24) NOT NULL DEFAULT 'SOURCE_WINS',
  multi_value_mode varchar(16) NOT NULL DEFAULT 'SINGLE',
  multi_value_delimiter varchar(16) DEFAULT NULL,
  fixed_unit_id bigint DEFAULT NULL,
  sort_order integer NOT NULL DEFAULT 0,
  enabled char(1) NOT NULL DEFAULT '1',
  description varchar(255) DEFAULT NULL,
  revision bigint NOT NULL DEFAULT 0,
  create_by varchar(64) DEFAULT ' ',
  create_time timestamp NOT NULL DEFAULT now(),
  update_by varchar(64) DEFAULT ' ',
  update_time timestamp DEFAULT NULL,
  del_flag char(1) NOT NULL DEFAULT '0',
  PRIMARY KEY (id),
  CONSTRAINT fk_ont_field_map_entity FOREIGN KEY (entity_mapping_id)
    REFERENCES ont_entity_mapping(id) ON DELETE CASCADE,
  CONSTRAINT fk_ont_field_map_property FOREIGN KEY (target_data_property_id)
    REFERENCES ont_data_property(id) ON DELETE RESTRICT,
  CONSTRAINT fk_ont_field_map_unit FOREIGN KEY (fixed_unit_id)
    REFERENCES ont_unit(id) ON DELETE RESTRICT,
  CONSTRAINT ck_ont_field_map_source_kind
    CHECK (source_kind IN ('COLUMN','CONSTANT')),
  CONSTRAINT ck_ont_field_map_source_value CHECK (
    (source_kind = 'COLUMN' AND source_column IS NOT NULL AND constant_value IS NULL) OR
    (source_kind = 'CONSTANT' AND source_column IS NULL AND constant_value IS NOT NULL)
  ),
  CONSTRAINT ck_ont_field_map_null
    CHECK (null_policy IN ('SKIP_VALUE','USE_DEFAULT','REJECT_RECORD','CLEAR_OWNED_VALUE')),
  CONSTRAINT ck_ont_field_map_error
    CHECK (error_policy IN ('REJECT_RECORD','SKIP_FIELD')),
  CONSTRAINT ck_ont_field_map_owner
    CHECK (ownership_policy IN ('SOURCE_WINS','MANUAL_WINS','REJECT_CONFLICT')),
  CONSTRAINT ck_ont_field_map_multi
    CHECK (multi_value_mode IN ('SINGLE','DELIMITED')),
  CONSTRAINT ck_ont_field_map_enabled CHECK (enabled IN ('0','1')),
  CONSTRAINT ck_ont_field_map_order CHECK (sort_order >= 0),
  CONSTRAINT ck_ont_field_map_revision CHECK (revision >= 0),
  CONSTRAINT ck_ont_field_map_del CHECK (del_flag IN ('0','1'))
);

CREATE UNIQUE INDEX uk_ont_field_map_code
  ON ont_field_mapping(entity_mapping_id, mapping_code)
  WHERE del_flag = '0';
CREATE INDEX idx_ont_field_map_property
  ON ont_field_mapping(target_data_property_id)
  WHERE del_flag = '0';
```

`source_kind=COLUMN`读取源列；`CONSTANT`用于`externalSystem`等非敏感固定值。常量不得保存凭证、Token或环境密钥。

默认不禁止多个来源项映射同一目标属性，因为多值属性可能需要；发布校验根据属性基数和`is_unique`决定是否合法。

## 7. 转换器注册表

```java
public interface MappingValueTransformer {
    String code();
    Set<JdbcTypeFamily> supportedSources();
    Set<OntologyLiteralType> supportedTargets();
    TransformResult transform(SourceValue source, TransformConfig config);
}
```

V1内置：

| code | 用途 |
|---|---|
| `IDENTITY` | 类型兼容时直传 |
| `TRIM` | 去首尾空格 |
| `LOWER`/`UPPER` | Locale.ROOT大小写 |
| `TO_STRING` | 数字/布尔转规范字符串 |
| `TO_INTEGER` | 精确整数，禁止静默舍入 |
| `TO_DECIMAL` | BigDecimal规范化 |
| `TO_BOOLEAN` | 配置true/false值集合 |
| `DATE_FORMAT` | 日期时间转目标DATE词法值 |
| `ENUM_MAP` | 显式字典映射 |
| `PREFIX`/`SUFFIX` | 固定前后缀 |
| `TRUNCATE` | 显式最大长度，报告中可见 |

> `MASKED_COPY`不适用于持久化安全，禁止用其代替模块36脱敏；V1不实现，后续版本如有需要再评估。

### 7.1 ENUM_MAP

```json
{

    "0": "正常",
    "9": "锁定"

  "unknownPolicy": "REJECT",
  "unknownValue": null
```

### 7.2 日期

当前实例值`literal_type`只支持`DATE`而非独立DATETIME。V1规则：

- 目标数据属性baseType=DATE时输出`YYYYMMDD`或现有模块定义的规范值；
- 组织账号需要完整时间戳，V22统一扩展数据属性和实例字面量类型为`DATETIME`，不能把`2026-07-14 12:00:00`伪装成DATE；
- V23的`createdAt/updatedAt`直接使用该类型。

V22必须同时扩展数据属性定义和实例字面量：

```sql
ALTER TABLE ont_data_property
  DROP CONSTRAINT IF EXISTS ck_ont_data_property_base_type;
ALTER TABLE ont_data_property
  ADD CONSTRAINT ck_ont_data_property_base_type
  CHECK (base_type IN ('BOOLEAN','DATE','DATETIME','NUMERIC','TEXT','URI','UNIT_REF','TEXT_OR_NUMERIC'));

ALTER TABLE ont_instance_data_value
  DROP CONSTRAINT IF EXISTS ck_ont_instance_value_literal_type;
ALTER TABLE ont_instance_data_value
  ADD CONSTRAINT ck_ont_instance_value_literal_type
  CHECK (literal_type IN ('STRING','URI','DATE','DATETIME','INTEGER','DECIMAL','BOOLEAN'));
```

同时更新模块05、08、09、10相关枚举、动态表单、校验器和序列化器，`DATETIME`导出为`xsd:dateTime`。该改造是数据源时间字段正确映射的必要前置，不能通过字符串规避。

具体需改造的Java类清单（按模块）：

```text
模块05 数据属性定义:
  - DataPropertyBaseType.java              # 枚举增加 DATETIME
  - DataPropertyFormService.java            # 动态表单增加DATETIME选项和编辑控件
  - DataPropertyServiceImpl.java            # base_type写入校验

模块08 实例值:
  - InstanceLiteralType.java                # 枚举增加 DATETIME
  - OntInstanceDataValue.java               # literal_type字段映射
  - InstanceDataValueServiceImpl.java       # 值类型写入和读取

模块09 校验:
  - DataPropertyValidator.java              # base_type=DATETIME的值域校验
  - LiteralTypeValidator.java               # literal_type=DATETIME的格式校验(ISO-8601)
  - ShaclValidator.java                     # SHACL规则中xsd:dateTime约束

模块10 序列化:
  - OntologyModelExporter.java              # DATETIME导出为 xsd:dateTime
  - RdfLiteralMapper.java                    # Java时间类型→RDF字面量映射
  - JsonSerializer.java                      # JSON输出包含ISO-8601时间戳
```

模块18映射自身:
  - `MappingValueTransformer` 的 `DateFormatTransformer` 需支持输出DATETIME类型；
  - `TransformResult` 中 `OntologyLiteralType` 枚举需同步增加 DATETIME。

## 8. 空值语义

| 策略 | 行为 |
|---|---|
| `SKIP_VALUE` | 不写入新值，也不删除旧来源值 |
| `USE_DEFAULT` | 使用显式default值，default仍需转换和校验 |
| `REJECT_RECORD` | 整条源记录失败，不部分更新 |
| `CLEAR_OWNED_VALUE` | 删除本字段映射拥有的旧值，不影响人工/其他来源值 |

必填属性遇到SKIP/CLEAR后仍为空时，增量校验失败。不得把SQL NULL自动转换为空字符串。

## 9. 多值

V1支持：

- `SINGLE`：单值；
- `DELIMITED`：字符串按固定分隔符拆分。

DELIMITED规则：

- 分隔符长度1～8；
- 支持转义会增加复杂度，V1不支持转义，含分隔符的真实值不适用；
- 拆分后trim、过滤空元素、保持源顺序；
- 每个元素分别转换和校验；
- 目标属性必须允许多值；
- 最大100个值，超过拒绝记录。

JSON数组源列留作V1.1，不在V1隐式解析。

## 10. 单位

- 目标属性`unit_ref_mode`要求单位时，字段映射必须配置`fixed_unit_id`或后续单位列映射；
- V1只支持固定单位，动态单位列留作V1.1；
- fixedUnit必须属于目标属性要求的单位分类；
- 写入时同时保存unitId和literalSymbol快照；
- 不能仅把“℃”拼进字符串值。

## 10.1 软删除列与过滤条件

配置`source_delete_flag_column`后，扫描过滤条件不得把所有删除标记值提前排除。执行器先读取记录，再根据删除列决定摄入或失活：

```text
读取源记录
 → delete flag命中：执行删除策略，不执行普通字段映射
 → 未命中：执行字段转换并写lifecycleStatus=ACTIVE
```

发布校验会分析简单Filter DSL；若发现`del_flag = '0'`与`sourceDeleteValues=['1']`同时存在，导致增量作业永远看不到删除行，则产生VIOLATION。纯FULL物理删除检测不受此规则替代。

## 11. 映射编译

`MappingPlanCompiler`在发布和作业启动时编译：

```java
CompiledEntityPlan {
  SourceScanPlan sourceScan;
  SourceKeyPlan sourceKey;
  IriPlan iriPlan;
  LabelPlan labelPlan;
  List<CompiledFieldPlan> fields;
  DeletePlan deletePlan;
  IngestionPolicy ingestionPolicy;
}
```

编译失败属于配置错误，不进入记录级循环。Worker只执行已编译计划，不能每条记录解析模板和JSON配置。

执行计划按`mappingVersionId + configHash`缓存。新版本发布或应用重启后按需重建。

## 15. 测试与验收

- 复合键规范化顺序稳定；
- IRI只使用keyColumns，特殊字符正确编码；
- 相同记录多次生成相同IRI和recordKey；
- NUMBER/DECIMAL不受Locale影响；
- 日期与DATETIME严格区分；
- UNKNOWN枚举按策略处理；
- CLEAR只删除本字段来源值；
- CLOSED_ENUM、单位、必填和唯一性校验正确；
- 多值保持顺序且不超过上限；
- 发布版本不允许编辑；
- 编译计划不包含源凭证和样例值；
- `sys_user.user_id`可稳定生成UserAccount IRI；
- password/salt字段在组织账号模板中不存在映射。
