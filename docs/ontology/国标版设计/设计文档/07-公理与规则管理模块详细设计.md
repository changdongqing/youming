> 对应 PRD：§1.3、§2.7、§3.3、§4.5、§4.7、§5.2、§6.2.1、§7.1、§8.2、§14.2
>
> 直接依据：GB/T 48000.3—2026 第8章（公理与规则）、第5.3条（形式化要求）、附录A.2
>
> 前置模块：01-模块化架构、02-单位字典、03-命名空间与IRI、04-实体类型、05-数据属性、06-对象属性（均已实现）
>
> 设计日期：2026-07-11

## 1. 模块定位与边界

### 1.1 定位

公理与规则（Axiom & Rule）定义实体类型、属性和关系的不可违反的逻辑约束。国标第8章要求定义三大类核心规则——实体类型规则、属性规则、关系规则——并用 OWL 公理和 SHACL 约束双重形式化表达。

本模块是**规则注册与形式化中心**：管理规则的元数据、分类、启用/停用状态、OWL/SHACL 形式化文本和目标引用；同时接管实体类型模块遗留的不相交/等价关系写入口。

### 1.2 本期边界

本期包含：

1. 公理规则定义 CRUD、分页/列表/详情查询、来源标识和内置保护；
2. 国标第8.2条三大类核心规则预置（实体类型规则2项 + 属性规则5项 + 关系规则5项 = 12项）；
3. OWL 公理文本和 SHACL Shape 文本的存储与预览（文本形式，不本期执行）；
4. 规则目标实体类型、数据属性、对象属性的引用关联；
5. 规则启用/停用（扩展规则可启停；核心规则不可停用）；
6. 实体类型不相交/等价关系的写管理接口（V6已建表，写入口归本模块）；
7. 为后续校验引擎（§4.7）、实例建模（§4.6）、序列化（§4.8）提供稳定契约。

本期不包含：SHACL 校验执行引擎、OWL 公理一致性推理执行、Jena/SHACL 运行时集成、实例层实时校验。这些能力由后续校验引擎模块（M2下半期/独立交付）实现，但本设计给出规则的形式化契约和执行接口的稳定签名。

### 1.3 与校验引擎的关系

| 职责 | 本模块（公理规则） | 校验引擎（后续） |
|------|-------------------|-----------------|
| 规则定义 | ✅ CRUD、分类、目标引用 | 只读引用 |
| 形式化文本 | ✅ 生成/存储 OWL+SHACL 文本 | 加载文本执行 |
| 启用/停用 | ✅ 管理开关 | 读取开关决定是否执行 |
| 校验执行 | ❌ 提供接口签名但不执行 | ✅ Jena Reasoner + SHACL API |
| 校验报告 | ❌ 不生成 | ✅ ValidationReport 结构 |
| 不相交/等价写入口 | ✅ 增删改 | 只读引用 |

> 设计决策：校验执行涉及将关系库 Schema 转换为内存 OWL Model、加载 SHACL Shapes、调用 Jena Reasoner，技术复杂度高且依赖实例数据（当前实例模块未实现）。本期将规则注册和形式化文本做扎实，校验引擎以独立模块在实例模块就绪后交付。PRD §4.7 的 `validate` 接口在本模块预签名为"返回校验引擎未就绪"占位。

## 2. 领域模型与本体语义

### 2.1 国标第8.2条三大类规则

| 规则类别 | 国标依据 | 平台 `category` | 规则项 |
|----------|----------|-----------------|--------|
| 实体类型规则 | 第8.2条①② | `ENTITY_TYPE` | 不相交约束、全局唯一标识 |
| 属性规则 | 第8.2条③④⑤⑥⑦ | `PROPERTY` | 唯一性、日期有效、枚举值、取值约束、单位一致性 |
| 关系规则 | 第8.2条⑧⑨⑩⑪ | `RELATION` | 功能性、版本替代、层次包含、结构限制、引用区分 |

### 2.2 OWL公理与SHACL约束的双重形式化

国标第5.3条要求采用 W3C 本体语言（OWL）和支持 SHACL 约束验证。平台对每条规则同时维护两种形式化表达：

**OWL公理（`owl_axiom`）**：描述类级、属性级的逻辑声明，由 OWL Reasoner 推理验证。

```turtle
# 示例：功能性属性约束
std:issuedBy a owl:FunctionalProperty .

# 示例：实体类型不相交
std:NormativeElement owl:disjointWith std:InformativeElement .
```

**SHACL约束（`shacl_shape`）**：描述数据级约束，由 SHACL 引擎验证实例值。

```turtle
# 示例：标准编号唯一性
std:StandardShape a sh:NodeShape ;
    sh:targetClass std:Standard ;
    sh:property [
        sh:path std:standardNumber ;
        sh:minCount 1 ;
        sh:maxCount 1 ;
        sh:severity sh:Violation ;
        sh:message "标准编号必须唯一且必填"
    ] .
```

**文本存储策略**：本期以 Turtle 文本形式存储 `owl_axiom` 和 `shacl_shape`，不解析执行。校验引擎模块上线时加载这些文本构建内存模型。内置规则的形式化文本由 Flyway 种子精确预置。

### 2.3 规则子类型（`sub_type`）

| category | sub_type | 说明 |
|----------|----------|------|
| `ENTITY_TYPE` | `DISJOINT` | 实体类型不相交（owl:disjointWith） |
| `ENTITY_TYPE` | `UNIQUE_IDENTIFIER` | 全局唯一标识（信息单元唯一标识符） |
| `PROPERTY` | `UNIQUENESS` | 属性唯一性（如标准编号唯一） |
| `PROPERTY` | `DATE_VALIDITY` | 日期有效性（实施≥发布、开始≤结束） |
| `PROPERTY` | `ENUM_VALUE` | 枚举值约束（已在数据属性值域定义，此为公理登记） |
| `PROPERTY` | `VALUE_CONSTRAINT` | 取值约束（如约束类型限定） |
| `PROPERTY` | `UNIT_CONSISTENCY` | 单位一致性（maxValue/minValue与measurementUnit量纲一致） |
| `RELATION` | `FUNCTIONAL` | 功能性属性约束（已由对象属性标记声明，此为公理登记） |
| `RELATION` | `VERSION_REPLACEMENT` | 版本替代（废止标准指向替代标准） |
| `RELATION` | `HIERARCHY_CONTAINMENT` | 层次包含（章包含零或多个条） |
| `RELATION` | `STRUCTURAL_LIMIT` | 结构限制（无标题条不可含子条） |
| `RELATION` | `REFERENCE_DISTINCTION` | 引用区分（标准间引用≠条款引用） |

### 2.4 不相交/等价关系的语义

**不相交（`owl:disjointWith`）**：声明两个实体类型的实例集合无交集。如果某实例同时被断言为两个不相交类的实例，OWL 推理机将报告不一致。

**等价（`owl:equivalentClass`）**：声明两个实体类型具有完全相同的实例集合。**不得用于表达"同时属于两个父类"的意图**——后者应使用多继承（subClassOf）。V6 已预置 Clause 多继承（同时继承 StructuralElement 和 InformationUnit），不使用等价类。

## 3. 数据模型

> 对齐现有实现：PostgreSQL、`ont_` 前缀、MyBatis-Plus `ASSIGN_ID`、`char(1)`布尔、审计字段、逻辑删除、Flyway增量迁移。

### 3.1 主表 `ont_axiom_rule`

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `id` | bigint | 是 | MyBatis-Plus `ASSIGN_ID`；核心种子使用固定ID |
| `name` | varchar(128) | 是 | 规则名称（中英文均可） |
| `category` | varchar(32) | 是 | `ENTITY_TYPE/PROPERTY/RELATION` |
| `sub_type` | varchar(64) | 否 | §2.3定义的规则子类型 |
| `description` | varchar(512) | 否 | 规则描述（国标依据说明） |
| `owl_axiom` | text | 否 | OWL形式化表达（Turtle片段） |
| `shacl_shape` | text | 否 | SHACL约束表达（Turtle片段） |
| `is_enabled` | char(1) | 是 | 是否启用，`1`启用`0`停用 |
| `severity` | varchar(32) | 是 | `VIOLATION/WARNING/INFO`，违规严重级别 |
| `source_type` | varchar(32) | 是 | `GB_CLAUSE_8/EXTENSION` |
| `source_reference` | varchar(64) | 否 | 如 `第8.2条①`、`第8.2条⑧` |
| `is_builtin` | char(1) | 是 | 国标规则固定为1，用户扩展为0 |
| `ontology_id` | bigint | 是 | 引用 `ont_ontology_project.id`，首期默认935001 |
| `namespace_id` | bigint | 否 | 扩展规则的命名空间；核心规则使用核心命名空间930001 |
| `sort_order` | integer | 是 | 排序，默认0 |
| `remarks` | varchar(255) | 否 | 平台治理备注 |
| 审计/逻辑删除字段 | — | — | `create_by/create_time/update_by/update_time/del_flag` |

核心约束：

1. `name` 在同一本体工程有效数据中唯一。
2. `category` 取值 `ENTITY_TYPE/PROPERTY/RELATION`。
3. `severity` 取值 `VIOLATION/WARNING/INFO`。
4. `source_type=EXTENSION` 必须 `is_builtin='0'`；`GB_CLAUSE_8` 必须 `is_builtin='1'`。
5. `is_builtin='1'`（核心规则）不可删除；仅允许修改 `is_enabled`（允许停用以支持扩展进一步限定）、`sort_order`、`remarks`。
6. `ontology_id` 使用 `ON DELETE RESTRICT`；`namespace_id` 使用 `ON DELETE RESTRICT`。

### 3.2 规则目标关联表 `ont_axiom_rule_target`

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `axiom_rule_id` | bigint | 是 | 引用主表，`ON DELETE CASCADE` |
| `target_type` | varchar(32) | 是 | `ENTITY_TYPE/DATA_PROPERTY/OBJECT_PROPERTY/UNIT_CATEGORY` |
| `target_id` | bigint | 是 | 目标元素ID（实体类型ID/数据属性ID/对象属性ID/单位分类ID） |
| `target_iri` | varchar(512) | 否 | 目标元素IRI（冗余存储，供序列化直接引用，避免联表） |

主键：`(axiom_rule_id, target_type, target_id)`。

> 设计说明：PRD §7.1 原型使用 `target_type` + `target_iri`（文本IRI）。落地为 `target_id`（bigint外键引用）+ `target_iri`（冗余文本），既保留Schema层强引用完整性，又方便序列化模块直接使用IRI文本。`target_iri` 在主表/目标变更时由Service同步更新。

### 3.3 复用现有表

以下表在V6已创建，本模块不重建，仅提供写管理接口：

- `ont_entity_type_disjoint`：不相交类对 `(type_a, type_b)`，V6已建表，预置1条（NormativeElement ⇄ InformativeElement）。
- `ont_entity_type_equivalent`：等价类对 `(entity_type_id, equivalent_id)`，V6已建表，无预置。

### 3.4 跨表完整性责任

1. 规则目标关联的 `target_id` 必须引用有效且未删除的实体类型/数据属性/对象属性/单位分类。
2. 删除上述元素前检查规则目标引用——有引用时拒绝删除并提示数量（补齐05/06模块遗留的"公理引用检查"扩展点）。
3. 不相交/等价关系的两端实体类型必须存在、有效且属于同一本体工程。

V6已预置1条不相交关系：`(940028 NormativeElement, 940034 InformativeElement)`。本模块的970001规则与此关系对应，规则详情中展示该关系。

### 4.4 形式化文本预置示例

以970003（标准编号唯一性）为例：

**OWL公理文本（`owl_axiom`）**：
```turtle

```

**SHACL约束文本（`shacl_shape`）**：
```turtle
std:StandardShape a sh:NodeShape ;
    sh:targetClass std:Standard ;
    sh:property [
        sh:path std:standardNumber ;
        sh:minCount 1 ;
        sh:maxCount 1 ;
        sh:severity sh:Violation ;
        sh:message "标准编号必须唯一且必填"
    ] .
```

所有12条核心规则的OWL/SHACL文本均由Flyway种子精确预置。

## 5. 服务规则

### 5.1 新增扩展规则

1. `name/label/category/severity/domainEntityTypeIds`必填；`ontologyId`缺省为935001。
2. 普通接口只能创建 `is_builtin='0'` 的扩展规则。
3. `name` 在同本体工程内不得与任何有效规则重名。
4. `category` 取值 `ENTITY_TYPE/PROPERTY/RELATION`；`sub_type` 须与 `category` 对应（§2.3映射）。
5. `severity` 取值 `VIOLATION/WARNING/INFO`。
6. 规则目标（`targetEntityTypeIds`等）引用实体类型/数据属性/对象属性时，目标必须存在、未删除、同本体工程。
7. 新增数据固定 `source_type=EXTENSION/is_builtin='0'/is_enabled='1'`。
8. 主表、规则目标关联在同一事务保存。
9. `owl_axiom` 和 `shacl_shape` 为用户提供的文本，Service不做语法校验（后续校验引擎模块负责解析执行）。

### 5.2 修改

1. 不存在则返回"公理规则不存在"。
2. 内置规则仅允许修改 `isEnabled`（停用/启用）、`sortOrder`、`remarks`、`owl_axiom`、`shacl_shape`（允许修正形式化文本）；`category/subType/severity/name`不可修改。
3. 扩展规则可修改全部语义字段（标签、描述、名称、形式化文本、目标集合、严重级别）。
4. `ontologyId/sourceType/isBuiltin`不可修改。
5. 目标集合更新使用事务整体替换。

### 5.3 启用/停用

1. `PUT /ontology/axiom-rules/{id}/toggle`：切换 `is_enabled`。
2. 内置规则允许停用（支持扩展进一步限定场景）。
3. 扩展规则可自由启停。
4. 停用的规则在校验引擎执行时被跳过。

### 5.4 删除

1. 内置规则禁止删除。
2. 删除扩展规则前检查后续校验报告引用（尚未建表时以扩展点保留）。
3. 无引用时物理删除目标关联子表，再逻辑删除主表。

### 5.5 不相交/等价关系写管理

**新增不相交关系** `POST /ontology/axiom-rules/disjoint`：

1. 请求体：`{ entityTypeAId, entityTypeBId }`。
2. 两端实体类型必须存在、有效、同本体工程。
3. `type_a < type_b` 规范化（Service自动排序），避免重复存储。
4. 禁止自身与自身不相交。
5. 同一对已存在时返回"不相交关系已存在"。
6. 可选：同步创建一条 `DISJOINT` 类型的公理规则（首期不做自动关联，由用户手动创建规则并引用目标）。

**删除不相交关系** `DELETE /ontology/axiom-rules/disjoint/{typeAId}/{typeBId}`：

1. 规范化ID后查询并删除。
2. 检查是否有公理规则引用此不相交关系（规则目标关联）。

**等价关系**接口结构相同，路径为 `/ontology/axiom-rules/equivalent`。

### 5.6 前置模块联动保护

V9实现必须同步修改：

| 服务 | 联动规则 |
|------|----------|
| `OntEntityTypeServiceImpl.removeEntityType` | 若被不相交/等价关系引用，拒绝删除并提示 |
| `OntDataPropertyServiceImpl.removeDataProperty` | 若被公理规则目标引用（target_type=DATA_PROPERTY），拒绝删除 |
| `OntObjectPropertyServiceImpl.removeObjectProperty` | 若被公理规则目标引用（target_type=OBJECT_PROPERTY），拒绝删除 |

> 实体类型删除检查在V6/V8中已有不相交/等价引用检查（04模块§4.3），但数据属性和对象属性删除检查中的"公理引用"此前为扩展点保留。V9补齐这两处。
