# 公理与规则管理模块详细设计

> 对应 PRD：§1.3、§2.7、§3.3、§4.5、§4.7、§5.2、§7.1、§8.2、§11、§14.2
>
> 直接依据：GB/T 48000.3—2026 第5.3条、第8章、第9章；附录A.1；附录C表C.38～C.41；附录D步骤5
>
> 前置模块：01-模块化架构、02-单位字典、03-命名空间与IRI、04-实体类型、05-数据属性、06-对象属性（均已实现）
>
> 评审优化日期：2026-07-11

## 1. 评审结论

原设计的 Flyway V9、三类规则导航、规则目标引用、内置保护和实体类型不相交/等价关系写入口方向可复用，但在 OWL/SHACL 语义、可执行规则结构和数据库引用完整性方面存在阻断问题。本次评审已直接修订，关键结论如下。

| 级别 | 原设计问题 | 优化结论 |
|------|------------|----------|
| P0 | 认为每条规则都应同时维护 OWL 与 SHACL，并把二者都视为“违规校验” | OWL采用开放世界语义，主要表达本体公理和推理；SHACL/应用校验采用闭世界数据质量语义。规则按适用机制选择 OWL、SHACL Core、SHACL-SPARQL、应用校验或组合机制，不强制双份表达 |
| P0 | 用 `owl:hasKey`、`sh:minCount 1 + sh:maxCount 1`表达“标准编号全局唯一” | `owl:hasKey`主要产生个体同一性推断，`sh:maxCount`只限制单个焦点节点的值数量，均不能单独完成跨实例全局唯一校验；全局唯一规则使用 SHACL-SPARQL或应用唯一索引校验，且不擅自增加国标未声明的必填约束 |
| P0 | `ont_axiom_rule_target(target_type,target_id)`声称有强外键，但单一多态ID无法同时外键到四张目标表；目标也没有语义角色，无法区分发布日期与实施日期、父类与子类 | 目标表改为四个可空强外键列并用CHECK保证恰有一个非空；增加 `binding_role/binding_order`，使规则执行器能够确定每个目标的语义角色 |
| P0 | 直接保存用户任意OWL/SHACL文本且完全不做语法校验，未来校验引擎直接加载执行 | 内置及模板规则以结构化目标、执行器代码和配置为权威来源，形式化文本只作为生成快照；自定义文本本期只能保存为不可启用的DRAFT，待校验引擎具备解析、沙箱和超时控制后才能激活 |
| P0 | 内置规则既被描述为不可停用，又在服务规则和前端中允许停用、修改形式化文本，违反PRD核心Schema锁定原则 | ACTIVE内置规则固定启用且语义、目标、形式化快照均只读；内置BLOCKED规则固定停用。普通接口仅允许修改排序和备注 |
| P0 | 把12项全部标记为“国标第8.2条规则” | 国标第8.2条拆分后形成11个规则登记项；单位一致性是PRD结合第6.2.5.6、附录C和附录D增加的平台派生规则，来源改为 `PRD_DERIVED`，不冒充第8.2条原文 |
| P0 | 版本替代规则要求“替代关系或废止日期”，但当前V7没有废止日期属性，仍设计为可启用规则 | 该规则保留在核心目录中，状态设为 `BLOCKED/is_enabled=0`，明确缺失“废止日期”Schema；补齐字段或确认只采用替代关系路径后方可迁移激活 |
| P1 | “章可包含零或多个条”生成 `sh:minCount 0`，该约束恒成立；“引用关系区分”被错误描述为OWL属性不等式 | 层次包含规则复用对象属性定义域/值域校验，不生成无效Shape；引用区分由 `cites/citesStandard` 的定义域和写入选择器治理，不声明未经国标要求的 `owl:propertyDisjointWith` |
| P1 | 规则表复制枚举值、对象属性特性、不相交关系等前序Schema事实，容易与V6～V8源数据漂移 | V6不相交/等价表、V7数据属性约束、V8对象属性特性仍是权威来源；规则目录只登记执行策略和目标绑定，形式化内容由权威Schema生成 |
| P1 | 预留一个永远返回“未就绪”的 `/axiom-rules/validate` 接口 | 删除占位失败接口；校验执行统一由后续 `/ontology/validation/**` 接口提供，当前模块只提供规则定义和可执行契约 |
| P1 | DTO/VO引用未定义的 `OntAxiomRuleLabel`，同时主表又只有 `name`；规则无IRI却配置命名空间 | 首期规则名称直接使用 `name`，不创建标签表；规则是平台执行配置而非命名本体资源，不设置无实际用途的 `namespace_id` |

### 1.1 权威语义口径

1. **OWL公理不是一般意义上的表单校验规则。** 例如功能性对象属性出现两个客体时，OWL推理可能推导两个客体是同一个体；只有附加不同个体声明或其他冲突时才必然不一致。业务上的“最多一个值”仍需SHACL `sh:maxCount 1`或应用校验。
2. **`owl:hasKey`不是数据库唯一索引。** 相同键值可用于推导命名个体相同，不能替代跨实例重复值报告。
3. **SHACL Core的 `sh:maxCount`是单个焦点节点路径值数量约束。** 跨不同实例的属性值唯一性必须使用SHACL-SPARQL或应用侧全局索引。
4. **开放世界与闭世界并行而不混用：** OWL负责声明与推理，SHACL/应用执行器负责可操作的数据质量报告。
5. V6的 `ont_entity_type_disjoint/equivalent`、V7的数据属性元数据与枚举、V8的对象属性定义域/值域和语义特性是Schema事实源；本模块不得维护第二套可编辑副本。

### 1.2 本期边界

本期包含：

1. 公理规则目录 CRUD、分页/列表/详情、来源、状态和内置保护；
2. 国标第8.2条11项规则登记和1项PRD派生单位一致性规则，共12项受保护预置；
3. 规则模板、执行器代码、结构化配置和带角色的目标绑定；
4. 由Schema/模板生成的OWL、SHACL形式化快照及只读预览；
5. 扩展模板规则启停；自定义形式化文本以DRAFT方式保存；
6. V6不相交/等价关系的受控写入口；
7. 前序Schema删除、IRI修改的规则引用保护；
8. 为后续校验引擎、实例建模和序列化提供稳定契约。

本期不包含：

- SHACL运行、OWL一致性推理、校验报告生成；
- 实例数据读取与实时校验；
- 自定义SHACL-SPARQL的启用执行；
- 远程Reasoner、规则链和大规模推理；
- 永远失败的占位校验接口。

### 1.3 与校验引擎的边界

| 职责 | 本模块 | 后续校验引擎 |
|------|--------|--------------|
| 规则目录、分类、状态 | 负责 | 只读 |
| 目标绑定和配置 | 负责结构校验 | 解释执行 |
| Schema派生 | 记录执行器并生成预览 | 运行时从V6～V8权威表重新构建 |
| 自定义文本 | 仅DRAFT存储 | 解析、白名单、安全审查通过后激活 |
| SHACL/OWL执行 | 不执行 | 负责 |
| 校验报告 | 不生成 | 负责 |
| 不相交/等价Schema写入 | 负责受控接口 | 读取并推理 |

> 当前模块不引入Jena运行时，不对外暴露“看似存在但恒失败”的校验接口。校验引擎上线后使用独立Controller和权限，不修改本模块CRUD语义。

## 2. 领域模型与执行语义

### 2.1 国标规则拆分与来源

| 类别 | 国标第8.2条 | 平台分类 | 登记项数量 |
|------|-------------|----------|------------|
| 实体类型规则 | a)1～a)2 | `ENTITY_TYPE` | 2 |
| 属性规则 | b)1～b)4 | `PROPERTY` | 4 |
| 关系规则 | c)1～c)4，其中c)3拆为层级包含、结构限制 | `RELATION` | 5 |
| 单位一致性增强 | PRD §4.5、§4.11；第6.2.5.6、C.38～C.41、附录D | `PROPERTY` | 1 |

因此预置总数为12，但来源统计为 **11项 `GB_CLAUSE_8` + 1项 `PRD_DERIVED`**。

### 2.2 形式化与校验机制

| `formalization_mode` | 含义 |
|----------------------|------|
| `SCHEMA_DERIVED` | 从V6～V8权威Schema生成OWL/SHACL预览，不以规则表文本为源 |
| `GENERATED` | 根据模板、目标绑定和配置确定性生成形式化文本 |
| `CUSTOM_DRAFT` | 用户自定义文本，仅可保存为DRAFT，不可执行 |

| `validation_mode` | 含义 |
|-------------------|------|
| `NONE` | 目录/序列化登记，不单独执行验证 |
| `OWL_CONSISTENCY` | 由Reasoner执行一致性检查 |
| `SHACL_CORE` | 使用SHACL Core约束组件 |
| `SHACL_SPARQL` | 使用受控SHACL-SPARQL约束 |
| `APPLICATION` | 由平台Java执行器或存储层索引校验 |
| `COMPOSITE` | 组合OWL声明与SHACL/应用校验 |

`executor_code` 是校验引擎的稳定分派键，例如：

- `ENTITY_DISJOINT`
- `GLOBAL_UNIQUE_VALUE`
- `DATE_ORDER`
- `ENUM_MEMBERSHIP`
- `UNIT_DIMENSION_CONSISTENCY`
- `FUNCTIONAL_OBJECT_PROPERTY`
- `OBJECT_RELATION_RANGE`
- `MAX_RELATION_COUNT`

校验引擎不得根据中文名称或 `sub_type` 文本猜测执行逻辑。

### 2.3 典型规则的正确表达

#### 2.3.1 全局唯一属性

`sh:maxCount 1`只能保证一个实例至多有一个值，不能发现两个不同实例使用相同值。标准编号唯一性应使用受控SHACL-SPARQL或应用唯一索引，例如概念性Shape：

```turtle
[] a sh:NodeShape ;
   sh:targetClass <http://example.org/standard-ontology#Standard> ;
   sh:sparql [
     sh:message "标准编号在本体工程内重复" ;
     sh:select """
       SELECT $this ?value
       WHERE {
         $this <http://example.org/standard-ontology#standardNumber> ?value .
         ?other a <http://example.org/standard-ontology#Standard> ;
                <http://example.org/standard-ontology#standardNumber> ?value .
         FILTER (?other != $this)
       }
     """
   ] .
```

是否必填由独立基数规则或Schema字段决定，不能把“唯一”自动扩展成 `sh:minCount 1`。

#### 2.3.2 功能性对象属性

`issuedBy` 的Schema声明来自V8：

```turtle
<http://example.org/standard-ontology#issuedBy> a owl:FunctionalProperty .
```

操作性校验还需生成目标为 `Standard`、路径为 `issuedBy` 的 `sh:maxCount 1` Shape。前者表达OWL语义，后者产生稳定、可定位的违规报告，因此该规则使用 `validation_mode=COMPOSITE`。

#### 2.3.3 层级包含

“章可包含零个或多个条”不生成 `sh:minCount 0`。平台通过：

1. `Section`继承自`StructuralElement`；
2. `hasClause`定义域包含`StructuralElement`，值域为`Clause`；
3. 实例关系写入时执行定义域/值域校验；

来表达该规则。规则目录只登记 `OBJECT_RELATION_RANGE` 执行器。

### 2.4 规则子类型

| category | sub_type | 权威来源/执行方式 |
|----------|----------|-------------------|
| `ENTITY_TYPE` | `DISJOINT` | V6不相交表；OWL一致性 |
| `ENTITY_TYPE` | `UNIQUE_IDENTIFIER` | V7 `uniqueIdentifier.is_unique`；全局唯一执行器 |
| `PROPERTY` | `UNIQUENESS` | V7 `is_unique`；SHACL-SPARQL/应用索引 |
| `PROPERTY` | `DATE_VALIDITY` | 模板化日期顺序比较 |
| `PROPERTY` | `ENUM_VALUE` | V7 `value_mode`和枚举表派生 |
| `PROPERTY` | `VALUE_CONSTRAINT` | V7值域/枚举派生 |
| `PROPERTY` | `UNIT_CONSISTENCY` | 单位字典+实例单位引用；应用执行器 |
| `RELATION` | `FUNCTIONAL` | V8对象属性标记；OWL+SHACL组合 |
| `RELATION` | `VERSION_REPLACEMENT` | 状态、替代关系、废止日期条件；当前BLOCKED |
| `RELATION` | `HIERARCHY_CONTAINMENT` | V6继承+V8定义域/值域派生 |
| `RELATION` | `STRUCTURAL_LIMIT` | SHACL `maxCount 0` |
| `RELATION` | `REFERENCE_DISTINCTION` | V8两个引用属性的定义域治理 |
| 任一类别 | `CUSTOM` | 自定义草稿，本期不可激活 |

### 2.5 规则状态

| `status` | 含义 | 可启用 |
|----------|------|--------|
| `ACTIVE` | 结构、目标和执行器契约完整 | 是 |
| `DRAFT` | 自定义或未完成扩展规则 | 否 |
| `BLOCKED` | 已登记但受前置Schema缺口阻塞 | 否 |

约束：`status <> 'ACTIVE'` 时 `is_enabled` 必须为0。ACTIVE内置规则固定启用；ACTIVE扩展模板规则可启停。

### 2.6 不相交与等价关系

- `owl:disjointWith`：两个类的实例集合无交集；同一实例同时属于两类会导致OWL不一致。
- `owl:equivalentClass`：两个类具有相同扩展；不能用于表达多继承。
- Clause 同时继承 StructuralElement 和 InformationUnit 是多继承，不是等价类。
- 普通管理接口不得给两个内置核心类型新增等价/不相交关系；核心Schema只能由Flyway演进。
- 新增关系至少一端必须为扩展实体类型，并且不能与现有继承、等价或不相交关系形成明显矛盾。

## 3. 数据模型

> 对齐现有实现：PostgreSQL、`ont_`前缀、MyBatis-Plus `ASSIGN_ID`、`char(1)`布尔、审计字段、逻辑删除、Flyway增量迁移。

### 3.1 主表 `ont_axiom_rule`

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `id` | bigint | 是 | ASSIGN_ID；核心固定ID |
| `rule_code` | varchar(64) | 是 | 稳定机器代码，如 `GB8_STANDARD_NUMBER_UNIQUE` |
| `name` | varchar(128) | 是 | 页面显示名称，首期直接保存中文名称 |
| `category` | varchar(32) | 是 | `ENTITY_TYPE/PROPERTY/RELATION` |
| `sub_type` | varchar(64) | 是 | §2.4枚举 |
| `description` | varchar(512) | 否 | 规则说明及边界 |
| `template_code` | varchar(64) | 是 | 形式化/表单模板代码；自定义草稿使用 `CUSTOM` |
| `template_version` | integer | 是 | 模板版本，默认1 |
| `formalization_mode` | varchar(32) | 是 | `SCHEMA_DERIVED/GENERATED/CUSTOM_DRAFT` |
| `validation_mode` | varchar(32) | 是 | §2.2定义的验证机制 |
| `executor_code` | varchar(64) | 否 | ACTIVE规则必填的稳定执行器代码 |
| `config_json` | jsonb | 是 | 结构化参数，默认 `{}`；不得保存任意可执行Java类名 |
| `owl_axiom` | text | 否 | 生成的OWL预览快照；非权威源 |
| `shacl_shape` | text | 否 | 生成的SHACL预览快照；非权威源 |
| `status` | varchar(16) | 是 | `ACTIVE/DRAFT/BLOCKED` |
| `is_enabled` | char(1) | 是 | 是否参与后续执行 |
| `severity` | varchar(16) | 是 | `VIOLATION/WARNING/INFO` |
| `source_type` | varchar(32) | 是 | `GB_CLAUSE_8/PRD_DERIVED/EXTENSION` |
| `source_reference` | varchar(128) | 否 | 如 `8.2 b)2)`、`PRD §4.5单位一致性` |
| `blocked_reason` | varchar(255) | 否 | BLOCKED时必填 |
| `is_builtin` | char(1) | 是 | 受保护预置为1，扩展为0 |
| `ontology_id` | bigint | 是 | 引用 `ont_ontology_project.id` |
| `sort_order` | integer | 是 | 默认0 |
| `remarks` | varchar(255) | 否 | 治理备注 |
| 审计/逻辑删除字段 | — | — | 与现有模块一致 |

主表约束：

1. `(ontology_id, rule_code)`、`(ontology_id, name)`在有效数据中唯一。
2. `category/sub_type`组合由Service模板注册表校验；数据库校验一级枚举。
3. `template_version >= 1`；ACTIVE规则的模板代码必须存在于注册表。
4. `status <> ACTIVE`时 `is_enabled='0'`。
5. ACTIVE规则 `executor_code` 非空；BLOCKED规则 `blocked_reason` 非空。
6. `GB_CLAUSE_8/PRD_DERIVED`必须 `is_builtin='1'`；`EXTENSION`必须 `is_builtin='0'`。
7. ACTIVE内置规则固定 `is_enabled='1'`；BLOCKED内置规则固定0。
8. 规则没有本体IRI，不配置 `namespace_id`，也不纳入03全局IRI唯一性检查。
9. 内置规则普通接口仅允许修改 `sort_order/remarks`。

### 3.2 目标绑定表 `ont_axiom_rule_target`

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `id` | bigint | 是 | ASSIGN_ID主键 |
| `axiom_rule_id` | bigint | 是 | 引用规则主表，`ON DELETE CASCADE` |
| `binding_role` | varchar(64) | 是 | 如 `TARGET_CLASS/EARLIER_PROPERTY/LATER_PROPERTY` |
| `binding_order` | integer | 是 | 同角色多值顺序，默认0 |
| `target_type` | varchar(32) | 是 | `ENTITY_TYPE/DATA_PROPERTY/OBJECT_PROPERTY/UNIT_CATEGORY` |
| `entity_type_id` | bigint | 否 | 引用 `ont_entity_type.id`，`ON DELETE RESTRICT` |
| `data_property_id` | bigint | 否 | 引用 `ont_data_property.id`，`ON DELETE RESTRICT` |
| `object_property_id` | bigint | 否 | 引用 `ont_object_property.id`，`ON DELETE RESTRICT` |
| `unit_category_id` | bigint | 否 | 引用 `ont_unit_category.id`，`ON DELETE RESTRICT` |

约束：

1. 四个目标ID列必须恰有一个非空；`target_type`必须与非空列一致。
2. 唯一键 `(axiom_rule_id, binding_role, binding_order)`。
3. `binding_order >= 0`。
4. 不冗余保存 `target_iri`；查询和形式化生成时读取目标当前IRI，避免命名空间迁移后快照漂移。
5. Service按模板校验角色、目标类型和基数；实体类型、数据属性、对象属性必须与规则同本体工程，单位分类是平台全局字典，只校验有效性。

### 3.3 权威Schema表

本模块复用而不复制：

- `ont_entity_type_disjoint`、`ont_entity_type_equivalent`；
- `ont_data_property`、`ont_data_property_enum`；
- `ont_object_property`、定义域/值域表；
- `ont_unit_category`、`ont_unit`。

规则预览或执行配置应从这些表生成。修改扩展Schema后，相关规则预览按需重新生成；不得允许用户手工修改生成快照掩盖源数据。

### 3.4 跨表完整性

1. 目标绑定由真实外键保证物理存在，Service补充逻辑删除和同工程检查。
2. 被规则绑定的实体类型、数据属性、对象属性、单位分类不得删除。
3. 被ACTIVE或DRAFT规则绑定的Schema元素修改IRI前必须先解除绑定或删除规则；避免形式化快照和后续实例引用失配。
4. 删除规则时先物理删除目标绑定，再逻辑删除主表。

### 4.3 特殊规则说明

#### 4.3.1 970007单位一致性

目标必须包含 `thresholdRange(950040)`，不能只绑定maxValue、minValue和unit。执行器在实例模块上线后校验：同一Constraint实例的数值/范围解释与 `unit(950041)` 引用单位所属分类一致；属性层 `unit_category_id=NULL` 表示不限分类，不能误判为无量纲。

#### 4.3.2 970009版本替代

国标规则允许“指向替代标准”或“标明废止日期”。当前Schema只有 `status`、`replaces/isReplacedBy`，没有废止日期属性，因此：

- 规则保留为受保护目录项；
- `status=BLOCKED/is_enabled=0`；
- `blocked_reason`明确记录缺失废止日期Schema；
- 不生成会把“无替代标准的正常废止”误报为违规的可执行Shape。

### 4.4 形式化快照要求

1. SCHEMA_DERIVED规则的预览由V6～V8源数据生成；源数据是权威。
2. 模板代码和版本随规则保存；模板升级不得静默改变既有规则，须通过显式迁移或重新生成操作。
3. GENERATED规则由 `template_code + template_version + executor_code + config_json + binding`确定性生成。
4. 快照使用完整IRI或完整前缀声明，不能依赖未保存的外部前缀上下文。
5. 迁移种子可以保存预览快照，但后续序列化和校验引擎不得盲目拼接数据库文本。
6. CUSTOM_DRAFT时 `owl_axiom/shacl_shape`保存用户草稿；该模式必须与生成快照明确区分，文本不进入发布、导出或校验。

## 5. 服务规则

### 5.1 模板注册表

后端维护集中式 `OntAxiomRuleTemplateRegistry`，每个模板定义：

- templateCode/templateVersion；
- category/subType；
- formalizationMode/validationMode/executorCode；
- 允许的 `binding_role → target_type → 基数`；
- 配置JSON Schema或等价Java校验；
- 形式化快照生成器。

Controller、Service和前端不得分别硬编码不一致的角色矩阵；前端通过模板接口获取表单元数据。

### 5.2 新增扩展规则

1. `ruleCode/name/category/subType/severity/targets`必填；`ontologyId`缺省935001。
2. `ruleCode`使用 `^[A-Z][A-Z0-9_]*$`，同工程代码和名称唯一。
3. 目标存在且有效，角色和基数符合模板；实体类型、数据属性、对象属性须同工程，单位分类按全局字典引用。
4. 选择受支持模板时，Service生成执行模式、执行器、配置和形式化快照，状态为ACTIVE、默认启用。
5. 选择CUSTOM时，状态固定DRAFT、`formalization_mode=CUSTOM_DRAFT`、`validation_mode=NONE`、`is_enabled=0`；至少提供OWL或SHACL文本之一。
6. 普通请求不能提交 `sourceType/isBuiltin/status/executorCode`覆盖后端决策。
7. 主表和目标绑定在同一事务保存。

### 5.3 修改

1. 内置规则仅允许修改 `sortOrder/remarks`；任何其他变化明确失败。
2. ACTIVE扩展模板规则可修改名称、描述、严重级别、配置和目标；Service重新生成快照。
3. DRAFT自定义规则可修改文本和目标，但本期仍不可激活。
4. `ontologyId/sourceType/isBuiltin/ruleCode`创建后不可修改。
5. 目标更新采用“完整校验后事务整体替换”。

### 5.4 启用状态

使用幂等接口设置目标状态，不使用非幂等toggle：

1. 仅 `status=ACTIVE/is_builtin='0'` 的扩展模板规则可启停。
2. ACTIVE内置规则固定启用；BLOCKED内置规则固定停用。
3. DRAFT/BLOCKED规则请求启用时返回明确原因。
4. 请求体显式传入 `{ "enabled": "0|1" }`。

### 5.5 删除

1. 内置规则禁止删除。
2. 扩展规则如已被后续校验报告引用，报告应保留规则代码和快照，不通过外键阻止规则逻辑删除；是否允许删除由影响分析提示决定。
3. 删除时物理删除目标绑定，再逻辑删除规则主表。

### 5.6 不相交/等价关系写管理

共同规则：

1. 两端存在、有效、同工程，Service按ID升序规范化。
2. 禁止自身关系和重复关系。
3. 两个内置实体类型之间不得通过普通接口新增关系。
4. 不相交与等价不能同时存在于同一对。
5. 若两类存在祖先/后代可达关系，禁止声明不相交或等价：前者会使子类不可满足，后者会意外折叠层次。
6. 新增关系至少一端是扩展实体类型。
7. 核心不相交对 `(940028,940034)` 不可删除。
8. 等价关系仅表示实例集合相同，页面提交前显示高风险确认提示。

扩展关系直接写入V6关系表，序列化和Reasoner从关系表读取；不要求用户再创建重复的规则记录。

### 5.7 前置模块联动保护

V9实现必须同步修改：

| 服务 | 联动规则 |
|------|----------|
| `OntEntityTypeServiceImpl` | 删除或修改IRI前检查目标绑定；保留现有继承/不相交/等价保护 |
| `OntDataPropertyServiceImpl` | 删除或修改IRI前检查数据属性目标绑定 |
| `OntObjectPropertyServiceImpl` | 删除或修改IRI前检查对象属性目标绑定 |
| `OntUnitCategoryServiceImpl` | 删除或修改分类语义前检查单位分类目标绑定 |

目标表具有 `ON DELETE RESTRICT` 作为数据库最后防线；Service必须先返回可理解的规则名称和数量，不能把外键异常直接暴露给前端。

## 11. 与后续模块的稳定契约

| 后续模块 | 契约 |
|----------|------|
| 校验引擎 | 只加载 `status=ACTIVE/is_enabled=1`；按 `executor_code`分派；运行时从权威Schema和目标绑定构建模型，不盲目执行快照文本 |
| 实例建模 | 使用规则严重级别和执行器结果；只有VIOLATION阻断提交，WARNING/INFO展示但不阻断 |
| 序列化 | 不相交、等价、功能性、定义域/值域等从V6～V8权威Schema导出；规则快照仅用于预览，避免重复公理 |
| 校验报告 | 保存ruleId、ruleCode、ruleName、执行器版本和规则快照，使规则后续修改不改变历史报告解释 |
| 扩展管理 | 模板扩展可启用；CUSTOM文本必须经过未来解析、安全审查和资源限制后才能从DRAFT迁移ACTIVE |
| 影响分析 | Schema删除和IRI修改前统计目标绑定；规则变更展示受影响实例、报告和导出任务 |

## 12. 验收标准

1. V9创建规则主表和带真实外键、语义角色的目标绑定表，V1～V8校验和不变。
2. 预置12项受保护目录，其中11项来源于第8.2条、1项为PRD单位一致性派生，来源口径准确。
3. OWL、SHACL和应用校验职责明确；不再把 `owl:hasKey`或单节点 `sh:maxCount`误当跨实例唯一校验。
4. 权威Schema与规则目录不重复维护：枚举、功能性、不相交、定义域/值域均从V6～V8读取。
5. 970009因废止日期Schema缺口处于BLOCKED且不可启用；不会产生已知误报Shape。
6. 970007完整绑定maxValue、minValue、thresholdRange和unit。
7. ACTIVE内置规则固定启用且只读；BLOCKED内置规则固定停用；扩展模板规则可幂等启停；CUSTOM仅DRAFT。
8. 目标角色、目标类型、基数、同工程和逻辑有效性校验生效，数据库不存在伪多态外键。

10. 不提供恒失败的校验占位接口，后续校验引擎使用独立 `/ontology/validation/**` 契约。
11. 前序Schema引用保护覆盖实体类型、数据属性、对象属性的删除/IRI修改，以及单位分类的删除/分类语义修改。
12. 前端完整展示执行机制和状态，内置保护、模板表单、自定义草稿和关系高风险提示正确。
13. 后端测试、ontology前端类型检查和测试通过；完整前端构建无本模块新增错误。
