# 映射工程与版本管理功能详细设计

> 模块：18 数据源映射  
> 功能编号：18-03  
> 前置：14 本体版本演化、18-02 数据源注册  
> 设计日期：2026-07-14

## 1. 目标

管理映射配置的生命周期，使编辑态配置、校验结果、生产执行版本和历史作业可被准确追溯。生产作业只能执行不可变的PUBLISHED映射版本。

## 2. 领域边界

- 映射工程属于一个Ontology工程；
- 一个映射工程可以引用多个数据源，但V1组织账号场景只引用同一PostgreSQL源；
- 一个映射工程包含多个版本；
- 每个版本包含实体映射、字段映射和关系映射；
- 版本发布时生成规范化快照和SHA-256哈希；
- 发布版本不可修改，编辑必须复制为新DRAFT版本；
- 映射版本不是Ontology版本，两者通过兼容约束关联。

## 3. 映射工程表

```sql
CREATE TABLE ont_mapping_project (
  id bigint NOT NULL,
  mapping_code varchar(64) NOT NULL,
  mapping_name varchar(128) NOT NULL,
  ontology_id bigint NOT NULL,
  default_namespace_id bigint NOT NULL,
  active_version_id bigint DEFAULT NULL,
  project_status varchar(16) NOT NULL DEFAULT 'DRAFT',
  description text DEFAULT NULL,
  schedule_enabled char(1) NOT NULL DEFAULT '0',
  schedule_cron varchar(128) DEFAULT NULL,
  schedule_run_type varchar(16) DEFAULT NULL,
  execution_subject_type varchar(16) DEFAULT NULL,
  execution_subject_id bigint DEFAULT NULL,
  security_level_code varchar(32) NOT NULL DEFAULT 'INTERNAL',
  revision bigint NOT NULL DEFAULT 0,
  last_job_id bigint DEFAULT NULL,
  remarks varchar(255) DEFAULT NULL,
  create_by varchar(64) DEFAULT ' ',
  create_time timestamp NOT NULL DEFAULT now(),
  update_by varchar(64) DEFAULT ' ',
  update_time timestamp DEFAULT NULL,
  del_flag char(1) NOT NULL DEFAULT '0',
  PRIMARY KEY (id),
  CONSTRAINT fk_ont_map_project_ontology FOREIGN KEY (ontology_id)
    REFERENCES ont_ontology_project(id) ON DELETE RESTRICT,
  CONSTRAINT fk_ont_map_project_namespace FOREIGN KEY (default_namespace_id)
    REFERENCES ont_namespace(id) ON DELETE RESTRICT,
  CONSTRAINT fk_ont_map_project_security_level FOREIGN KEY (security_level_code)
    REFERENCES ont_security_level(level_code) ON DELETE RESTRICT,
  CONSTRAINT ck_ont_map_project_status
    CHECK (project_status IN ('DRAFT','ACTIVE','DISABLED','ARCHIVED')),
  CONSTRAINT ck_ont_map_project_schedule
    CHECK (schedule_enabled IN ('0','1')),
  CONSTRAINT ck_ont_map_project_run_type
    CHECK (schedule_run_type IS NULL OR schedule_run_type IN ('FULL','INCREMENTAL')),
  CONSTRAINT ck_ont_map_project_subject_type
    CHECK (execution_subject_type IS NULL OR execution_subject_type IN ('USER','ROLE')),
  CONSTRAINT ck_ont_map_project_revision CHECK (revision >= 0),
  CONSTRAINT ck_ont_map_project_del CHECK (del_flag IN ('0','1'))
);

CREATE UNIQUE INDEX uk_ont_map_project_code
  ON ont_mapping_project(mapping_code) WHERE del_flag = '0';
CREATE INDEX idx_ont_map_project_ontology
  ON ont_mapping_project(ontology_id, project_status) WHERE del_flag = '0';
```

`active_version_id`外键在`ont_mapping_version`建表后添加，避免建表循环。

### 3.1 调度字段

- `schedule_enabled=1`必须存在PUBLISHED active version；
- `schedule_run_type=INCREMENTAL`要求所有启用实体映射具备合法增量游标；
- cron由Quartz/Spring调度层校验，最短周期V1限制为1分钟；
- `execution_subject_type/id`用于计划任务授权，不代表SYSTEM超级权限；发布或启用调度时校验主体仍有效且拥有执行权限。

## 4. 映射版本表

```sql
CREATE TABLE ont_mapping_version (
  id bigint NOT NULL,
  mapping_project_id bigint NOT NULL,
  version_number varchar(32) NOT NULL,
  version_status varchar(16) NOT NULL DEFAULT 'DRAFT',
  prior_version_id bigint DEFAULT NULL,
  ontology_version_constraint varchar(128) NOT NULL,
  validated_ontology_version_id bigint DEFAULT NULL,
  validated_workspace_revision bigint DEFAULT NULL,
  config_snapshot jsonb DEFAULT NULL,
  config_hash varchar(64) DEFAULT NULL,
  metadata_dependencies jsonb NOT NULL DEFAULT '[]'::jsonb,
  validation_report_id bigint DEFAULT NULL,
  validation_summary jsonb DEFAULT NULL,
  release_notes text DEFAULT NULL,
  published_by varchar(64) DEFAULT NULL,
  published_at timestamp DEFAULT NULL,
  retired_at timestamp DEFAULT NULL,
  revision bigint NOT NULL DEFAULT 0,
  create_by varchar(64) DEFAULT ' ',
  create_time timestamp NOT NULL DEFAULT now(),
  update_by varchar(64) DEFAULT ' ',
  update_time timestamp DEFAULT NULL,
  del_flag char(1) NOT NULL DEFAULT '0',
  PRIMARY KEY (id),
  CONSTRAINT fk_ont_map_version_project FOREIGN KEY (mapping_project_id)
    REFERENCES ont_mapping_project(id) ON DELETE RESTRICT,
  CONSTRAINT fk_ont_map_version_prior FOREIGN KEY (prior_version_id)
    REFERENCES ont_mapping_version(id) ON DELETE RESTRICT,
  CONSTRAINT fk_ont_map_version_ontology_version FOREIGN KEY (validated_ontology_version_id)
    REFERENCES ont_ontology_version(id) ON DELETE RESTRICT,
  CONSTRAINT ck_ont_map_version_status
    CHECK (version_status IN ('DRAFT','VALIDATING','VALIDATED','PUBLISHED','RETIRED')),
  CONSTRAINT ck_ont_map_version_revision CHECK (revision >= 0),
  CONSTRAINT ck_ont_map_version_del CHECK (del_flag IN ('0','1'))
);

CREATE UNIQUE INDEX uk_ont_map_version_number
  ON ont_mapping_version(mapping_project_id, version_number)
  WHERE del_flag = '0';
CREATE UNIQUE INDEX uk_ont_map_one_draft
  ON ont_mapping_version(mapping_project_id)
  WHERE del_flag = '0' AND version_status IN ('DRAFT','VALIDATING','VALIDATED');
CREATE UNIQUE INDEX uk_ont_map_one_published
  ON ont_mapping_version(mapping_project_id)
  WHERE del_flag = '0' AND version_status = 'PUBLISHED';
CREATE INDEX idx_ont_map_version_project_time
  ON ont_mapping_version(mapping_project_id, create_time DESC)
  WHERE del_flag = '0';

ALTER TABLE ont_mapping_project
  ADD CONSTRAINT fk_ont_map_project_active_version
  FOREIGN KEY (active_version_id) REFERENCES ont_mapping_version(id) ON DELETE RESTRICT;
```

> `uk_ont_map_one_published`表示当前ACTIVE发布版本。旧发布版本在同一事务转为RETIRED后再发布新版本。历史“曾发布”由`published_at`保留。

## 5. 版本号与兼容约束

映射版本使用SemVer：

```text
MAJOR.MINOR.PATCH
```

- PATCH：描述、排序、无语义转换修正；
- MINOR：新增可选字段/关系映射，保持来源身份与IRI稳定；
- MAJOR：来源主键、目标类型、IRI模板、删除策略等可能影响身份或语义。

`ontology_version_constraint`使用受控表达式：

```text
=1.2.0
>=1.2.0 <2.0.0
>=2.0.0 <3.0.0
```

实现只支持比较符`=,>,>=,<,<=`和AND空格组合，不支持OR、通配函数和任意表达式。使用现有`java-semver`解析。

## 6. 配置快照

发布时将以下内容规范化写入`config_snapshot`：

```json
{
  "snapshotFormatVersion": 1,
  "mappingProject": {
    "id": 1,
    "code": "UPMS_ORG",
    "ontologyId": 935001,
    "defaultNamespaceId": 930200
  },
  "ontologyBinding": {
    "constraint": ">=1.0.0 <2.0.0",
    "validatedVersionId": 123,
    "validatedVersionNumber": "1.3.0",
    "workspaceRevision": 7
  },
  "entityMappings": [],
  "fieldMappings": [],
  "relationMappings": [],
  "metadataDependencies": []
}
```

规范化规则：

- 对象键按字典序；
- entityMapping按`mappingCode`；
- fieldMapping按`entityMappingCode + sortOrder + mappingCode`；
- relationMapping按`syncOrder + mappingCode`；
- JSON数字不使用科学计数法；
- null和空数组按Schema固定保留/删除规则；
- 不包含审计字段、凭证、最近作业和UI临时坐标；
- 哈希算法SHA-256，UTF-8。

生产Worker从`config_snapshot`编译执行计划，不从可编辑子表实时拼装，确保历史作业可重放解释。

## 7. 元数据依赖

`metadata_dependencies`示例：

```json
[
  {
    "sourceId": 100,
    "schema":"public",
    "object":"sys_user",
    "metadataHash":"...",
    "requiredColumns":["user_id","username","dept_id","update_time","del_flag"]
  }
]
```

执行前重新读取或验证缓存：

- 依赖列删除/类型不兼容/主键变化：阻断；
- 新增无关列：允许；
- 列长度扩大：允许并警告；
- 视图定义变化导致hash变化：默认阻断并重新校验；
- 元数据无法读取：生产执行失败关闭。

## 8. 状态转换

### 8.1 新建工程

```text
POST project
 → project=DRAFT
 → 创建version 0.1.0 DRAFT
 → 返回编辑器地址
```

### 8.2 创建下一版本

仅ACTIVE/DISABLED工程允许从active version复制：

```text
PUBLISHED snapshot
 → 复制实体/字段/关系子表
 → priorVersionId=activeVersionId
 → versionStatus=DRAFT
 → configSnapshot=NULL
```

若已有DRAFT/VALIDATING/VALIDATED版本，拒绝再次创建。

### 8.3 校验

- DRAFT → VALIDATING使用CAS更新；
- 校验通过 → VALIDATED，记录报告ID、当前本体版本、工作区修订；
- 失败 → DRAFT，报告仍保留；
- 编辑任何子表时仅允许DRAFT，并递增version.revision；
- VALIDATED若要修改，先显式`reopen`为DRAFT并清除发布候选信息。

### 8.4 发布

事务内：

1. 锁映射工程行；
2. 确认版本VALIDATED且配置revision/报告hash未变化；
3. 确认Ontology当前版本和工作区修订仍与校验一致；
4. 确认元数据依赖未漂移；
5. 构建规范快照和hash；
6. 将旧PUBLISHED改RETIRED；
7. 当前版本改PUBLISHED；
8. 更新project.activeVersionId和ACTIVE状态；
9. 写Outbox `MAPPING_VERSION_PUBLISHED`。

任一步失败整体回滚。

### 8.5 停用和归档

- DISABLED：禁止新作业，保留配置和历史；
- ARCHIVED：不可重新启用，不允许新版本；
- 运行中作业存在时不能ARCHIVED；
- 存在ACTIVE来源绑定时可DISABLED，不可物理删除；
- 映射工程只逻辑删除且仅限从未发布、无作业、无绑定的DRAFT工程。

## 9. 与本体版本集成

`MappingOntologyVersionGuard`：

```java
public interface MappingOntologyVersionGuard {
    VersionGuardResult validateForPreview(Long mappingVersionId);
    void assertExecutable(Long mappingVersionId);
}
```

生产执行检查：

- `ontology_project.current_version_id`存在；
- 当前版本为PUBLISHED；
- 当前版本号满足constraint；
- 当前版本ID等于`validated_ontology_version_id`；
- 当前`workspace_revision`等于`validated_workspace_revision`；
- `workspace_status=EDITABLE`。

不能仅因版本号仍满足范围就跳过重新校验，因为Schema可能在同一兼容范围内改变字段定义。

## 10. 乐观锁

工程和版本均使用`revision`：

```sql
UPDATE ont_mapping_version
SET ..., revision = revision + 1
WHERE id = :id AND revision = :expectedRevision AND version_status = 'DRAFT';
```

更新0行返回`ONT-MAP-011 VERSION_CONFLICT`。前端必须带revision，冲突后重新加载，不自动覆盖其他编辑者修改。

## 12. 配置差异分类

| 变化 | 分类 |
|---|---|
| 描述/排序变化 | PATCH |
| 新增非必填字段映射 | MINOR |
| 新增关系且missingTarget=PENDING | MINOR |
| 修改转换器、目标属性 | MAJOR |
| 修改主键、IRI模板、目标类型 | MAJOR_HIGH_RISK |
| 修改删除策略为SOFT_DELETE | MAJOR_HIGH_RISK |
| 修改数据源或源对象 | MAJOR_HIGH_RISK |

高风险变化发布时前端二次确认；可选择接模块36审批，V1至少要求管理员权限和审计。

## 14. 测试与验收

1. 一个工程最多一个可编辑候选版本；
2. 一个工程最多一个当前PUBLISHED版本；
3. 发布后子表和快照不可修改；
4. 配置相同多次构建hash一致；
5. 修改IRI模板被识别为高风险；
6. 当前Ontology版本ID变化即使仍满足SemVer也阻断执行；
7. 工作区revision漂移阻断发布和执行；
8. 元数据主键变化阻断发布；
9. 乐观锁冲突不覆盖其他用户修改；
10. 发布事务失败时旧active version保持不变；
11. 已发布工程不能删除；
12. 快照和diff响应不包含凭证或源样例值。
