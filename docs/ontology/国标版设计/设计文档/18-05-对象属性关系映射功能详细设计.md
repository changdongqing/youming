# 对象属性关系映射功能详细设计

> 模块：18 数据源映射  
> 功能编号：18-05  
> 前置：06 对象属性、08 实例、18-01、18-04  
> 设计日期：2026-07-14

## 1. 目标

将源数据库中的外键、自关联和中间表关系转换为Ontology对象属性断言，并支持目标实例尚未创建时的延迟解析、幂等去重和来源关系删除。

## 2. V1关系模式

| 模式 | 示例 | 说明 |
|---|---|---|
| `FOREIGN_KEY` | `sys_user.dept_id → sys_dept.dept_id` | 主体记录自身包含客体键 |
| `SELF_REFERENCE` | `sys_dept.parent_id → sys_dept.dept_id` | 同一实体映射内层级关系 |
| `JOIN_TABLE` | `sys_user_post(user_id,post_id)` | 独立中间表连接两个实体映射 |

不支持：

- 任意多表SQL Join；
- 基于名称的模糊匹配；
- 空间距离、图算法或推理生成关系；
- 自动保存逆属性三元组；
- 关系客体为ENTITY_TYPE；映射只生成INSTANCE客体。

## 3. 关系映射表

```sql
CREATE TABLE ont_relation_mapping (
  id bigint NOT NULL,
  mapping_version_id bigint NOT NULL,
  mapping_code varchar(64) NOT NULL,
  mapping_name varchar(128) NOT NULL,
  relation_mode varchar(24) NOT NULL,
  object_property_id bigint NOT NULL,
  subject_entity_mapping_id bigint NOT NULL,
  object_entity_mapping_id bigint NOT NULL,
  source_id bigint NOT NULL,
  source_schema varchar(128) NOT NULL,
  source_object varchar(128) NOT NULL,
  subject_key_mapping jsonb NOT NULL,
  object_key_mapping jsonb NOT NULL,
  relation_key_columns jsonb NOT NULL,
  filter_dsl jsonb DEFAULT NULL,
  missing_target_policy varchar(16) NOT NULL DEFAULT 'PENDING',
  delete_strategy varchar(24) NOT NULL DEFAULT 'REMOVE_ASSERTION',
  ownership_policy varchar(24) NOT NULL DEFAULT 'SOURCE_WINS',
  sync_order integer NOT NULL DEFAULT 1000,
  enabled char(1) NOT NULL DEFAULT '1',
  description text DEFAULT NULL,
  revision bigint NOT NULL DEFAULT 0,
  create_by varchar(64) DEFAULT ' ',
  create_time timestamp NOT NULL DEFAULT now(),
  update_by varchar(64) DEFAULT ' ',
  update_time timestamp DEFAULT NULL,
  del_flag char(1) NOT NULL DEFAULT '0',
  PRIMARY KEY (id),
  CONSTRAINT fk_ont_rel_map_version FOREIGN KEY (mapping_version_id)
    REFERENCES ont_mapping_version(id) ON DELETE CASCADE,
  CONSTRAINT fk_ont_rel_map_property FOREIGN KEY (object_property_id)
    REFERENCES ont_object_property(id) ON DELETE RESTRICT,
  CONSTRAINT fk_ont_rel_map_subject FOREIGN KEY (subject_entity_mapping_id)
    REFERENCES ont_entity_mapping(id) ON DELETE CASCADE,
  CONSTRAINT fk_ont_rel_map_object FOREIGN KEY (object_entity_mapping_id)
    REFERENCES ont_entity_mapping(id) ON DELETE CASCADE,
  CONSTRAINT fk_ont_rel_map_source FOREIGN KEY (source_id)
    REFERENCES ont_data_source(id) ON DELETE RESTRICT,
  CONSTRAINT ck_ont_rel_map_mode
    CHECK (relation_mode IN ('FOREIGN_KEY','SELF_REFERENCE','JOIN_TABLE')),
  CONSTRAINT ck_ont_rel_map_missing
    CHECK (missing_target_policy IN ('PENDING','SKIP','FAIL_RECORD')),
  CONSTRAINT ck_ont_rel_map_delete
    CHECK (delete_strategy IN ('REMOVE_ASSERTION','KEEP_ASSERTION','BLOCK_AND_REVIEW')),
  CONSTRAINT ck_ont_rel_map_owner
    CHECK (ownership_policy IN ('SOURCE_WINS','MANUAL_WINS','REJECT_CONFLICT')),
  CONSTRAINT ck_ont_rel_map_enabled CHECK (enabled IN ('0','1')),
  CONSTRAINT ck_ont_rel_map_order CHECK (sync_order >= 0),
  CONSTRAINT ck_ont_rel_map_revision CHECK (revision >= 0),
  CONSTRAINT ck_ont_rel_map_del CHECK (del_flag IN ('0','1'))
);

CREATE UNIQUE INDEX uk_ont_rel_map_code
  ON ont_relation_mapping(mapping_version_id, mapping_code)
  WHERE del_flag = '0';
CREATE INDEX idx_ont_rel_map_order
  ON ont_relation_mapping(mapping_version_id, sync_order)
  WHERE del_flag = '0' AND enabled = '1';
```

## 4. 键映射结构

### 4.1 FOREIGN_KEY

```json
{
  "subject": [
    {"sourceColumn":"user_id","bindingKeyColumn":"user_id"}
  ],
  "object": [
    {"sourceColumn":"dept_id","bindingKeyColumn":"dept_id"}
  ]
}
```

`source_object`为`sys_user`，主体映射为USER_ACCOUNT，客体映射为DEPARTMENT。

### 4.2 SELF_REFERENCE

```json
{
  "subject": [{"sourceColumn":"dept_id","bindingKeyColumn":"dept_id"}],
  "object": [{"sourceColumn":"parent_id","bindingKeyColumn":"dept_id"}]
}
```

根节点`parent_id`为空或等于约定根值时跳过，不创建指向虚拟0实例的关系。

### 4.3 JOIN_TABLE

```json
{
  "subject": [{"sourceColumn":"user_id","bindingKeyColumn":"user_id"}],
  "object": [{"sourceColumn":"post_id","bindingKeyColumn":"post_id"}]
}
```

`relation_key_columns`通常为中间表复合主键：

```json
["user_id","post_id"]
```

用于来源关系幂等和删除检测。

## 5. 语义校验

发布时校验：

1. 主体和客体实体映射属于同一映射版本；
2. 源数据源和源对象存在；
3. 键列存在且类型可规范化；
4. 对象属性属于目标Ontology工程；
5. 主体类型满足对象属性domain，包括继承；
6. 客体类型满足range，包括继承；
7. 功能属性同一主体最多一个客体；
8. 逆功能属性同一客体最多一个主体；
9. 不自动插入inverseOf关系；
10. relationKey在预览样本中唯一；
11. SELF_REFERENCE允许主体=客体与否取决于公理，不能硬编码全局禁止；若当前没有irreflexive公理，仅警告明显自环。

## 6. 待解析关系表

```sql
CREATE TABLE ont_pending_relation (
  id bigint NOT NULL,
  mapping_project_id bigint NOT NULL,
  mapping_version_id bigint NOT NULL,
  relation_mapping_code varchar(64) NOT NULL,
  source_id bigint NOT NULL,
  source_relation_key varchar(1024) NOT NULL,
  source_relation_key_hash varchar(64) NOT NULL,
  subject_entity_mapping_code varchar(64) NOT NULL,
  subject_record_key varchar(1024) NOT NULL,
  subject_record_key_hash varchar(64) NOT NULL,
  object_entity_mapping_code varchar(64) NOT NULL,
  object_record_key varchar(1024) NOT NULL,
  object_record_key_hash varchar(64) NOT NULL,
  pending_reason varchar(32) NOT NULL,
  pending_status varchar(16) NOT NULL DEFAULT 'PENDING',
  retry_count integer NOT NULL DEFAULT 0,
  next_retry_at timestamp DEFAULT NULL,
  last_error_code varchar(64) DEFAULT NULL,
  last_error_message varchar(512) DEFAULT NULL,
  first_job_id bigint NOT NULL,
  last_job_id bigint NOT NULL,
  resolved_relation_id bigint DEFAULT NULL,
  create_by varchar(64) DEFAULT 'system',
  create_time timestamp NOT NULL DEFAULT now(),
  update_by varchar(64) DEFAULT 'system',
  update_time timestamp DEFAULT NULL,
  del_flag char(1) NOT NULL DEFAULT '0',
  PRIMARY KEY (id),
  CONSTRAINT fk_ont_pending_project FOREIGN KEY (mapping_project_id)
    REFERENCES ont_mapping_project(id) ON DELETE RESTRICT,
  CONSTRAINT fk_ont_pending_version FOREIGN KEY (mapping_version_id)
    REFERENCES ont_mapping_version(id) ON DELETE RESTRICT,
  CONSTRAINT fk_ont_pending_source FOREIGN KEY (source_id)
    REFERENCES ont_data_source(id) ON DELETE RESTRICT,
  CONSTRAINT fk_ont_pending_relation FOREIGN KEY (resolved_relation_id)
    REFERENCES ont_instance_object_relation(id) ON DELETE SET NULL,
  CONSTRAINT ck_ont_pending_reason
    CHECK (pending_reason IN ('SUBJECT_MISSING','OBJECT_MISSING','BOTH_MISSING')),
  CONSTRAINT ck_ont_pending_status
    CHECK (pending_status IN ('PENDING','RESOLVED','FAILED','IGNORED')),
  CONSTRAINT ck_ont_pending_del CHECK (del_flag IN ('0','1'))
);

CREATE UNIQUE INDEX uk_ont_pending_relation
  ON ont_pending_relation(mapping_project_id, relation_mapping_code, source_relation_key_hash)
  WHERE del_flag = '0' AND pending_status = 'PENDING';
CREATE INDEX idx_ont_pending_retry
  ON ont_pending_relation(pending_status, next_retry_at, retry_count)
  WHERE del_flag = '0';
```

不保存源整行，只保存规范化关系键和两端记录键。错误消息先脱敏再截断。

## 7. 两阶段执行

```text
阶段A：按syncOrder执行所有实体映射
  → 创建/更新来源绑定

阶段B：按syncOrder执行所有关系映射
  → 由subject/object recordKey查来源绑定
  → 两端存在则upsert关系
  → 缺失按missingTargetPolicy处理

阶段C：重试本作业产生和历史到期的pending relation
```

不要在每条实体记录摄入时即时查询所有关系，否则会造成N+1查询和顺序不确定。

## 8. 关系Upsert

```text
1. 规范化sourceRelationKey并计算hash
2. 查subject binding和object binding
3. 校验实例均ACTIVE且同Ontology
4. 校验domain/range/功能性
5. 根据三元组唯一索引查询现有关系
6. 不存在则插入显式INSTANCE关系
7. upsert relation provenance
8. 已存在且来自人工/其他映射时：
   - 不重复插入
   - 可增加当前来源证明需支持多来源
```

一个显式三元组可以有多条来源证明。18-01以`mapping_project_id + relation_mapping_code + source_relation_key_hash`唯一标识来源关系，并对`relation_id`建立普通索引。只有所有来源都移除且没有人工声明时才允许删除断言。

## 9. 人工断言与来源断言

当前关系主表没有asserted source字段。V1按以下规则识别：

- 存在provenance：至少由映射来源支持；
- 不存在provenance：人工/种子/其他非映射来源；
- 同一三元组既可有人工断言又有来源证明，但主表无法单独表达人工声明标志。

为避免删除误判，V22必须给关系主表增加：

```sql
ALTER TABLE ont_instance_object_relation
  ADD COLUMN IF NOT EXISTS assertion_origin varchar(16) NOT NULL DEFAULT 'MANUAL';

ALTER TABLE ont_instance_object_relation
  ADD CONSTRAINT ck_ont_relation_origin
  CHECK (assertion_origin IN ('MANUAL','SEED','DATA_MAPPING','IMPORT','IOT','RULE'));
```

历史附录D关系应在V22回填`SEED`，普通现有扩展关系保持`MANUAL`。映射新建关系使用`DATA_MAPPING`。

V22回填SQL（在添加列和约束之后执行）：

```sql
-- 附录D种子数据关系：subject或object实例的source_type为APPENDIX_D
UPDATE ont_instance_object_relation
SET assertion_origin = 'SEED'
WHERE subject_instance_id IN (
    SELECT id FROM ont_entity_instance
    WHERE source_type = 'APPENDIX_D' AND del_flag = '0'
)
AND del_flag = '0';

-- 扩展模块种子关系（如消防系统附录D扩展）同理回填为SEED
UPDATE ont_instance_object_relation
SET assertion_origin = 'SEED'
WHERE object_instance_id IN (
    SELECT id FROM ont_entity_instance
    WHERE source_type = 'APPENDIX_D' AND del_flag = '0'
)
AND assertion_origin = 'MANUAL'
AND del_flag = '0';
```

普通现有扩展关系（`source_type='EXTENSION'`的实例关联关系）保持默认值`MANUAL`，无需额外UPDATE。

若人工后来确认同一三元组，需要将origin升级为`MANUAL`或增加单独人工来源表。V1采用升级为`MANUAL`，此后映射删除不会删除关系主记录，只删除自己的provenance。

## 10. 功能属性冲突

对象属性`is_functional=1`时：

- SOURCE_WINS：只允许删除当前关系映射拥有、且无人工/其他来源证明的旧客体关系，再插入新关系；
- MANUAL_WINS：存在人工关系时保留人工关系，来源关系标记OVERRIDDEN；
- REJECT_CONFLICT：记录级失败；
- 不能删除其他映射来源仍支持的旧关系。

逆功能属性同理按客体检查主体冲突。

## 11. 关系删除检测

- JOIN_TABLE全量作业可通过本次seen relation keys与历史provenance比较发现删除；
- FOREIGN_KEY字段由旧值A变B时，移除本映射对A的provenance并建立B；
- 增量作业如果源表没有删除标志或变更日志，无法可靠发现中间表物理删除；发布校验应提示`DELETE_NOT_DETECTABLE`；
- `REMOVE_ASSERTION`只在无人工声明、无其他来源证明时删除关系主记录；
- `KEEP_ASSERTION`只将当前provenance标记STALE；
- `BLOCK_AND_REVIEW`写作业错误，等待人工处理。

## 12. Pending重试

- 本作业实体阶段完成后立即重试一次；
- 后台每分钟领取到期记录；
- 使用`FOR UPDATE SKIP LOCKED`防重复处理；
- 指数退避：1m、5m、30m、2h、12h；
- 默认最多10次；
- 达上限进入FAILED并发布`MAPPING_RELATION_UNRESOLVED`；
- 新来源绑定创建后可按recordKeyHash主动唤醒相关pending记录；
- 映射版本RETIRED后只允许完成已存在pending，不从其创建新作业；若目标Schema不兼容则FAILED。

## 13. API

> 所有路径前缀为 `/ontology/data-mapping`。

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/versions/{versionId}/relation-mappings` | 列表 |
| POST | `/versions/{versionId}/relation-mappings` | 新增 |
| PUT | `/relation-mappings/{id}` | 修改DRAFT |
| DELETE | `/relation-mappings/{id}` | 删除DRAFT |
| POST | `/relation-mappings/{id}/key-preview` | 样例键解析 |
| GET | `/pending-relations/page` | 待解析分页 |
| POST | `/pending-relations/{id}/retry` | 人工重试 |
| POST | `/pending-relations/{id}/ignore` | 管理员忽略 |

Pending详情不得显示源敏感字段，只显示映射码、键摘要、错误码和脱敏错误消息。

## 14. 事件

- `RELATION_INGESTED`
- `RELATION_UPDATED_FROM_SOURCE`
- `RELATION_SOURCE_REMOVED`
- `MAPPING_RELATION_PENDING`
- `MAPPING_RELATION_RESOLVED`
- `MAPPING_RELATION_UNRESOLVED`

事件不包含主体/客体完整源记录键；可包含bindingId、instanceId和keyHash。

## 16. 测试与验收

1. `sys_dept.parent_id`正确形成部门层级；
2. `sys_user.dept_id`形成主部门关系；
3. `sys_user_dept`和`sys_user_post`复合键幂等；
4. 两端实例顺序不同不丢关系；
5. 缺失目标按PENDING/SKIP/FAIL执行；
6. Pending在目标绑定创建后成功解析；
7. 同一三元组允许多个来源证明；
8. 删除一个来源不会删除其他来源或人工支持的关系；
9. 功能属性冲突按所有权策略执行；
10. 不自动物化inverseOf；
11. 关系事件不包含源键明文；
12. JOIN_TABLE物理删除不可检测时发布校验明确警告。
