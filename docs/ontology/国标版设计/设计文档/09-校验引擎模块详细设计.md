## 1. 评审结论与设计边界

### 1.1 现状评审

截至本设计时点，前述8个模块已全部落地：命名空间、实体类型、数据属性、对象属性、公理规则（含12条内置规则、24条目标绑定）、实体对象实例（含附录D 29个实例、83条数据值、39条对象断言）均已通过 Flyway V4–V10 迁移脚本预置。但代码库中存在以下校验引擎缺口：

| 缺口 | 现状 | 影响 |
|------|------|------|
| **执行器未实现** | 12条内置规则的 `executor_code` 已预置（ENTITY_DISJOINT、GLOBAL_UNIQUE_VALUE、DATE_ORDER、ENUM_MEMBERSHIP、UNIT_DIMENSION_CONSISTENCY、FUNCTIONAL_OBJECT_PROPERTY、OBJECT_RELATION_RANGE、MAX_RELATION_COUNT 等），但无任何执行器类 | 规则配置无法执行，PRD §8.2 三类公理校验无法运行 |
| **Jena 仅 test scope** | `jena-core:5.5.0` scope=test，仅被 `ClauseMultipleInheritanceSemanticTests` 使用；无 `jena-shacl`、无 `jena-arq`、无 TopBraid SHACL 依赖 | 生产运行时无 OWL 推理机和 SHACL 验证器 |
| **SHACL 文本未执行** | `ont_axiom_rule.shacl_shape` 字段存储了完整 SHACL Turtle 文本（7条规则有预置），但仅作为 `generatedShaclPreview` 在前端只读展示 | PRD §5.3 要求的 SHACL 约束验证未落地 |
| **即时校验已存在** | `OntEntityInstanceServiceImpl` 中 `validateDataValue()`/`validateRelation()`/`revalidateForTypeChange()` 已实现定义域/值域继承、枚举、正则、单位引用、唯一性、功能性校验 | 校验引擎需复用而非重复，避免双轨逻辑冲突 |
| **无 validation_report 表** | V10 中未建校验报告表 | PRD §4.7.2 的 `ValidationReport`/`ValidationResult` 模型无持久化载体 |

### 1.2 优化结论

| 级别 | 评审发现 | 优化结论 |
|------|----------|----------|
| P0 | PRD §4.7.4 提出 `ReasonerAdapter` SPI 适配层，但现有公理规则的 `executor_code` + `validation_mode` 已构成更细粒度的执行器分发体系，两套体系需统一 | 以现有 `validation_mode` 路由 + `executor_code` 分发为主轴，`ReasonerAdapter` 降级为 OWL 推理子能力的 SPI 扩展点，不另起炉灶 |
| P0 | 现有即时校验（`OntEntityInstanceServiceImpl`）与校验引擎存在职责重叠，若校验引擎全量重跑会导致双轨冲突 | 校验引擎聚焦**批量/全量/按需校验**场景（PRD §4.7.1 "全量校验"），即时校验保持写入路径不变；两者共享同一组规则配置，但执行入口和报告通道分离 |
| P0 | SHACL 校验需要运行时 Jena 依赖，但 `jena-core` 当前为 test scope | 新增 `jena-shacl`（含 SHACL 验证器）+ `jena-arq`（含 SPARQL 引擎）为 compile scope，版本对齐 `jena-core` 5.5.0；`jena-core` 同步提为 compile |
| P0 | `validation_report` 表未建，校验报告无法持久化 | 新增 Flyway V11 建表 `ont_validation_report` + `ont_validation_result`，存储全量校验报告与违规明细 |
| P1 | PRD §4.7.4 的 `ReasonerAdapter` 接口定义了 `checkConsistency` 和 `inferEntailments` 两个方法，但本期只做轻量公理检测 | 本期实现 `JenaReasonerAdapter`（仅 `checkConsistency`），`inferEntailments` 返回未启用；SPI 注册通过 Spring Bean 而非 `META-INF/services`（适配 Spring Boot 生态） |
| P1 | 校验报告需支持增量校验（PRD §12 风险对策"增量校验+异步全量校验+缓存"） | 提供 `validateInstance`（单实例增量）和 `validateOntology`（全量）两个入口；全量校验支持异步执行 |
| P1 | 前端 PRD §6.3 要求"页面右侧固定校验结果面板"，但当前前端无校验中心页面 | 新增 `views/ontology/validation/` 前端模块，含校验中心列表页 + 校验报告详情 + 实例编辑器内嵌实时校验面板 |
| P2 | OWL 不相交检测需要构建 RDF Model 并加载 Schema（类层次 + 不相交声明），但当前 Schema 存于关系库 | 设计 `OntologyModelAssembler` 组件，从关系库读取 Schema 组装 Jena `Model`，供 OWL Reasoner 使用；不引入 Triplestore 双写 |

### 1.3 本期范围

**本期包含：**

1. 校验执行器注册表（`ValidationExecutorRegistry`）与分发机制
2. 五类校验执行器实现：
   - **APPLICATION 执行器**（4个）：单位一致性、对象关系域值域、引用区分、层次包含——纯 Java 逻辑，从关系库直接校验
   - **SHACL_CORE 执行器**（3个）：枚举成员、取值约束、结构限制——构建 SHACL Shapes 图 + 数据图，调用 Jena SHACL 验证器
   - **SHACL_SPARQL 执行器**（3个）：全局唯一标识、标准编号唯一、日期顺序——构建 SHACL SPARQL 约束 + 数据图，调用 Jena SHACL 验证器
   - **OWL_CONSISTENCY 执行器**（1个）：实体类型不相交——构建 Schema Model + 实例 Model，调用 Jena OWL Reasoner
   - **COMPOSITE 执行器**（1个）：功能性对象属性——OWL FunctionalProperty + SHACL maxCount 双轨校验
3. `ReasonerAdapter` SPI 接口 + `JenaReasonerAdapter` 默认实现
4. `OntologyModelAssembler` 组件——从关系库 Schema 组装 Jena `Model`
5. 校验报告模型 + 持久化（`ont_validation_report` / `ont_validation_result`）
6. 校验引擎 REST API（全量校验、单实例校验、报告查询）
7. 异步全量校验支持（`@Async` + 状态轮询）
8. 前端校验中心模块（列表页 + 报告详情 + 实例编辑器实时校验面板）
9. Flyway V11 迁移脚本（建表 + 种子数据）
10. 附录D全量校验验收种子数据

**本期不包含：**

- 大规模图谱推理（传递闭包、规则链推理）——`ReasonerAdapter.inferEntailments` 返回未启用
- Triplestore 双写——校验引擎只读关系库，不引入 Jena TDB/GraphDB 持久化
- 校验规则的可视化编辑器——规则仍由公理规则模块（07）管理
- 校验结果自动修复——仅提供建议（`suggestion` 字段），不自动修改数据
- 校验报告版本对比——本期仅保存最近一次全量报告
- 自定义 SHACL 规则编辑——内置规则的 `shacl_shape` 由模板生成，扩展规则由公理规则模块管理

### 1.4 与前置模块的边界

| 能力 | 前置模块（已完成） | 本模块（校验引擎） |
|------|-------------------|-------------------|
| 规则配置（CRUD/启停/模板） | 公理规则模块（07）负责 | 只读引用 |
| 实例写入时即时校验 | 实体实例模块（08）负责 | 不干预写入路径 |
| 定义域/值域/枚举/正则/单位引用校验 | 实体实例模块写入时负责 | 可在全量校验中复查 |
| 功能性约束 | 实体实例模块写入时负责 | 可在全量校验中复查 |
| SHACL/OWL一致性和报告 | 不负责 | **本模块负责** |
| 推理引擎适配 | 不涉及 | **本模块负责** |
| 校验报告持久化 | 不涉及 | **本模块负责** |

### 1.5 权威语义口径

1. 校验引擎是**只读消费者**：读取 `ont_axiom_rule`（规则定义）、`ont_axiom_rule_target`（目标绑定）、`ont_entity_instance`/`ont_instance_data_value`/`ont_instance_object_relation`（实例数据）、`ont_entity_type`/`ont_data_property`/`ont_object_property`（Schema 元数据），不修改任何数据。
2. 校验引擎不替代即时校验：写入路径的即时校验（`OntEntityInstanceServiceImpl`）保持不变，校验引擎提供的是"全量校验"和"按需校验"能力，对应 PRD §4.7.1 的"全量校验"和"实时校验"两个层次。
3. `validation_mode` 是路由键：每条规则的 `validation_mode` 决定执行器类型（NONE/OWL_CONSISTENCY/SHACL_CORE/SHACL_SPARQL/APPLICATION/COMPOSITE），`executor_code` 是执行器实例标识。
4. SHACL 校验基于 Jena SHACL 验证器（`org.apache.jena.shacl.ShaclValidator`，Jena 4.x+ 内置），不使用 TopBraid SHACL API（减少外部依赖）。
5. OWL 一致性检测基于 Jena OWL Reasoner（`ReasonerRegistry.getOWLReasoner()`），承接国标 §5.3 要求的公理级推理（不相交冲突检测）。
6. `ReasonerAdapter` 是 SPI 扩展点，本期仅注册 `JenaReasonerAdapter`；行业扩展可通过 Spring `@Component` 注册新实现，不修改核心校验逻辑。
7. 校验报告按 `severity`（VIOLATION/WARNING/INFO）分级，Error 级违规阻断发布/导出（PRD §3.3"校验前置与阻断"）。

### 2.2 核心设计决策

| 决策 | 选择 | 理由 |
|------|------|------|
| 校验数据源 | PostgreSQL 关系库（只读） | 与模块08一致，不引入 Triplestore 双写；Jena Model 在内存中临时构建，校验完即释放 |
| SHACL 验证器 | `org.apache.jena.shacl.ShaclValidator`（Jena 内置） | Jena 4.x+ 自带 SHACL 验证器，无需引入 TopBraid；减少外部依赖 |
| OWL Reasoner | `ReasonerRegistry.getOWLReasoner()` | 国标 §5.3 要求的轻量公理检测，Jena 内置 OWL 推理机即可 |
| 执行器分发 | Spring Bean 注册 + `executor_code` 映射 | 利用 Spring 容器管理执行器生命周期，支持 `@ConditionalOnProperty` 按需启用 |
| 异步校验 | `@Async` + 状态轮询 | 全量校验可能耗时（PRD 要求≤30s/10万实例），异步执行避免请求超时 |
| 报告持久化 | JSONB 存储完整结果 + 关系表存索引 | `ont_validation_result` 存逐条违规明细（可查询），`result_json` 存完整 JSON 快照 |
| Model 组装 | 按需组装、按 ontologyId 隔离 | 每次校验构建独立的 Jena `Model`，不跨本体工程共享，避免并发污染 |

## 3. 执行器架构设计

### 3.1 执行器 SPI 接口

```java
/**
 * 校验执行器 SPI 接口
 * <p>
 * 每个执行器对应一个 {@code executorCode}，负责执行特定类型的公理规则校验。
 * 执行器是只读消费者，不修改任何数据。
 * </p>
 */
public interface ValidationExecutor {

    /**
     * 执行器编码，对应 {@code ont_axiom_rule.executor_code}
     */
    String getExecutorCode();

    /**
     * 校验模式，对应 {@code ont_axiom_rule.validation_mode}
     */
    ValidationMode getValidationMode();

    /**
     * 执行单条规则的校验
     *
     * @param rule    规则定义（含 configJson、owlAxiom、shaclShape）
     * @param targets 规则目标绑定（按 bindingRole 分组）
     * @param context 校验上下文（ontologyId、Model 缓存、数据访问器）
     * @return 校验结果列表（空列表表示通过）
     */
    List<ValidationResult> validate(OntAxiomRule rule,
                                     List<OntAxiomRuleTarget> targets,
                                     ValidationContext context);
}
```

### 3.3 执行器注册表

```java
/**
 * 执行器注册表
 * <p>
 * 启动时扫描所有 {@link ValidationExecutor} Bean，按 {@code executorCode} 注册。
 * 校验编排器通过 {@code executorCode} 查找对应执行器。
 * </p>
 */
@Component
public class ValidationExecutorRegistry {

    private final Map<String, ValidationExecutor> executors = new ConcurrentHashMap<>();

    public ValidationExecutorRegistry(List<ValidationExecutor> executorList) {
        for (ValidationExecutor executor : executorList) {
            String code = executor.getExecutorCode();
            Assert.state(!executors.containsKey(code),
                "重复的执行器编码: " + code);
            executors.put(code, executor);
        }
    }

    /**
     * 按执行器编码查找执行器
     *
     * @param executorCode ont_axiom_rule.executor_code
     * @return 执行器实例，不存在则抛出 IllegalStateException
     */
    public ValidationExecutor getExecutor(String executorCode) {
        ValidationExecutor executor = executors.get(executorCode);
        if (executor == null) {
            throw new IllegalStateException(
                "执行器未注册: " + executorCode + "，请检查该规则对应的执行器是否已实现");
        }
        return executor;
    }

    /**
     * 获取所有已注册的执行器编码
     */
    public Set<String> getRegisteredCodes() {
        return Collections.unmodifiableSet(executors.keySet());
    }
}
```

### 3.4 校验编排器

```java
/**
 * 校验编排服务
 * <p>
 * 统一入口：加载规则 → 分发执行器 → 聚合结果 → 持久化报告。
 * 支持全量校验（异步）和单实例校验（同步）。
 * </p>
 */
public interface ValidationOrchestrator {

    /**
     * 全量校验（异步）
     * <p>
     * 对指定本体工程下所有 ACTIVE 规则执行校验，返回报告 ID。
     * 校验在后台异步执行，前端通过 GET /validation/status 轮询状态。
     * </p>
     */
    R<Long> validateOntology(Long ontologyId);

    /**
     * 单实例校验（同步）
     * <p>
     * 对指定实例执行所有适用的 ACTIVE 规则校验，返回结果列表。
     * 用于实例编辑器实时校验面板。
     * </p>
     */
    List<ValidationResult> validateInstance(Long instanceId);
}
```

### 3.5 编排流程

```

  │
  ├── 1. 创建 ValidationContext（ontologyId, FULL scope）
  │
  ├── 2. 加载 ACTIVE 规则
  │     SELECT * FROM ont_axiom_rule
  │     WHERE ontology_id = ? AND status = 'ACTIVE' AND is_enabled = '1'

  │
  ├── 3. 加载规则目标绑定
  │     SELECT * FROM ont_axiom_rule_target WHERE axiom_rule_id IN (...)

  │

  │
  ├── 6. 持久化报告
  │     INSERT ont_validation_report (ontology_id, conforms, triggered_at, result_json)
  │     INSERT ont_validation_result (batch, 逐条违规明细)
  │
  ├── 7. 发布事件
  │     ValidationCompletedEvent(reportId, ontologyId, conforms, violationCount)
  │     → 前端可 WebSocket 推送或轮询获取
  │
  └── 8. 返回 reportId
```

## 4. 四类校验引擎详细设计

### 4.1 APPLICATION 执行器（纯 Java 逻辑）

APPLICATION 执行器不依赖 Jena，直接从关系库读取数据执行 Java 逻辑校验。适用于规则逻辑明确、不需要 RDF 模型推理的场景。

#### 4.1.1 UnitDimensionConsistencyExecutor（单位一致性约束）

> 对应规则：970007 PRD_CONSTRAINT_UNIT_CONSISTENCY
> validation_mode=APPLICATION, executor_code=UNIT_DIMENSION_CONSISTENCY
> 国标依据：第8.2条 b)5) 单位一致性约束

**校验逻辑：**

```
对 ontology_id 下所有 Constraint 类型的实例（rdf_type_id 指向 Constraint 实体类型）：
  1. 读取该实例的 maxValue / minValue / thresholdRange 数据属性值
  2. 读取该实例的 measurementUnit / unit 数据属性值（UNIT_REF 类型，引用 ont_unit）
  3. 通过 ont_unit.category_id 获取单位分类
  4. 校验：maxValue/minValue/thresholdRange 引用的单位分类须与 measurementUnit 的单位分类一致
     - 若 maxValue 有 unit_id，则 maxValue.unit_id → category == measurementUnit.unit_id → category
     - 若 minValue 有 unit_id，同理
     - 若均无 unit_id，则跳过（无单位约束的数值不校验量纲）
  5. 若不一致，生成 VIOLATION 结果：
     focusNode = 实例 IRI
     resultPath = measurementUnit 的 IRI
     message = "约束实例的 maxValue/minValue 与 measurementUnit 量纲不一致"
     expectedValue = measurementUnit 的单位分类名
     actualValue = maxValue/minValue 的单位分类名
     suggestion = "请统一数值约束与测量单位的物理量分类"
```

**configJson 角色映射：**

```json
{
  "maxPropertyRole": "maxValue 数据属性 ID",
  "minPropertyRole": "minValue 数据属性 ID",
  "rangePropertyRole": "thresholdRange 数据属性 ID",
  "unitPropertyRole": "measurementUnit 数据属性 ID",
  "targetClassRole": "Constraint 实体类型 ID"
}
```

**数据查询：**

```sql
-- 查找 Constraint 类型实例的所有数值约束 + 单位引用
SELECT i.iri, i.id,
       dv_max.literal_value AS max_value,
       dv_max.unit_id AS max_unit_id,
       dv_min.literal_value AS min_value,
       dv_min.unit_id AS min_unit_id,
       dv_unit.unit_id AS measurement_unit_id,
       u_unit.category_id AS measurement_category_id
FROM ont_entity_instance i
JOIN ont_entity_type t ON i.rdf_type_id = t.id
LEFT JOIN ont_instance_data_value dv_max
  ON dv_max.instance_id = i.id AND dv_max.data_property_id = #{maxPropertyId}
LEFT JOIN ont_instance_data_value dv_min
  ON dv_min.instance_id = i.id AND dv_min.data_property_id = #{minPropertyId}
LEFT JOIN ont_instance_data_value dv_unit
  ON dv_unit.instance_id = i.id AND dv_unit.data_property_id = #{unitPropertyId}
LEFT JOIN ont_unit u_unit ON u_unit.id = dv_unit.unit_id
WHERE i.ontology_id = #{ontologyId}
  AND t.id = #{targetClassId}
```

#### 4.1.3 MaxRelationCountExecutor（结构限制）

> 对应规则：970011 GB8_UNTITLED_NO_SUBCLAUSE
> validation_mode=SHACL_CORE, executor_code=MAX_RELATION_COUNT
> 国标依据：第8.2条 c)3)第二项 无标题条不可含子条

> **注意**：该规则的 `validation_mode` 为 SHACL_CORE，但实际校验逻辑是"对特定类型实例的对象属性断言计数"，可以同时用 SHACL `sh:maxCount` 和 Java 计数两种方式实现。本期采用 **Java 计数 + SHACL Shapes 双轨**，SHACL 作为形式化表达，Java 作为实际执行（因为 SHACL 需要完整数据图，而 Java 计数更高效）。

```
  2. 读取该实例通过 hasSubClause 的断言数
     SELECT COUNT(*) FROM ont_instance_object_relation

     actualValue = "{count}"
     suggestion = "请将无标题条改为有标题条，或移除其子条"
```

### 4.2 SHACL 执行器（Jena SHACL 验证器）

SHACL 执行器使用 Jena 内置的 `ShaclValidator` 执行约束验证。流程为：构建 SHACL Shapes 图（规则） + 构建数据图（实例三元组） → 调用 `ShaclValidator.get().validate(shapesGraph, dataModel)` → 解析报告。

#### 4.2.1 SHACL 公共基类

```java
/**
 * SHACL 执行器公共基类
 * <p>
 * 提供从规则配置构建 SHACL Shapes 图、从实例数据构建数据图、
 * 调用 Jena SHACL 验证器、解析报告为 ValidationResult 的通用逻辑。
 * </p>
 */
public abstract class AbstractShaclExecutor extends AbstractValidationExecutor {

    @Override
    public List<ValidationResult> validate(OntAxiomRule rule,
                                           List<OntAxiomRuleTarget> targets,
                                           ValidationContext context) {
        // 1. 构建 SHACL Shapes 图（从 rule.shaclShape 或 configJson 动态构建）
        Model shapesModel = buildShapesModel(rule, targets, context);

        // 2. 构建数据图（只包含规则目标类型的实例三元组）
        Model dataModel = buildDataModel(rule, targets, context);

        // 3. 调用 Jena SHACL 验证器
        org.apache.jena.shacl.Shapes shapes = Shapes.parse(shapesModel);
        ValidationReport shaclReport = ShaclValidator.get().validate(shapes, dataModel);

        // 4. 解析 SHACL 报告为 ValidationResult 列表
        return parseShaclReport(shaclReport, rule);
    }

    /**
     * 构建 SHACL Shapes 图
     * 若 rule.shaclShape 已有预置文本，直接解析；
     * 否则根据 configJson 动态构建。
     */
    protected abstract Model buildShapesModel(OntAxiomRule rule,
                                              List<OntAxiomRuleTarget> targets,
                                              ValidationContext context);

    /**
     * 构建数据图（实例三元组）
     */
    protected Model buildDataModel(OntAxiomRule rule,
                                    List<OntAxiomRuleTarget> targets,
                                    ValidationContext context) {
        return context.getDataGraphBuilder().buildForRule(rule, targets);
    }

    /**
     * 解析 SHACL 报告
     */
    protected List<ValidationResult> parseShaclReport(ValidationReport shaclReport,
                                                       OntAxiomRule rule) {
        List<ValidationResult> results = new ArrayList<>();
        for (ValidationReport.Entry entry : shaclReport.getEntries()) {
            results.add(ValidationResult.builder()
                .severity(mapSeverity(entry.severity(), rule))
                .focusNode(entry.focusNode().toString())
                .resultPath(entry.resultPath() != null ? entry.resultPath().toString() : null)
                .ruleName(rule.getName())
                .ruleCode(rule.getRuleCode())
                .message(entry.message().toString())
                .expectedValue(entry.value() != null ? entry.value().toString() : null)
                .actualValue(null)  // SHACL 报告不提供 actualValue
                .suggestion(buildSuggestion(rule, entry))
                .build());
        }
        return results;
    }
}
```

#### 4.2.4 DateOrderExecutor（日期顺序校验）

> 对应规则：970004 GB8_EFFECTIVE_DATE_ORDER
> validation_mode=SHACL_SPARQL, executor_code=DATE_ORDER
> 国标依据：第8.2条 b)2) 日期有效性验证（实施日期≥发布日期）

**SHACL SPARQL 构建策略：**

规则 970004 的 `shacl_shape` 已预置（V9 种子数据），使用 SHACL SPARQL 比较日期：

```turtle
:EffectiveDateOrderShape a sh:NodeShape ;
    sh:targetClass :Standard ;
    sh:sparql [
        sh:message "实施日期必须大于等于发布日期" ;
        sh:prefixes : ;
        sh:select """
            SELECT $this ?issuedDate ?effectiveDate
            WHERE {
                $this :issuedDate ?issuedDate .
                $this :effectiveDate ?effectiveDate .
                FILTER(?effectiveDate < ?issuedDate)
            }
        """ ;
    ] .
```

> **日期序列化注意**：平台规范值为 `YYYYMMDD`（如 `20240929`），SHACL SPARQL 中按字符串比较即可保证时间顺序正确（因为 YYYYMMDD 的字符串字典序与日期序一致）。导出 RDF 为 `xsd:date` 时转换为 `YYYY-MM-DD`，SHACL 验证器内部也支持 `xsd:date` 比较。本期数据图统一使用平台规范值 `YYYYMMDD` 作为 `xsd:string` 字面量。

### 4.3 OWL_CONSISTENCY 执行器（Jena OWL Reasoner）

#### 4.3.1 EntityDisjointExecutor（实体类型不相交检测）

> 对应规则：970001 GB8_ENTITY_DISJOINT
> validation_mode=OWL_CONSISTENCY, executor_code=ENTITY_DISJOINT
> 国标依据：第8.2条 a)1) 实体类型不相交规则

**校验逻辑：**

```
1. 构建 Schema Model（类层次 + 不相交声明）：
   a. 从 ont_entity_type 和 ont_entity_type_hierarchy 读取所有类和 subClassOf 关系
   b. 从 ont_entity_type_disjoint 读取所有不相交对
   c. 转为 RDF 三元组：
      <typeIRI> a owl:Class .
      <typeIRI> rdfs:subClassOf <parentIRI> .
      <typeAIRI> owl:disjointWith <typeBIRI> .

2. 构建 Instance Model（实例 rdf:type 三元组）：
   SELECT iri, rdf_type_iri FROM ont_entity_instance WHERE ontology_id = ?
   → <instanceIRI> a <typeIRI> .
   → <instanceIRI> a <ancestorTypeIRI> . （通过 OWL 推理自动推导）

3. 创建 InfModel：
   InfModel infModel = ModelFactory.createInfModel(
       ReasonerRegistry.getOWLReasoner(), schemaModel);
   infModel.add(instanceModel);  // 合并实例三元组

4. 检测不相交冲突：
   // 遍历所有实例，检查是否有实例同时属于两个不相交的类
   StmtIterator it = infModel.listStatements(null, RDF.type, (RDFNode) null);
   while (it.hasNext()) {
       Statement stmt = it.nextStatement();
       Resource instance = stmt.getSubject();
       Resource type = stmt.getResource();
       // 检查该实例是否被推断为某个不相交类
       // Jena OWL Reasoner 会为不相交冲突生成 violation
   }

5. 提取 Jena 推理报告：
   infModel.validate();  // 触发一致性检测
   List<ValidityReport.Report> reports = infModel.getValidityReport().getReports();
   // 每个 violation 对应一个不相交冲突
```

**Jena 代码示例：**

```java
@Override
public List<ValidationResult> validate(OntAxiomRule rule,
                                        List<OntAxiomRuleTarget> targets,
                                        ValidationContext context) {
    // 1. 组装 Schema Model
    Model schemaModel = context.getModelAssembler().buildSchemaModel(context.getOntologyId());

    // 2. 组装 Instance Model
    Model instanceModel = context.getModelAssembler().buildInstanceModel(context.getOntologyId());

    // 3. 创建推理模型
    InfModel infModel = ModelFactory.createInfModel(
        ReasonerRegistry.getOWLReasoner(), schemaModel);
    infModel.add(instanceModel);

    // 4. 执行一致性检测
    ValidityReport validity = infModel.validate();
    List<ValidationResult> results = new ArrayList<>();

    if (!validity.isValid()) {
        for (Iterator<ValidityReport.Report> it = validity.getReports(); it.hasNext(); ) {
            ValidityReport.Report report = it.next();
            if (report.conclusionType == ValidityReport.INDIVIDUAL_CONSISTENT
                || report.conclusionType == ValidityReport.CONTRADICTION) {
                results.add(ValidationResult.builder()
                    .severity(Severity.VIOLATION)
                    .focusNode(extractInstanceIRI(report))
                    .resultPath("owl:disjointWith")
                    .ruleName(rule.getName())
                    .ruleCode(rule.getRuleCode())
                    .message("实体类型不相交冲突：" + report.getDescription())
                    .suggestion("该实例同时属于互斥的实体类型，请检查 rdf:type 绑定")
                    .build());
            }
        }
    }

    infModel.close();  // 释放推理模型
    return results;
}
```

### 4.4 COMPOSITE 执行器（OWL + SHACL 组合）

#### 4.4.1 FunctionalObjectPropertyExecutor（功能性对象属性校验）

> 对应规则：970008 GB8_ISSUED_BY_FUNCTIONAL
> validation_mode=COMPOSITE, executor_code=FUNCTIONAL_OBJECT_PROPERTY
> 国标依据：第8.2条 c)1) 功能性属性约束（每个标准只能由一个机构发布）

**双轨校验逻辑：**

```
轨道1: OWL FunctionalProperty 一致性检测
  1. 构建 Schema Model，包含 :issuedBy a owl:FunctionalProperty 声明
  2. 构建 Instance Model，包含所有 issuedBy 断言三元组
  3. InfModel infModel = ModelFactory.createInfModel(
         ReasonerRegistry.getOWLReasoner(), schemaModel);
     infModel.add(instanceModel);
  4. infModel.validate() → 若同一主体有两个不同客体，生成 violation

轨道2: SHACL maxCount 1 约束校验
  1. 构建 SHACL Shapes：
     :IssuedByFunctionalShape a sh:NodeShape ;
         sh:targetClass :Standard ;
         sh:property [
             sh:path :issuedBy ;
             sh:maxCount 1 ;
             sh:severity sh:Violation ;
             sh:message "每个标准只能由一个机构发布" ;
         ] .
  2. 构建数据图
  3. ShaclValidator.validate(shapes, data) → 若同一主体有2+条断言，生成 violation

结果合并：取并集去重（按 focusNode + resultPath 去重）
```

> **设计注意**：双轨校验会产生重复结果，需按 `focusNode + resultPath + ruleCode` 去重。本期以 SHACL 轨道结果为主，OWL 轨道作为补充（当 SHACL 未检测到但 OWL 检测到时，可能是推理推导出的间接冲突）。

### 4.5 ReasonerAdapter SPI（推理引擎适配层）

```java
    private boolean consistent;
    private List<ConsistencyViolation> violations;
}

@Data
public class ConsistencyViolation {
    private String instanceIRI;
    private String violationType;  // DISJOINT / FUNCTIONAL / ...
    private String description;
    private Set<String> conflictingTypes;

/**
 * Jena 默认实现
 */
@Component
public class JenaReasonerAdapter implements ReasonerAdapter {

    @Override
    public String getReasonerName() {
        return "JenaOWLReasoner";
    }

    @Override
    public Set<ReasonerCapability> getReasonerCapabilities() {
        return Set.of(
            ReasonerCapability.DISJOINT_CHECK,
            ReasonerCapability.FUNCTIONAL_CHECK,
            ReasonerCapability.SUBCLASS_INFERENCE
        );
    }

    @Override
    public ConsistencyReport checkConsistency(Model schemaModel, Model instanceModel) {
        InfModel infModel = ModelFactory.createInfModel(
            ReasonerRegistry.getOWLReasoner(), schemaModel);
        infModel.add(instanceModel);

        ValidityReport validity = infModel.validate();
        ConsistencyReport report = new ConsistencyReport();
        report.setConsistent(validity.isValid());

        List<ConsistencyViolation> violations = new ArrayList<>();
        for (Iterator<ValidityReport.Report> it = validity.getReports(); it.hasNext(); ) {
            ValidityReport.Report r = it.next();
            ConsistencyViolation v = new ConsistencyViolation();
            v.setViolationType(mapViolationType(r.conclusionType));
            v.setDescription(r.getDescription());
            violations.add(v);
        }
        report.setViolations(violations);

        infModel.close();
        return report;
    }
}
```

## 5. Model 组装层设计

### 5.1 OntologyModelAssembler

```java
/**
 * 本体模型组装器
 * <p>
 * 从关系库读取 Schema 和实例数据，组装为 Jena {@link Model}。
 * 按 ontologyId 隔离，每次组装创建独立 Model，不跨工程共享。
 * </p>
 */
@Component
public class OntologyModelAssembler {

    private final EntityTypeMapper entityTypeMapper;
    private final EntityInstanceMapper instanceMapper;
    private final InstanceDataValueMapper dataValueMapper;
    private final InstanceObjectRelationMapper relationMapper;

    /**
     * 构建 Schema Model（类层次 + 不相交 + 等价声明）
     */
    public Model buildSchemaModel(Long ontologyId) {
        Model model = ModelFactory.createDefaultModel();
        String ns = getNamespaceUri(ontologyId);

        // 1. 类声明 + subClassOf
        List<OntEntityType> types = entityTypeMapper.selectByOntologyId(ontologyId);
        for (OntEntityType type : types) {
            Resource cls = model.createResource(type.getIri());
            model.add(cls, RDF.type, OWL.Class);
        }

        // 2. 继承关系
        List<EntityTypeHierarchyDTO> hierarchies = entityTypeMapper.selectHierarchy(ontologyId);
        for (EntityTypeHierarchyDTO h : hierarchies) {
            Resource child = model.createResource(h.getChildIri());
            Resource parent = model.createResource(h.getParentIri());
            model.add(child, RDFS.subClassOf, parent);
        }

        // 3. 不相交
        List<EntityTypeDisjointDTO> disjoints = entityTypeMapper.selectDisjoints(ontologyId);
        for (EntityTypeDisjointDTO d : disjoints) {
            Resource a = model.createResource(d.getTypeAIri());
            Resource b = model.createResource(d.getTypeBIri());
            model.add(a, OWL.disjointWith, b);
            model.add(b, OWL.disjointWith, a);  // 不相交是对称的
        }

        return model;
    }

    /**
     * 构建实例 Model（rdf:type + 数据属性值 + 对象属性断言）
     */
    public Model buildInstanceModel(Long ontologyId) {
        Model model = ModelFactory.createDefaultModel();

        // 1. 实例 rdf:type
        List<OntEntityInstance> instances = instanceMapper.selectByOntologyId(ontologyId);
        for (OntEntityInstance inst : instances) {
            Resource res = model.createResource(inst.getIri());
            Resource type = model.createResource(inst.getRdfTypeIri());
            model.add(res, RDF.type, type);
        }

        // 2. 数据属性值
        List<InstanceDataValueDTO> values = dataValueMapper.selectByOntologyId(ontologyId);
        for (InstanceDataValueDTO dv : values) {
            Resource subject = model.createResource(dv.getInstanceIri());
            Property predicate = model.createProperty(dv.getPropertyIri());
            RDFNode object = createLiteralNode(model, dv);
            model.add(subject, predicate, object);
        }

        // 3. 对象属性断言
        List<InstanceObjectRelationDTO> relations = relationMapper.selectByOntologyId(ontologyId);
        for (InstanceObjectRelationDTO rel : relations) {
            Resource subject = model.createResource(rel.getSubjectIri());
            Property predicate = model.createProperty(rel.getPropertyIri());
            Resource object = model.createResource(rel.getObjectIri());
            model.add(subject, predicate, object);
        }

        return model;
    }

    /**
     * 创建 RDF 字面量
     */
    private RDFNode createLiteralNode(Model model, InstanceDataValueDTO dv) {
        switch (dv.getLiteralType()) {
            case "INTEGER":
                return model.createTypedLiteral(Long.parseLong(dv.getLiteralValue()),
                    XSDDatatype.XSDinteger);
            case "DECIMAL":
                return model.createTypedLiteral(new BigDecimal(dv.getLiteralValue()),
                    XSDDatatype.XSDdecimal);
            case "BOOLEAN":
                return model.createTypedLiteral(Boolean.parseBoolean(dv.getLiteralValue()),
                    XSDDatatype.XSDboolean);
            case "DATE":
                // 平台规范值 YYYYMMDD，转为 xsd:date 的 YYYY-MM-DD
                String dateStr = dv.getLiteralValue();
                if (dateStr.length() == 8) {
                    dateStr = dateStr.substring(0, 4) + "-" + dateStr.substring(4, 6) + "-" + dateStr.substring(6, 8);
                }
                return model.createTypedLiteral(dateStr, XSDDatatype.XSDdate);
            case "URI":
                return model.createResource(dv.getLiteralValue());
            default:  // STRING
                return model.createLiteral(dv.getLiteralValue());
        }
    }
}
```

```java
        // 4. 构建 rdf:type + 数据属性值 + 对象属性断言三元组
        // ...（同 OntologyModelAssembler.buildInstanceModel 的子集）

        return dataModel;
    }

    /**
     * 收集目标类型及其所有子类型（递归）
     */
    private Set<Long> collectSubTypes(Long rootTypeId) {
        Set<Long> result = new HashSet<>();
        Deque<Long> queue = new ArrayDeque<>();
        queue.add(rootTypeId);
        while (!queue.isEmpty()) {
            Long current = queue.poll();
            if (result.add(current)) {
                List<Long> children = entityTypeMapper.selectChildIds(current);
                queue.addAll(children);
            }
        }
        return result;
    }
```

```java
/**
 * 校验编排器实现
 */
@Service
@RequiredArgsConstructor
@Slf4j
public class ValidationOrchestratorImpl implements ValidationOrchestrator {

    private final OntAxiomRuleMapper axiomRuleMapper;
    private final OntAxiomRuleTargetMapper targetMapper;
    private final ValidationExecutorRegistry executorRegistry;
    private final ValidationReportService reportService;
    private final OntologyModelAssembler modelAssembler;
    private final OntEntityInstanceMapper instanceMapper;

    @Override
    public R<Long> validateOntology(Long ontologyId) {
        // 1. 创建报告记录（RUNNING 状态）
        OntValidationReport report = new OntValidationReport();
        report.setOntologyId(ontologyId);
        report.setScope("FULL");
        report.setStatus("RUNNING");
        report.setTriggeredBy(SecurityUtils.getUser().getUsername());
        report.setTriggeredAt(LocalDateTime.now());
        reportService.saveReport(report);

        // 2. 异步执行校验
        executeAsync(report.getId(), ontologyId);

        return R.ok(report.getId());
    }

    @Async("validationExecutor")
    public void executeAsync(Long reportId, Long ontologyId) {
        long startTime = System.currentTimeMillis();
        try {
            // 1. 构建上下文
            ValidationContext context = ValidationContext.builder()
                .ontologyId(ontologyId)
                .scope(ValidationScope.FULL)
                .modelAssembler(modelAssembler)
                .build();

            // 2. 加载 ACTIVE 规则
            List<OntAxiomRule> rules = axiomRuleMapper.selectActiveByOntologyId(ontologyId);

            // 3. 加载规则目标绑定
            Map<Long, List<OntAxiomRuleTarget>> targetMap = loadTargets(rules);

            // 4. 逐规则执行
            List<ValidationResult> allResults = new ArrayList<>();
            for (OntAxiomRule rule : rules) {
                List<OntAxiomRuleTarget> targets = targetMap.getOrDefault(rule.getId(), List.of());
                try {
                    ValidationExecutor executor = executorRegistry.getExecutor(rule.getExecutorCode());
                    List<ValidationResult> results = executor.validate(rule, targets, context);
                    allResults.addAll(results);
                } catch (Exception e) {
                    log.error("执行器 {} 执行失败: {}", rule.getExecutorCode(), e.getMessage(), e);
                    allResults.add(ValidationResult.builder()
                        .severity(Severity.WARNING)
                        .ruleName(rule.getName())
                        .ruleCode(rule.getRuleCode())
                        .message("执行器执行异常: " + e.getMessage())
                        .build());
                }
            }

            // 5. 聚合结果
            allResults.sort(Comparator
                .comparing((ValidationResult r) -> r.getSeverity().ordinal()));

            int violationCount = (int) allResults.stream()
                .filter(r -> r.getSeverity() == Severity.VIOLATION).count();
            int warningCount = (int) allResults.stream()
                .filter(r -> r.getSeverity() == Severity.WARNING).count();
            int infoCount = (int) allResults.stream()
                .filter(r -> r.getSeverity() == Severity.INFO).count();

            // 6. 更新报告
            long duration = System.currentTimeMillis() - startTime;
            reportService.completeReport(reportId, OntValidationReport.builder()
                .conforms(violationCount == 0)
                .totalCount(allResults.size())
                .violationCount(violationCount)
                .warningCount(warningCount)
                .infoCount(infoCount)
                .ruleCount(rules.size())
                .instanceCount(instanceMapper.countByOntologyId(ontologyId))
                .durationMs(duration)
                .status("COMPLETED")
                .completedAt(LocalDateTime.now())
                .build());

            // 7. 持久化逐条结果
            reportService.saveResults(reportId, allResults);

        } catch (Exception e) {
            log.error("全量校验失败: reportId={}", reportId, e);
            reportService.failReport(reportId, e.getMessage());
        }
    }

    @Override
    public List<ValidationResult> validateInstance(Long instanceId) {
        OntEntityInstance instance = instanceMapper.selectById(instanceId);
        if (instance == null) {
            throw new IllegalArgumentException("实例不存在: " + instanceId);
        }

        // 1. 构建上下文（单实例增量）
        ValidationContext context = ValidationContext.builder()
            .ontologyId(instance.getOntologyId())
            .scope(ValidationScope.INSTANCE)
            .targetInstanceId(instanceId)
            .modelAssembler(modelAssembler)
            .build();

        // 2. 加载 ACTIVE 规则
        List<OntAxiomRule> rules = axiomRuleMapper.selectActiveByOntologyId(
            instance.getOntologyId());

        // 3. 只执行与该实例类型相关的规则
        List<ValidationResult> results = new ArrayList<>();
        for (OntAxiomRule rule : rules) {
            List<OntAxiomRuleTarget> targets = targetMapper.selectByRuleId(rule.getId());
            if (isRuleApplicable(rule, targets, instance)) {
                ValidationExecutor executor = executorRegistry.getExecutor(
                    rule.getExecutorCode());
                results.addAll(executor.validate(rule, targets, context));
            }
        }

        return results;
    }

    /**
     * 判断规则是否适用于该实例
```

## 14. 性能设计

### 14.1 性能目标

| 场景 | 目标 | 对应PRD非功能要求 |
|------|------|-----------------|
| 单实例校验 | ≤ 500ms | §9 实时校验 |
| 全量校验（≤1000实例） | ≤ 5s | §9 全量校验 |
| 全量校验（≤10万实例） | ≤ 30s | §9 性能要求 |
| Model 组装（≤1000实例） | ≤ 2s | — |
| SHACL 验证（≤1000实例） | ≤ 3s | — |

### 14.2 性能优化策略

| 策略 | 说明 |
|------|------|
| **按需组装 Model** | `DataGraphBuilder.buildForRule()` 只构建规则目标范围内的实例三元组，不全量加载 |
| **Model 缓存** | `ValidationContext` 在单次校验会话内缓存 Schema Model 和数据 Model，多规则复用 |
| **APPLICATION 优先** | 能用 Java 逻辑校验的（单位一致性、域值域）不走 Jena，避免 Model 构建 |
| **异步全量** | 全量校验异步执行，不阻塞请求线程 |
| **增量索引** | `ont_validation_result` 按 `report_id + severity + sort_order` 建索引，支持分页查询 |
| **SHACL Shapes 缓存** | 内置规则的 `shacl_shape` 文本解析结果在应用级缓存（Caffeine），避免重复解析 |

### 14.3 异步超时处理

```java
/**
 * 异步校验超时配置
 * application.yml:
 * pig:
 *   ontology:
 *     validation:
 *       async-timeout: 300s   # 单次全量校验超时
 *       poll-interval: 2s    # 前端轮询间隔建议
 */
```

超时处理：若 `@Async` 线程池满，任务降级为调用者线程执行（`CallerRunsPolicy`）；若执行超时，`ValidationContext` 中的 Model 会被 GC 回收，报告状态保持 `RUNNING`，需定时任务清理超时报告（设置 `scheduledCleanup` 每5分钟扫描超过10分钟的 `RUNNING` 报告，标记为 `FAILED`）。

### 15.1 权限矩阵

| 操作 | 权限码 | 角色 |

### 15.2 数据隔离

校验引擎按 `ontologyId` 隔离数据：
- 全量校验只读取指定 `ontology_id` 的规则和实例
- 单实例校验通过 `instance.ontology_id` 关联到规则
- 校验报告按 `ontology_id` 查询，不跨工程

### 15.3 审计

全量校验记录 `triggered_by`（触发人用户名），便于追溯。校验报告持久化后不可删除（仅允许 `ON DELETE CASCADE` 跟随本体工程删除）。

## 18. 风险与对策

| 风险 | 影响 | 对策 |
|------|------|------|
| Jena Model 内存溢出 | 10万实例全量组装 Model 可能 OOM | `DataGraphBuilder` 按规则目标范围过滤实例；APPLICATION 执行器不走 Jena；远期引入分批校验 |
| SHACL SPARQL 性能 | SHACL SPARQL 约束在数据量大时慢 | 内置规则数据量小（附录D 29实例）；远期增加 SHACL Shapes 缓存 + 数据图分批 |
| 异步校验超时 | 全量校验长时间 RUNNING | 设置超时清理定时任务（5分钟扫描，10分钟超时标记 FAILED） |
| 执行器未注册 | 规则 `executor_code` 无对应执行器 | 启动时校验所有 ACTIVE 规则的 `executor_code` 已注册，否则拒绝启动（fail-fast） |
| OWL Reasoner 推理深度 | Jena OWL Reasoner 对复杂本体推理慢 | 本期仅检测不相交冲突，不启用传递闭包推理；`ReasonerAdapter` 控制推理范围 |
| 双轨校验重复 | COMPOSITE 执行器 OWL + SHACL 双轨可能产生重复结果 | 按 `focusNode + resultPath + ruleCode` 去重 |
| 报告表膨胀 | 每次全量校验产生大量结果记录 | 每个本体工程仅保留最近10次报告（定时清理）；`result_json` 存 JSON 快照减少关系记录 |
