# 对象属性管理模块详细设计

> 对应 PRD：§2.6、§4.4、§5.1、§5.2、§6.2.1、§14.2
>
> 直接依据：GB/T 48000.3—2026 第7.3条、表1（34个核心对象属性）
>
> 前置模块：01-模块化架构、02-单位字典、03-命名空间与IRI、04-实体类型、05-数据属性（均已实现）
>
> 设计日期：2026-07-10

## 1. 模块定位与边界

### 1.1 定位

对象属性（ObjectProperty）描述实体类型之间的关系，是 OWL/RDFS 本体的核心组成部分。本模块管理 Schema 层对象属性定义——即"标准实体 *可以* 发布于 机构"这类关系类型的声明，而非具体实例间的连接（实例间关系由实体对象实例模块在后续 M3 交付）。

对应国标第7.3条及表1，国标定义了 **34 个核心对象属性**，每个属性含附录A.2的7项元数据描述（IRI、名称、标签、定义、定义域、值域、属性类型），以及对象属性特有的语义特性标记（功能性、逆属性、传递性、对称性）。

### 1.2 本期边界

本期包含：

1. 对象属性定义 CRUD、查询、来源标识和内置保护；
2. 附录A.2七项元数据映射；
3. 表1全部34项核心对象属性预置；
4. 定义域/值域绑定实体类型，支持按定义域、按值域查询；
5. 对象属性继承/适用性：子类实体类型适用的对象属性通过定义域向上继承获得；
6. 逆属性（inverseOf）双向维护：修改一方时自动维护另一方；
7. 功能性/反功能性/传递性/对称性语义标记；
8. 与实体类型、命名空间的引用保护联动。

本期不包含：实例间关系的建立与持久化、SHACL校验执行、RDF/OWL实际导出、公理一致性检测。这些能力由后续实例（M3）、校验（M2）、序列化（M4）模块实现，但本设计给出稳定契约。

### 1.3 与数据属性模块的异同

| 维度 | 数据属性（V7） | 对象属性（V8） |
|------|----------------|----------------|
| 语义 | 描述实体内在特征（DatatypeProperty） | 描述实体间关系（ObjectProperty） |
| 值域 | 7种基础类型 + 枚举 + 单位引用 | 实体类型IRI（rdfs:range指向类） |
| 定义域 | 单一实体类型 | 单一实体类型 |
| 特殊标记 | 无 | 逆属性、功能性、反功能性、传递性、对称性 |
| 子表 | 标签表 + 枚举值表 | 标签表（无枚举） |
| 继承机制 | 按定义域BFS向上继承 | 按定义域BFS向上继承（同算法） |
| 预置规模 | 56项（47附录C + 2条款 + 7附录D） | 34项（表1） |
| IRI消歧 | 3个constraintType需消歧 | 无重名（34项英文名均唯一） |
| 别名 | C.41 unit/measurementUnit | 无 |

## 2. 领域模型与本体语义

### 2.1 附录A.2七项元数据映射

| 国标描述项 | 平台字段/结构 | 说明 |
|------------|---------------|------|
| IRI | `ont_object_property.iri` | 平台内部全局唯一IRI；对象属性无 `standard_iri` 双轨需求（表1无重名） |
| Name | `ont_object_property.name` | 保留国标英文名，首字母小写（如 `issuedBy`） |
| Label | `ont_object_property_label` | 首期预置 `zh`，支持后续多语言 |
| Definition | `definition` | 核心种子按国标表1语义说明落库 |
| Domain | `domain_entity_type_id` | 一个对象属性绑定一个直接定义域实体类型 |
| Range | `range_entity_type_id` | 一个对象属性绑定一个直接值域实体类型 |
| TypeofTerms | 常量 `owl:ObjectProperty` | 对象属性模块内恒定，不冗余落库 |

### 2.2 对象属性语义特性

对象属性相比数据属性多出4种 OWL 语义特性标记。这些标记在 Schema 层声明，由后续公理校验模块（M2）在实例层执行：

| 特性 | OWL表达 | 平台字段 | 国标/语义含义 |
|------|---------|----------|---------------|
| 功能性 | `owl:FunctionalProperty` | `is_functional` | 每个主体最多有一个客体。如 `issuedBy`（每个标准只由一个机构发布） |
| 反功能性 | `owl:InverseFunctionalProperty` | `is_inverse_functional` | 每个客体最多有一个主体。如 `includesStandard` 的逆属性语义 |
| 传递性 | `owl:TransitiveProperty` | `is_transitive` | aRb ∧ bRc → aRc。如 `hasPart`（标准A有部分标准B，标准B有部分标准C，则A有部分C） |
| 对称性 | `owl:SymmetricProperty` | `is_symmetric` | aRb → bRa。如潜在的行业扩展属性 |
| 逆属性 | `owl:inverseOf` | `inverse_of_id` | 两个属性互为逆。如 `replaces`↔`isReplacedBy`（代替↔被代替） |

**特性标记规则（OWL语义约束）：**

1. `owl:FunctionalProperty` 和 `owl:InverseFunctionalProperty` 可同时为真（即 `owl:FunctionalProperty` + `owl:InverseFunctionalProperty` = 一一对应）。
2. `owl:SymmetricProperty` 的逆属性是其自身；声明对称性时 `inverse_of_id` 应为自身或留空。
3. `owl:TransitiveProperty` 不能同时为 `owl:FunctionalProperty`（OWL DL约束：传递且功能的属性会推出全局等价，语义矛盾）。Service层须拒绝此组合。
4. 逆属性关系是对称的：A.inverseOf = B 蕴含 B.inverseOf = A。Service层修改一方时须同步另一方。

### 2.3 对象属性继承/适用性

与数据属性相同，对象属性本身只有一个直接定义域。若实体类型B是A的子类，则定义域为A的对象属性对B实例适用。平台按实体类型DAG向上查询祖先类型实现该规则：

1. 返回当前类型直接适用的对象属性和所有祖先类型适用的对象属性；
2. 多继承路径命中同一对象属性时按属性ID去重；
3. 返回 `inherited`、`inheritanceDistance`、`declaredDomainEntityTypeId`；
4. 直接属性优先，其次继承距离升序，再按 `sort_order/id` 排序；
5. DAG遍历沿用实体类型模块的显式队列、访问集合和100层上限。

> 对称地，值域侧也有适用性：若对象属性的值域为类型A，则A的子类实例均可作为值。本期 `by-range` 查询接口返回直接值域匹配，值域侧继承适用性由实例模块在运行时校验，不在Schema层查询展开。

### 2.4 定义域/值域绑定策略

表1中部分对象属性的定义域或值域是复合类型（如"标准实体/层次""信息单元/特性"）。平台采用**绑定最贴近的公共父类**策略，子类通过继承获得适用性。这与数据属性 V7 的做法一致（如 C.28 `uniqueIdentifier` 定义域绑定 `InformationUnit(940048)`，`Clause` 通过继承获得）。

复合类型绑定决策表：

| 表1复合定义域/值域 | 绑定实体类型 | 理由 |
|--------------------|-------------|------|
| 标准实体/层次 | StructuralElement(940038) | 层次的公共父类，标准实体通过另一条关系或独立属性覆盖 |
| 机构/个人 | Stakeholder(940011) | 相关方抽象类，机构和个人均继承自Stakeholder |
| 信息单元/特性 | InformationUnit(940048) | 信息单元为公共父类；若需精确到特性侧，由扩展属性补充 |
| 标准实体/要素 | ContentElement(940027) | 要素为公共父类 |
| 标准实体/条款 | Clause(940040) | 条款为公共父类 |
| 信息单元/条款 | Clause(940040) | 条款本身是信息单元子类 |

> 对于表1定义域含"标准实体"且另一类的情况（如 hasClause 定义域为"要素/层次"），按主要语义绑定到最贴近的父类。精确到单一类型的属性（如 `issuedBy` 定义域仅为"标准实体"）直接绑定 Standard(940001)。

## 3. 数据模型

> 对齐现有实现：PostgreSQL、`ont_` 前缀、MyBatis-Plus `ASSIGN_ID`、`char(1)`布尔、审计字段、逻辑删除、Flyway增量迁移。

### 3.1 主表 `ont_object_property`

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `id` | bigint | 是 | MyBatis-Plus `ASSIGN_ID`；核心种子使用固定ID |
| `iri` | varchar(512) | 是 | 平台内部全局唯一IRI |
| `iri_local_name` | varchar(128) | 是 | 实际拼接IRI的本地名；核心种子等于 `name` |
| `name` | varchar(128) | 是 | 附录A.2 Name；核心值保持国标英文原名 |
| `definition` | varchar(512) | 否 | 定义（表1语义说明） |
| `domain_entity_type_id` | bigint | 是 | 直接定义域，引用 `ont_entity_type.id` |
| `range_entity_type_id` | bigint | 是 | 直接值域，引用 `ont_entity_type.id` |
| `semantic_note` | varchar(512) | 否 | 语义说明（表1备注，补充定义） |
| `inverse_of_id` | bigint | 否 | 逆属性引用，指向 `ont_object_property.id`；互为逆属性 |
| `is_functional` | char(1) | 是 | 功能性属性，`1`=owl:FunctionalProperty |
| `is_inverse_functional` | char(1) | 是 | 反功能性属性，`1`=owl:InverseFunctionalProperty |
| `is_transitive` | char(1) | 是 | 传递性属性，`1`=owl:TransitiveProperty |
| `is_symmetric` | char(1) | 是 | 对称性属性，`1`=owl:SymmetricProperty |
| `source_type` | varchar(32) | 是 | `GB_TABLE1/EXTENSION` |
| `source_reference` | varchar(64) | 否 | 如 `表1-1`、`表1-6` |
| `is_builtin` | char(1) | 是 | 表1属性固定为1，用户扩展为0 |
| `ontology_id` | bigint | 是 | 引用 `ont_ontology_project.id`，首期默认935001 |
| `namespace_id` | bigint | 是 | 引用 `ont_namespace.id` |
| `sort_order` | integer | 是 | 排序 |
| `remarks` | varchar(255) | 否 | 平台治理备注 |
| 审计/逻辑删除字段 | — | — | `create_by/create_time/update_by/update_time/del_flag` |

核心约束：

1. `iri` 在有效数据中全局唯一。
2. `(ontology_id, namespace_id, iri_local_name)` 在有效数据中唯一。
3. `(ontology_id, namespace_id, name)` 在有效数据中唯一（对象属性不绑定定义域+name联合唯一，因为对象属性的name在同一命名空间内全局唯一即可，不像数据属性可能在不同定义域下重名）。
4. `iri = namespace.uri + iri_local_name`，后端为权威生成方。
5. `domain_entity_type_id`、`range_entity_type_id`、`ontology_id`、`namespace_id` 均使用 `ON DELETE RESTRICT`。
6. `inverse_of_id` 使用 `ON DELETE SET NULL`（删除一方逆属性时不级联删除另一方，仅解除引用）。
7. 核心/表1属性的来源、IRI、名称、定义域、值域、语义特性不可通过普通管理接口修改；仅允许更新 `sort_order/remarks`。
8. OWL DL一致性：`is_transitive='1'` 时 `is_functional` 必须为 `'0'`。

### 3.2 多语言标签表 `ont_object_property_label`

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `object_property_id` | bigint | 是 | 外键，`ON DELETE CASCADE` |
| `locale` | varchar(16) | 是 | 如 `zh`、`en` |
| `label` | varchar(128) | 是 | 标签文本 |

主键：`(object_property_id, locale)`。首期DTO仍维护一个必填中文标签；多语言独立编辑后续扩展。

### 3.3 与数据属性表结构的差异说明

对象属性不需要 `ont_object_property_enum`（对象属性值域是实体类型引用，无枚举），也不需要 `standard_iri`/`preferred_alias`（表1无重名、无别名）。但增加了 `range_entity_type_id`（数据属性无值域实体类型）、`semantic_note`、`inverse_of_id` 和4个语义特性布尔标记。

### 4.3 逆属性预置

表1第2号 `replaces(代替)` 有逆属性语义（被代替），第34号 `includesStandard` 是第33号 `hasDevelopmentStage` 的逆属性方向。为保持表1 34项的精确口径，核心预置**只包含表1的34项**，逆属性作为扩展属性补充：

| ID | name | 中文标签 | 定义域 | 值域 | inverse_of_id | source_type |
|----|------|----------|--------|------|---------------|-------------|
| 960035 | isReplacedBy | 被代替 | Standard(940001) | Standard(940001) | 960002 | EXTENSION（平台补充逆属性） |

> 逆属性 `isReplacedBy` 不计入"表1 34项"口径，标记为 `source_type=EXTENSION`、`is_builtin='1'`（平台受保护补充，非用户扩展）。`includesStandard(960034)` 与 `hasDevelopmentStage(960033)` 的逆关系通过 `inverse_of_id` 双向指向实现，不额外增加记录。

### 4.4 定义文本要求

所有34条均保存 `source_reference`（如 `表1-1`）和基于国标表1语义说明的 `definition` 文本。迁移实现中的定义文本以国标表1内容为依据，不能用空串或仅复制中文标签代替定义。

## 5. 服务规则

### 5.1 新增扩展对象属性

1. `namespaceId/name/label/domainEntityTypeId/rangeEntityTypeId` 必填；`ontologyId`缺省为935001。
2. 普通接口只能向 `is_builtin='0'` 的扩展命名空间写入。
3. `name` 使用扩展命名规范 `^[a-z][a-zA-Z0-9]*$`（首字母小写）。
4. `iriLocalName`可省略，省略时等于`name`；格式使用 `^[a-zA-Z][a-zA-Z0-9_]*$`。
5. 后端生成 `iri=namespace.uri+iriLocalName`；若请求携带 `iri`，必须完全一致。
6. IRI、IRI本地名作用域、命名空间内Name冲突均在事务开始前校验。
7. 定义域和值域必须存在、未删除且与属性属于同一 `ontologyId`。
8. 新增数据固定 `source_type=EXTENSION/is_builtin='0'`。
9. 主表、中文标签在同一事务保存。
10. 语义特性组合校验（见§5.2）。
11. 逆属性若指定，校验目标存在且双向维护（见§5.4）。

### 5.2 语义特性组合校验

| 条件 | 规则 |
|------|------|
| `is_transitive='1'` 且 `is_functional='1'` | 拒绝：OWL DL禁止传递且功能的属性（语义矛盾） |
| `is_symmetric='1'` 且 `is_functional='1'` | 警告但不阻断：对称且功能意味着一一对应，通常用 `is_inverse_functional` 表达 |
| `is_symmetric='1'` | `inverse_of_id` 应为自身或留空（对称属性的逆是其自身） |
| `is_functional='1'` 且 `is_inverse_functional='1'` | 允许：表示一一对应关系 |
| 定义域=值域 且 `is_symmetric='1'` | 合理组合（如行业扩展的"相关"关系） |
| 定义域≠值域 且 `is_symmetric='1'` | 拒绝：对称属性的定义域和值域必须相同 |

### 5.3 修改

1. 不存在则返回"对象属性不存在"。
2. 内置属性仅允许修改 `sortOrder/remarks`；其他字段即使请求传入也不得静默忽略，应返回"内置对象属性语义字段不可修改"。
3. 扩展属性可修改标签、定义、Name、IRI本地名、定义域、值域、语义特性标记和逆属性；`ontologyId/sourceType/isBuiltin`不可修改。
4. 修改Name不自动修改IRI；修改IRI本地名必须显式提交并重新校验。
5. 后续公理/实例模块上线后，只要IRI已被引用，就禁止修改 `namespaceId/iriLocalName/iri`。
6. 修改定义域/值域时重新校验实体类型存在性和同工程约束。
7. 修改语义特性时重新执行§5.2组合校验。

### 5.4 逆属性双向维护

逆属性关系是对称的。当扩展属性的 `inverseOfId` 被设置或修改时：

1. 校验目标对象属性存在、同工程、同命名空间；
2. 将目标对象属性的 `inverseOfId` 设置为当前属性ID（双向指向）；
3. 若当前属性此前有其他逆属性指向，先将旧逆属性的 `inverseOfId` 置空；
4. 取消逆属性（设为null）时，同步将原目标的 `inverseOfId` 置空；
5. 以上操作与主表修改在同一事务。

内置属性的逆属性关系由 Flyway 种子直接建立（如 `replaces(960002).inverse_of_id = 960035`，`isReplacedBy(960035).inverse_of_id = 960002`），不经过普通修改接口。

### 5.5 删除

1. 内置属性禁止删除。
2. 删除扩展属性前检查公理目标、实例关系、SHACL Shape等引用；尚未建表的检查以扩展点保留。
3. 删除前先解除逆属性关系：将 `inverse_of_id` 指向本属性的其他记录的 `inverse_of_id` 置空。
4. 有引用返回可理解的引用类型和数量。
5. 无引用时物理删除标签子表，再逻辑删除主表。

### 5.6 查询

**按定义域查询（含继承）** `GET /ontology/object-properties/by-domain/{entityTypeId}`：

1. 校验实体类型存在；
2. BFS向上收集自身及全部祖先ID和最短距离；
3. 一次查询所有定义域上的有效对象属性；
4. 以属性ID去重并组装中文标签、定义域名称、值域名称；
5. 返回 `OntApplicableObjectPropertyVO`，直接属性 `inherited=false/distance=0`；
6. 多继承下同一属性只返回一次，保留最短继承距离；
7. 结果不分页。

**按值域查询** `GET /ontology/object-properties/by-range/{entityTypeId}`：

1. 校验实体类型存在；
2. 返回值域直接等于该类型的有效对象属性（不向上展开继承，值域侧继承由实例模块校验）；
3. 结果不分页。

### 5.7 前置模块联动保护

V8实现必须同步修改：

| 服务 | 联动规则 |
|------|----------|
| `OntEntityTypeServiceImpl.removeEntityType` | 若存在有效对象属性直接引用该类型为定义域或值域，拒绝删除并提示数量 |

CREATE INDEX idx_ont_object_property_range
  ON ont_object_property (range_entity_type_id) WHERE del_flag = '0';

CREATE INDEX idx_ont_object_property_inverse
  ON ont_object_property (inverse_of_id) WHERE inverse_of_id IS NOT NULL AND del_flag = '0';

  ON ont_object_property (ontology_id) WHERE del_flag = '0';
