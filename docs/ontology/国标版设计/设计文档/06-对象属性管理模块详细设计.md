# 对象属性管理模块详细设计

> 对应 PRD：§2.6、§3.3、§4.4、§5、§6.2.1、§7.1、§8.2、§14.2
>
> 直接依据：GB/T 48000.3—2026 第7.3条、表1（34个核心对象属性）、第8.2条关系规则、附录A.2
>
> 前置模块：01-模块化架构、02-单位字典、03-命名空间与IRI、04-实体类型、05-数据属性（均已实现）
>
> 评审优化日期：2026-07-10

## 1. 评审结论

原设计的模块边界、Flyway V8、`ont_` 表前缀、后端包位置、前端左树右表布局和内置保护方向可以复用，但存在会造成国标关系语义丢失、错误生成 OWL 公理或使后续实例编辑器误判合法关系的阻断问题。本次评审已直接修订，关键结论如下。

| 级别 | 原设计问题 | 优化结论 |
|------|------------|----------|
| P0 | 用单个 `domain_entity_type_id/range_entity_type_id` 表达表1的“标准实体/层次”“信息单元/特性”等并集定义域，并以“选择主要类型/公共父类”处理，实际会静默丢失另一分支；多条 `rdfs:domain` 又会被 OWL/RDFS 解释为交集而非并集 | 主表不再保存单值定义域/值域，新增定义域、值域关联表；多项声明按“或”解释，后续序列化必须生成 `owl:unionOf`，禁止输出多个并列 `rdfs:domain/rdfs:range` 三元组 |
| P0 | 将 `hasPart` 标记为传递、`hasDevelopmentStage` 标记为功能性、`includesStandard` 标记为反功能性，但国标表1及第8.2条没有这些明确声明 | 核心种子只固化有直接依据的语义：`issuedBy` 功能性、两组明确逆属性；其余特性默认0，不凭名称或直觉推断 |
| P0 | 将“传递+功能”描述成语义矛盾，并遗漏“传递+反功能”；同时错误地把“对称属性定义域必须等于值域”作为 OWL DL 硬约束 | 按 OWL 2 DL 的简单对象属性限制，传递属性不得再声明功能性或反功能性；对称属性不要求定义域和值域相同，仅在建模上提示潜在类型交叉推断，不做错误阻断 |
| P0 | 把 `isReplacedBy` 标记为 `EXTENSION` 却放入核心命名空间，违反“扩展必须使用新命名空间”的治理原则 | 增加 `GB_TABLE1_DERIVED` 来源类型，表示由表1第2项语义说明直接派生的受保护属性；仍不计入“表1 34项”统计口径 |
| P1 | `by-range` 只做直接值域匹配，导致 `issuedBy` 的值域为 `Organization` 时，其子类 `PublishingOrganization` 等不能被识别为合法客体类型 | 定义域侧和值域侧均按实体类型 DAG 向上匹配祖先；两个接口都返回直接/继承、最短距离和命中的声明类型 |
| P1 | 逆属性限制为同命名空间，缺少自引用、唯一配对、已配对冲突和并发维护规则 | 逆属性只要求同本体工程，不强制同命名空间；普通接口只允许两个扩展属性配对，禁止自引用和抢占已有配对，并在事务内加锁维护双向指针 |
| P1 | 对象属性名称只在命名空间内唯一，允许扩展命名空间重新使用核心名称，不符合国标第9章“名称不应与已有名称相同” | `name` 在同一本体工程内全局唯一；IRI本地名仍只在命名空间内唯一 |
| P1 | 03设计要求逐步补齐全局IRI校验，但当前 `OntIriController` 仍只检查命名空间URI，实体类型和数据属性写入也未与对象属性做跨表冲突校验 | V8同步把IRI校验范围扩展到命名空间、实体类型、数据属性、对象属性；对象属性写入必须检查已有实体/数据属性，数据属性和实体类型后续写入也必须检查对象属性 |
| P1 | DTO、VO、前端表单和迁移断言都以单定义域/单值域及错误核心特性为前提 | 全部改为定义域/值域列表；迁移按34项逐号断言声明集合、来源和明确语义，不再断言未经国标确认的特性 |

### 1.1 权威口径澄清

1. 表1第2项 `replaces` 的语义说明明确给出逆属性“被代替（`isReplacedBy`）”，可作为受保护派生属性预置。
2. 表1第34项 `includesStandard` 明确说明其为第33项 `hasDevelopmentStage` 的逆向属性，两项应建立双向 `inverse_of_id`。
3. 表1第16项 `hasSubClause` 仅描述“条包含子条”，不是逆属性声明；PRD §4.4.3 中“第16号为逆属性场景”的备注不作为实现依据。
4. 第8.2条仅明确举例“每个标准只能由一个机构发布”，因此核心种子将 `issuedBy` 标为功能性；`hasPart` 的传递性、`hasDevelopmentStage` 的功能性及 `includesStandard` 的反功能性均不从名称推断。
5. 对象属性特性字段表示**显式声明**。由逆属性等公理可推导出的特性不重复写回数据库，例如 A 为功能性且 B 为 A 的逆属性时，B 的反功能性可由推理得到，但 `B.is_inverse_functional` 不因此自动置1。

### 1.2 本期边界

本模块管理的是 **Schema 层对象属性定义**，不在关系库中保存实体实例之间的对象属性断言。本期包含：

1. 对象属性定义 CRUD、分页/列表/详情查询、来源标识和内置保护；
2. 附录A.2七项元数据映射；
3. 表1全部34项核心对象属性和1项表1语义派生逆属性预置；
4. 单一或并集定义域、单一或并集值域配置；
5. 定义域和值域基于实体类型 DAG 的继承适用性查询；
6. 逆属性双向维护；
7. 功能性、反功能性、传递性、对称性显式标记；
8. 与实体类型、命名空间的引用保护联动；
9. 为后续公理、实例、校验、序列化模块提供稳定契约。

本期不包含：实例关系持久化、SHACL执行、RDF/OWL实际导出、完整本体一致性推理、属性链、非对称性、自反性、非自反性。这些能力由后续 M2～M4 模块实现。

### 1.3 与数据属性模块的异同

| 维度 | 数据属性（V7） | 对象属性（V8） |
|------|----------------|----------------|
| 语义 | 描述实体内在特征（`owl:DatatypeProperty`） | 描述实体间关系（`owl:ObjectProperty`） |
| 值域 | 基础类型、枚举、字典、单位引用 | 一个或多个实体类型，多个时为并集 |
| 定义域 | 首期单一实体类型 | 一个或多个实体类型，多个时为并集 |
| 特殊标记 | 唯一性、值模式等 | 逆属性、功能性、反功能性、传递性、对称性 |
| 子表 | 标签表、枚举值表 | 标签表、定义域表、值域表 |
| 适用性 | 按单一定义域向上匹配祖先 | 对每个定义域/值域声明分别向上匹配祖先并去重 |
| 预置规模 | 56项受保护属性 | 34项表1属性 + 1项表1派生逆属性 |
| IRI消歧 | 3个 `constraintType` 需固定消歧 | 表1及派生逆属性名称均唯一，无双轨IRI需求 |

## 2. 领域模型与本体语义

### 2.1 附录A.2七项元数据映射

| 国标描述项 | 平台字段/结构 | 说明 |
|------------|---------------|------|
| IRI | `ont_object_property.iri` | 平台内部全局唯一IRI |
| Name | `ont_object_property.name` | 核心值保持表1英文名，首字母小写 |
| Label | `ont_object_property_label` | 首期预置 `zh`，结构支持多语言 |
| Definition | `ont_object_property.definition` | 核心种子保存表1“语义说明”；不再另设内容重复的 `semantic_note` |
| Domain | `ont_object_property_domain` | 至少1项；多项表示并集 |
| Range | `ont_object_property_range` | 至少1项；多项表示并集 |
| TypeofTerms | 常量 `owl:ObjectProperty` | 模块内恒定，不冗余落库 |

### 2.2 多定义域/多值域的语义

表1中的斜杠表示“或”，例如：

- `hasStructuralElement` 定义域为 `Standard` **或** `StructuralElement`；
- `imposesConstraint` 定义域为 `InformationUnit` **或** `Property`；
- `draftedBy` 值域为 `Organization` **或** `Individual`。

平台将每一项保存为独立关联记录，并按并集解释。后续 RDF/OWL 序列化必须遵守：

```turtle
# 单项定义域：直接输出
:issuedBy rdfs:domain :Standard .

# 多项定义域：输出匿名并集类表达式
:hasStructuralElement rdfs:domain [
  a owl:Class ;
  owl:unionOf ( :Standard :StructuralElement )
] .
```

不得把多个候选类型输出成多条并列 `rdfs:domain`。在 RDFS/OWL 中，多条 domain/range 公理会形成交集约束，含义不是“任一类型均可使用”。

### 2.3 对象属性语义特性

| 特性 | OWL表达 | 平台字段 | 含义 |
|------|---------|----------|------|
| 功能性 | `owl:FunctionalProperty` | `is_functional` | 每个主体最多关联一个客体 |
| 反功能性 | `owl:InverseFunctionalProperty` | `is_inverse_functional` | 每个客体最多对应一个主体 |
| 传递性 | `owl:TransitiveProperty` | `is_transitive` | aRb 且 bRc 可推出 aRc |
| 对称性 | `owl:SymmetricProperty` | `is_symmetric` | aRb 可推出 bRa |
| 逆属性 | `owl:inverseOf` | `inverse_of_id` | A、B 表示方向相反的同一关系 |

显式特性校验规则：

1. `is_transitive='1'` 时，`is_functional` 和 `is_inverse_functional` 均必须为 `'0'`。原因是 OWL 2 DL 中功能性/反功能性声明要求简单对象属性，而传递属性不是简单对象属性。
2. 功能性和反功能性可以同时为真，表示显式声明的一一关系。
3. 对称性不要求定义域和值域集合相同；若二者不同，可能通过对称推理使关系两端同时获得额外类型，只提示建模影响，不按 OWL 语法错误阻断。
4. 对称属性不需要把 `inverse_of_id` 指向自身。平台禁止自引用，序列化直接输出 `owl:SymmetricProperty`。
5. 逆属性双方的定义域/值域通常应互换，但 OWL 允许更宽或更窄的显式声明。首期详情页显示兼容性提示，不强制要求集合完全相等；核心种子必须精确互换。

### 2.4 定义域/值域继承适用性

若实体类型 B 是 A 的子类，则：

- 定义域包含 A 的对象属性可用于 B 的实例作为主体；
- 值域包含 A 的对象属性允许 B 的实例作为客体。

查询算法：

1. 从目标实体类型出发，沿 `ont_entity_type_hierarchy` 向上 BFS 收集自身和全部祖先；
2. 记录每个祖先的最短距离，沿用实体类型模块的显式队列、访问集合和100层上限；
3. 与定义域或值域关联表一次性联查；
4. 同一属性因多声明或多继承路径命中时按属性ID去重，保留最短距离；
5. 若任一声明直接命中目标类型，则 `inherited=false/inheritanceDistance=0`；
6. 排序为直接优先、距离升序、`sort_order`升序、ID升序。

## 3. 数据模型

> 对齐现有实现：PostgreSQL、`ont_` 前缀、MyBatis-Plus `ASSIGN_ID`、`char(1)`布尔、`create_time/update_time`审计字段、逻辑删除、Flyway增量迁移。

### 3.1 主表 `ont_object_property`

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `id` | bigint | 是 | MyBatis-Plus `ASSIGN_ID`；核心种子使用固定ID |
| `iri` | varchar(512) | 是 | 平台内部全局唯一IRI |
| `iri_local_name` | varchar(128) | 是 | 与命名空间URI拼接的本地名 |
| `name` | varchar(128) | 是 | 附录A.2 Name；核心保持表1英文名 |
| `definition` | varchar(512) | 否 | 核心保存表1语义说明；扩展属性由用户维护 |
| `inverse_of_id` | bigint | 否 | 逆属性ID，双向指向；禁止指向自身 |
| `is_functional` | char(1) | 是 | `1`表示显式声明功能性 |
| `is_inverse_functional` | char(1) | 是 | `1`表示显式声明反功能性 |
| `is_transitive` | char(1) | 是 | `1`表示显式声明传递性 |
| `is_symmetric` | char(1) | 是 | `1`表示显式声明对称性 |
| `source_type` | varchar(32) | 是 | `GB_TABLE1/GB_TABLE1_DERIVED/EXTENSION` |
| `source_reference` | varchar(64) | 否 | 如 `表1-1`、`表1-2语义说明` |
| `is_builtin` | char(1) | 是 | 国标及派生预置为1，用户扩展为0 |
| `ontology_id` | bigint | 是 | 引用 `ont_ontology_project.id`，首期默认935001 |
| `namespace_id` | bigint | 是 | 引用 `ont_namespace.id` |
| `sort_order` | integer | 是 | 排序，默认0 |
| `remarks` | varchar(255) | 否 | 平台治理备注 |
| 审计/逻辑删除字段 | — | — | `create_by/create_time/update_by/update_time/del_flag` |

主表约束：

1. `iri` 在对象属性有效数据中由部分唯一索引保证唯一；Service还必须按03设计跨 `ont_namespace/ont_entity_type/ont_data_property/ont_object_property` 校验平台全局IRI冲突。
2. `(ontology_id, namespace_id, iri_local_name)` 在有效数据中唯一。
3. `(ontology_id, name)` 在有效数据中唯一，防止扩展属性复用核心或其他扩展属性名称。
4. `iri = namespace.uri + iri_local_name`，后端为权威生成方。
5. `ontology_id/namespace_id` 使用 `ON DELETE RESTRICT`；`inverse_of_id` 使用 `ON DELETE SET NULL`。
6. `inverse_of_id <> id`。
7. 有效数据中一个属性最多被一个属性声明为逆属性，使用部分唯一索引约束 `inverse_of_id`。
8. `source_type=EXTENSION` 必须 `is_builtin='0'`；另外两种来源必须 `is_builtin='1'`。
9. `is_transitive='1'` 时 `is_functional='0'` 且 `is_inverse_functional='0'`。
10. 内置属性普通接口仅允许修改 `sort_order/remarks`。

### 3.2 定义域表 `ont_object_property_domain`

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `object_property_id` | bigint | 是 | 引用主表，`ON DELETE CASCADE` |
| `entity_type_id` | bigint | 是 | 引用 `ont_entity_type.id`，`ON DELETE RESTRICT` |
| `sort_order` | integer | 是 | 并集成员展示/序列化顺序，默认0 |

主键：`(object_property_id, entity_type_id)`。

### 3.3 值域表 `ont_object_property_range`

字段和约束与定义域表一致，主键为 `(object_property_id, entity_type_id)`。

### 3.4 多语言标签表 `ont_object_property_label`

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `object_property_id` | bigint | 是 | 引用主表，`ON DELETE CASCADE` |
| `locale` | varchar(16) | 是 | 如 `zh`、`en` |
| `label` | varchar(128) | 是 | 标签文本 |

主键：`(object_property_id, locale)`。首期 DTO 维护一个必填中文标签，后续可增加独立多语言编辑入口。

### 3.5 跨表完整性责任

“每个有效对象属性至少一个定义域、至少一个值域”无法用主表普通 CHECK 约束表达，由以下三层保证：

1. DTO 使用非空列表校验，列表元素非空且去重；
2. Service 在同一事务内保存主表、定义域、值域、标签，任一步失败整体回滚；
3. V8 迁移末尾断言所有35条预置属性均至少有一个定义域和值域。

更新扩展属性时采用“校验完整请求 → 物理删除旧关联 → 批量插入新关联”的事务替换方式，不允许产生中间提交状态。

3. 不允许用空串或仅复制中文标签代替定义。
4. 迁移断言至少校验定义非空；逐字内容由迁移测试按受控基准表校验，避免只验数量。

## 5. 服务规则

### 5.1 新增扩展对象属性

1. `namespaceId/name/label/domainEntityTypeIds/rangeEntityTypeIds` 必填；`ontologyId`缺省为935001。
2. 定义域和值域列表各至少1项，元素不得为空、不得重复。
3. 普通接口只能向 `is_builtin='0'` 的扩展命名空间写入。
4. `name` 使用 `^[a-z][a-zA-Z0-9]*$`；同本体工程内不得与任何有效对象属性重名。
5. `iriLocalName`可省略，省略时等于 `name`；格式使用 `^[a-zA-Z][a-zA-Z0-9_]*$`。
6. 后端生成 `iri=namespace.uri+iriLocalName`；若请求携带 `iri`，必须与生成值完全一致，并调用统一IRI冲突检查，拒绝与命名空间URI、实体类型、数据属性或其他对象属性IRI重复。
7. 所有定义域、值域实体类型必须存在、未删除且与对象属性属于同一 `ontologyId`。
8. 新增数据固定 `source_type=EXTENSION/is_builtin='0'`。
9. 四个语义特性缺省为0，按§5.2校验。
10. 主表、定义域、值域、中文标签和逆属性维护处于同一事务。

### 5.2 语义特性组合校验

| 条件 | 处理 |
|------|------|
| 传递=1 且 功能=1 | 拒绝：违反 OWL 2 DL 简单对象属性限制 |
| 传递=1 且 反功能=1 | 拒绝：违反 OWL 2 DL 简单对象属性限制 |
| 功能=1 且 反功能=1 | 允许：显式声明一一关系 |
| 对称=1 且定义域/值域集合不同 | 允许；前端和详情VO给出类型交叉推断提示 |
| 对称=1 且配置 `inverseOfId` | 允许但提示冗余；禁止 `inverseOfId` 指向自身 |
| 任一标记不是0/1 | 拒绝 |

数据库 CHECK 覆盖可静态判断的0/1取值和传递组合；提示类规则由 Service/前端语义工具处理。

### 5.3 逆属性双向维护

普通管理接口只允许两个 `is_builtin='0'` 的扩展属性建立或调整逆属性关系，规则如下：

1. 目标属性必须存在、有效、与当前属性属于同一本体工程；不要求同命名空间。
2. 禁止指向自身。
3. 当前属性和目标属性均不得为内置属性，防止通过扩展编辑间接修改核心定义。
4. 一个属性最多有一个逆属性；目标已与第三方配对时拒绝“抢占”，必须先显式解除原关系。
5. 设置 A.inverseOf=B 时，同步设置 B.inverseOf=A；取消 A 的逆属性时，仅在 B 当前确实指向 A 时清空 B。
6. 修改配对时对涉及的属性ID按升序执行行锁，避免并发形成 A↔B、A↔C 等不一致状态。
7. 操作与主表、定义域、值域、标签更新处于同一事务。
8. 核心两组逆属性只由 Flyway 建立，不经过普通接口。

### 5.4 修改

1. 不存在则返回“对象属性不存在”。
2. 后端以数据库旧记录的 `is_builtin` 决定更新路径，不信任请求中的来源字段。
3. 内置属性仅允许修改 `sortOrder/remarks`；请求携带其他变化时明确失败，不得静默忽略。
4. 扩展属性可修改标签、定义、Name、IRI本地名、命名空间、定义域集合、值域集合、语义特性和逆属性；`ontologyId/sourceType/isBuiltin`不可修改。
5. 修改Name不自动修改IRI；修改命名空间或IRI本地名必须显式提交并重新校验IRI。
6. 后续公理/实例模块上线后，只要IRI已被引用，就禁止修改 `namespaceId/iriLocalName/iri`，并返回影响类型和数量。
7. 定义域/值域更新使用事务整体替换，执行与新增相同的存在性、同工程、非空和去重校验。
8. 修改逆属性和语义特性时重新执行§5.2、§5.3。

### 5.5 删除

1. 内置属性禁止删除。
2. 删除扩展属性前检查公理目标、实例关系、SHACL Shape等引用；相关表尚未实现时保留显式扩展接口，不得伪造“已检查”。
3. 删除前锁定并解除双向逆属性关系。
4. 有引用时返回引用类型和数量。
5. 无引用时物理删除标签、定义域、值域子表，再逻辑删除主表。
6. 整个删除流程处于同一事务。

### 5.6 查询

**按定义域查询** `GET /ontology/object-properties/by-domain/{entityTypeId}`：

1. 校验实体类型存在且有效；不存在时返回明确失败，不以空列表掩盖错误。
2. BFS收集自身和祖先最短距离。
3. 联查 `ont_object_property_domain` 和有效主表。
4. 同一属性多次命中时保留最短距离；摘要中仍返回完整定义域和值域集合。
5. 返回 `OntApplicableObjectPropertyVO`，包含 `matchedDomainEntityTypeId`、直接/继承和距离。
6. 结果不分页。

**按值域查询** `GET /ontology/object-properties/by-range/{entityTypeId}`：

1. 把路径参数解释为“候选客体的实体类型”。
2. 同样向上收集祖先，使声明值域为父类的属性可接受子类客体。
3. 返回 `OntApplicableObjectPropertyByRangeVO`，包含 `matchedRangeEntityTypeId`、直接/继承和距离。
4. 结果不分页。

**管理分页/列表查询**：

- `domainEntityTypeId/rangeEntityTypeId` 表示直接声明成员过滤，不展开继承；
- 分页先确定主表ID集合，再批量查询标签、定义域和值域，禁止逐行N+1；
- `list` 接口用于逆属性下拉等轻量引用场景，可按 `ontologyId/namespaceId/isBuiltin` 过滤。

### 5.7 前置模块联动保护

V8实现必须同步修改：

| 服务 | 联动规则 |
|------|----------|
| `OntEntityTypeServiceImpl.removeEntityType` | 若定义域表或值域表存在有效对象属性引用，拒绝删除并分别提示数量 |
| `OntNamespaceServiceImpl.updateNamespace` | 命名空间已被对象属性引用时禁止修改URI |
| `OntNamespaceServiceImpl.removeNamespace` | 增加对象属性引用检查 |
| `OntIriController.validate` | 从仅校验命名空间URI扩展为校验命名空间、实体类型、数据属性和对象属性IRI |
| `OntEntityTypeServiceImpl` / `OntDataPropertyServiceImpl` | 新增或修改IRI时增加对象属性IRI冲突检查，保证V8上线后的所有Schema写入口口径一致 |

跨表全局IRI唯一无法由单个普通唯一索引完成，所有Schema写接口必须复用同一校验组件，避免Controller与各Service各写一套不一致逻辑。实体类型引用检查应联查对象属性主表 `del_flag='0'`，不能只统计已逻辑删除属性残留的子表记录。

### 7.4 事务与并发

1. `save/update/remove` 使用 `@Transactional(rollbackFor = Exception.class)`。
2. 逆属性建立、解除或改配时，使用自定义 `SELECT ... FOR UPDATE` 按ID升序锁定当前、旧目标、新目标。
3. 数据库部分唯一索引是最后防线；捕获唯一冲突后转换为“目标对象属性已存在逆属性关系”的业务提示。
4. 更新关联表使用批量插入，不在循环中逐条提交。
5. 查询标签、定义域、值域和实体类型信息均按ID集合批量查询。
6. IRI冲突判断复用统一组件，至少覆盖命名空间URI、实体类型、数据属性和对象属性；排除当前更新记录。

### 7.5 全局IRI校验组件

`OntIriUniquenessService` 接收完整IRI、当前元素类型和可选排除ID，返回是否可用及冲突元素类型。`OntIriController`、实体类型Service、数据属性Service和对象属性Service统一调用该组件。

校验只统计有效Schema记录；更新时仅排除当前表的当前记录，不排除其他表同IRI记录。后续实例模块上线后，在该组件中继续增加实例IRI检查，不改变现有调用方。

- 语义特性以标签展示：功能(F)、反功能(IF)、传递(T)、对称(S)、逆属性(↔)。

### 9.2 新增/编辑表单

分组：

1. 基本信息：命名空间、Name、IRI本地名、IRI预览、中文标签、定义；
2. 定义域/值域：定义域实体类型多选、值域实体类型多选；
3. 语义特性：功能性、反功能性、传递性、对称性、逆属性选择器；
4. 治理：排序、备注、来源只读信息。

关键联动：

- 新增只能选择扩展命名空间；
- 新增时Name变化同步建议IRI本地名，用户手工修改后停止同步；编辑Name不自动修改IRI；
- 定义域和值域使用支持多选的实体类型树选择器，至少选择一项；
- 选择逆属性时列出同本体工程、未配对的扩展对象属性；允许跨扩展命名空间；
- 勾选传递性时禁用并清空功能性、反功能性；勾选功能性或反功能性时禁用传递性；
- 对称性与不同定义域/值域不是提交错误，但显示“可能推导关系两端属于额外类型”的提示；
- 对称属性选择自身作为逆属性时前端直接阻止；
- 内置记录仅排序、备注可编辑，其他字段全部禁用；后端仍独立校验。

## 11. 与后续模块的稳定契约

| 后续模块 | 使用字段/接口 | 契约 |
|----------|---------------|------|
| 公理规则 | IRI、显式特性、逆属性 | 只把数据库标记当作显式公理；不得把命名直觉转为特性；可计算逆属性带来的派生特性 |
| 实例建模 | `by-domain`、`by-range`、定义域/值域集合 | 主体或客体类型是任一声明类型的子类即合法；前端动态关系编辑器使用适用性接口 |
| 校验引擎 | 特性、定义域/值域集合 | 功能性做最大基数1校验；域/值域按并集校验；传递闭包属于推理增强，不等同于普通数据校验 |
| 序列化 | IRI、集合、特性、逆属性 | 单域直接输出；多域/多值域输出 `owl:unionOf`；逆属性公理按较小ID一侧输出一次即可 |
| 扩展管理 | namespace、name、sourceType | 扩展必须使用扩展命名空间；同工程Name不可复用核心或其他扩展名称 |
| 影响分析 | 属性ID/IRI及关联表 | 修改或删除前统计公理、实例三元组、Shape、导出任务引用 |
