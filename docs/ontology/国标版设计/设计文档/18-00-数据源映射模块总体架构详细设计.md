## 1. 评审结论

数据源映射是平台由“人工维护A-Box实例”进入“外部业务数据驱动语义实例”的第一项运行时能力。当前实例模块、版本模块、EDA和安全模块已经提供目标模型、写入保护、事件骨干与安全决策，但不能直接用现有页面CRUD代替映射引擎。

本设计作出以下关键决策。

| 级别 | 问题 | 设计结论 |
|---|---|---|
| P0 | 现有实例新增接口将来源固定为`EXTENSION`，不支持外部记录身份和幂等更新 | 新增统一`OntologyInstanceIngestionService`，映射、IoT、规则和API导入后续统一调用 |
| P0 | 若直接按`sys_user`等表结构建类，本体会与pig物理模型强耦合 | 先定义稳定的组织账号扩展本体，再由映射配置连接物理表与语义模型 |
| P0 | 只做字段映射无法表达部门层级、用户部门和用户岗位 | 模块必须同时支持实体映射、数据属性映射、外键/中间表对象属性映射 |
| P0 | 全量重跑可能重复建实例或覆盖人工数据 | 使用来源绑定唯一键、内容哈希、属性所有权和冲突策略保证幂等 |
| P0 | 映射针对可变Schema，若本体发生breaking变化会产生错误实例 | 每个发布映射版本绑定已发布本体版本和兼容约束；存在未发布Schema变更时生产执行失败关闭 |
| P0 | 任意SQL/脚本会引入注入、越权和不可重放问题 | V1仅允许元数据白名单对象、结构化过滤DSL和内置确定性转换器，不开放任意SQL/脚本 |
| P0 | 异步任务若以SYSTEM身份绕过权限会破坏模块36边界 | 作业创建时固化授权上下文，Worker只能按已发布映射授权执行，不提供通用SYSTEM明文通道 |
| P1 | 直接复用`gen_datasource_conf`会把Ontology绑定到可选代码生成模块 | 不依赖codegen业务表；V1建立Ontology数据源注册，底层连接能力抽象为Connector SPI |
| P1 | 实时CDC会放大删除、乱序和幂等问题 | V1先实现全量和`更新时间+主键`增量；CDC留作V1.1，不阻塞首期交付 |
| P1 | 原始数据和错误快照可能包含密码、手机、邮箱 | 作业日志只保存记录键、摘要和脱敏错误上下文，不保存整行原始数据 |

### 3.1 V1包含

- PostgreSQL JDBC数据源注册、连接测试和元数据发现；
- 映射工程和不可变发布版本；
- 表/视图到实体类型映射；
- 列到数据属性映射；
- 外键、自关联和中间表到对象属性映射；
- 稳定IRI、标签模板和内置转换器；
- 抽样预览、静态校验、SHACL预校验；
- 手工全量、定时全量、定时增量和失败记录重试；
- 来源绑定、幂等写入、延迟关系解析、删除策略；
- 与本体版本、工作区锁、EDA、安全和审计集成；
- 以UPMS用户、部门、岗位完成首个自举场景。

### 3.2 V1不包含

- 任意SQL、存储过程、Groovy/JavaScript/SpEL脚本；
- MySQL、Oracle、SQL Server等多数据库实现，仅保留Connector SPI；
- REST、Excel、文件、Kafka、MQTT连接器；
- Debezium/WAL级实时CDC；
- 自动实体消歧、模糊匹配和模块15本体对齐；
- 高频IoT遥测写入和时序存储；
- 双向回写业务数据库；
- 直接控制设备或触发外部服务；
- 将映射配置导出为完整R2RML；可在后续增加兼容导出器。

## 4. 核心术语

| 术语 | 定义 |
|---|---|
| 数据源 `DataSource` | 可读取的外部数据系统及其受控连接配置 |
| 源对象 `SourceObject` | 数据源中的表或视图，V1不支持任意查询 |
| 映射工程 `MappingProject` | 面向一个本体工程的一组实体、字段和关系映射 |
| 映射版本 `MappingVersion` | 映射配置的不可变发布快照 |
| 实体映射 `EntityMapping` | 源对象记录到目标实体类型实例的规则 |
| 字段映射 `FieldMapping` | 源列到本体数据属性值的规则 |
| 关系映射 `RelationMapping` | 外键或关联表到对象属性断言的规则 |
| 来源绑定 `SourceBinding` | 外部记录稳定身份与本体实例的唯一绑定 |
| 摄入 `Ingestion` | 将规范化命令幂等写入实例、值和关系的内部过程 |
| 映射作业 `MappingJob` | 映射版本的一次预览、全量、增量或重试执行 |
| 待解析关系 `PendingRelation` | 因目标实例尚未摄入而延迟创建的对象属性断言 |
| 生产执行 | 会修改Ontology实例数据的FULL/INCREMENTAL/RETRY作业 |

## 6. 统一领域状态机

### 6.1 数据源状态

```text
DRAFT ──连接测试成功并启用──▶ ACTIVE ──停用──▶ DISABLED
  ▲                                │              │
  └────────────修改连接信息────────┘              └──启用并重测──▶ ACTIVE
```

生产作业只能使用`ACTIVE`数据源。修改连接参数后自动回到`DRAFT`并清除成功测试状态。

### 6.2 映射工程状态

```text
DRAFT ──首个版本发布──▶ ACTIVE ──停用──▶ DISABLED ──启用──▶ ACTIVE
                               └────────归档──▶ ARCHIVED
```

### 6.3 映射版本状态

```text
DRAFT ──validate──▶ VALIDATING ──通过──▶ VALIDATED ──publish──▶ PUBLISHED
  │                       │                 │                       │
  └────────失败──────────▶ DRAFT            └──配置变化──▶ DRAFT   └──retire──▶ RETIRED
```

- DRAFT可编辑；
- VALIDATING期间拒绝修改；
- VALIDATED只代表当前配置哈希通过校验，任何修改使其回到DRAFT；
- PUBLISHED不可变；
- 同一映射工程只有一个ACTIVE发布版本，旧版本进入RETIRED；
- RETIRED版本可查看和用于历史作业解释，但不能新建生产作业。

### 6.4 作业状态

```text
QUEUED → STARTING → RUNNING → SUCCEEDED
                    │  │  ├──▶ PARTIAL_SUCCESS
                    │  │  └──▶ FAILED
                    │  └─────cancel──▶ CANCELLING → CANCELLED
                    └──租约失效/节点故障──▶ RECOVERING → RUNNING/FAILED
```

## 8. 统一事务与一致性原则

1. 映射配置事实源为PostgreSQL；发布版本不可变。
2. 单条源记录的实例、值、来源绑定和Outbox事件在同一事务提交。
3. 作业不是跨全部记录的大事务；按页读取、按记录或小批次提交。
4. 至少一次执行，业务结果依靠来源绑定和唯一索引实现幂等。
5. Connector读取失败不得回滚已提交页；作业从持久化游标恢复。
6. 关系与实体分两阶段执行，避免目标实体顺序导致静默丢关系。
7. EDA事件不是映射或实例事实源，回放事件不能替代作业重试。
8. 生产作业启动前再次校验数据源状态、映射版本、本体版本和工作区状态。

## 9. 本体版本与工作区约束

生产执行必须同时满足：

```text
project.workspace_status = EDITABLE
mapping_version.status = PUBLISHED
mapping_version.validated_ontology_version_id = ontology_project.current_version_id
mapping_version.validated_workspace_revision = ontology_project.workspace_revision
current ontology version release_status = PUBLISHED
```

若当前工作区存在未发布Schema修改，即工作区修订号与映射发布时不一致：

- PREVIEW允许执行，但报告必须提示`SCHEMA_DRIFT`；
- FULL/INCREMENTAL/RETRY生产执行失败关闭；
- 用户需发布新的本体版本并重新验证/发布映射版本。

实例数据本身不进入模块14 Schema快照，映射写入实例不得递增Schema工作区修订号。

## 11. 统一错误码

| 前缀 | 范围 | 子段分配 |
|---|---|---|
| `ONT-DS-xxx` | 数据源、连接和元数据 | 001~099（18-02定义） |
| `ONT-MAP-0xx` | 映射工程、版本管理 | 001~099（18-03定义） |
| `ONT-MAP-1xx` | 实体与数据属性映射 | 100~199（18-04定义） |
| `ONT-MAP-2xx` | 校验、预览与发布 | 200~299（18-06定义） |
| `ONT-ING-xxx` | 摄入、幂等和来源绑定 | 001~099（18-01定义） |
| `ONT-REL-xxx` | 对象关系和延迟解析 | 001~099（18-05定义） |
| `ONT-JOB-xxx` | 作业、游标、取消和恢复 | 001~099（18-07定义） |
| `ONT-SEC-xxx` | 数据源凭证和映射授权，复用模块36通用错误时除外 | 001~099（18-08定义） |

错误响应不得包含JDBC密码、完整URL参数、源行明文或SQL语句。日志可以记录稳定错误码、数据源ID、映射版本ID、作业ID和源记录键摘要。

## 16. 与后续模块的关系

| 模块 | 关系 |
|---|---|
| 15 本体对齐 | 多源同一实体消歧和跨本体字段等价后续由15提供，V1不做模糊合并 |
| 16 SKOS | 枚举和行业词表转换可后续引用Concept，不阻塞V1内置字典转换 |
| 19 IoT接入 | 复用18-01摄入服务和来源绑定思想，不复用JDBC扫描作业 |
| 20 物模型 | 复用映射版本、转换器、版本兼容和预览框架，建立独立物模型映射语义 |
| 21 时序数据 | 高频值不进入本模块作业表和实例全量历史，只写最新状态摘要 |
| 23 告警 | 消费映射产生的语义实例变化事件，不读取源数据库 |
| 26 EDA | 承载映射和实例领域事件；不承载原始整行数据 |
| 36 安全 | 承载凭证加密、ACL、策略和审计；数据源映射不得建立安全旁路 |
| 37 可观测 | 接入本模块指标、日志和trace；首期先输出Micrometer指标 |

> 最终定位：模块18是“受控外部数据到Ontology A-Box的语义映射与摄入平台”，不是通用ETL产品、任意SQL工具、CDC平台或IoT遥测平台。
