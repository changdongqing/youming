# 数据源映射前端管理控制台详细设计

> 模块：18 数据源映射  
> 功能编号：18-10  
> 前端：Vue 3 + TypeScript + Element Plus，遵循现有pig-ui目录和请求封装  
> 设计日期：2026-07-14

## 1. 目标

提供数据源、映射工程、映射设计、预览校验、版本发布、同步作业、错误明细和来源追踪的可视化管理能力，使用户无需编辑JSON或SQL即可完成受控映射。

## 2. 页面结构

菜单：

```text
本体建模
  └── 数据源映射 /ontology/data-mapping/index
```

主页面使用Tabs：

```text
数据源 | 映射工程 | 同步作业 | 待解析关系
```

映射工程进入独立编辑器视图，避免在表格弹窗内承载复杂配置：

```text
/ontology/data-mapping/designer?projectId=...&versionId=...
```

路由可由主页面内部动态组件切换；若系统菜单只注册index组件，designer作为同一目录子组件并通过query展示。

- 启用/停用；

### 3.3 映射设计器

布局：

```text
┌ 顶部：工程/版本/本体版本/状态/保存/校验/发布 ┐
├──────────────┬────────────────────┬──────────────┤
│ 左：源数据   │ 中：映射工作区     │ 右：本体模型 │
│ 数据源       │ 实体映射卡片       │ 实体类型树   │
│ Schema/表树  │ 字段映射表         │ 数据属性     │
│ 列/PK/FK     │ 关系映射卡片       │ 对象属性     │
├──────────────┴────────────────────┴──────────────┤
│ 底部抽屉：预览/校验问题/版本差异/操作日志        │
└──────────────────────────────────────────────────┘
```

V1不强制实现自由拖拽连线。优先采用稳定的选择器和映射表：

```text
源列下拉 → 转换器 → 目标数据属性下拉
```

对象关系使用向导配置。自由画布可在后续增强，不能因画布复杂度延迟核心映射能力。

## 4. 数据源表单

步骤式表单：

```text
1. 基本信息
2. 连接配置
3. 凭证
4. Schema/对象白名单
5. 测试并启用
```

校验：

- sourceCode：`^[A-Z][A-Z0-9_]{2,63}$`；
- host/port/database或JDBC URL二选一；
- JDBC URL中前端也提示禁止user/password，但后端为最终边界；
- 白名单至少一个业务Schema；
- 新建必须输入凭证；编辑可保持原凭证；
- 测试成功后才显示“启用”，但仍以后端状态为准。

## 5. 映射设计器状态

## 5. 映射设计器状态

使用Pinia store管理设计器全局状态（`useMappingDesignerStore`），便于跨组件共享和Vue DevTools调试：

```text
stores/ontology/useMappingDesignerStore.ts
  project
  version
  sourceMetadata
  ontologySchema
  entityMappings
  relationMappings
  dirtyState
  loadingState
  conflictState
```

不使用单个超大reactive对象深度监听全部配置。编辑动作通过显式方法更新局部状态并标记dirty。

### 5.1 保存

- 子表独立保存，携带revision；
- 保存成功更新本地revision；
- 409/版本冲突显示差异提示并要求重新加载；
- 不自动覆盖服务端；
- 离开页面有未保存修改时弹确认；
- PUBLISHED/VALIDATED只读。

### 5.2 元数据浏览

- Schema、对象和列按需加载；
- 表树远程过滤；
- 列展示PK/FK、JDBC类型、nullable、长度；
- 元数据过期显示刷新提示；
- metadata hash漂移显示红色状态，不自动替换当前映射选择。

### 5.3 本体模型浏览

复用实体类型树和属性接口/工具：

- 只显示目标Ontology工程；
- 实体选择后按继承收集适用数据属性；
- 对象属性按domain/range过滤；
- 显示属性baseType、valueMode、单位、安全级别、必填/唯一；
- CONFIDENTIAL/RESTRICTED用锁图标；
- 不在前端自行判定最终兼容，后端校验为准。

## 6. 实体映射编辑

表单区：

- mappingCode/name；
- 数据源、Schema、表/视图；
- 目标实体类型、命名空间；
- 主键列；
- IRI模板和即时样例；
- label模板；
- 过滤条件构建器；
- 增量列；
- 删除列和值；
- 删除/冲突策略；
- syncOrder。

IRI模板编辑器只允许从主键列插入变量，不提供任意文本脚本自动完成。样例渲染调用后端`iri-preview`。

## 7. 字段映射编辑

表格列：

```text
启用 | 映射编码 | 来源类型 | 源列/常量 | 源类型 |
转换器 | 目标属性 | 目标类型 | 单位 | 空值策略 |
错误策略 | 所有权 | 排序 | 操作
```

交互：

- 选择目标属性后过滤转换器；
- CLOSED_ENUM打开字典映射弹窗；
- UNIT_REF显示固定单位选择器；
- CONSTANT显示常量输入，不显示源列；
- password/salt等禁止列在选择器禁用并解释原因；
- email/phone显示敏感提示；
- DATETIME目标在后端能力未启用时禁用。

## 8. 关系映射向导

```text
步骤1：关系模式
步骤2：源对象
步骤3：主体实体映射和键
步骤4：对象实体映射和键
步骤5：对象属性
步骤6：缺失目标/删除/所有权策略
步骤7：样例预览
```

不同模式动态表单：

- FOREIGN_KEY：源对象通常为主体表；
- SELF_REFERENCE：主体/客体映射相同；
- JOIN_TABLE：要求relationKeyColumns。

对象属性选择器必须显示domain/range兼容结果。即使前端显示兼容，提交仍由后端校验。

### 8.1 已有关系映射的编辑

首次创建关系映射通过 `RelationMappingWizard.vue` 向导完成。已创建的关系映射后续微调（如修改filter、调整策略、切换启用）使用 `RelationMappingEditor.vue` 独立编辑组件，无需重新走7步向导：

- 以表单形式展示当前关系映射的全部字段；
- 关系模式（FOREIGN_KEY/SELF_REFERENCE/JOIN_TABLE）不可修改，需删除后重建；
- 键映射、对象属性、策略等可编辑，携带revision乐观锁；
- 样例预览内嵌，修改键映射后可即时验证。

## 9. 过滤DSL构建器

UI仅提供受控条件：

- 列；
- 操作符；
- 参数值；
- AND/OR分组，最大嵌套3层；
- IN最大100值。

不提供SQL文本框。序列化为18-02 DSL JSON。前端预校验不能替代后端列白名单和参数化编译。

## 10. 预览和校验

### 10.1 预览抽屉

- 选择实体映射和样本数，默认20、最大100；
- 显示WOULD_CREATE/UPDATE/UNCHANGED/FAIL；
- IRI、label、目标属性和脱敏值；
- 关系预览；
- 问题按severity过滤；
- 源记录仅显示键掩码；
- 提示“样本通过不代表全量通过”。

### 10.2 校验报告

- 顶部计数；
- 按scope树定位到实体/字段/关系；
- 点击问题自动选中设计器对应项；
- WARNING逐项确认；
- VIOLATION无忽略按钮；
- 报告过期时禁用发布并提示重新校验。

## 11. 发布流程

```text
点击发布
 → 若dirty先保存
 → 调用validate或确认最新报告
 → 展示Prepare风险摘要
 → 展示Ontology版本、workspace revision、metadata依赖
 → 高风险项要求输入映射工程编码确认
 → 如需审批，显示审批状态
 → 发布
 → 页面切换只读并刷新active/draft状态
```

不能只弹简单“是否确认”。IRI变化、SOFT_DELETE、数据源变化必须分项展示。

## 12. 作业启动

启动对话框：

- FULL/INCREMENTAL；
- 映射版本只读；
- 上次成功游标；
- 删除检测能力提示；
- 预计源对象；
- 高风险策略摘要；
- 不允许前端修改服务端pageSize/timeout。

启动成功跳转作业详情。进度轮询：

- RUNNING默认3秒；
- 后台标签页降为10秒；
- 终态停止；
- 后续可改SSE/WebSocket，V1轮询足够；
- 页面卸载取消定时器。

## 13. 错误展示

统一展示：

```text
错误码
用户可理解消息
scope/mappingCode
源记录键掩码
traceId
建议
```

不直接展示后端堆栈、SQL、JDBC URL或原始异常。管理员复制诊断信息时也只复制安全字段。

## 17. 前端测试

Vitest重点：

- 状态机按钮可用性；
- revision冲突处理；
- IRI模板变量只来自keyColumns；
- Filter DSL序列化/反序列化；
- 密码编辑不回填掩码；
- 禁止列不可选择；
- CONFIDENTIAL值预览不显示明文；
- VALIDATED/PUBLISHED只读；
- WARNING可确认、VIOLATION不可忽略；
- 作业终态停止轮询；
- 页面卸载清理timer；
- relation wizard三种模式生成正确DTO；
- DATETIME能力开关；
- 错误复制不包含敏感字段。

关键E2E：

1. 新建本地PostgreSQL数据源并测试；
2. 从UPMS模板创建工程；
3. 查看5张表元数据；
4. 预览用户、部门、岗位；
5. 查看并确认可接受WARNING；
6. 发布映射；
7. 执行FULL；
8. 查看作业、失败记录和图谱结果；
9. 修改源用户显示名后执行INCREMENTAL；
10. 验证原实例被更新且IRI不变。

## 18. 验收标准

- 用户无需编写SQL/JSON即可配置首期映射；
- 所有状态和高风险操作有明确反馈；
- 凭证和敏感源值不在DOM、缓存、日志中出现；
- 设计器能够定位后端校验问题；
- 大表元数据按需加载，不一次渲染所有表列；
- 作业页面能够解释“执行到哪里、失败多少、为什么失败、如何重试”；
- 前端不承担最终安全、兼容和状态校验，后端拒绝结果能正确展示。
