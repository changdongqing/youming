## 1. 评审结论与设计边界

### 1.1 现状评审

截至本设计时点，前述 11 个模块已全部落地：命名空间、实体类型、数据属性、对象属性、公理规则、实体对象实例、校验引擎、序列化与交换、扩展管理均已通过 Flyway V4–V13 迁移脚本预置并验证。后端已具备完整的图谱数据构建能力（`OntologyModelAssembler` 构建 Schema Model + Instance Model、`DataGraphBuilder` 按类型过滤构建子图），前端已安装 echarts 5.6.0 + vue-echarts 7.0.3（vite 构建已预留 echarts chunk），但尚未在任何页面中引用。代码库中存在以下可视化缺口：

| 缺口 | 现状 | 影响 |
|------|------|------|
| **无可视化专用 API** | 后端无 `/ontology/visualization/*` 端点，图谱数据分散在各模块的 detail/tree/list 接口中（`GET /ontology/entity-types/tree` 返回继承树、`GET /ontology/instances/{id}` 返回单实例出入边、`GET /ontology/axiom-rules/disjoint` 返回不相交对） | 前端无法通过一次请求获取完整图谱数据（节点+边），需多次调用拼接，性能差且交互割裂 |
| **无 Schema 层关系图** | 实体类型继承树以 `el-tree` 树形组件展示（仅父子层级），对象属性关系（域→值域有向边）、等价类、不相交类等关系无图形化展示 | 用户无法直观感知实体类型间的对象属性关系拓扑、等价/不相交等公理约束 |
| **无实例层图谱** | 实例详情页仅展示单个实例的出入关系列表（`outgoingRelations` + `inboundRelations`），无法以图谱形式展示整个本体工程的实例网络 | PRD §4.10"实例图谱"和 §5 附录D"电池标准实例图谱"无法落地，用户无法验证附录D 9步实例化的全局关系完整性 |
| **无公理标注** | 不相交、功能属性、等价类等公理约束仅在公理规则模块中以表格形式展示，图谱节点/边上无标注 | PRD §4.10"公理标注：图谱上标注不相交、功能属性等约束"无法落地 |
| **无图谱导出** | 序列化模块（10）支持 RDF 格式导出（Turtle/JSON-LD/RDF-XML/N-Triples），但无 PNG/SVG 图片导出 | PRD §4.10"图谱导出：导出为 PNG/SVG"无法落地 |
| **无数据属性面板联动** | 选中实体类型时仅展示详情表单，无与图谱联动的"数据属性面板" | PRD §4.10"数据属性面板：选中实体类型展示其数据属性"交互缺失 |
| **echarts 已安装但未使用** | `web/package.json` 已含 echarts 5.6.0 + vue-echarts 7.0.3，`vite.config.mts` 已预留 echarts chunk，但 `src/` 下无任何 import | 依赖已就绪但能力闲置，引入 G6 会增加额外依赖与包体积 |

### 1.2 优化结论

| 级别 | 评审发现 | 优化结论 |
|------|----------|----------|
| P0 | PRD §4.10 要求"前端采用 AntV G6 渲染有向图"，但 echarts 5.6 已安装且 vite 已预留 chunk，引入 G6 会增加 ~400KB 包体积 | **采用 echarts graph 系列替代 G6**：echarts 的 `graph` series 原生支持力导向/固定布局、有向边、节点分类着色、边标签、缩放/拖拽/高亮，完全满足 PRD 6 项功能需求；同时复用已安装依赖，零新增包体积。技术选型变更依据见 §2.3 |
| P0 | 图谱数据分散在各模块接口中，前端多次调用拼接性能差 | **新建可视化专用 API 层**：后端 `OntVisualizationController` + `OntVisualizationService` 提供聚合查询，一次请求返回完整图谱的 nodes+edges JSON，前端无需多次调用 |
| P0 | 实例图谱可能节点数量大（附录D 29个实例 + 39条关系尚小，但国标要求支持≤10万实例），全量加载会卡死浏览器 | **分层加载 + 子图展开策略**：默认仅加载"实体类型层"概览图（节点≤86）；实例图谱默认按实体类型分组折叠，点击展开某个类型的实例子图；支持按 IRI/标签搜索定位节点；节点数超过阈值（默认500）时自动切换为分层摘要模式 |
| P1 | 公理标注需在图谱上叠加不相交/功能属性/等价类等约束信息 | **边样式 + 节点徽标双通道标注**：不相交类对用红色虚线边标注，等价类用绿色双向边标注，功能属性在边标签后追加 `[F]` 徽标，节点上叠加约束数量气泡 |
| P1 | 图谱导出 PNG/SVG 需在前端实现 | **echarts 原生 `getDataURL` + `renderToSVGString`**：echarts 5.x 支持 `chart.getDataURL({ type: 'png' })` 和 SVG 渲染模式直接导出，无需额外依赖 |
| P1 | 数据属性面板需与图谱联动 | **左图右面板布局**：选中图谱节点时右侧面板展示该实体类型的适用数据属性列表（复用 `GET /ontology/data-properties/by-domain/{entityTypeId}`），选中实例节点时展示该实例的数据属性值（复用 `GET /ontology/instances/{id}/data-values`） |
| P2 | PRD §6.3 要求"图谱浏览支持过滤、高亮路径、展开/折叠子图" | **工具栏集成**：顶部工具栏提供实体类型筛选（多选下拉）、关系类型筛选（对象属性多选）、布局切换（力导向/层次/环形）、搜索框、导出按钮；点击节点高亮其1跳邻居路径，其余节点降透明度 |
| P2 | 访客角色需只读图谱浏览权限 | **独立权限码 `ontology_visualization_view`**：可视化模块全部 API 为只读 GET，仅需一个 view 权限；访客角色默认分配该权限 |

### 1.3 本期范围

**本期包含：**

1. 可视化专用 REST API（Schema 图谱、实例图谱、子图展开、图谱统计）
2. 可视化应用服务层（`OntVisualizationService`——聚合查询各模块数据组装为 graph JSON）
3. 可视化前端模块（Schema 继承树图、对象属性关系图、实例图谱、公理标注、数据属性面板、图谱导出）
4. 可复用 echarts graph 图谱组件（`OntologyGraph.vue`——封装 echarts graph series，支持节点着色/边样式/缩放/拖拽/高亮/导出）
5. Flyway V14 迁移脚本（菜单权限 + 种子数据——可视化菜单项注册）
6. 图谱导出能力（PNG/SVG，复用 echarts 原生能力）

**本期不包含：**

- 三元组库（Jena TDB/GraphDB）的 SPARQL 查询可视化（本期从关系库聚合查询，不直连 Triplestore）
- 实时图谱更新（实例/Schema 变更后需手动刷新图谱，不做 WebSocket 推送）
- 图谱编辑能力（不在图谱上直接拖拽创建/删除节点和边，编辑操作仍在各模块页面进行）
- 3D 图谱/VR 可视化（本期仅 2D 有向图）
- 校验结果在图谱上的热力图叠加（校验报告仍在校验中心模块查看，本期仅标注公理约束）
- 图谱布局算法自定义（使用 echarts 内置力导向/层次/环形布局，不实现自定义图布局算法）
- 大规模图谱（>1万节点）的性能优化（本期支持≤500节点的流畅渲染，更大规模通过分层摘要+按需展开应对）

### 1.5 权威语义口径

1. 可视化模块是**只读展示层**，不拥有任何数据的写入权限——所有图谱数据来源于各已有模块的只读查询，可视化模块不创建、修改、删除任何实体。
2. 可视化模块**不复用 Jena Model**——`OntologyModelAssembler` 和 `DataGraphBuilder` 构建 Jena `Model` 对象用于 SHACL 校验和 RDF 序列化，其三元组模型适合 RDF 交换但不适合前端图谱渲染（需额外遍历 Model 提取 nodes/edges）。可视化模块直接从关系库表查询，组装为前端可直接消费的 `{ nodes: [...], edges: [...] }` JSON 结构，避免 Jena Model 的序列化/反序列化开销。
3. 图谱数据按**本体工程隔离**：所有可视化 API 均接收 `ontologyId` 参数，仅返回该工程范围内的节点和边。跨工程图谱不在本期范围。
4. 图谱分为**两个层级**：**(a) Schema 层**——节点为实体类型（owl:Class），边为继承关系（subClassOf）/对象属性（域→值域）/等价类/不相交；**(b) 实例层**——节点为实例（individual），边为对象属性断言（subject→object）。两层独立渲染，通过 Tab 切换。
5. **分层加载策略**：Schema 图谱默认全量加载（核心实体类型≤86个节点，性能可控）；实例图谱默认按实体类型分组折叠展示摘要，点击展开某类型的实例子图，避免大规模实例一次性加载。
6. **公理标注双通道**：**(a) 边样式通道**——不相交类对用红色虚线边、等价类用绿色双向实线边、继承用蓝色实线箭头边、对象属性用灰色实线箭头边；**(b) 节点徽标通道**——节点右上角叠加约束数量气泡（如"3 条公理"），hover 显示公理详情。
7. **图谱导出为图片**（PNG/SVG），非 RDF 序列化——导出的是可视化渲染结果，用于报告插图和文档嵌入；RDF 格式导出仍由序列化模块（10）负责。
8. **权限模型极简**：可视化模块全部 API 为只读 GET，仅需 `ontology_visualization_view` 一个权限码；管理员/建模工程师/审核员/访客均默认拥有该权限（访客仅此模块+工作台只读权限）。
9. **技术选型变更**：PRD §4.10 原文"前端采用 AntV G6"，本设计变更为 **echarts graph 系列**。变更依据：(a) echarts 5.6 + vue-echarts 7.0 已安装且 vite 已预留 chunk，零新增依赖；(b) echarts graph series 支持有向图、力导向布局、节点分类着色、边标签、缩放/拖拽/高亮，满足 PRD 全部 6 项功能需求；(c) G6 额外引入 ~400KB 包体积且与 echarts 能力重叠；(d) echarts 原生支持 PNG/SVG 导出，G6 需额外依赖 canvas-to-svg。
10. **节点 ID 全局唯一**：图谱中节点 ID 使用 IRI（实体类型 IRI 或实例 IRI），边 ID 使用 `subjectIRI-predicateIRI-objectIRI` 组合键，确保跨层级引用无冲突。

### 2.2 模块定位

可视化模块位于 PRD §3.1 四层架构的**可视化展示层**，是所有底层模块数据的"可视化投影"：

```
┌─────────────────────────────────────────────────────┐
│              可视化展示层 (§4.10 本模块)               │
│    Schema图谱 │ 实例图谱 │ 公理标注 │ 图谱导出        │
├─────────────────────────────────────────────────────┤
│  输出层: 序列化(10) │ 扩展(11)                       │
├─────────────────────────────────────────────────────┤
│  约束层: 校验引擎(09)                                │
├─────────────────────────────────────────────────────┤
│  实例层: 实体对象实例(08)                             │
├─────────────────────────────────────────────────────┤
│  Schema层: 命名空间(03)│实体类型(04)│数据属性(05)    │
│           │对象属性(06)│公理规则(07)│单位字典(02)    │
└─────────────────────────────────────────────────────┘
```

可视化模块横跨 Schema 层和实例层，从命名空间、实体类型、数据属性、对象属性、公理规则、实体实例六个模块聚合数据，组装为统一的有向图结构，通过 echarts 渲染为交互式图谱。

### 2.3 技术选型：echarts graph 替代 AntV G6

| 对比维度 | AntV G6（PRD 原文） | echarts graph（本设计选型） | 结论 |
|----------|---------------------|---------------------------|------|
| **依赖状态** | 未安装，需新增 `@antv/g6` 依赖 (~400KB gzip) | 已安装 echarts 5.6.0 + vue-echarts 7.0.3，vite 已预留 chunk | ✅ echarts 零新增依赖 |
| **有向图渲染** | 原生支持，DAG/树/力导向布局 | `graph` series 原生支持 force/circular/layout，`lineStyle.type` 支持箭头 | ✅ 均满足 |
| **节点分类着色** | `node.type` + 自定义渲染 | `categories` + `itemStyle.color` | ✅ 均满足 |
| **边标签** | `edge.label` | `edge.label` + `labelLine` | ✅ 均满足 |
| **缩放/拖拽/高亮** | `behaviors` 内置 | `roam: true` + `emphasis` + `focusNodeAdjacency` | ✅ 均满足 |
| **PNG/SVG 导出** | 需额外依赖 `canvas-to-svg` | `chart.getDataURL({ type:'png' })` / SVG 渲染模式原生支持 | ✅ echarts 原生 |
| **学习成本** | G6 专有 API 体系 | echarts 通用 option 配置，团队已有 echarts 使用经验 | ✅ echarts 更低 |
| **包体积** | +400KB | 0（已含） | ✅ echarts 更优 |
| **PRD 符合度** | PRD §4.10 原文指定 | 技术等价替代，功能完全覆盖 | ⚠️ 需设计变更说明 |

**变更结论**：采用 echarts graph 系列替代 AntV G6，功能完全覆盖 PRD §4.10 的 6 项需求，零新增依赖，包体积更优。此变更已在 §1.2 P0 评审结论中记录依据。

### 2.4 与 OntologyModelAssembler 的关系

| 维度 | OntologyModelAssembler / DataGraphBuilder | OntVisualizationService |
|------|------------------------------------------|------------------------|
| **用途** | 构建 Jena `Model` 用于 SHACL 校验和 RDF 序列化 | 组装 `{ nodes, edges }` JSON 用于前端图谱渲染 |
| **数据格式** | Jena RDF 三元组（Subject-Predicate-Object） | echarts graph series option（nodes+edges） |
| **查询方式** | 全量加载 Schema + Instance 到 Model | 按需聚合查询，支持分页/过滤/子图展开 |
| **性能优化** | 无（全量加载） | 分层加载 + 子图展开 + 节点阈值保护 |
| **输出** | `org.apache.jena.rdf.model.Model` | `GraphDataVO`（JSON） |
| **调用方** | 校验引擎、序列化导出 | 可视化 Controller |

可视化模块**不复用** `OntologyModelAssembler`，原因：(1) Jena Model 的三元组模型需额外遍历提取 nodes/edges，增加不必要转换；(2) `OntologyModelAssembler` 全量加载无分页/过滤，不适合大规模图谱的按需加载；(3) 可视化需要附加 UI 元数据（节点颜色、边样式、约束标注），Jena Model 不承载这些。`OntVisualizationService` 直接查询关系库表，一步组装为前端可消费的 graph JSON。

### 3.3 边类型与样式映射

| edgeType | 描述 | lineStyle | color | directed | 来源表 |
|----------|------|-----------|-------|----------|--------|
| `SUBCLASS_OF` | 继承关系（子类→父类） | solid | `#409EFF`（蓝） | true | `ont_entity_type_hierarchy` |
| `OBJECT_PROPERTY` | 对象属性（域→值域） | solid | `#909399`（灰） | true | `ont_object_property` + `domain`/`range` |
| `EQUIVALENT` | 等价类 | solid | `#67C23A`（绿） | false（双向） | `ont_entity_type_equivalent` |
| `DISJOINT` | 不相交类 | dashed | `#F56C6C`（红） | false（双向） | `ont_entity_type_disjoint` |
| `INSTANCE_OF` | 实例→实体类型（rdf:type） | dotted | `#E6A23C`（橙） | true | `ont_entity_instance.rdf_type_id` |
| `INSTANCE_RELATION` | 实例间对象属性断言 | solid | `#909399`（灰） | true | `ont_instance_object_relation` |

### 3.4 节点分类与着色

Schema 图谱节点按实体类型的"顶层祖先类型"着色（让同一继承分支的节点视觉聚合）：

| category | 颜色 | 描述 | 示例 |
|----------|------|------|------|
| 标准化对象类 | `#5470C6`（蓝） | StandardizationObject 分支 | Standard, StandardizationObject, ExternalResource |
| 结构层次类 | `#91CC75`（绿） | StructuralElement 分支 | Section, Clause, InformationUnit |
| 描述对象类 | `#FAC858`（黄） | Object 分支 | Object, Property, Constraint |
| 行动类 | `#EE6666`（红） | ActionClass 分支 | ActionClass |
| 表示形式类 | `#73C0DE`（青） | RepresentationForm 分支 | TextualParagraph, Table, Figure |
| 术语类 | `#3BA272`（深绿） | Term 分支 | Term |
| 扩展类 | `#FC8452`（橙） | 扩展命名空间下的实体类型 | 用户自定义类型 |
| 实例节点 | 按 rdf:type 对应分类着色 | — | — |

> 着色规则：实体类型节点的 category 按其继承树的顶层祖先（`Thing` 的直接子类）确定。`OntVisualizationService` 在构建 Schema 图谱时执行 BFS 向上追溯到顶层祖先，映射到上述分类。无法确定祖先的归入"扩展类"。

**实现逻辑：**

1. 查询 `ont_entity_type`（按 `ontology_id` 过滤）→ 构建实体类型节点
2. 查询 `ont_entity_type_hierarchy` → 构建 `SUBCLASS_OF` 边
3. 查询 `ont_object_property` + `ont_object_property_domain` + `ont_object_property_range` → 构建 `OBJECT_PROPERTY` 边（每个对象属性的每个 domain→range 组合生成一条边）

8. 查询 `ont_axiom_rule_target` → 统计每个实体类型的 `axiomCount`
9. BFS 向上追溯每个实体类型的顶层祖先 → 确定节点 `category`
10. 按节点度数（出入边数）动态计算 `symbolSize`（最小20，最大60）
11. 组装 `GraphDataVO` 返回

#### 4.2.2 GET /ontology/visualization/instance-graph

获取实例层完整图谱。

**请求参数：**

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| ontologyId | Long | 是 | 本体工程ID |
| entityTypeId | Long | 否 | 按实体类型过滤（仅返回该类型及子类型的实例） |
| maxNodes | Integer | 否 | 最大节点数阈值，默认500。超过时返回摘要模式 |

**响应：** `R<GraphDataVO>`

**实现逻辑：**

1. 查询 `ont_entity_instance`（按 `ontology_id` 过滤，可选 `entityTypeId` + 子类型过滤）→ 构建实例节点
2. 节点数超过 `maxNodes` 时切换为**摘要模式**：按 `rdf_type_id` 分组，每组只保留一个代表节点 + 数量标签
3. 查询 `ont_instance_object_relation`（按 `subject_instance_id` 在实例ID集合内过滤）→ 构建 `INSTANCE_RELATION` 边
4. 查询 `ont_entity_type` → 获取实例的 rdf:type IRI 和标签，确定节点 `category`
5. 组装 `GraphDataVO` 返回

#### 4.2.3 GET /ontology/visualization/instance-subgraph

获取某实例的 N 跳邻居子图（用于"展开"操作）。

**请求参数：**

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| instanceId | Long | 是 | 中心实例ID |
| depth | Integer | 否 | 展开深度，默认1（仅直接邻居） |
| direction | String | 否 | 方向：OUTGOING / INCOMING / BOTH，默认 BOTH |

**响应：** `R<GraphDataVO>`

**实现逻辑：**

1. 以 `instanceId` 为起点，BFS 遍历 `ont_instance_object_relation`
2. `direction=OUTGOING`：仅遍历 `subject_instance_id = 当前实例` 的边
3. `direction=INCOMING`：仅遍历 `object_instance_id = 当前实例` 的边（需反查）
4. `direction=BOTH`：双向遍历
5. `depth` 控制遍历层数（默认1，最大3，防止过度展开）
6. 返回子图的 nodes + edges（包含中心节点）

#### 4.2.4 GET /ontology/visualization/entity-type-subgraph

获取某实体类型及其子类型的 Schema 子图。

**请求参数：**

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| entityTypeId | Long | 是 | 根实体类型ID |
| includeObjectProperties | Boolean | 否 | 是否包含对象属性边，默认 true |
| includeAxioms | Boolean | 否 | 是否包含等价/不相交边，默认 true |

**响应：** `R<GraphDataVO>`

**实现逻辑：**

1. BFS 向下收集 `entityTypeId` 及其所有子类型（复用 `DataGraphBuilder.collectDescendants` 模式）
2. 查询这些类型之间的继承关系 → `SUBCLASS_OF` 边
3. 可选查询这些类型相关的对象属性 → `OBJECT_PROPERTY` 边
4. 可选查询这些类型之间的等价/不相交 → `EQUIVALENT` / `DISJOINT` 边
5. 返回子图

#### 4.2.5 GET /ontology/visualization/stats

获取可视化首页统计摘要。

**请求参数：**

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| ontologyId | Long | 是 | 本体工程ID |

**响应：** `R<VisualizationStatsVO>`

**实现逻辑：**

1. `COUNT` 查询各表记录数（entity_type / data_property / object_property / instance / axiom_rule）
2. 查询最近校验报告状态（`ont_validation_report` 按 `ontology_id` 取最新一条）
3. 查询序列化导出次数（`ont_serialization_log` 按 `ontology_id` COUNT）
4. 查询扩展模块数（`ont_extension_module` 按 `ontology_id` COUNT）
5. 实体类型分布：`GROUP BY is_builtin` 统计核心/扩展数量
6. 实例分布：`GROUP BY rdf_type_id` 统计各类型实例数，JOIN 实体类型名称，取 Top 10

```java
@Override
public GraphDataVO buildSchemaGraph(Long ontologyId) {
    // 1. 加载所有实体类型
    List<OntEntityType> types = entityTypeMapper.selectList(
            Wrappers.<OntEntityType>lambdaQuery().eq(OntEntityType::getOntologyId, ontologyId));
    Map<Long, OntEntityType> typeById = types.stream()
            .collect(Collectors.toMap(OntEntityType::getId, t -> t));

    // 2. 加载命名空间（用于节点 namespacePrefix）
    Map<Long, OntNamespace> nsById = loadNamespaces();

    // 3. 构建节点
    List<GraphNodeVO> nodes = types.stream().map(t -> {
        GraphNodeVO node = new GraphNodeVO();
        node.setId(t.getIri());
        node.setLabel(t.getName()); // 中文名
        node.setName(t.getName());
        node.setLayer("SCHEMA");
        node.setNodeType("ENTITY_TYPE");
        node.setEntityTypeId(t.getId());
        node.setIsBuiltin("1".equals(t.getIsBuiltin()));
        node.setIsAbstract("1".equals(t.getIsAbstract()));
        node.setDefinition(t.getDefinition());
        OntNamespace ns = nsById.get(t.getNamespaceId());
        node.setNamespacePrefix(ns != null ? ns.getPrefix() : null);
        return node;
    }).collect(Collectors.toList());

    // 4. 构建边（继承 + 对象属性 + 等价 + 不相交）
    List<GraphEdgeVO> edges = new ArrayList<>();
    edges.addAll(buildSubclassEdges(typeById));
    edges.addAll(buildObjectPropertyEdges(types));
    edges.addAll(buildEquivalentEdges(typeById));
    edges.addAll(buildDisjointEdges(typeById));

    // 5. 计算节点 category（按顶层祖先着色）
    Map<Long, Integer> categoryByTypeId = computeCategories(typeById);
    nodes.forEach(n -> n.setCategory(categoryByTypeId.getOrDefault(n.getEntityTypeId(), 6)));

    // 6. 统计每个实体类型的数据属性数和实例数
    Map<Long, Integer> dataPropCountByType = countDataPropertiesByDomain(types);
    Map<Long, Integer> instanceCountByType = countInstancesByType(ontologyId);
    Map<Long, Integer> axiomCountByType = countAxiomsByTarget(types);
    nodes.forEach(n -> {
        n.setDataPropertyCount(dataPropCountByType.getOrDefault(n.getEntityTypeId(), 0));
        n.setInstanceCount(instanceCountByType.getOrDefault(n.getEntityTypeId(), 0));
        n.setAxiomCount(axiomCountByType.getOrDefault(n.getEntityTypeId(), 0));
    });

    // 7. 计算节点 symbolSize（按度数）
    Map<String, Integer> degreeMap = computeDegree(nodes, edges);
    nodes.forEach(n -> {
        int degree = degreeMap.getOrDefault(n.getId(), 0);
        n.setSymbolSize(Math.min(60, 20 + degree * 3));
    });

    // 8. 组装 categories
    List<GraphCategoryVO> categories = buildSchemaCategories();

    // 9. 组装 summary
    GraphSummaryVO summary = buildSummary(types, edges);

    GraphDataVO graph = new GraphDataVO();
    graph.setNodes(nodes);
    graph.setEdges(edges);
    graph.setCategories(categories);
    graph.setSummary(summary);
    return graph;
}
```

#### 5.4.2 顶层祖先着色算法

```java
/**
 * 计算每个实体类型的顶层祖先，用于节点着色分类。
 * <p>
 * BFS 向上追溯继承树，直到找到没有父类的根类型，
 * 根据根类型的 IRI 映射到预设分类。
 * 无法确定祖先的（如扩展类型无核心祖先）归入"扩展类"。
 * </p>
 */
private Map<Long, Integer> computeCategories(Map<Long, OntEntityType> typeById) {
    // 预设分类映射：根类型IRI → category索引
    Map<String, Integer> rootCategoryMap = Map.of(
        "http://example.org/standard-ontology#StandardizationObject", 0,
        "http://example.org/standard-ontology#StructuralElement", 1,
        "http://example.org/standard-ontology#Object", 2,
        "http://example.org/standard-ontology#ActionClass", 3,
        "http://example.org/standard-ontology#RepresentationForm", 4,
        "http://example.org/standard-ontology#Term", 5
    );

    Map<Long, Integer> result = new HashMap<>();
    // 一次性加载所有继承关系
    List<OntEntityTypeHierarchy> allHierarchies = hierarchyMapper.selectList(null);
    Map<Long, List<Long>> parentMap = allHierarchies.stream()
            .collect(Collectors.groupingBy(
                    OntEntityTypeHierarchy::getChildId,
                    Collectors.mapping(OntEntityTypeHierarchy::getParentId, Collectors.toList())));

    for (Long typeId : typeById.keySet()) {
        // BFS 向上追溯
        Set<Long> visited = new HashSet<>();
        Deque<Long> queue = new ArrayDeque<>();
        queue.add(typeId);
        Integer category = null;
        while (!queue.isEmpty() && category == null) {
            Long current = queue.poll();
            if (!visited.add(current)) continue;
            OntEntityType type = typeById.get(current);
            if (type == null) continue;
            // 检查当前类型是否是预设根类型
            category = rootCategoryMap.get(type.getIri());
            if (category == null) {
                // 继续向上找父类
                List<Long> parents = parentMap.get(current);
                if (parents != null) {
                    queue.addAll(parents);
                }
            }
        }
        // 默认归入"扩展类"
        result.put(typeId, category != null ? category : 6);
    }
    return result;
}
```

#### 5.4.3 对象属性边构建

```java
/**
 * 构建对象属性边（domain → range）。
 * <p>
 * 每个对象属性的每个 domain × range 组合生成一条边。
 * 边标签为对象属性中文名，边样式为灰色实线箭头。
 * 功能属性（isFunctional='1'）在边标记 isFunctional=true。
 * </p>
 */
private List<GraphEdgeVO> buildObjectPropertyEdges(List<OntEntityType> types) {
    Set<Long> typeIds = types.stream().map(OntEntityType::getId).collect(Collectors.toSet());
    Map<Long, String> iriById = types.stream()
            .collect(Collectors.toMap(OntEntityType::getId, OntEntityType::getIri));

    List<OntObjectProperty> props = objectPropertyMapper.selectList(
            Wrappers.<OntObjectProperty>lambdaQuery()
                    .eq(OntObjectProperty::getOntologyId, types.get(0).getOntologyId()));

    List<GraphEdgeVO> edges = new ArrayList<>();
    for (OntObjectProperty prop : props) {
        List<OntObjectPropertyDomain> domains = domainMapper.selectList(
                Wrappers.<OntObjectPropertyDomain>lambdaQuery()
                        .eq(OntObjectPropertyDomain::getObjectPropertyId, prop.getId()));
        List<OntObjectPropertyRange> ranges = rangeMapper.selectList(
                Wrappers.<OntObjectPropertyRange>lambdaQuery()
                        .eq(OntObjectPropertyRange::getObjectPropertyId, prop.getId()));

        for (OntObjectPropertyDomain domain : domains) {
            for (OntObjectPropertyRange range : ranges) {
                if (!typeIds.contains(domain.getEntityTypeId()) || !typeIds.contains(range.getEntityTypeId())) {
                    continue; // 跳过不在当前工程内的类型
                }
                GraphEdgeVO edge = new GraphEdgeVO();
                String sourceIri = iriById.get(domain.getEntityTypeId());
                String targetIri = iriById.get(range.getEntityTypeId());
                edge.setId(sourceIri + "-" + prop.getIri() + "-" + targetIri);
                edge.setSource(sourceIri);
                edge.setTarget(targetIri);
                edge.setLabel(prop.getName());
                edge.setEdgeType("OBJECT_PROPERTY");
                edge.setObjectPropertyId(prop.getId());
                edge.setLineStyle("solid");
                edge.setColor("#909399");
                edge.setDirected(true);
                edge.setWidth(1);
                edge.setIsFunctional("1".equals(prop.getIsFunctional()));
                edge.setSortOrder(range.getSortOrder());
                edges.add(edge);
            }
        }
    }
    return edges;
}
```

```java
@Override
public GraphDataVO buildInstanceGraph(Long ontologyId, Long entityTypeId, Integer maxNodes) {
    // 1. 确定实例范围
    Set<Long> targetTypeIds = null;
    if (entityTypeId != null) {
        targetTypeIds = collectDescendants(entityTypeId); // 含子类型
    }

    // 2. 查询实例
    List<OntEntityInstance> instances;
    if (targetTypeIds != null) {
        instances = instanceMapper.selectList(
                Wrappers.<OntEntityInstance>lambdaQuery()
                        .eq(OntEntityInstance::getOntologyId, ontologyId)
                        .in(OntEntityInstance::getRdfTypeId, targetTypeIds));
    } else {
        instances = instanceMapper.selectList(
                Wrappers.<OntEntityInstance>lambdaQuery()
                        .eq(OntEntityInstance::getOntologyId, ontologyId));
    }

    // 3. 摘要模式判断
    boolean summaryMode = instances.size() > maxNodes;
    if (summaryMode) {
        return buildInstanceSummaryGraph(instances, ontologyId);
    }

    // 4. 构建实例节点
    Map<Long, String> instanceIdToIri = instances.stream()
            .collect(Collectors.toMap(OntEntityInstance::getId, OntEntityInstance::getIri));
    Set<Long> typeIds = instances.stream()
            .map(OntEntityInstance::getRdfTypeId).collect(Collectors.toSet());
    Map<Long, OntEntityType> typeMap = entityTypeMapper.selectBatchIds(typeIds).stream()
            .collect(Collectors.toMap(OntEntityType::getId, t -> t));

    List<GraphNodeVO> nodes = instances.stream().map(inst -> {
        GraphNodeVO node = new GraphNodeVO();
        node.setId(inst.getIri());
        node.setLabel(inst.getLabel() != null ? inst.getLabel() : inst.getIri());
        node.setLayer("INSTANCE");
        node.setNodeType("INSTANCE");
        node.setInstanceId(inst.getId());
        OntEntityType type = typeMap.get(inst.getRdfTypeId());
        if (type != null) {
            node.setRdfTypeIri(type.getIri());
            node.setRdfTypeLabel(type.getName());
            node.setEntityTypeId(type.getId());
        }
        node.setIsBuiltin("1".equals(inst.getIsBuiltin()));
        return node;
    }).collect(Collectors.toList());

    // 5. 构建实例关系边
    Set<Long> instanceIds = instances.stream().map(OntEntityInstance::getId).collect(Collectors.toSet());
    List<OntInstanceObjectRelation> relations = relationMapper.selectList(
            Wrappers.<OntInstanceObjectRelation>lambdaQuery()
                    .in(OntInstanceObjectRelation::getSubjectInstanceId, instanceIds));

    List<GraphEdgeVO> edges = relations.stream()
            .filter(r -> instanceIds.contains(r.getSubjectInstanceId())
                    && ("INSTANCE".equals(r.getObjectKind())
                        ? instanceIds.contains(r.getObjectInstanceId())
                        : true)) // ENTITY_TYPE 类型的 object 保留
            .map(r -> {
        GraphEdgeVO edge = new GraphEdgeVO();
        String sourceIri = instanceIdToIri.get(r.getSubjectInstanceId());
        String targetIri = null;
        if ("INSTANCE".equals(r.getObjectKind())) {
            targetIri = instanceIdToIri.get(r.getObjectInstanceId());
        } else if ("ENTITY_TYPE".equals(r.getObjectKind())) {
            OntEntityType type = typeMap.get(r.getObjectEntityTypeId());
            targetIri = type != null ? type.getIri() : null;
        }
        if (sourceIri == null || targetIri == null) return null;
        OntObjectProperty prop = objectPropertyMapper.selectById(r.getObjectPropertyId());
        edge.setId(sourceIri + "-" + (prop != null ? prop.getIri() : "rel") + "-" + targetIri);
        edge.setSource(sourceIri);
        edge.setTarget(targetIri);
        edge.setLabel(prop != null ? prop.getName() : "关联");
        edge.setEdgeType("INSTANCE_RELATION");
        edge.setLineStyle("solid");
        edge.setColor("#909399");
        edge.setDirected(true);
        edge.setWidth(1);
        return edge;
    }).filter(Objects::nonNull).collect(Collectors.toList());

    // 6. 节点 category 按 rdf:type 的顶层祖先着色
    // ...（复用 computeCategories 逻辑）

    // 7. 组装返回
    GraphDataVO graph = new GraphDataVO();
    graph.setNodes(nodes);
    graph.setEdges(edges);
    graph.setCategories(buildSchemaCategories());
    graph.setSummary(buildInstanceSummary(instances, edges, ontologyId));
    return graph;
}
```

```java
@Override
public GraphDataVO buildInstanceSubgraph(Long instanceId, Integer depth, String direction) {
    int actualDepth = Math.min(Math.max(depth, 1), 3); // 限制 1-3

    Set<Long> visitedInstanceIds = new HashSet<>();
    Set<Long> frontier = new HashSet<>();
    frontier.add(instanceId);

    List<OntInstanceObjectRelation> allRelations = new ArrayList<>();

    for (int d = 0; d < actualDepth && !frontier.isEmpty(); d++) {
        Set<Long> nextFrontier = new HashSet<>();
        for (Long currentId : frontier) {
            if (!visitedInstanceIds.add(currentId)) continue;

            // 查询出边
            if ("OUTGOING".equals(direction) || "BOTH".equals(direction)) {
                List<OntInstanceObjectRelation> outgoing = relationMapper.selectList(
                        Wrappers.<OntInstanceObjectRelation>lambdaQuery()
                                .eq(OntInstanceObjectRelation::getSubjectInstanceId, currentId));
                allRelations.addAll(outgoing);
                outgoing.stream()
                        .filter(r -> "INSTANCE".equals(r.getObjectKind()))
                        .map(OntInstanceObjectRelation::getObjectInstanceId)
                        .filter(Objects::nonNull)
                        .forEach(nextFrontier::add);
            }

            // 查询入边
            if ("INCOMING".equals(direction) || "BOTH".equals(direction)) {
                List<OntInstanceObjectRelation> incoming = relationMapper.selectList(
                        Wrappers.<OntInstanceObjectRelation>lambdaQuery()
                                .eq(OntInstanceObjectRelation::getObjectInstanceId, currentId)
                                .eq(OntInstanceObjectRelation::getObjectKind, "INSTANCE"));
                allRelations.addAll(incoming);
                incoming.stream()
                        .map(OntInstanceObjectRelation::getSubjectInstanceId)
                        .forEach(nextFrontier::add);
            }
        }
        frontier = nextFrontier;
        frontier.removeAll(visitedInstanceIds);
    }

    // 收集所有涉及的实例ID
    Set<Long> allInstanceIds = new HashSet<>(visitedInstanceIds);
    allInstanceIds.add(instanceId);
    for (OntInstanceObjectRelation r : allRelations) {
        allInstanceIds.add(r.getSubjectInstanceId());
        if ("INSTANCE".equals(r.getObjectKind()) && r.getObjectInstanceId() != null) {
            allInstanceIds.add(r.getObjectInstanceId());
        }
    }

    // 加载实例和类型数据，组装 GraphDataVO
    // ...（与 buildInstanceGraph 类似的节点/边构建逻辑）
}
```

```vue
  if (!chart || !props.graphData) return;

  chart.setOption(option, { notMerge: true });
}

/** 导出 PNG */
function exportPNG(filename: string = 'ontology-graph') {
  if (!chart) return;
  const url = chart.getDataURL({
    type: 'png',
    pixelRatio: 2,
    backgroundColor: '#fff',
  });
  const link = document.createElement('a');
  link.href = url;
  link.download = `${filename}.png`;
  link.click();
}

/** 导出 SVG */
function exportSVG(filename: string = 'ontology-graph') {
  if (!chart) return;
  // SVG 渲染模式下可直接获取 SVG 字符串
  const svgStr = chart.renderToSVGString();
  const blob = new Blob([svgStr], { type: 'image/svg+xml' });
  const url = URL.createObjectURL(blob);
  const link = document.createElement('a');
  link.href = url;
  link.download = `${filename}.svg`;
  link.click();
  URL.revokeObjectURL(url);
}

/** 搜索定位节点 */
function focusNode(nodeId: string) {
  if (!chart) return;
  chart.dispatchAction({ type: 'highlight', seriesIndex: 0, name: nodeId });
  chart.dispatchAction({ type: 'showTip', seriesIndex: 0, name: nodeId });
}

/** 切换布局 */
function changeLayout(layout: GraphLayout) {
  if (!chart) return;
  chart.setOption({ series: [{ layout }] });
}

onMounted(() => {
  if (chartRef.value) {
    chart = echarts.init(chartRef.value, null, {
      renderer: props.renderer || 'canvas',
    });

}

</script>
```

### 6.5 图谱数据转换工具（graph-utils.ts）

```typescript
import type { GraphData, GraphLayout, GraphNode, GraphEdge } from '/@/types/ontology/visualization';
import type { EChartsOption } from 'echarts';

/**
 * 将后端 GraphData 转换为 echarts graph series option。
 */
export function transformToEchartsOption(
  graphData: GraphData,
  layout: GraphLayout = 'force',
): EChartsOption {
  const { nodes, edges, categories } = graphData;

  // 布局配置
  const layoutConfig = layout === 'force'
    ? {
        layout: 'force',
        force: {
          repulsion: 200,
          edgeLength: [80, 200],
          gravity: 0.1,
          layoutAnimation: true,
        },
      }
    : layout === 'circular'
    ? { layout: 'circular' }
    : {
        layout: 'none', // hierarchy 使用预设坐标或 dagre 外部计算
      };

  return {
    tooltip: {
      formatter: (params: any) => {
        if (params.dataType === 'node') {
          const n: GraphNode = params.data;
          return [
            `<b>${n.label}</b>`,
            n.rdfTypeLabel ? `类型: ${n.rdfTypeLabel}` : '',
            n.definition ? `定义: ${n.definition}` : '',
            n.isBuiltin ? '🔒 核心内置' : '扩展',
            n.dataPropertyCount != null ? `数据属性: ${n.dataPropertyCount}` : '',
            n.instanceCount != null ? `实例数: ${n.instanceCount}` : '',
            n.axiomCount != null ? `公理约束: ${n.axiomCount}` : '',
          ].filter(Boolean).join('<br/>');
        }
        if (params.dataType === 'edge') {
          const e: GraphEdge = params.data;
          return [
            `<b>${e.label}</b>`,
            `类型: ${getEdgeTypeLabel(e.edgeType)}`,
            e.isFunctional ? '⚙ 功能属性' : '',
          ].filter(Boolean).join('<br/>');
        }
        return '';
      },
    },
    legend: {
      data: categories.map(c => c.name),
      bottom: 10,
      textStyle: { fontSize: 12 },
    },
    toolbox: {
      right: 10,
      feature: {
        restore: { title: '重置' },
        saveAsImage: { title: '保存图片', name: 'ontology-graph' },
      },
    },
    series: [
      {
        type: 'graph',
        ...layoutConfig,
        roam: true, // 缩放+拖拽
        draggable: true, // 节点可拖拽
        focusNodeAdjacency: true, // 高亮邻居
        categories: categories.map(c => ({ name: c.name })),
        data: nodes.map(n => ({
          ...n,
          name: n.id, // echarts 用 name 作为节点标识
          value: n.label,
          symbolSize: n.symbolSize,
          category: n.category,
          itemStyle: {
            color: categories[n.category]?.color,
            borderColor: n.isBuiltin ? '#333' : 'transparent',
            borderWidth: n.isBuiltin ? 2 : 0,
          },
          label: {
            show: true,
            position: 'bottom',
            formatter: n.label,
            fontSize: 11,
          },
        })),
        links: edges.map(e => ({
          ...e,
          source: e.source,
          target: e.target,
          label: {
            show: true,
            formatter: e.label + (e.isFunctional ? ' [F]' : ''),
            fontSize: 10,
            color: '#666',
          },
          lineStyle: {
            type: e.lineStyle,
            color: e.color,
            width: e.width,
            curveness: 0.1,
          },
          symbol: e.directed ? ['none', 'arrow'] : 'none',
          symbolSize: e.directive ? [0, 8] : 0,
        })),
        emphasis: {
          focus: 'adjacency',
          lineStyle: { width: 4 },
          label: { fontSize: 14 },
        },
      },
    ],
  };
}

function getEdgeTypeLabel(edgeType: string): string {
  const map: Record<string, string> = {
    SUBCLASS_OF: '继承关系',
    OBJECT_PROPERTY: '对象属性',
    EQUIVALENT: '等价类',
    DISJOINT: '不相交',
    INSTANCE_OF: '实例类型',
    INSTANCE_RELATION: '实例关系',
  };
  return map[edgeType] || edgeType;
}
```

## 8. 性能设计

### 8.1 性能目标

| 场景 | 目标 | 策略 |
|------|------|------|
| Schema 图谱全量加载（≤86节点 + ≤200边） | ≤1s | 后端单次聚合查询 + 前端 echarts force 布局 |
| 实例图谱摘要模式（>500节点） | ≤2s | 按类型分组折叠为摘要节点 |
| 实例图谱正常模式（≤500节点 + ≤1000边） | ≤2s | 后端单次聚合查询 + 前端 echarts force 布局 |
| 子图展开（1跳邻居） | ≤500ms | 后端 BFS 1层遍历 |
| 统计概览 | ≤500ms | 后端 COUNT 查询 |
| 图谱交互（缩放/拖拽/高亮） | ≤16ms（60fps） | echarts canvas 渲染原生支持 |
| PNG/SVG 导出 | ≤1s | echarts `getDataURL` / `renderToSVGString` 原生 |

### 8.2 大规模图谱应对策略

| 节点规模 | 策略 | 说明 |
|----------|------|------|
| ≤100 | 全量加载 + 力导向布局 | 附录D规模（29实例），最优体验 |
| 100-500 | 全量加载 + 力导向布局 | 性能可控，echarts canvas 渲染 |
| 500-5000 | 摘要模式 + 按需展开 | 按类型折叠为摘要节点，点击展开子图 |
| >5000 | 分层摘要 + 类型过滤 | 强制按实体类型过滤后展示，禁用全量加载 |

### 8.3 后端查询优化

1. **批量查询**：`buildSchemaGraph` 使用 `selectList` 一次性加载所有实体类型、继承关系、对象属性域值域、等价/不相交对，避免 N+1 查询。
2. **ID→IRI 映射缓存**：构建 `Map<Long, String> idToIri` 缓存实体类型 ID 到 IRI 的映射，避免在边构建中重复查询。
3. **度数计算内存化**：节点 symbolSize 按度数计算在内存中完成，不额外查询数据库。
4. **子图展开 BFS 深度限制**：`buildInstanceSubgraph` 限制 `depth` 最大为 3，防止全图遍历。
5. **统计查询使用 COUNT**：`getStats` 使用 MyBatis-Plus `selectCount` 而非 `selectList`，避免全量数据加载。

## 12. 风险与对策

| 风险 | 影响 | 对策 |
|------|------|------|
| 大规模实例图谱（>500节点）渲染卡顿 | 浏览器卡死或白屏 | 摘要模式 + 按需展开 + 类型过滤；节点数超阈值自动切换摘要模式 |
| echarts force 布局不稳定 | 节点位置每次刷新不同，用户难定位 | 提供布局锁定按钮（`force.layoutAnimation: false`）和布局切换（环形/层次） |
| 对象属性边爆炸（N×M domain×range组合） | Schema 图谱边过多导致视觉混乱 | 对象属性边默认半透明展示，选中实体类型时高亮其关联边；提供边类型筛选器 |
| 后端聚合查询慢（全量加载 Schema + Instance） | API 响应超时 | 批量查询 + ID→IRI 映射缓存；Schema 图谱可按工程缓存（HTTP ETag 或前端 LocalStorage） |
| echarts SVG 导出中文乱码 | SVG 文件中文字体缺失 | SVG 导出时在 `<svg>` 根节点注入 `<style>` 声明中文字体 fallback |
| 技术选型变更（G6→echarts）的 PRD 偏差 | PRD 审查不通过 | §2.3 已记录变更依据和功能等价性分析；echarts 完全覆盖 PRD §4.10 全部 6 项功能需求 |
| 实例图谱中 INSTANCE_RELATION 边的 object 为 ENTITY_TYPE | 图谱中出现实例→实体类型的跨层边 | 实例图谱中仅展示 INSTANCE→INSTANCE 边；INSTANCE→ENTITY_TYPE 边在 Schema 图谱的 INSTANCE_OF 边中展示 |
