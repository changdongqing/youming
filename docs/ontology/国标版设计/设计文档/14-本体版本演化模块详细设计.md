## 1. 评审结论与设计边界

### 1.1 现状评审

截至本设计时点，前述 13 个模块已全部落地。在本体版本演化能力方面，代码库现状如下：

| 缺口 | 现状 | 影响 |
|------|------|------|
| **无本体版本概念** | `OntOntologyProject` 实体无 version 字段，仅有 `projectCode`/`projectName`/`description`/审计字段；模块 11（扩展）有 `version` 字段但只是字符串标签，无 diff/兼容性/迁移 | 差距分析 §3.13 指出：本体是长期演化的活资产，需要版本管理（v1.0→v1.1→v2.0）、差异比较、兼容性管理、回滚；现有设计连"本体当前是什么版本"都无法回答 |
| **无版本快照** | 模块 10（序列化）有 `ont_serialization_log` 审计，但那是**导出操作日志**（记录谁在何时导出了什么格式的文件），不是本体版本快照（不包含完整 Schema + 实例的版本化存储） | Schema 变更后无法回到历史版本；无法对比两个版本的差异；无法回答"v1.0 和 v1.1 之间新增了哪些实体类型" |
| **逻辑删除不可回溯** | 模块 04/05/06/07/08 的 `del_flag` 逻辑删除是单线性变更——删除后 `del_flag='1'` 但无版本标记，无法区分"v1.0 删除"和"v1.1 删除" | 无法版本级回滚（恢复到某版本需精确知道该版本有哪些数据） |
| **无 owl:versionIRI 序列化** | 模块 10（序列化）的 `OntologyModelExporter` 不输出 `owl:versionIRI`/`owl:priorVersion`/`owl:backwardCompatibleWith` | 导出的 RDF 文件缺少标准版本声明，不符合 OWL 本体版本管理规范 |
| **无实例迁移策略** | Schema 变更（如给实体类型新增必填属性、删除属性、改值域）后，已存在的实例如何处理无任何机制——类比 Flyway 管 DDL，本体需要管 Schema 演化的"本体迁移" | 差距分析 §3.13：当本体 Schema 变更，已存在的实例如何处理？现有设计无迁移策略 |
| **扩展模块版本游离** | 模块 11（扩展）的 `ont_extension_module.version` 是独立字符串，与本体工程版本无关联 | 扩展模块的版本演化与本体工程版本脱节，无法回答"本体 v1.1 用了哪个版本的扩展模块" |

### 1.2 优化结论

| 级别 | 评审发现 | 优化结论 |
|------|----------|----------|
| P0 | `OntOntologyProject` 无版本字段，本体当前版本不可知 | **为本体工程增加版本模型**：`ont_ontology_project` 新增 `current_version`（当前版本号）字段；新建 `ont_ontology_version` 版本表记录每次版本发布 |
| P0 | 无版本快照机制 | **版本快照表**：新建 `ont_ontology_version_snapshot` 表，存储每次版本发布时的 Schema 快照（实体类型/属性/公理/实例的 JSON 序列化）；快照采用增量存储（仅存储与上一版本的 diff），避免全量冗余 |
| P0 | 无版本差异比较 | **版本 diff 工具**：`OntologyVersionDiffService` 计算两个版本的差异——新增/删除/修改的实体类型、数据属性、对象属性、公理规则、实例；输出结构化 diff 报告 |
| P0 | 无兼容性声明 | **兼容性声明**：版本发布时声明兼容性——`BACKWARD_COMPATIBLE`（向后兼容，旧实例可用）、`BREAKING`（破坏性变更，需实例迁移）、`PATCH`（补丁，仅修 bug 不改 Schema）；对应 OWL 的 `owl:backwardCompatibleWith`/`owl:incompatibleWith` |
| P1 | 无 owl:versionIRI 序列化 | **序列化增强**：模块 10 的 `OntologyModelExporter` 在导出时增加 `owl:versionIRI`/`owl:priorVersion`/`owl:backwardCompatibleWith` 声明 |
| P1 | 无实例迁移策略 | **实例迁移规则**：版本发布时声明迁移规则——新增属性默认值、删除属性清理、值域变更转换；`OntologyInstanceMigrationService` 在版本切换时执行迁移 |
| P1 | 无版本回滚 | **版本回滚**：将本体工程回滚到指定历史版本——恢复 Schema 到快照状态，实例按迁移规则逆向处理（仅向后兼容版本可无损回滚） |
| P2 | 无版本对比可视化 | **前端版本对比页**：双栏 diff 展示（左旧右新），高亮新增（绿）/删除（红）/修改（黄）的 Schema 元素 |

### 1.3 本期范围

**本期包含：**

1. 本体版本模型（`ont_ontology_project` 增加 `current_version` 字段 + 新建 `ont_ontology_version` 版本表 + `ont_ontology_version_snapshot` 快照表）
2. 版本发布服务（`OntologyVersionService`——创建版本、生成快照、声明兼容性）
3. 版本差异比较（`OntologyVersionDiffService`——计算两个版本的 Schema diff）
4. 实例迁移框架（`OntologyInstanceMigrationService`——按迁移规则处理存量实例）
5. 版本回滚（`OntologyVersionRollbackService`——回滚到指定版本）
6. 序列化增强（`OntologyModelExporter` 增加 `owl:versionIRI` 等声明——模块 10 小型增量改造）
7. Flyway V16 迁移脚本（版本表 + 快照表 + 本体工程表字段 + 菜单权限）
8. 前端版本管理页（版本列表、发布对话框、diff 对比页、回滚确认）

**本期不包含：**

- 自动兼容性检测——本期兼容性由人工声明（发布时选择 `BACKWARD_COMPATIBLE`/`BREAKING`/`PATCH`），不做自动推断（远期可基于 diff 规则自动判定）
- 分支版本管理——本期为线性版本（v1.0→v1.1→v2.0），不支持分支（如 feature-branch 并行开发）；远期按需评估
- 跨本体版本联邦——本期仅管理单个本体工程的版本，不支持多本体联合版本
- 版本级 ACL——本期版本数据不设独立权限，继承本体工程权限
- 自动实例迁移规则推断——本期迁移规则由人工配置（JSON 描述），不自动生成
- 实时版本同步——本期版本操作为同步事务，不做分布式版本同步

### 1.4 与前置模块的边界

| 能力 | 前置模块（已完成） | 本模块（版本演化） |
|------|-------------------|-------------------|
| 本体工程 | 实体类型模块（04）`ont_ontology_project` | **扩展**——增加 `current_version` 字段 |
| Schema 数据 | 实体类型（04）/数据属性（05）/对象属性（06）/公理规则（07） | **快照引用**——版本发布时从这些表读取当前 Schema 生成快照 |
| 实例数据 | 实例模块（08）`ont_entity_instance` + `_data_value` + `_object_relation` | **迁移引用**——版本切换时按迁移规则处理存量实例 |
| RDF 序列化 | 序列化模块（10）`OntologyModelExporter` | **增强**——导出时增加 `owl:versionIRI` 等版本声明 |
| 扩展模块版本 | 扩展管理模块（11）`ont_extension_module.version` | **关联**——版本发布时记录当前启用的扩展模块版本 |
| SPARQL 缓存 | SPARQL 端点（13）`OntSparqlCacheManager` | **失效**——版本切换时触发 SPARQL 缓存失效 |
| 序列化日志 | 序列化模块（10）`ont_serialization_log` | **不复用**——序列化日志是导出操作审计，版本快照是 Schema 状态快照，语义不同 |

### 1.5 权威语义口径

1. 版本号遵循 **语义化版本**（Semantic Versioning）：`MAJOR.MINOR.PATCH`（如 `1.0.0`）。
   - **MAJOR**：破坏性变更（删除实体类型/属性、改值域、改公理语义），需实例迁移
   - **MINOR**：向后兼容的新增（新增实体类型/属性/公理），旧实例可用
   - **PATCH**：补丁修正（修标签/定义/排序等非语义字段），不影响实例
2. 版本快照存储 **Schema 增量 diff**——首次发布存储全量 Schema 快照，后续版本仅存储与前一版本的 diff（新增/删除/修改的元素列表），避免全量冗余。全量快照可通过 diff 链式重建。
3. 版本发布是 **不可逆操作**——版本一旦发布不可修改（版本号、快照、兼容性声明固化）；回滚是通过"创建新版本指向旧版本快照"实现，不是删除版本。
4. 兼容性声明对应 **OWL 标准谓词**：
   - `BACKWARD_COMPATIBLE` → `owl:backwardCompatibleWith <priorVersionIRI>`
   - `BREAKING` → `owl:incompatibleWith <priorVersionIRI>`
   - `PATCH` → 不输出兼容性声明（补丁级不涉及 Schema 变更）
5. 实例迁移规则是 **JSON 描述的结构化规则**，非代码：
   ```json
   {
     "rules": [
       {"type": "ADD_PROPERTY_DEFAULT", "entityTypeIri": "...", "propertyIri": "...", "defaultValue": "..."},
       {"type": "REMOVE_PROPERTY", "entityTypeIri": "...", "propertyIri": "..."},
       {"type": "TRANSFORM_VALUE", "propertyIri": "...", "fromType": "TEXT", "toType": "ENUM", "mapping": {...}}
     ]
   }
   ```
6. 版本回滚 **仅向后兼容版本可无损回滚**——如果从 v2.0（BREAKING）回滚到 v1.0，v2.0 新增的实例数据无法自动迁移到 v1.0 Schema（需人工处理）；回滚操作必须二次确认。
7. SPARQL 缓存（模块 13）在版本切换时 **自动失效**——版本回滚/切换后，`OntSparqlCacheManager.evict(ontologyId)` 被调用。
8. **权限模型**：版本发布需 `ontology_version_publish` 权限（管理员/审核员）；版本查看需 `ontology_version_view` 权限（所有角色）；版本回滚需 `ontology_version_rollback` 权限（仅管理员）。
9. **版本快照不可编辑**——快照是只读历史记录，不允许修改；如需修正错误，发布新版本。
10. **附录D初始版本**——附录D种子数据（V10 迁移脚本预置的 29 个实例）对应本体工程的 v1.0.0 版本，作为基线版本。

### 2.3 技术选型

| 组件 | 选型 | 选型理由 |
|------|------|----------|
| 快照存储 | PostgreSQL JSONB | Schema 快照为 JSON 结构，JSONB 支持 GIN 索引查询；无需引入额外存储 |
| 版本号 | 语义化版本 (SemVer) | 行业标准，清晰表达兼容性：MAJOR.BREAKING / MINOR.BACKWARD / PATCH.FIX |
| Diff 算法 | 基于 IRI 的元素级 diff | 本体元素以 IRI 为唯一标识，diff 按 IRI 匹配元素，比较字段级变化；不使用文本 diff |
| 序列化声明 | OWL 标准谓词 | `owl:versionIRI`/`owl:priorVersion`/`owl:backwardCompatibleWith`/`owl:incompatibleWith` |
| 前端 diff 展示 | Element Plus Table + 行级着色 | 新增行绿色背景、删除行红色背景、修改行黄色背景；不引入 monaco-diff-editor（过重） |

## 3. 数据模型

### 3.1 本体版本表（ont_ontology_version）

```sql
-- 本体版本表
CREATE TABLE ont_ontology_version (
  id BIGSERIAL PRIMARY KEY,
  ontology_id BIGINT NOT NULL,                    -- 本体工程ID
  version_number VARCHAR(32) NOT NULL,             -- 语义化版本号 (如 1.0.0)
  version_iri TEXT,                                -- 版本IRI (owl:versionIRI)
  prior_version_id BIGINT,                         -- 前一版本ID (owl:priorVersion)
  compatibility VARCHAR(32) NOT NULL,              -- 兼容性: BACKWARD_COMPATIBLE / BREAKING / PATCH
  release_notes TEXT,                              -- 发布说明
  migration_rules JSONB,                           -- 实例迁移规则 (JSON)
  snapshot_type VARCHAR(16) NOT NULL DEFAULT 'INCREMENTAL', -- FULL / INCREMENTAL
  snapshot_data JSONB NOT NULL,                    -- 快照数据 (全量JSON或增量diff JSON)
  element_counts JSONB,                            -- 元素统计 ( entityTypeCount, dataPropertyCount, ... )
  is_current BOOLEAN DEFAULT FALSE,                -- 是否当前版本
  published_by VARCHAR(64) NOT NULL,                -- 发布人
  published_at TIMESTAMP NOT NULL DEFAULT NOW(),    -- 发布时间
  del_flag CHAR(1) DEFAULT '0' NOT NULL,
  UNIQUE(ontology_id, version_number),
  FOREIGN KEY (ontology_id) REFERENCES ont_ontology_project(id)
);
CREATE INDEX idx_ontology_version_project ON ont_ontology_version (ontology_id);
CREATE INDEX idx_ontology_version_current ON ont_ontology_version (ontology_id, is_current) WHERE is_current = true;
COMMENT ON TABLE ont_ontology_version IS '本体版本表';
```

## 4. 核心设计

### 4.1 版本发布流程

```
用户在前端发起版本发布
  → 前端 POST /ontology/versions/publish { ontologyId, versionNumber, compatibility, releaseNotes, migrationRules }
  → 后端 OntologyVersionController 接收请求
  → OntologyVersionService.publishVersion(request)
    ├── 1. 校验版本号
    │     ├── 格式校验 (SemVer: \d+\.\d+\.\d+)
    │     ├── 唯一性校验 (同一 ontologyId 下版本号不重复)
    │     └── 递增校验 (新版本号必须大于当前版本号)
    ├── 2. 获取当前版本 (priorVersion)
    │     └── 如果是首次发布 → snapshot_type=FULL
    │     └── 如果有前版本 → snapshot_type=INCREMENTAL
    ├── 3. 构建快照 (OntologySnapshotBuilder)
    │     ├── FULL: 从关系库读取全部 Schema + 实例 → 序列化为 JSON
    │     └── INCREMENTAL: 与前一版本快照比较 → 生成 diff JSON
    ├── 4. 计算元素统计 (elementCounts)
    ├── 5. 生成版本IRI (version_iri_prefix + version_number)
    ├── 6. 持久化版本记录 (ont_ontology_version 表)
    ├── 7. 更新本体工程当前版本 (ont_ontology_project.current_version_id)
    ├── 8. 如果有迁移规则 → 执行实例迁移 (OntologyInstanceMigrationService)
    ├── 9. 触发 SPARQL 缓存失效 (OntSparqlCacheManager.evict)
    └── 10. 返回版本 VO
  → 前端刷新版本列表
```

### 4.2 快照构建器

```java
/**
 * 本体快照构建器。
 * <p>
 * 从关系库读取 Schema + 实例数据，组装为版本快照 JSON。
 * 支持全量快照和增量快照（diff）。
 * </p>
 */
@Component
@Slf4j
@RequiredArgsConstructor
public class OntologySnapshotBuilder {

    private final OntEntityTypeMapper entityTypeMapper;
    private final OntEntityTypeHierarchyMapper hierarchyMapper;
    private final OntEntityTypeDisjointMapper disjointMapper;
    private final OntEntityTypeEquivalentMapper equivalentMapper;
    private final OntDataPropertyMapper dataPropertyMapper;
    private final OntDataPropertyEnumMapper dataPropertyEnumMapper;
    private final OntObjectPropertyMapper objectPropertyMapper;
    private final OntObjectPropertyDomainMapper objectPropertyDomainMapper;
    private final OntObjectPropertyRangeMapper objectPropertyRangeMapper;
    private final OntAxiomRuleMapper axiomRuleMapper;
    private final OntEntityInstanceMapper instanceMapper;
    private final OntExtensionModuleMapper extensionModuleMapper;
    private final OntNamespaceMapper namespaceMapper;
    private final ObjectMapper objectMapper;

    /**
     * 构建全量快照。
     */
    public String buildFullSnapshot(Long ontologyId) {
        SnapshotData snapshot = new SnapshotData();

        // 1. 实体类型（含继承/不相交/等价）
        snapshot.setEntityTypes(buildEntityTypeSnapshots(ontologyId));

        // 2. 数据属性（含枚举）
        snapshot.setDataProperties(buildDataPropertySnapshots(ontologyId));

        // 3. 对象属性（含域/值域）
        snapshot.setObjectProperties(buildObjectPropertySnapshots(ontologyId));

        // 4. 公理规则
        snapshot.setAxiomRules(buildAxiomRuleSnapshots(ontologyId));

        // 5. 实例（IRI + rdf:type + label，不含属性值——属性值量大，按需快照）
        snapshot.setInstances(buildInstanceSnapshots(ontologyId));

        // 6. 扩展模块
        snapshot.setExtensionModules(buildExtensionModuleSnapshots(ontologyId));

        return objectMapper.writeValueAsString(snapshot);
    }

    /**
     * 构建增量快照（与基准快照的 diff）。
     */
    public String buildIncrementalSnapshot(Long ontologyId, String baseSnapshotJson) {
        String currentSnapshot = buildFullSnapshot(ontologyId);
        SnapshotData base = objectMapper.readValue(baseSnapshotJson, SnapshotData.class);
        SnapshotData current = objectMapper.readValue(currentSnapshot, SnapshotData.class);

        IncrementalDiff diff = new IncrementalDiff();
        diff.setBaseVersionId(null); // 由调用方设置

        // 按 IRI 匹配计算 diff
        diff.setAdded(computeAdded(base, current));
        diff.setRemoved(computeRemoved(base, current));
        diff.setModified(computeModified(base, current));

        return objectMapper.writeValueAsString(diff);
    }

    /**
     * 链式重建全量快照（从增量 diff 重建）。
     * <p>
     * 从首个 FULL 版本开始，逐个应用 INCREMENTAL diff，重建指定版本的全量快照。
     * </p>
     */
    public String reconstructSnapshot(Long ontologyId, Long targetVersionId) {
        // 1. 查询从首版到目标版本的全部版本记录（按时间排序）
        List<OntOntologyVersion> versions = versionMapper.selectList(
            Wrappers.<OntOntologyVersion>lambdaQuery()
                .eq(OntOntologyVersion::getOntologyId, ontologyId)
                .le(OntOntologyVersion::getId, targetVersionId)
                .orderByAsc(OntOntologyVersion::getPublishedAt));

        // 2. 找到首个 FULL 快照作为基准
        OntOntologyVersion fullVersion = versions.stream()
            .filter(v -> "FULL".equals(v.getSnapshotType()))
            .reduce((first, second) -> second) // 最后一个 FULL
            .orElseThrow(() -> new IllegalStateException("无全量快照基准"));

        SnapshotData snapshot = objectMapper.readValue(
            fullVersion.getSnapshotData(), SnapshotData.class);

        // 3. 逐个应用增量 diff
        for (OntOntologyVersion v : versions) {
            if (v.getId().equals(fullVersion.getId())) continue;
            if ("INCREMENTAL".equals(v.getSnapshotType())) {
                IncrementalDiff diff = objectMapper.readValue(
                    v.getSnapshotData(), IncrementalDiff.class);
                snapshot = applyDiff(snapshot, diff);
            }
        }
        return objectMapper.writeValueAsString(snapshot);
    }
}
```

### 4.3 版本差异比较

```java
/**
 * 版本差异计算服务。
 */
@Service
@Slf4j
@RequiredArgsConstructor
public class OntologyVersionDiffService {

    private final OntologySnapshotBuilder snapshotBuilder;
    private final OntOntologyVersionMapper versionMapper;
    private final ObjectMapper objectMapper;

    /**
     * 计算两个版本的差异。
     */
    public VersionDiffVO diff(Long fromVersionId, Long toVersionId) {
        // 1. 重建两个版本的全量快照
        OntOntologyVersion fromVersion = versionMapper.selectById(fromVersionId);
        OntOntologyVersion toVersion = versionMapper.selectById(toVersionId);

        SnapshotData fromSnapshot = reconstructFullSnapshot(fromVersion);
        SnapshotData toSnapshot = reconstructFullSnapshot(toVersion);

        // 2. 按 IRI 匹配计算差异
        VersionDiffVO diff = new VersionDiffVO();
        diff.setFromVersion(toVersionVO(fromVersion));
        diff.setToVersion(toVersionVO(toVersion));

        // 实体类型 diff
        diffEntityTypes(diff, fromSnapshot, toSnapshot);
        // 数据属性 diff
        diffDataProperties(diff, fromSnapshot, toSnapshot);
        // 对象属性 diff
        diffObjectProperties(diff, fromSnapshot, toSnapshot);
        // 公理规则 diff
        diffAxiomRules(diff, fromSnapshot, toSnapshot);
        // 实例 diff
        diffInstances(diff, fromSnapshot, toSnapshot);

        // 摘要统计
        diff.setSummary(computeSummary(diff));
        return diff;
    }

    /**
     * 实体类型差异计算。
     */
    private void diffEntityTypes(VersionDiffVO diff, SnapshotData from, SnapshotData to) {
        Map<String, EntityTypeSnapshot> fromMap = from.getEntityTypes().stream()
            .collect(Collectors.toMap(EntityTypeSnapshot::getIri, Function.identity()));
        Map<String, EntityTypeSnapshot> toMap = to.getEntityTypes().stream()
            .collect(Collectors.toMap(EntityTypeSnapshot::getIri, Function.identity()));

        // 新增：在 to 中但不在 from 中
        diff.setAddedEntityTypes(toMap.keySet().stream()
            .filter(iri -> !fromMap.containsKey(iri))
            .map(iri -> toDiffElement(toMap.get(iri)))
            .collect(Collectors.toList()));

        // 删除：在 from 中但不在 to 中
        diff.setRemovedEntityTypes(fromMap.keySet().stream()
            .filter(iri -> !toMap.containsKey(iri))
            .map(iri -> toDiffElement(fromMap.get(iri)))
            .collect(Collectors.toList()));

        // 修改：两边都有但字段不同
        List<ModifiedElementVO> modified = new ArrayList<>();
        for (String iri : fromMap.keySet()) {
            if (toMap.containsKey(iri)) {
                List<FieldChangeVO> changes = compareFields(fromMap.get(iri), toMap.get(iri));
                if (!changes.isEmpty()) {
                    ModifiedElementVO mod = new ModifiedElementVO();
                    mod.setIri(iri);
                    mod.setName(toMap.get(iri).getName());
                    mod.setChanges(changes);
                    modified.add(mod);
                }
            }
        }
        diff.setModifiedEntityTypes(modified);
    }
}
```

```java
@Service
@Slf4j
@RequiredArgsConstructor
public class OntologyInstanceMigrationService {

    private final OntEntityInstanceMapper instanceMapper;
    private final OntInstanceDataValueMapper dataValueMapper;
    private final OntDataPropertyMapper dataPropertyMapper;
    private final OntEntityTypeMapper entityTypeMapper;

    /**
     * 预览迁移影响。
     */
    public MigrationPreviewVO previewMigration(Long ontologyId, MigrationRules rules) {
        MigrationPreviewVO preview = new MigrationPreviewVO();
        int affectedCount = 0;
        List<String> warnings = new ArrayList<>();

        for (MigrationRule rule : rules.getRules()) {
            switch (rule.getType()) {
                case "ADD_PROPERTY_DEFAULT":
                    int count = countInstancesByEntityType(ontologyId, rule.getEntityTypeIri());
                    affectedCount += count;
                    break;
                case "REMOVE_PROPERTY":
                    int removeCount = countInstancesWithProperty(ontologyId, rule.getPropertyIri());
                    affectedCount += removeCount;
                    break;
                case "TRANSFORM_VALUE":
                    int transformCount = countInstancesWithProperty(ontologyId, rule.getPropertyIri());
                    affectedCount += transformCount;
                    warnings.add("TRANSFORM_VALUE 需人工确认值映射完整性");
                    break;
                case "RENAME_PROPERTY":
                    // 重命名不影响实例数量，但需更新属性引用
                    break;
            }
        }

        preview.setEstimatedAffectedInstances(affectedCount);
        preview.setWarnings(warnings);
        return preview;
    }

    /**
     * 执行迁移。
     */
    @Transactional(rollbackFor = Exception.class)
    public MigrationResultVO migrate(Long ontologyId, MigrationRules rules) {
        MigrationResultVO result = new MigrationResultVO();
        int totalProcessed = 0;

        for (MigrationRule rule : rules.getRules()) {
            switch (rule.getType()) {
                case "ADD_PROPERTY_DEFAULT":
                    totalProcessed += addPropertyDefault(ontologyId, rule);
                    break;
                case "REMOVE_PROPERTY":
                    totalProcessed += removeProperty(ontologyId, rule);
                    break;
                case "TRANSFORM_VALUE":
                    totalProcessed += transformValue(ontologyId, rule);
                    break;
                case "RENAME_PROPERTY":
                    totalProcessed += renameProperty(ontologyId, rule);
                    break;
            }
        }

        result.setProcessedCount(totalProcessed);
        result.setMigratedAt(LocalDateTime.now());
        return result;
    }

    /**
     * 新增属性默认值。
     */
    private int addPropertyDefault(Long ontologyId, MigrationRule rule) {
        // 查询该实体类型的全部实例
        Long entityTypeId = entityTypeMapper.selectOne(...).getId();
        List<OntEntityInstance> instances = instanceMapper.selectList(
            Wrappers.<OntEntityInstance>lambdaQuery()
                .eq(OntEntityInstance::getOntologyId, ontologyId)
                .eq(OntEntityInstance::getRdfTypeId, entityTypeId));

        Long propertyId = dataPropertyMapper.selectOne(...).getId();
        for (OntEntityInstance inst : instances) {
            OntInstanceDataValue dv = new OntInstanceDataValue();
            dv.setInstanceId(inst.getId());
            dv.setDataPropertyId(propertyId);
            dv.setLiteralValue(rule.getDefaultValue());
            dv.setLiteralType("TEXT");
            dataValueMapper.insert(dv);
        }
        return instances.size();
    }
```

### 4.5 版本回滚服务

```java
/**
 * 版本回滚服务。
 */
@Service
@Slf4j
@RequiredArgsConstructor
public class OntologyVersionRollbackService {

    private final OntologyVersionService versionService;
    private final OntologySnapshotBuilder snapshotBuilder;
    private final OntologyInstanceMigrationService migrationService;

    /**
     * 回滚到指定版本。
     * <p>
     * 回滚不是删除版本，而是创建一个新版本，其快照指向目标版本。
     * 如果目标版本与当前版本之间有 BREAKING 变更，回滚需人工确认。
     * </p>
     */
    @Transactional(rollbackFor = Exception.class)
    public RollbackResultVO rollback(Long ontologyId, Long targetVersionId, Boolean confirmed) {
        OntOntologyVersion targetVersion = versionService.getById(targetVersionId);
        OntOntologyVersion currentVersion = versionService.getCurrentVersion(ontologyId);

        // 1. 检查中间是否有 BREAKING 变更
        boolean hasBreaking = checkBreakingBetween(currentVersion.getId(), targetVersionId);
        if (hasBreaking && !Boolean.TRUE.equals(confirmed)) {
            throw new OntVersionException(
                "回滚路径中存在 BREAKING 版本，存量实例可能无法自动回退，需二次确认");
        }

        // 2. 重建目标版本的全量快照
        String fullSnapshot = snapshotBuilder.reconstructSnapshot(ontologyId, targetVersionId);

        // 3. 创建回滚版本（新版本，指向目标版本快照）
        VersionPublishRequest rollbackReq = new VersionPublishRequest();
        rollbackReq.setOntologyId(ontologyId);
        rollbackReq.setVersionNumber(incrementPatch(currentVersion.getVersionNumber()) + "-rollback");
        rollbackReq.setCompatibility("PATCH");
        rollbackReq.setReleaseNotes("回滚到版本 " + targetVersion.getVersionNumber());
        rollbackReq.setSnapshotType("FULL");
        rollbackReq.setSnapshotData(fullSnapshot);

        OntOntologyVersion rollbackVersion = versionService.publishVersion(rollbackReq);

        // 4. Schema 恢复（从快照恢复到关系库）
        restoreSchemaFromSnapshot(ontologyId, fullSnapshot);

        // 5. 触发 SPARQL 缓存失效
        // (由 versionService 内部触发)

        RollbackResultVO result = new RollbackResultVO();
        result.setRollbackVersionId(rollbackVersion.getId());
        result.setTargetVersionId(targetVersionId);
        result.setSchemaRestored(true);
        result.setWarning(hasBreaking ? "存在BREAKING变更，实例数据可能需人工处理" : null);
        return result;
    }
}
```

## 7. Flyway 迁移脚本（V16）

```sql
-- ============================================================
-- V16__ontology_versioning.sql
-- 本体版本演化模块
-- 对应差距分析: §3.13 维度⑬ 本体版本演化
-- ============================================================

-- 1. 本体工程表增加版本字段
ALTER TABLE ont_ontology_project ADD COLUMN IF NOT EXISTS current_version_id BIGINT;
ALTER TABLE ont_ontology_project ADD COLUMN IF NOT EXISTS version_iri_prefix TEXT;
COMMENT ON COLUMN ont_ontology_project.current_version_id IS '当前版本ID';
COMMENT ON COLUMN ont_ontology_project.version_iri_prefix IS '版本IRI前缀';

-- 2. 本体版本表
CREATE TABLE IF NOT EXISTS ont_ontology_version (
  id BIGSERIAL PRIMARY KEY,
  ontology_id BIGINT NOT NULL,
  version_number VARCHAR(32) NOT NULL,
  version_iri TEXT,
  prior_version_id BIGINT,
  compatibility VARCHAR(32) NOT NULL,
  release_notes TEXT,
  migration_rules JSONB,
  snapshot_type VARCHAR(16) NOT NULL DEFAULT 'INCREMENTAL',
  snapshot_data JSONB NOT NULL,
  element_counts JSONB,
  is_current BOOLEAN DEFAULT FALSE,
  published_by VARCHAR(64) NOT NULL,
  published_at TIMESTAMP NOT NULL DEFAULT NOW(),
  create_by VARCHAR(64) DEFAULT ' ',
  update_by VARCHAR(64) DEFAULT ' ',
  create_time TIMESTAMP DEFAULT NOW(),
  update_time TIMESTAMP DEFAULT NOW(),
  del_flag CHAR(1) DEFAULT '0' NOT NULL,
  UNIQUE(ontology_id, version_number)
);
CREATE INDEX IF NOT EXISTS idx_ontology_version_project ON ont_ontology_version (ontology_id);
CREATE INDEX IF NOT EXISTS idx_ontology_version_current ON ont_ontology_version (ontology_id, is_current) WHERE is_current = true AND del_flag = '0';

COMMENT ON TABLE ont_ontology_version IS '本体版本表';
COMMENT ON COLUMN ont_ontology_version.version_number IS '语义化版本号 MAJOR.MINOR.PATCH';
COMMENT ON COLUMN ont_ontology_version.version_iri IS '版本IRI (owl:versionIRI)';
COMMENT ON COLUMN ont_ontology_version.prior_version_id IS '前一版本ID (owl:priorVersion)';
COMMENT ON COLUMN ont_ontology_version.compatibility IS '兼容性 BACKWARD_COMPATIBLE/BREAKING/PATCH';
COMMENT ON COLUMN ont_ontology_version.migration_rules IS '实例迁移规则 JSON';
COMMENT ON COLUMN ont_ontology_version.snapshot_type IS '快照类型 FULL/INCREMENTAL';
COMMENT ON COLUMN ont_ontology_version.snapshot_data IS '快照数据 (全量JSON或增量diff JSON)';
COMMENT ON COLUMN ont_ontology_version.element_counts IS '元素统计 JSON';

-- 3. 为已有本体工程创建基线版本 v1.0.0
INSERT INTO ont_ontology_version (ontology_id, version_number, version_iri, compatibility, release_notes, snapshot_type, snapshot_data, element_counts, is_current, published_by, published_at)
SELECT
  p.id,
  '1.0.0',
  COALESCE(p.version_iri_prefix, 'http://example.org/standard-ontology/') || '1.0.0/',
  'BACKWARD_COMPATIBLE',
  '基线版本 - 附录D GB/T 31486—2024 初始实例化',
  'FULL',
  '{}'::jsonb,
  '{}'::jsonb,
  TRUE,
  'system',
  NOW()
FROM ont_ontology_project p
WHERE p.del_flag = '0'
  AND NOT EXISTS (
    SELECT 1 FROM ont_ontology_version v
    WHERE v.ontology_id = p.id AND v.version_number = '1.0.0' AND v.del_flag = '0'
  );

-- 更新本体工程的当前版本ID
UPDATE ont_ontology_project p
SET current_version_id = (
  SELECT id FROM ont_ontology_version v
  WHERE v.ontology_id = p.id AND v.version_number = '1.0.0' AND v.del_flag = '0'
  LIMIT 1
)
WHERE p.del_flag = '0' AND p.current_version_id IS NULL;

-- 4. 菜单与权限注册
INSERT INTO sys_menu (menu_id, name, permission, path, component, parent_id, menu_type, sort_order, del_flag, create_time) VALUES
(901300, '版本管理', NULL, '/ontology/version/index', 'ontology/version/index', 900000, '0', 13, '0', NOW()),
(901301, '版本查看', 'ontology_version_view', NULL, NULL, 901300, '1', 1, '0', NOW()),
(901302, '版本发布', 'ontology_version_publish', NULL, NULL, 901300, '1', 2, '0', NOW()),
(901303, '版本回滚', 'ontology_version_rollback', NULL, NULL, 901300, '1', 3, '0', NOW())
ON CONFLICT (menu_id) DO NOTHING;

-- 5. 角色权限分配
INSERT INTO sys_role_menu (role_id, menu_id) VALUES
(1, 901300), (1, 901301), (1, 901302), (1, 901303),  -- 管理员
(2, 901300), (2, 901301),                              -- 建模工程师（查看+发布需审核员审批）
(3, 901300), (3, 901301), (3, 901302),                 -- 审核员（查看+发布）
(4, 901301)                                            -- 访客仅查看
ON CONFLICT (role_id, menu_id) DO NOTHING;

-- 6. 迁移完整性校验
DO $$ BEGIN
  IF NOT EXISTS (SELECT 1 FROM information_schema.columns WHERE table_name = 'ont_ontology_project' AND column_name = 'current_version_id') THEN
    RAISE EXCEPTION 'V16: ont_ontology_project.current_version_id 字段添加失败';
  END IF;
  IF NOT EXISTS (SELECT 1 FROM information_schema.tables WHERE table_name = 'ont_ontology_version') THEN
    RAISE EXCEPTION 'V16: ont_ontology_version 表创建失败';
  END IF;
  IF NOT EXISTS (SELECT 1 FROM sys_menu WHERE menu_id = 901300) THEN
    RAISE EXCEPTION 'V16: 版本管理菜单注册失败';
  END IF;
  RAISE NOTICE 'V16__ontology_versioning 完成';
END $$;
```

### 验收用例

| 用例 | 操作 | 预期 |
|------|------|------|
| 基线版本 | V16 迁移后 | 已有本体工程自动生成 v1.0.0 基线版本 |
| 发布新版本 | 新增一个扩展实体类型后发布 v1.1.0 | 快照为 INCREMENTAL，diff 显示新增 1 个实体类型 |
| 版本 diff | 查看 v1.0.0 → v1.1.0 | 显示新增元素列表 |
| 序列化增强 | 导出 v1.1.0 的 Turtle | 包含 `owl:versionIRI`/`owl:priorVersion`/`owl:backwardCompatibleWith` |
| 实例迁移 | 发布 v1.2.0 带 ADD_PROPERTY_DEFAULT 规则 | 存量实例新增默认值 |
| 回滚 | 从 v1.1.0 回滚到 v1.0.0 | 创建回滚版本，Schema 恢复 |
| 回滚拦截 | 路径含 BREAKING 且未确认 | 抛出异常需二次确认 |
