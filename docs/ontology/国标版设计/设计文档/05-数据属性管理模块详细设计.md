# 数据属性管理模块详细设计

> 对应 PRD：§2.5、§3.3、§4.3、§4.11、§5、§6.2.2、§7.1、§14.2、§14.3
>
> 直接依据：GB/T 48000.3—2026 第6.2条、第7.2条、附录A.2、附录A.3、附录C、附录D
>
> 前置模块：01-模块化架构、02-单位字典、03-命名空间与IRI、04-实体类型（均已实现）
>
> 评审优化日期：2026-07-10

## 1. 评审结论

原设计的模块划分、`ont_` 表前缀、Flyway V7、后端包位置、前端左树右表布局等总体方向可复用，但存在会导致国标数据缺失、IRI 不稳定或后续实例校验错误的阻断问题。本次评审已直接修订，关键结论如下。

| 级别 | 原设计问题 | 优化结论 |
|------|------------|----------|
| P0 | 将附录C的47项与条款直采、附录D兼容属性混为47条，实际遗漏相关方、领域类别、要素、生效时间等大量国标属性，并加入非国标属性 | 严格按表C.1～表C.47建立连续映射；条款直采2项、附录D兼容7项使用独立编号段和来源类型，合计预置56条受保护属性 |
| P0 | `constraintType` 跨定义域重名时按“当前库中是否已有”动态加后缀，生成结果依赖插入顺序，且丢失国标原始IRI | 增加 `iri_local_name` 与 `standard_iri`；3个核心冲突项使用固定、确定性的内部IRI，同时保留国标 `#constraintType` 溯源值；扩展属性不再隐式改写既有IRI |
| P0 | 将 `maxValue`、`minValue`、`measurementUnit` 固定绑定无量纲分类，导致 V/W/℃ 等国标合法单位无法使用 | 三者均不预绑定单位分类；`NULL` 表示不限分类，实例层按同一约束对象中的单位引用校验量纲一致性 |
| P0 | 将附录C表C.41的标准属性直接建模为 `measurementUnit` | 标准名称和标准IRI保持 `unit/#unit`，增加首选兼容别名 `measurementUnit`；默认UI和附录D导出可显示别名，严格国标导出使用 `unit` |
| P0 | `propertyValue` 被简化为TEXT，无法表达附录C的 `xsd:string 或 xsd:decimal` | 增加平台复合值域 `TEXT_OR_NUMERIC`，实例层必须携带实际字面量类型，导出为 `xsd:string` 或 `xsd:decimal` |
| P1 | 枚举被视为仅TEXT可用且全部闭集；遗漏“描述”“约束型”，也无法表达“等”所代表的开放集合 | 引入 `value_mode`：自由值、闭合枚举、开放枚举、外部字典、单位字典；枚举值保留标准/兼容来源标记 |
| P1 | 只改造实体类型属性查询，未补实体类型删除、命名空间修改/删除、单位分类删除的引用保护 | V7开发必须同步改造三个前置服务，避免外键异常、IRI失配或语义约束被静默解除 |
| P1 | `R<List<Object>>` 保持原泛型但实际返回详情VO，类型不安全；页面“分页查询”和“含继承查询”语义混用 | 改为明确的摘要VO、详情VO、适用属性VO；选中实体类型调用非分页适用属性接口，“全部”场景调用分页接口 |
| P1 | 迁移断言只校验数量，无法发现“数量正确但内容错误” | 增加表C编号、名称、定义域、值域、来源类型、冲突IRI、单位别名及枚举集合的精确断言 |

### 1.1 本期边界

本模块管理的是 **Schema 层数据属性定义**，不在关系库中保存实体实例的数据属性值。本期包含：

1. 数据属性定义 CRUD、查询、来源标识和内置保护；
2. 附录A.2七项元数据映射；
3. 附录A.3值域、枚举、正则、格式、唯一性和单位字典约束；
4. 附录C 47项完整预置；
5. 第6.2.5.1条“术语名称/术语定义”预置；
6. 附录D实例复现所需、但未列入附录C的7个兼容属性预置；
7. 按定义域查询直接属性和继承属性；
8. 与实体类型、命名空间、单位分类的引用保护联动。

本期不包含：实例值持久化、SHACL执行、RDF/OWL实际导出、运行时属性多定义域编辑、枚举字典独立管理页面。这些能力由后续实例、校验、序列化模块实现，但本设计给出稳定契约。

## 2. 领域模型与本体语义

### 2.1 附录A.2七项元数据映射

| 国标描述项 | 平台字段/结构 | 说明 |
|------------|---------------|------|
| IRI | `ont_data_property.iri`、`standard_iri` | `iri` 是平台内部唯一IRI；`standard_iri` 保存国标原始IRI，可重复 |
| Name | `ont_data_property.name` | 保留国标或用户定义的元数据名称，不因内部IRI消歧而改写 |
| Label | `ont_data_property_label` | 首期预置 `zh`，支持后续多语言 |
| Definition | `definition` | 核心种子按国标含义落库；用户扩展可维护 |
| Domain | `domain_entity_type_id` | 首期一个属性定义绑定一个直接定义域；适用范围可通过实体类型继承扩展 |
| Range | `base_type` + `value_mode` + 约束字段 | 关系型展开存储，详见§2.3 |
| TypeofTerms | 常量 `owl:DatatypeProperty` | 数据属性模块内恒定，不冗余落库 |

### 2.2 内部IRI、国标IRI与别名

国标附录C中 `constraintType` 同时用于 Standard、Clause、Constraint，并给出相同 `#constraintType`。若在OWL中直接对同一属性声明多个独立 `rdfs:domain`，语义是定义域交集，而不是“按类重载”，会错误推导一个使用者同时属于三个类。因此平台不能仅靠重复输出同一IRI解决冲突。

本期采用“**内部唯一IRI + 国标IRI溯源 + 序列化策略选择**”方案：

| 定义域 | `name` | `iri_local_name` | 平台 `iri` 后缀 | `standard_iri` 后缀 |
|--------|--------|------------------|---------------------|---------------------|
| Standard | constraintType | constraintTypeStandard | `#constraintTypeStandard` | `#constraintType` |
| Clause | constraintType | constraintTypeClause | `#constraintTypeClause` | `#constraintType` |
| Constraint | constraintType | constraintTypeConstraint | `#constraintTypeConstraint` | `#constraintType` |

规则：

1. 平台运行、引用、外键索引、默认OWL导出均使用唯一 `iri`，避免定义域交集错误。
2. `standard_iri` 只用于标准溯源、导入识别和严格兼容策略，不建唯一索引。
3. 严格国标导出若折叠为 `#constraintType`，序列化模块不得简单输出三个 `rdfs:domain`；应使用类级 SHACL Shape 表达不同枚举约束，并显式标记这是兼容输出。
4. 扩展属性创建时 `iriLocalName` 缺省等于 `name`。若发生冲突，后端返回冲突并给出 `name + DomainName` 建议，不允许因插入先后自动修改既有记录IRI。
5. 扩展属性更新 `name` 时不自动修改 `iriLocalName/iri`；IRI变更必须显式提交，并在后续被公理或实例引用后禁止修改。
6. 表C.41保持 `name=unit`、`iri_local_name=unit`、`standard_iri=#unit`，`preferred_alias=measurementUnit`。列表VO提供 `displayName`，默认取别名，严格国标视图显示 `unit`。

### 2.3 值域模型

`base_type` 取值如下：

| 平台类型 | 国标/OWL映射 | 实例层要求 |
|----------|--------------|------------|
| `BOOLEAN` | `xsd:boolean` | 规范化为 `true/false` |
| `DATE` | `xsd:date` | API允许 `YYYYMMDD` 或 `YYYY-MM-DD`；内部校验规范化，RDF输出 `YYYY-MM-DD` |
| `NUMERIC` | `xsd:decimal`，无小数时可输出 `xsd:integer` | 禁止将单位拼入数字字面量 |
| `TEXT` | `xsd:string` | 普通文本 |
| `URI` | `xsd:anyURI` | URI语法校验 |
| `UNIT_REF` | 平台派生类型，RDF为单位符号字符串或单位IRI | 必须引用有效 `ont_unit`；不可退化为任意文本 |
| `TEXT_OR_NUMERIC` | `xsd:string` 或 `xsd:decimal` | 用于表C.35 `propertyValue`；实例请求须携带实际字面量类型 |

`value_mode` 取值如下：

| 模式 | 含义 | 本地枚举表 |
|------|------|------------|
| `FREE` | 自由值，可附加正则/格式 | 不使用 |
| `CLOSED_ENUM` | 只允许预置枚举值 | 必须至少1条 |
| `OPEN_ENUM` | 预置推荐值，但允许其他合法值 | 可有0～N条 |
| `EXTERNAL_DICTIONARY` | 值来自外部分类字典，如ICS/CCS | 不在本表批量预置，使用 `value_source_ref` 标识来源 |
| `UNIT_DICTIONARY` | 值引用 `ont_unit` | `base_type` 必须为 `UNIT_REF` |

说明：

- “V、W、℃等”“描述型、能力型、约束型……”中的“等/……”必须建模为开放集合。
- `constraintType(Constraint)` 的附录C推荐值为“数值区间、枚举值、逻辑表达式”，附录D又使用“符合性、相对值”，因此设为 `OPEN_ENUM`，五个值均预置并标记来源。
- `ICS_code/ICS_name/CCS_code/CCS_name` 设为 `EXTERNAL_DICTIONARY`，本期只保存来源代码，不把完整分类表复制进属性枚举表。
- 唯一性约束固定解释为“同一本体工程内、同一数据属性IRI的规范化值唯一”，由实例模块实现；Schema表本身不为实例值建立唯一索引。

### 2.4 属性继承/适用性

数据属性本身仍只有一个直接定义域。若实体类型B是A的子类，则A定义域上的数据属性对B实例适用。平台按实体类型DAG向上查询祖先类型实现该规则：

1. 返回当前类型直接属性和所有祖先类型属性；
2. 多继承路径命中同一属性时按属性ID去重；
3. 返回 `inherited`、`inheritanceDistance`、`declaredDomainEntityTypeId`，禁止前端根据当前树位置自行猜测；
4. 直接属性优先，其次继承距离升序，再按 `sort_order/id` 排序；
5. DAG遍历沿用实体类型模块的显式队列、访问集合和100层上限；
6. Clause(940040)应继承 InformationUnit(940048) 的 `uniqueIdentifier/contentDescription`，不得再创建Clause定义域的重复 `uniqueIdentifier`。

## 3. 数据模型

> 对齐现有实现：PostgreSQL、`ont_` 前缀、MyBatis-Plus `ASSIGN_ID`、`char(1)`布尔、审计字段、逻辑删除、Flyway增量迁移。

### 3.1 主表 `ont_data_property`

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `id` | bigint | 是 | MyBatis-Plus `ASSIGN_ID`；核心种子使用固定ID |
| `iri` | varchar(512) | 是 | 平台内部全局唯一IRI |
| `iri_local_name` | varchar(128) | 是 | 实际拼接IRI的本地名；扩展属性默认等于 `name` |
| `standard_iri` | varchar(512) | 否 | 国标原始IRI；允许因国标重名而重复 |
| `name` | varchar(128) | 是 | 附录A.2 Name；核心值保持国标原名 |
| `preferred_alias` | varchar(128) | 否 | UI/兼容导入导出的首选别名，如 `measurementUnit` |
| `definition` | varchar(512) | 否 | 定义 |
| `domain_entity_type_id` | bigint | 是 | 直接定义域，引用 `ont_entity_type.id` |
| `base_type` | varchar(32) | 是 | §2.3定义的7种平台值域类型 |
| `value_mode` | varchar(32) | 是 | `FREE/CLOSED_ENUM/OPEN_ENUM/EXTERNAL_DICTIONARY/UNIT_DICTIONARY` |
| `value_source_ref` | varchar(64) | 否 | 外部值源代码，如 `ICS`、`CCS` |
| `regex_pattern` | varchar(512) | 否 | 正则约束 |
| `format_hint` | varchar(255) | 否 | 人类可读格式提示；不是唯一校验手段 |
| `is_unique` | char(1) | 是 | 实例值是否在本体工程内唯一 |
| `unit_category_id` | bigint | 否 | 可选单位分类限制；NULL表示不限分类 |
| `unit_ref_mode` | varchar(32) | 否 | `DICTIONARY_SYMBOL`；仅UNIT_REF使用 |
| `source_type` | varchar(32) | 是 | `APPENDIX_C/CLAUSE_REQUIRED/APPENDIX_D_COMPAT/EXTENSION` |
| `source_reference` | varchar(64) | 否 | 如 `C.41`、`6.2.5.1`、`D-Step5` |
| `is_builtin` | char(1) | 是 | 前三种来源固定为1，用户扩展为0 |
| `ontology_id` | bigint | 是 | 引用 `ont_ontology_project.id`，首期默认935001 |
| `namespace_id` | bigint | 是 | 引用 `ont_namespace.id` |
| `sort_order` | integer | 是 | 排序 |
| `remarks` | varchar(255) | 否 | 平台治理备注，不作为标准定义导出 |
| 审计/逻辑删除字段 | — | — | `create_by/create_time/update_by/update_time/del_flag` |

核心约束：

1. `iri` 在有效数据中全局唯一；`standard_iri` 不唯一。
2. `(ontology_id, namespace_id, iri_local_name)` 在有效数据中唯一。
3. `(ontology_id, namespace_id, domain_entity_type_id, name)` 在有效数据中唯一。
4. `preferred_alias` 在同一工程和命名空间内不得与其他有效记录的 `iri_local_name/preferred_alias` 冲突；跨列冲突由Service校验，迁移断言兜底。
5. `iri = namespace.uri + iri_local_name`，后端为权威生成方。
6. `unit_category_id` 外键使用 `ON DELETE RESTRICT`，禁止删除分类后静默放宽属性语义。
7. `domain_entity_type_id`、`ontology_id`、`namespace_id` 均使用 `ON DELETE RESTRICT`。
8. 核心/兼容属性的来源、IRI、名称、定义域、值域、约束、中文标准标签不可通过普通管理接口修改；仅允许更新 `sort_order/remarks`。

### 3.2 多语言标签表 `ont_data_property_label`

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `data_property_id` | bigint | 是 | 外键，`ON DELETE CASCADE` |
| `locale` | varchar(16) | 是 | 如 `zh`、`en` |
| `label` | varchar(128) | 是 | 标签文本 |

主键：`(data_property_id, locale)`。首期DTO仍维护一个必填中文标签；多语言独立编辑后续扩展。

### 3.3 枚举值表 `ont_data_property_enum`

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `data_property_id` | bigint | 是 | 外键，`ON DELETE CASCADE` |
| `enum_value` | varchar(256) | 是 | 可接受的枚举词法值 |
| `canonical_value` | varchar(256) | 否 | 兼容别名归一后的标准值；标准值本身为NULL |
| `is_standard` | char(1) | 是 | `1`来自附录C，`0`为附录D兼容、别名或平台推荐 |
| `source_reference` | varchar(64) | 否 | 如 `C.37`、`D-Step5` |
| `sort_order` | integer | 是 | 排序 |

主键：`(data_property_id, enum_value)`。增加自引用复合外键 `(data_property_id, canonical_value) → (data_property_id, enum_value)`；若 `canonical_value` 非空，目标行必须是同一属性下的标准枚举值，Service再校验目标行 `is_standard=1`。实例校验通过后先归一再持久化。扩展属性更新枚举采用“校验后整体替换”；内置属性枚举不可修改。

## 5. 服务规则

### 5.1 新增扩展属性

1. `namespaceId/name/label/domainEntityTypeId/baseType/valueMode` 必填；`ontologyId`缺省为935001。
2. 普通接口只能向 `is_builtin='0'` 的扩展命名空间写入。
3. `name` 使用扩展命名规范 `^[a-z][a-zA-Z0-9]*$`；国标种子中的下划线名称由Flyway写入，不经过普通新增接口。
4. `iriLocalName`可省略，省略时等于`name`；格式使用命名空间模块既有本地名规则 `^[a-zA-Z][a-zA-Z0-9_]*$`。
5. 后端生成 `iri=namespace.uri+iriLocalName`；若请求携带 `iri`，必须完全一致。
6. IRI、IRI本地名作用域、定义域内Name和别名冲突均在事务开始前校验。
7. 定义域必须存在、未删除且与属性属于同一 `ontologyId`；首期不开放跨工程定义域。
8. 新增数据固定 `source_type=EXTENSION/is_builtin='0'/standard_iri=NULL`。
9. 主表、中文标签、枚举值在同一事务保存。
10. 枚举值去首尾空格、去重并保留用户排序；空字符串拒绝；兼容别名在实例层按 `canonicalValue` 归一。

### 5.2 值域一致性校验

| 条件 | 规则 |
|------|------|
| `valueMode=CLOSED_ENUM` | 至少1个枚举值 |
| `valueMode=OPEN_ENUM` | 枚举值可空；存在时逐项按baseType校验 |
| `valueMode=FREE` | 不允许提交枚举值 |
| `valueMode=EXTERNAL_DICTIONARY` | `valueSourceRef`必填，不允许本地枚举值 |
| `valueMode=UNIT_DICTIONARY` | `baseType=UNIT_REF`、`unitRefMode=DICTIONARY_SYMBOL`，不允许本地枚举值 |
| `baseType=UNIT_REF` | `valueMode`只能是UNIT_DICTIONARY；`unitCategoryId`可空，空表示所有分类 |
| `baseType=NUMERIC` | 可选`unitCategoryId`；枚举值须可解析为Decimal |
| `baseType=BOOLEAN` | 枚举值若存在只能是true/false；不允许正则 |
| `baseType=DATE` | 不允许正则；格式统一由日期规范化器处理 |
| `baseType=URI` | 正则可作为附加限制，但必须先通过URI语法校验 |
| `baseType=TEXT_OR_NUMERIC` | 允许FREE/OPEN_ENUM/CLOSED_ENUM；实例值必须显式标明TEXT或NUMERIC |
| `unitCategoryId` | 仅NUMERIC、UNIT_REF可填写，且分类必须有效 |

`formatHint`是提示，不代替后端类型校验；正则需限制长度，并在保存前编译验证，防止无效表达式进入数据库。

### 5.3 修改

1. 不存在则返回“数据属性不存在”。
2. 内置属性仅允许修改 `sortOrder/remarks`；其他字段即使请求传入也不得静默忽略，应返回“内置数据属性语义字段不可修改”，避免调用方误判成功。
3. 扩展属性可修改标签、定义、Name、IRI本地名、定义域、值域和约束字段；`ontologyId/sourceType/isBuiltin/standardIri`不可修改。
4. 修改Name不自动修改IRI；修改IRI本地名必须显式提交并重新校验。
5. 后续公理/实例模块上线后，只要IRI已被引用，就禁止修改 `namespaceId/iriLocalName/iri`。
6. 枚举整体替换与主表修改处于同一事务；任一枚举非法则全部回滚。

### 5.4 删除

1. 内置属性禁止删除。
2. 删除扩展属性前检查公理目标、实例值、SHACL Shape、序列化映射等引用；尚未建表的检查以扩展点保留，相关模块上线时必须补齐。
3. 有引用返回可理解的引用类型和数量，不依赖数据库外键异常作为业务提示。
4. 无引用时物理删除标签/枚举子表，再逻辑删除主表。由于主表是逻辑删除，不能误以为数据库CASCADE会自动清理子表。

### 5.5 按定义域查询（含继承）

`GET /ontology/data-properties/by-domain/{entityTypeId}`：

1. 校验实体类型存在；
2. BFS向上收集自身及全部祖先ID和最短距离；
3. 一次查询所有定义域上的有效属性；
4. 以属性ID去重并组装中文标签、定义域名称；
5. 返回 `OntApplicableDataPropertyVO`，直接属性 `inherited=false/distance=0`；
6. 多继承下同一属性只返回一次，保留最短继承距离；
7. 结果不分页，供实例动态表单和实体类型详情使用。当前核心规模56项，后续规模过大时再增加游标，不与管理分页接口混用。

### 5.6 前置模块联动保护

V7实现必须同步修改：

| 服务 | 联动规则 |
|------|----------|
| `OntEntityTypeServiceImpl.removeEntityType` | 若存在有效数据属性直接引用该类型为定义域，拒绝删除并提示数量 |
| `OntNamespaceServiceImpl.updateNamespace` | 命名空间已被数据属性引用时禁止修改URI，否则已存IRI与命名空间失配 |
| `OntNamespaceServiceImpl.removeNamespace` | 增加数据属性引用检查 |
| `OntUnitCategoryServiceImpl.removeCategory` | 增加数据属性 `unit_category_id` 引用检查；先返回业务错误，再由FK RESTRICT兜底 |

## 9. 前端交互设计

### 9.1 页面结构

采用现有 `splitpanes`：

```text
数据属性管理
├── 左：实体类型树
│   ├── 名称/标签过滤
│   ├── “全部属性”入口
│   └── 复用 GET /ontology/entity-types/tree

    ├── 操作：新增、刷新
    └── 表格：显示名、标准Name、IRI、标准IRI、定义域、值域、值模式、来源、直接/继承、操作
```

交互口径：

- 选中实体类型：调用 `by-domain`，展示直接+继承属性，不显示分页器；
- 选择“全部属性”：调用分页接口，展示属性定义记录，不展开继承副本；
- 继承属性显示“继承自××”标签，不能在当前类型下误认为直接声明；
- 来源标签区分“附录C”“条款直采”“附录D兼容”“扩展”；
- C.41默认显示 `measurementUnit`，同时展示标准Name `unit`。

### 9.2 新增/编辑表单

分组：

1. 基本信息：命名空间、Name、IRI本地名、IRI预览、中文标签、定义、定义域；
2. 值域：基础类型、值模式、外部字典来源、枚举编辑器；
3. 约束：正则、格式、唯一性、单位分类；
4. 治理：排序、备注、来源只读信息。

关键联动：

- 新增只能选择扩展命名空间；
- 新增时Name变化可同步建议IRI本地名，用户手动修改后停止自动同步；
- 编辑时Name变化不自动改IRI；
- CLOSED_ENUM至少一个值；OPEN_ENUM提示“列表为推荐值，仍允许其他值”；
- EXTERNAL_DICTIONARY显示来源选择，不显示枚举编辑器；
- UNIT_REF自动设为UNIT_DICTIONARY和DICTIONARY_SYMBOL，单位分类为可选而非必选；
- TEXT_OR_NUMERIC提示实例层必须选择文本或数值字面量类型；
- 内置记录仅排序、备注可编辑，其他字段和枚举全部禁用；前端禁用只是体验，后端必须独立校验。

## 11. 与后续模块的稳定契约

| 后续模块 | 使用字段/接口 | 契约 |
|----------|---------------|------|
| 对象属性/公理 | 数据属性 `iri` | 平台内部引用只使用唯一IRI，不使用可重复 `standard_iri` |
| 实例建模 | `by-domain`、baseType、valueMode、enum、unitCategory | 动态表单必须区分直接/继承属性并执行值域校验 |
| 校验引擎 | 属性定义与实例值 | 生成类级SHACL；唯一性按ontology+propertyIri+规范化值校验 |
| 序列化 | `iri/standard_iri/preferred_alias` | 默认安全IRI；附录D可用measurementUnit；严格C.41使用unit |
| 单位字典 | `unit_category_id`、UNIT_REF | 属性层分类可空；实例值必须引用有效单位，约束内数值与单位分类一致 |
| 外部分类字典 | `value_mode=EXTERNAL_DICTIONARY` | 通过 `value_source_ref=ICS/CCS` 解析，不复制大枚举到属性表 |
