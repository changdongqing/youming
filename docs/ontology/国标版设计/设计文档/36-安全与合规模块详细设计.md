## 1. 评审结论与设计边界

### 1.1 现状评审

截至本设计时点，前述 14 个模块已全部落地。在安全与合规方面，pig 框架提供的基础设施和代码库现状如下：

| 缺口 | 现状 | 影响 |
|------|------|------|
| **RBAC 仅到菜单级** | pig 框架 `@HasPermission("ontology_xxx_yyy")` 实现菜单级权限控制，4 角色（管理员/建模工程师/审核员/访客）由 `sys_role` + `sys_role_menu` 管理 | PRD §10 满足菜单级 RBAC，但**无数据级权限**（谁能看哪个本体工程的数据、哪个实体类型的数据）和**字段级权限**（哪些字段对哪些角色可见/可编辑） |
| **无数据分级分类** | 无数据安全级别标签（公开/内部/敏感/机密）；本体实例、属性值均无分级 | 差距分析 §3.32：园区/医院涉及大量个人信息（人脸/车牌/患者数据），必须数据分级分类、脱敏、加密、最小化采集；合规红线（等保 2.0/数据安全法/个人信息保护法） |
| **无动态脱敏** | `sys_sensitive_word` 是敏感词过滤（内容审查），不是动态脱敏（数据展示时按角色遮蔽敏感字段值）；现有 API 返回明文数据 | 敏感数据（如个人身份证号、手机号、医疗数据）在 API 响应中全量明文返回，任何有查询权限的角色都能看到全部字段 |
| **无字段级权限** | 无"字段 X 对角色 Y 不可见"的配置能力；实体类型详情接口返回全部字段 | 访客角色可看到本体实例的全部数据属性值，无法按字段级控制可见性 |
| **无数据访问审计** | `sys_log`（pig-common-log `@SysLog`）记录**操作行为**（谁在何时调用了哪个 API），不记录**数据访问行为**（谁查询了哪条敏感数据）；缺数据级审计 | 差距分析 §3.32：细粒度审计（不只是操作日志，还有数据访问日志）是合规要求 |
| **无 IoT 设备认证** | 无 IoT 设备身份认证机制（证书/Token）；接入层未设计 | 差距分析 §3.32：IoT 设备接入必须双向认证，防止伪设备注入——这是 M7 IoT 接入层（模块 19）的前置条件 |
| **无命令二次确认** | 无高风险操作二次确认机制；现有 DELETE 操作仅前端弹窗确认 | 差距分析 §3.32：下行控制（模块 24）必须校验权限 + 联锁 + 确认回执；安全攸关操作（启泵/锁梯/开门）强制双人确认 |
| **无数据加密存储** | PostgreSQL 存储明文数据，无字段级加密 | 敏感字段（身份证号、手机号、医疗数据）在数据库中明文存储，DBA 可直接查看 |
| **审计日志不可追溯** | `sys_log` 的 `params` 字段记录请求参数但不记录响应数据；审计日志无防篡改机制 | 合规审计要求操作全链路可追溯 + 不可篡改 |

### 1.2 优化结论

| 级别 | 评审发现 | 优化结论 |
|------|----------|----------|
| P0 | 无数据分级分类 | **数据分级标签体系**：为实体类型、数据属性、实例值增加安全级别标签（PUBLIC/INTERNAL/CONFIDENTIAL/RESTRICTED）；核心 Schema 标签只读锁定（国标实体类型默认 INTERNAL，扩展可调整） |
| P0 | 无动态脱敏 | **脱敏引擎**：`DataMaskingService` 按角色 + 字段安全级别动态脱敏 API 响应——脱敏规则（手机号 `138****1234`、身份证号 `110***********1234`、IP 地址 `192.168.*.**`）；通过 Jackson `@JsonSerialize` 自定义序列化器在响应序列化时自动脱敏 |
| P0 | 无字段级权限 | **字段级权限控制**：`ont_field_permission` 表配置"角色 × 字段 → 可见/可编辑/脱敏"；通过 MyBatis-Plus 拦截器在查询时动态 SELECT 字段集 + Jackson 序列化时过滤 |
| P0 | 无数据访问审计 | **细粒度审计**：`ont_data_access_log` 表记录数据访问行为（谁查询了哪个本体工程的哪些实例/属性、返回了多少行、是否包含敏感数据）；与 `sys_log` 操作日志互补 |
| P1 | 无 IoT 设备认证 | **设备认证框架**：`ont_device_credential` 表 + `DeviceAuthService`（Token/证书认证 SPI）；为 M7 IoT 接入层（模块 19）提供设备身份校验基础；本期实现 Token 模式，证书模式预留 |
| P1 | 无命令二次确认 | **高风险操作确认**：`@RequireConfirm` 注解 + `ont_operation_confirm` 表；对 DELETE/版本回滚/批量操作等高风险操作记录确认链路（谁发起、谁确认、何时确认） |
| P1 | 无数据加密存储 | **字段级加密**：`@Encrypted` 注解 + `EncryptDecryptHandler`（MyBatis-Plus TypeHandler）；敏感字段在写入时 AES-256 加密、读取时解密；加密密钥从环境变量注入，不存数据库 |
| P2 | 审计日志不可追溯 | **审计日志防篡改**：每条审计日志附加前一条的 SHA-256 链式哈希，篡改任意记录会导致链断裂；提供完整性校验接口 |

### 1.3 本期范围

**本期包含：**

1. 数据分级标签体系（实体类型/数据属性/实例值的安全级别标签）
2. 动态脱敏引擎（`DataMaskingService` + Jackson 自定义序列化器）
3. 字段级权限控制（`ont_field_permission` 表 + 查询拦截器 + 序列化过滤器）
4. 细粒度数据访问审计（`ont_data_access_log` 表 + 审计拦截器）
5. IoT 设备认证框架（`ont_device_credential` 表 + `DeviceAuthService` SPI + Token 模式实现）
6. 高风险操作二次确认（`@RequireConfirm` 注解 + `ont_operation_confirm` 表）
7. 字段级加密存储（`@Encrypted` 注解 + MyBatis-Plus TypeHandler + AES-256）
8. 审计日志链式哈希防篡改
9. Flyway V17 迁移脚本（7 张新表 + 菜单权限 + 种子数据）
10. 前端安全配置页（数据分级标签管理、字段权限矩阵、脱敏规则预览、审计日志查询、设备凭证管理）

**本期不包含：**

- IoT 设备证书认证（PKI/X.509）——本期实现 Token 模式，证书模式远期按需评估
- 数据库 TDE（透明数据加密）——本期做应用层字段级加密，数据库级 TDE 由 DBA 按需配置
- 等保 2.0 三级测评——本期实现技术能力，等保测评需独立进行
- 零信任网络架构——本期在应用层做权限与加密，网络层零信任由基础设施团队负责
- 数据最小化采集策略——本期不做采集前的数据最小化（如只采集必要字段），由各业务模块在建模时人工控制
- 隐私影响评估（PIA）——本期不做 PIA 流程，由合规团队独立进行
- 跨系统联邦身份认证（SSO/OIDC）——pig 框架已集成 OAuth2，本期不扩展

### 1.5 权威语义口径

1. 安全与合规模块是**横切基础设施层**，所有业务模块的安全能力都通过本模块的组件实现——数据分级标签、脱敏引擎、字段权限、审计日志、设备认证、操作确认、字段加密，均为横切关注点，通过注解/AOP/拦截器非侵入式集成。
2. **数据分级四级模型**（参照等保 2.0 数据分类分级指引）：
   - `PUBLIC`（公开）：可公开访问的数据，如标准编号、发布日期
   - `INTERNAL`（内部）：内部使用但不敏感的数据，如实体类型定义、公理规则（**国标核心 Schema 默认级别**）
   - `CONFIDENTIAL`（机密）：涉及个人信息或商业敏感的数据，如起草人姓名、机构联系方式
   - `RESTRICTED`（受限）：高敏感数据，如身份证号、医疗数据、设备控制凭证——仅特定角色可见，导出需审批
3. **脱敏引擎**在 API 响应序列化时自动执行——通过 Jackson `@JsonSerialize(using = DataMaskingSerializer.class)` 自定义序列化器，根据当前用户角色和数据安全级别决定脱敏策略；脱敏在服务端完成，前端收到的已是脱敏后数据。
4. **字段级权限**通过 MyBatis-Plus 查询拦截器在 SQL 层面控制——拦截器根据当前用户的角色和字段权限配置，动态修改 SELECT 字段集（不可见字段不查询），而非在应用层过滤（避免数据已加载到内存再过滤的安全风险）。
5. **审计日志**记录数据访问行为，与 `sys_log`（操作行为日志）互补——`sys_log` 记录"调用了什么 API"，`ont_data_access_log` 记录"查询了什么数据、返回了多少行、是否包含敏感数据"。
6. **IoT 设备认证**通过 SPI 接口 `DeviceAuthService` 解耦——本期实现 `TokenDeviceAuthService`（Token 模式），远期可扩展 `CertificateDeviceAuthService`（X.509 证书模式）；设备凭证独立于用户凭证，不混用 OAuth2 Token。
7. **高风险操作二次确认**通过 `@RequireConfirm` 注解声明——注解标注的方法在执行前需先调用 `POST /ontology/security/confirm` 获取确认 Token，携带确认 Token 才能执行实际操作；确认 Token 一次性使用，5 分钟过期。
8. **字段级加密**通过 MyBatis-Plus TypeHandler 实现——`@Encrypted` 注解标注的实体字段在 `INSERT`/`UPDATE` 时自动 AES-256 加密，`SELECT` 时自动解密；加密密钥从环境变量 `ONT_ENCRYPT_KEY` 注入，不存数据库，不记日志。
9. **审计日志链式哈希**——每条审计日志包含前一条记录 ID 的 SHA-256 哈希 `prev_hash`，形成防篡改链；提供 `GET /ontology/security/audit/verify` 接口校验链完整性。
10. **权限模型**：安全管理需 `ontology_security_admin` 权限（仅管理员）；审计查看需 `ontology_audit_view` 权限（管理员+审核员）；设备凭证管理需 `ontology_device_credential_manage` 权限（管理员）。

### 2.3 技术选型

| 组件 | 选型 | 版本 | 选型理由 |
|------|------|------|----------|
| 权限框架 | pig-common-security `@HasPermission` | 已有 | pig 框架已集成 Spring Security OAuth2，菜单级 RBAC 成熟；本模块在其上叠加数据级/字段级权限 |
| 脱敏引擎 | Jackson 自定义序列化器 | Spring Boot 自带 | 在 JSON 序列化阶段脱敏，无需修改业务代码；通过 `ObjectMapper.configure()` 全局注册 |
| 字段权限 | MyBatis-Plus Inner Interceptor | 3.5.x | MyBatis-Plus 的 `InnerInterceptor` 可拦截 SQL 并动态修改 SELECT 字段集；已有分页拦截器先例 |
| 数据加密 | AES-256-CBC + MyBatis-Plus TypeHandler | JDK Crypto | AES-256 是等保 2.0 认可的加密算法；TypeHandler 在 MyBatis 层面透明加解密，业务代码无感知 |
| 审计 AOP | Spring AOP + `@Aspect` | Spring Boot 自带 | 通过切面拦截 Service 方法调用，记录数据访问行为；与 `@SysLog`（Controller 层）互补 |
| 链式哈希 | SHA-256 (JDK `MessageDigest`) | JDK 自带 | SHA-256 是防篡改标准做法；每条日志附加前一条的哈希，形成链式结构 |
| IoT 设备认证 | SPI 接口 + Token 实现 | 自研 | SPI 解耦认证方式（Token/证书），本期 Token，远期证书；设备 Token 独立于用户 OAuth2 Token |
| 确认 Token | Redis + UUID | 已有 Redis | 一次性 Token 存 Redis（5 分钟 TTL），高性能 + 自动过期 |

## 3. 数据模型

### 3.1 数据分级标签表（ont_security_level）

```sql
-- 数据安全级别定义
CREATE TABLE ont_security_level (
  id BIGSERIAL PRIMARY KEY,
  level_code VARCHAR(32) NOT NULL UNIQUE,      -- PUBLIC / INTERNAL / CONFIDENTIAL / RESTRICTED
  level_name VARCHAR(64) NOT NULL,              -- 公开 / 内部 / 机密 / 受限
  level_rank INTEGER NOT NULL,                  -- 安全等级排序 (1-4)
  description TEXT,
  is_builtin BOOLEAN DEFAULT FALSE,             -- 内置级别不可删
  export_policy VARCHAR(32) NOT NULL,           -- 导出策略: ALLOW / MASKED / BLOCKED
  sort_order INTEGER DEFAULT 0,
  create_by VARCHAR(64) DEFAULT ' ',
  create_time TIMESTAMP DEFAULT NOW(),
  update_by VARCHAR(64) DEFAULT ' ',
```

### 4.2 动态脱敏引擎

```java
/**
 * 数据脱敏服务。
 * <p>
 * 按角色 + 字段安全级别动态脱敏。
 * 脱敏策略在 Jackson 序列化阶段执行，前端收到的已是脱敏后数据。
 * </p>
 */
@Service
@Slf4j
@RequiredArgsConstructor
public class DataMaskingService {

    private final OntSecurityLevelMapper securityLevelMapper;
    private final OntFieldPermissionMapper fieldPermissionMapper;

    /**
     * 脱敏值。
     * @param value 原始值
     * @param maskType 脱敏类型
     * @return 脱敏后的值
     */
    public String mask(String value, String maskType) {
        if (value == null || value.isEmpty()) {
            return value;
        }
        return switch (maskType) {
            case "PHONE" -> value.replaceAll("(\\d{3})\\d{4}(\\d{4})", "$1****$2");
            case "ID_CARD" -> value.replaceAll("(\\d{3})\\d{11}(\\w{4})", "$1***********$2");
            case "EMAIL" -> {
                int at = value.indexOf('@');
                if (at > 1) {
                    yield value.substring(0, 1) + "***" + value.substring(at);
                }
                yield value;
            }
            case "IP" -> value.replaceAll("(\\d+\\.\\d+)\\.\\d+\\.\\d+", "$1.*.*");
            case "NAME" -> value.length() > 1 ? value.charAt(0) + "*".repeat(value.length() - 1) : value;
            case "CUSTOM" -> value; // 自定义模式由调用方处理
            default -> value;
        };
    }

    /**
     * 根据角色和字段安全级别判断是否需要脱敏。
     */
    public boolean shouldMask(Long roleId, Long entityTypeId, Long dataPropertyId, Long ontologyId) {
        OntFieldPermission perm = fieldPermissionMapper.selectOne(
            Wrappers.<OntFieldPermission>lambdaQuery()
                .eq(OntFieldPermission::getRoleId, roleId)
                .eq(OntFieldPermission::getEntityTypeId, entityTypeId)
                .eq(OntFieldPermission::getDataPropertyId, dataPropertyId)
                .eq(OntFieldPermission::getOntologyId, ontologyId)
                .last("LIMIT 1"));
        return perm != null && "MASKED".equals(perm.getAccessMode());
    }

    /**
     * 获取角色对字段的脱敏类型。
     */
    public String getMaskType(Long roleId, Long entityTypeId, Long dataPropertyId, Long ontologyId) {
        OntFieldPermission perm = fieldPermissionMapper.selectOne(
            Wrappers.<OntFieldPermission>lambdaQuery()
                .eq(OntFieldPermission::getRoleId, roleId)
                .eq(OntFieldPermission::getEntityTypeId, entityTypeId)
                .eq(OntFieldPermission::getDataPropertyId, dataPropertyId)
                .eq(OntFieldPermission::getOntologyId, ontologyId)
                .last("LIMIT 1"));
        return perm != null ? perm.getMaskType() : null;
    }
}

/**
 * 数据脱敏 Jackson 序列化器。
 * <p>
 * 在 API 响应序列化时自动脱敏敏感字段。
 * 使用方式：在 VO 字段上标注 @JsonSerialize(using = DataMaskingSerializer.class)
 * + @MaskContext(entityTypeId=..., dataPropertyId=...)
 * </p>
 */
public class DataMaskingSerializer extends JsonSerializer<String>
        implements ContextualSerializer {

    private DataMaskingService maskingService;
    private Long entityTypeId;
    private Long dataPropertyId;

    @Override
    public void serialize(String value, JsonGenerator gen, SerializerProvider sp)
            throws IOException {
        PigUser user = SecurityUtils.getUser();
        if (user == null || maskingService == null) {
            gen.writeString(value); // 无用户上下文时不脱敏（内部调用）
            return;
        }
        // 取第一个角色（简化，实际应遍历角色取最严格脱敏）
        Long roleId = user.getRoleIds().isEmpty() ? null : user.getRoleIds().get(0);
        if (roleId != null && maskingService.shouldMask(roleId, entityTypeId, dataPropertyId, null)) {
            String maskType = maskingService.getMaskType(roleId, entityTypeId, dataPropertyId, null);
            gen.writeString(maskingService.mask(value, maskType));
        } else {
            gen.writeString(value);
        }
    }

    @Override
    public JsonSerializer<?> createContextual(SerializerProvider prov, BeanProperty prop) {
        // 从字段注解获取上下文信息
        // ...
        return this;
    }
}
```

```java
 * MyBatis-Plus 字段级权限拦截器。
 * <p>
 * 在 SQL 查询时，根据当前用户角色和字段权限配置，

    private final OntFieldPermissionMapper fieldPermissionMapper;

    @Override
    public void beforeQuery(Executor executor, MappedStatement ms,
                            Object parameter, BoundSql boundSql,
                            ResultMap resultMap, Connection connection) {

        if (user == null) {
            return; // 内部调用（无用户上下文），不拦截
        }

        // 仅拦截 ontology 模块的查询（通过 Mapper 类名判断）
        String mapperClass = ms.getId().substring(0, ms.getId().lastIndexOf('.'));
        if (!mapperClass.startsWith("com.pig4cloud.ontology")) {
            return;

        String sql = boundSql.getSql();

        if (!sql.equals(rewrittenSql)) {
            // 通过反射替换 BoundSql 中的 SQL
            ReflectUtil.setFieldValue(boundSql, "sql", rewrittenSql);
        }
    }

     * 重写 SELECT 字段集。

        // 从列列表中移除这些字段。
        // 注意：SELECT * 的情况需要展开为具体列名再过滤
        // ...
        return sql;
    }
```

```java
            // 审计失败不影响业务
        }
    }

/**
 * 审计日志链式哈希计算器。
 */
@Component
@Slf4j
@RequiredArgsConstructor
public class AuditChainHashCalculator {

    private final OntDataAccessLogMapper logMapper;

    /**
     * 为审计日志附加链式哈希。
     * prev_hash = 前一条记录的 current_hash
     * current_hash = SHA-256(id + operated_by + operated_at + access_type + prev_hash)
     */
    public void appendHash(DataAccessLog log) {
        // 获取前一条记录
        DataAccessLog prev = logMapper.selectOne(
            Wrappers.<DataAccessLog>lambdaQuery()
                .orderByDesc(DataAccessLog::getId)
                .last("LIMIT 1"));
        String prevHash = prev != null ? prev.getCurrentHash() : "GENESIS";

        // 计算 current_hash
        String input = log.getId() + log.getOperatedBy() + log.getOperatedAt()
                     + log.getAccessType() + prevHash;
        String currentHash = sha256(input);

        log.setPrevHash(prevHash);
        log.setCurrentHash(currentHash);
    }

    /**
     * 校验审计日志链完整性。
     */
    public boolean verifyChain() {
        List<DataAccessLog> logs = logMapper.selectList(
            Wrappers.<DataAccessLog>lambdaQuery()
                .orderByAsc(DataAccessLog::getId));
        String expectedPrevHash = "GENESIS";
        for (DataAccessLog log : logs) {
            if (!log.getPrevHash().equals(expectedPrevHash)) {
                log.error("审计日志链断裂: id={}, expected prev={}, actual={}",
                    log.getId(), expectedPrevHash, log.getPrevHash());
                return false;
            }
            String input = log.getId() + log.getOperatedBy() + log.getOperatedAt()
                         + log.getAccessType() + log.getPrevHash();
            String expectedHash = sha256(input);
            if (!log.getCurrentHash().equals(expectedHash)) {
                log.error("审计日志哈希不匹配: id={}", log.getId());
                return false;
            }
            expectedPrevHash = log.getCurrentHash();
        }
        return true;
    }
}
```

```java
        cred.setLastAuthIp(RequestContextHolder.getRemoteAddr());
```

```java
/**
 * 高风险操作确认注解。
 * <p>
 * 标注在 Controller 方法上，执行前需先获取确认 Token。
 * </p>
 */
@Target(ElementType.METHOD)
@Retention(RetentionPolicy.RUNTIME)
public @interface RequireConfirm {
    /**
     * 操作类型描述。
     */
    String operationType();

    /**
     * 是否需要双人确认（false=单人确认即可，true=需另一人确认）。
     */
    boolean dualConfirm() default false;
}

/**
 * 高风险操作确认服务。
 */
@Service
@Slf4j
@RequiredArgsConstructor
public class OperationConfirmService {

    private final RedisTemplate<String, String> redisTemplate;
    private final OntOperationConfirmMapper confirmMapper;

    /**
     * 发起确认请求。
     */
    public String requestConfirm(String operationType, String targetResource, boolean dualConfirm) {
        PigUser user = SecurityUtils.getUser();
        String token = UUID.randomUUID().toString().replace("-", "");

        // 写入 Redis (5 分钟过期)
        redisTemplate.opsForValue().set(
            "confirm:" + token,
            operationType + ":" + user.getUsername(),
            Duration.ofMinutes(5));

        // 写入数据库
        OntOperationConfirm confirm = new OntOperationConfirm();
        confirm.setConfirmToken(token);
        confirm.setOperationType(operationType);
        confirm.setTargetResource(targetResource);
        confirm.setRequestedBy(user.getUsername());
        confirm.setRequestedAt(LocalDateTime.now());
        confirm.setStatus("PENDING");
        confirm.setExpiresAt(LocalDateTime.now().plusMinutes(5));
        confirmMapper.insert(confirm);

        return token;
    }

    /**
     * 校验确认 Token。
     */
    public boolean validateConfirm(String token) {
        String key = "confirm:" + token;
        String value = redisTemplate.opsForValue().get(key);
        if (value == null) {
            return false; // Token 不存在或已过期
        }
        // 一次性使用：删除 Token
        redisTemplate.delete(key);

        // 更新数据库状态
        OntOperationConfirm confirm = confirmMapper.selectOne(
            Wrappers.<OntOperationConfirm>lambdaQuery()
                .eq(OntOperationConfirm::getConfirmToken, token)
                .last("LIMIT 1"));
        if (confirm != null) {
            confirm.setStatus("CONFIRMED");
            confirm.setConfirmedBy(SecurityUtils.getUser().getUsername());
            confirm.setConfirmedAt(LocalDateTime.now());
            confirm.setIpAddress(RequestContextHolder.getRemoteAddr());
            confirmMapper.updateById(confirm);
        }
        return true;
    }
}

/**
 * 确认拦截器 AOP。
 * <p>
 * 拦截 @RequireConfirm 标注的方法，校验确认 Token。
 * </p>
 */
@Aspect
@Component
@Slf4j
@RequiredArgsConstructor
public class RequireConfirmInterceptor {

    private final OperationConfirmService confirmService;

    @Before("@annotation(requireConfirm) && args(.., confirmToken)")
    public void checkConfirm(JoinPoint jp, RequireConfirm requireConfirm, String confirmToken) {
        if (!confirmService.validateConfirm(confirmToken)) {
            throw new OntSecurityException(
                "操作未确认或确认已过期，请先发起确认请求");
        }
        log.info("高风险操作确认通过: type={}, user={}",
            requireConfirm.operationType(),
            SecurityUtils.getUser().getUsername());
    }
}
```

### 4.7 字段级加密

```java
/**
 * 加密字段注解。
 */
@Target(ElementType.FIELD)
@Retention(RetentionPolicy.RUNTIME)
public @interface Encrypted {
}

/**
 * 加密解密 TypeHandler。
 * <p>
 * MyBatis-Plus TypeHandler，在写入时 AES-256 加密，读取时解密。
 * 密钥从环境变量 ONT_ENCRYPT_KEY 获取。
 * </p>
 */
@MappedTypes(String.class)
public class FieldEncryptionHandler extends BaseTypeHandler<String> {

    private static final String ENCRYPT_KEY = System.getenv("ONT_ENCRYPT_KEY");

    @Override
    public void setNonNullParameter(PreparedStatement ps, int i,
                                     String parameter, JdbcType jdbcType) throws SQLException {
        ps.setString(i, encrypt(parameter));
    }

    @Override
    public String getNullableResult(ResultSet rs, String columnName) throws SQLException {
        return decrypt(rs.getString(columnName));
    }

    @Override
    public String getNullableResult(ResultSet rs, int columnIndex) throws SQLException {
        return decrypt(rs.getString(columnIndex));
    }

    private String encrypt(String plaintext) {
        if (plaintext == null || ENCRYPT_KEY == null) return plaintext;
        // AES-256-CBC 加密
        // ...
        return Base64.getEncoder().encodeToString(encrypted);
    }

    private String decrypt(String ciphertext) {
        if (ciphertext == null || ENCRYPT_KEY == null) return ciphertext;
        // AES-256-CBC 解密
        // ...
        return plaintext;
    }
}
```
