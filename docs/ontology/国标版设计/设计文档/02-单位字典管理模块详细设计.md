# 单位字典管理模块详细设计

> 对应 PRD：§4.11 单位字典管理模块  
> 编写日期：2026-07-09

## 1. 领域定位

单位字典用于统一治理“测量单位”。它不是普通枚举字典，而是后续本体数据属性、约束逻辑实例、公理校验共同引用的基础 Schema/Data 字典。

国标依据：

1. 第 6.2.5.6 条：约束逻辑类属性含测量单位。
2. 附录 C 表 C.41：测量单位数据属性定义，备注列示例为 `V、W、℃ 等`。
3. 附录 D 步骤 5：实例化中实际使用 `%`。

因此首期需要：

1. 预置国标例举和附录 D 使用单位。
2. 支持行业扩展单位。
3. 保护内置单位语义字段。
4. 为后续数值属性和实例 `measurementUnit` 引用提供稳定 ID、代码和符号。

## 2. 数据模型

### 2.1 单位分类 `ont_unit_category`

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `id` | bigint | 是 | MyBatis-Plus `ASSIGN_ID` |
| `category_code` | varchar(64) | 是 | 分类编码，全局唯一，如 `temperature` |
| `category_name` | varchar(128) | 是 | 分类名称，如 `温度` |
| `base_unit_symbol` | varchar(32) | 是 | 基准单位符号，如 `K`、`V`、`%` |
| `is_builtin` | char(1) | 是 | `1` 内置，`0` 扩展 |
| `sort_order` | integer | 是 | 排序 |
| `remarks` | varchar(255) | 否 | 备注 |
| `create_by` | varchar(64) | 否 | 创建人 |
| `create_time` | timestamp | 是 | 创建时间 |
| `update_by` | varchar(64) | 否 | 修改人 |
| `update_time` | timestamp | 否 | 更新时间 |
| `del_flag` | char(1) | 是 | 逻辑删除标志 |

约束：

1. `category_code` 在未删除数据中唯一。
2. 内置分类不可删除。
3. 内置分类语义字段锁定：`category_code`、`base_unit_symbol`、`is_builtin` 不允许通过接口改变；允许修改 `category_name`、`sort_order`、`remarks`。
4. 删除分类前必须确认该分类下没有有效单位条目。后续数据属性/规则引用上线后，再追加跨模块引用检查。

### 2.2 单位条目 `ont_unit`

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `id` | bigint | 是 | MyBatis-Plus `ASSIGN_ID` |
| `category_id` | bigint | 是 | 外键，指向 `ont_unit_category.id` |
| `unit_code` | varchar(64) | 是 | 单位编码，全局唯一，如 `volt` |
| `unit_symbol` | varchar(32) | 是 | 单位符号，允许 Unicode，如 `℃`、`%` |
| `unit_name` | varchar(128) | 是 | 中文名，如 `摄氏度` |
| `is_base_unit` | char(1) | 是 | 是否分类基准单位 |
| `is_builtin` | char(1) | 是 | 是否内置单位 |
| `factor` | numeric(30, 12) | 否 | 可选换算乘系数 |
| `offset_value` | numeric(30, 12) | 否 | 可选换算偏移 |
| `sort_order` | integer | 是 | 排序 |
| `namespace` | varchar(255) | 否 | 扩展命名空间 URI/标识 |
| `remarks` | varchar(255) | 否 | 备注 |
| `create_by` | varchar(64) | 否 | 创建人 |
| `create_time` | timestamp | 是 | 创建时间 |
| `update_by` | varchar(64) | 否 | 修改人 |
| `update_time` | timestamp | 否 | 更新时间 |
| `del_flag` | char(1) | 是 | 逻辑删除标志 |

约束：

1. `unit_code` 在未删除数据中唯一。
2. 同一分类下 `unit_symbol` 在未删除数据中唯一。
3. 单位所属分类必须存在且未删除。
4. 一个分类只允许一个有效基准单位。
5. 内置单位不可删除。
6. 内置单位语义字段锁定：`category_id`、`unit_code`、`unit_symbol`、`is_base_unit`、`is_builtin`、`factor`、`offset_value`、`namespace` 不允许通过接口改变；允许修改 `unit_name`、`sort_order`、`remarks`。
7. 扩展单位必须填写 `namespace`，避免污染核心口径。

## 3. 预置数据

首期按 PRD §4.11.3 预置国标口径最小可用集：

| 分类 | 编码 | 基准单位 | 预置单位 |
|------|------|----------|----------|
| 电压 | `voltage` | `V` | `V` |
| 功率 | `power` | `W` | `W`、`kW` |
| 温度 | `temperature` | `K` | `℃`、`K` |
| 无量纲 | `dimensionless` | `%` | `%` |
| 电流 | `current` | `A` | `A` |
| 质量 | `mass` | `kg` | `kg`、`g` |
| 长度 | `length` | `m` | `m`、`mm`、`cm` |
| 时间 | `time` | `s` | `s`、`min`、`h` |
| 容量 | `battery` | `Ah` | `Ah`、`Wh` |
| 计数 | `count` | `个` | `次`、`台`、`个` |

说明：

1. 可线性换算的预置单位初始化 `factor` / `offset_value`：如 `kW -> W`、`g -> kg`、`cm/mm -> m`、`min/h -> s`、`℃ -> K`。
2. 无法无上下文换算的单位保留换算参数 `NULL`，例如 `Ah` 与 `Wh` 之间需要额外电压上下文，计数类 `次/台/个` 语义不同。
3. 换算公式采用 `base = factor * value + offset_value`，再换算到目标单位。

## 4. 服务规则

### 4.1 新增分类

校验流程：

1. `categoryCode`、`categoryName`、`baseUnitSymbol` 必填。
2. `categoryCode` 格式为小写英文/数字/下划线/中划线，建议如 `elevator_speed`。
3. `categoryCode` 不重复。
4. 新增数据默认 `isBuiltin=0`。

### 4.2 修改分类

1. 若分类不存在，返回失败。
2. 若为内置分类，只更新 `categoryName`、`sortOrder`、`remarks`。
3. 若为扩展分类，可更新 `categoryCode`、`categoryName`、`baseUnitSymbol`、`sortOrder`、`remarks`。
4. 修改 `categoryCode` 时检查唯一性。

### 4.3 删除分类

1. 内置分类禁止删除。
2. 分类下存在有效单位时禁止删除。
3. 通过 MyBatis-Plus 逻辑删除更新 `del_flag`。

### 4.4 新增单位

校验流程：

1. `categoryId`、`unitCode`、`unitSymbol`、`unitName` 必填。
2. 分类必须存在。
3. `unitCode` 不重复。
4. 同分类下 `unitSymbol` 不重复。
5. 如果 `isBaseUnit=1`，同分类下不能已有其他基准单位。
6. 新增数据默认 `isBuiltin=0`；扩展单位必须填写 `namespace`。

### 4.5 修改单位

1. 若单位不存在，返回失败。
2. 若为内置单位，只更新 `unitName`、`sortOrder`、`remarks`。
3. 若为扩展单位，可更新分类、编码、符号、名称、基准标志、换算参数、命名空间、排序、备注。
4. 修改分类、符号、编码、基准标志时重新执行唯一性和基准单位校验。

### 4.6 删除单位

1. 内置单位禁止删除。
2. 后续实例/数据属性/公理规则上线后，删除前追加引用检查。
3. 首期只执行内置保护和逻辑删除。

### 4.7 符号解析

`GET /admin/ontology/units/by-symbol/{symbol}` 用于导入和附录 D 兼容：

1. 优先精确匹配 `unit_symbol`。
2. 若多个分类存在相同符号，返回排序最靠前的一条；当前预置数据避免同分类重复。
3. 建议调用方在需要强约束时同时传入分类上下文；首期接口保持简单。

### 4.8 单位换算

`GET /admin/ontology/units/convert?from=&to=&value=` 是可选增强：

1. from/to 必须是同分类单位。
2. from/to 都必须配置 `factor`，`offsetValue` 为空时按 0 处理。
3. 基准值计算：`base = factor_from * value + offset_from`。
4. 目标值计算：`target = (base - offset_to) / factor_to`。
5. 若未配置换算参数，返回失败提示“该单位未配置换算参数”。

## 5. 前端交互设计

### 5.1 页面结构

```text
单位字典页面
├── 左侧分类卡片
│   ├── 搜索框
│   ├── 分类列表/树
│   └── 新增、编辑、删除、刷新按钮
└── 右侧单位卡片
    ├── 当前分类标题
    ├── 查询表单：单位代码、符号、名称
    ├── 操作栏：新增、刷新
    └── 单位表格：符号、名称、编码、基准、内置、命名空间、排序、备注、操作
```

### 5.2 内置保护交互

1. 内置分类/单位显示“内置”标签。
2. 删除按钮对内置数据禁用。
3. 编辑内置单位时，语义字段置灰，只开放名称、排序、备注。
4. 编辑内置分类时，分类编码、基准单位置灰。

### 5.3 扩展单位交互

1. 新增单位默认 `isBuiltin=0`。
2. 命名空间必填，默认建议 `http://example.org/ontology/ext#`。
3. 符号允许 Unicode 输入，例如 `m/s²`、`℃`。

## 6. 验收点

1. Flyway 能创建 `ont_unit_category`、`ont_unit` 并初始化预置数据和菜单。
2. 后端 Maven 编译通过。
3. 前端 TypeScript/Vite 构建通过。
4. 登录管理员后可在“本体建模 / 单位字典”看到页面。
5. 可新增扩展分类和扩展单位。
6. 内置分类、内置单位不可删除。
7. 按符号 `%`、`V`、`W`、`℃` 能解析到预置单位。
