## 一、计划总览

本计划把 PRD 的 6 个里程碑（M0 模块骨架 / M1 属性模板+供给 / M2 分类模板+编码+类树 / M3 单位注册表 / M4 注释属性注册表 / 贯穿：参考本体）拆成 **6 个详细设计单元**，每单元产出一份独立详细设计文档，存放于 `docs/ontology/模板化建模平台设计/prd/` 目录，命名 `详细设计-DDx-<主题>.md`。

```
DD1 (M0) 模块骨架与基础设施   ✅ 已完成（详细设计 + 代码落地 + V4/V5）
DD2 (M1) 属性模板库 + 供给接口  ✅ 已完成（详细设计 + 代码落地 + V6/V7）
DD3 (M2) 分类模板体系 + 编码 + 类层级镜像  ✅ 已完成（详细设计 + 代码落地 + V8）
DD4 (M3) 单位注册表（QUDT 引用）  ✅ 已完成（详细设计 + 代码落地 + V9）
DD5 (M4) 注释属性注册表  ✅ 已完成（详细设计 + 代码落地 + V10）
DD6 (贯穿) 参考本体库浏览与导入  ← 本次产出（详细设计）
```

每个详细设计单元遵循统一结构：
1. 设计目标与范围（对应 PRD 的 FR 与里程碑）
2. 落地清单（文件清单：pom/类/配置/sql/vue/ts）
3. 数据库设计（DDL + 种子，含字段类型与约束）
4. 后端设计（包结构、Entity/Service/Controller、接口签名、鉴权）
5. 前端设计（页面、API、路由挂载、组件复用）
6. 横切设计（缓存/校验/异常/审计/i18n）
7. 验收映射（AC 编号 -> 实现点）
8. 测试要点

## 三、设计原则与通用约定（所有 DD 共享）

### 3.1 后端约定

- **模块**：仅 `pig-ontology-biz`（S-4），包根 `com.pig4cloud.pig.ontology`。
- **启动类**：`com.pig4cloud.pig.ontology.PigOntologyApplication`，注解 `@EnableOpenApi("ontology")` + `@EnablePigResourceServer` + `@EnableDiscoveryClient` + `@SpringBootApplication`（对齐 PigAdminApplication）。单体模式下不启用，由 PigBootApplication 聚合。
- **分层**：`controller` / `service`(+`impl`) / `mapper` / `api/entity` / `api/dto` / `api/vo`。
- **Entity 范式**：继承 `Model<T>` + `@TableId(type=IdType.ASSIGN_ID)` + `@TableName`（治理表名与类名驼峰推断不一致，**需显式标注**）+ `@TableLogic` 标 `delFlag`（String "0"/"1"）+ `@TableField(fill=...)` 标审计字段。
- **返回与鉴权**：Controller 用 `R<T>` 统一返回；`@HasPermission("ont_xxx")` 鉴权；写操作加 `@SysLog("...")`。
- **供给接口版本化**：路径 `/admin/ont/supply/v1/**`，返回结构以 VO 稳定化，表结构变更不破坏 VO。

### 3.2 数据库约定

- **Flyway 脚本**：放 `pig-common-data` 的共享 `db/migration/`，治理用 V4（结构）+ V5（种子）+ V6+（后续里程碑增量）。**禁改已应用脚本**。
- **字段类型**：主键 `bigint NOT NULL`；布尔 `char(1) DEFAULT '0'/'1'`（不用 smallint/boolean）；时间 `timestamp DEFAULT now()`；审计 `create_by varchar(64)`/`update_by varchar(64)`；逻辑删除 `del_flag char(1) DEFAULT '0'`。
- **表前缀**：`ont_`。
- **注释**：每表每字段加 `COMMENT ON`。

### 3.3 前端约定

- **页面**：`web/src/views/ontology/<feature>/index.vue`，路径须与 sys_menu.path 严格对应（S-6）。
- **API**：`web/src/api/ontology/<feature>.ts`，用 `/@/utils/request`，函数名 `pageList/addObj/getObj/putObj/delObj`。
- **路由**：后端控路由，不写 route.ts；靠 sys_menu 种子 + `import.meta.glob` 动态装配。
- **树组件**：分类模板树/类树复用 `components/QueryTree` + `splitpanes` + `utils/other.ts:handleTree`。
- **i18n**：词条放 `views/ontology/<feature>/i18n/*.ts`，en/zh-cn 双语。

### 3.4 横切约定

- **缓存**：继承视图、单位换算系数用 Caffeine 本地缓存（key+TTL，变更失效）。
- **异常**：业务错误用 `R.failed(msg)`（非 500）；唯一约束冲突捕获并转友好提示。
- **审计**：MybatisPlusMetaObjectHandler 自动填充审计字段，无需手写。

## 四、交付顺序与依赖

```
DD1 (M0) ──┬─> DD2 (M1) ──> DD3 (M2)
           │
           └─> DD4 (M3) ──────────────────┐
                                           ├─> DD6 (贯穿, 依赖 M2+M3)
           DD2 (M1) ──> DD5 (M4) ──────────┘
```

- DD1 先行（骨架），是所有后续 DD 的基础。
- DD2 是首落地（属性模板 ROI 最高），供给接口 v1 随 DD2 起步、逐 DD 扩展。
- DD3 依赖 DD2（分类模板结构骨架引用属性模板）。
- DD4 可与 DD2 并行（只引用 QUDT，与 M1 仅在"模板预设单位"交汇）。
- DD5 依赖 DD2（templateRef 需注册）。
- DD6 贯穿，依赖 DD3（Brick 导入分类模板）+ DD4（QUDT 导入单位）。
