## 一、计划总览

本计划把建模域 PRD 的 5 个里程碑（M5 本体项目 / M6 类实体+模板实例化 / M7 属性+关系+类层级 / M8 序列化与解析 / M9 可视化画布）拆成 **5 个详细设计单元**，每单元产出一份独立详细设计文档，存放于 `docs/ontology/模板化建模平台设计/prd/` 目录，命名 `详细设计-DDx-<主题>.md`。

```
DD7  (M5) 本体项目管理与命名空间          ← 待设计
DD8  (M6) 类实体创建与模板实例化          ← 待设计
DD9  (M7) 属性与关系建模 + 类层级回推     ← 待设计
DD10 (M8) RDF 序列化与解析               ← 待设计
DD11 (M9) 可视化建模画布                 ← 待设计
```

> 编号衔接：治理域 DD1–DD6 已全部落地（M0–M4 + 贯穿），建模域从 DD7 起。个体实例（owl:NamedIndividual）后置为 M10/DD12，不在 v1 范围（PRD 第十八节）。

每个详细设计单元遵循统一结构（与治理域 DD1–DD6 一致）：
1. 设计目标与范围（对应 PRD 的 FR 与里程碑）
2. 落地清单（文件清单：pom/类/配置/sql/vue/ts）
3. 数据库设计（DDL + 种子，含字段类型与约束）
4. 后端设计（包结构、Entity/Service/Controller、接口签名、鉴权）
5. 前端设计（页面、API、路由挂载、组件复用）
6. 横切设计（缓存/校验/异常/审计/i18n）
7. 验收映射（AC 编号 -> 实现点）
8. 测试要点

## 二、各单元详细设计范围

### DD7（M5）本体项目管理与命名空间

- **范围**：FR-10（本体项目 CRUD + IRI 前缀注册 + 序列化策略配置 + 项目状态管理）。
- **输入**：PRD 3.1/3.2/3.3、7.FR-10、9.1/9.2、10.1、13.1/13.2、十四节 M5、十六节 M5。
- **数据**：`ont_model_project`（9.1）、`ont_model_prefix`（9.2）。**V12 建表 + V12 菜单种子**（11000 一级目录 + 11100 段菜单 + 11101~11104 权限点按钮）。
- **后端**：`ModelProjectController` + `ModelProjectService`(+Impl) + `ModelPrefixService`(+Impl) + 2 Entity/2 Mapper + DTO/VO。包路径 `com.pig4cloud.pig.ontology.modeling.*`（在 pig-ontology-biz 内新增 modeling 包）。
- **前端**：`views/admin/ontology-model/project/index.vue`（列表+表单弹窗+前缀管理子表）+ `api/ontology-model/project.ts` + `composables.ts` + `i18n/{zh-cn,en}.ts`。
- **AC**：AC-10.1~10.5。
- **关键设计点**：
  - 项目创建时默认 `serialization_strategy='B'`（方案 B 零风险）；`strategy='A'` 字段存在但 v1 禁用切换（返回提示）。
  - 前缀 NCName 校验（正则 `^[A-Za-z_][A-Za-z0-9_.-]*$`）；同项目内前缀名唯一（DB 唯一约束 + 预查重）。
  - 项目删除时校验是否有关联类实体（查 `ont_model_class`），有则拒绝并提示。
  - archived 状态项目只读，Controller 层拦截写操作。
- **产出**：本文档 + `详细设计-DD7-本体项目管理与命名空间.md`。

### DD8（M6）类实体创建与模板实例化 --核心

- **范围**：FR-11（类实体 CRUD + 基于分类模板创建 + 模板实例化批量挂属性 + 溯源）。
- **输入**：PRD 7.FR-11、9.3、10.2、十一节场景一/三、十四节 M6、十六节 M6。
- **数据**：`ont_model_class`（9.3）。**V13 建表 + V13 菜单种子**（11200 段菜单 + 11201~11204 权限点）。
- **后端**：`ModelClassController` + `ModelClassService`(+Impl) + `ClassInstantiationService`（模板实例化核心）+ Entity/Mapper + DTO/VO。
  - **ClassInstantiationService** 是核心算法 Service（类似治理域 InheritedViewService 的定位）：
    - 输入：projectId + classId + 分类模板 templateCode
    - 调治理域 `/supply/v1/class-template/{code}/inherited` 获取继承视图
    - 遍历 propertyRefs，批量创建 `ont_model_datatype_property` / `ont_model_object_property` 记录
    - 每条挂 `templateRef` = 属性模板 templateCode
    - 类挂 `templateCode` = 分类模板 templateCode、`classificationCode` = 分类模板 classification_code
  - IRI 生成：`class_iri = project.namespace_base + localName`；同项目唯一（DB 唯一约束 + 预查重）。
- **前端**：`views/admin/ontology-model/class/index.vue`（splitpanes 左树右表，复用 QueryTree）+ `form.vue`（新建类弹窗，含模板选择+继承属性预览）+ `composables.ts` + `i18n/{zh-cn,en}.ts`。
- **AC**：AC-11.1~11.8。
- **关键设计点**：
  - 消费治理域 Supply API（HTTP 调用，同模块内也可只读查治理域表，但**只读不写**，R-23）。
  - 模板实例化是"复制字段值"非"引用模板"（PRD 5.2 约定）：复制 type/label/单位/枚举/基数到新建属性记录。
  - 基于模板创建 vs 空白创建走同一表单，模板选择为可选步骤。
  - 类删除时校验：是否被其他类 subClassOf 引用、是否有属性，拒绝或级联软删。
- **产出**：本文档 + `详细设计-DD8-类实体创建与模板实例化.md`。

### DD9（M7）属性与关系建模 + 类层级回推 --最复杂

- **范围**：FR-12（数据属性+单位绑定+枚举+基数+标识符）+ FR-13（对象属性+domain/range+反向关系）+ FR-14（subClassOf 建立+环路检测+镜像回推+一致性保证）。
- **输入**：PRD 7.FR-12/FR-13/FR-14、9.4/9.5/9.6、10.3/10.4/10.5、十一节场景一/四、十四节 M7、十六节 M7。
- **数据**：`ont_model_datatype_property`（9.4）、`ont_model_object_property`（9.5）、`ont_model_subclassof`（9.6）。**V14 建三表 + V14 菜单种子**（11300 段属性菜单 + 11301~11304 权限点；类层级复用 11200 段权限）。
- **后端**：3 套 Controller/Service(+Impl)/Entity/Mapper + 2 个核心算法 Service：
  - **ModelDatatypePropertyController/Service**：数据属性 CRUD + 从属性模板实例化（调 `/supply/v1/property-templates?kind=datatype`）+ 单位绑定（调 `/supply/v1/units`）。
  - **ModelObjectPropertyController/Service**：对象属性 CRUD + 从属性模板实例化（调 `/supply/v1/property-templates?kind=object`）+ 反向关系建议（FR-13.5）。
  - **ModelSubclassOfController/Service**：subClassOf CRUD + 环路检测（复用治理域 CycleDetectorService 思路，DFS）。
  - **HierarchySyncService**（核心算法 Service）：镜像回推一致性保证。
    - 建立 subClassOf 后：写 `ont_model_subclassof`（sync_status='0'）→ 组装 `ClassHierarchySyncDTO` → 调治理域 `POST /sync/class-hierarchy`（权限 `ont_sync_push`）→ 成功置 sync_status='1'，失败保持 '0'。
    - 删除 subClassOf 后：调治理域 `DELETE /sync/class-hierarchy` → 镜像 sync_status='2'。
    - **补偿机制**：`@Scheduled` 定时扫描 sync_status='0' 的记录，重试回推（最多 3 次，指数退避）。
- **前端**：`views/admin/ontology-model/property/index.vue`（Tab 切换数据属性/对象属性，两列表+两表单）+ `api/ontology-model/property.ts` + `composables.ts` + `i18n/{zh-cn,en}.ts`。
- **AC**：AC-12.1~12.7 + AC-13.1~13.5 + AC-14.1~14.6。
- **关键设计点**：
  - 数据属性 localName 同类内唯一（uk 约束 project_id+property_iri）；非数值型属性不可绑单位（Service 层校验 xsd_type）。
  - 对象属性 range 需手动选定（属性模板不含 range，PRD FR-13.2）；反向关系建议用前端弹窗确认（FR-13.5）。
  - 环路检测在建模域执行（与治理域 SyncController 不校验环路的注释一致：建模侧是权威源，环路校验由建模侧负责）。
  - 镜像回推不走分布式事务（R-19）：本地事务写建模域表 + HTTP 调同步接口，失败靠补偿重试。
  - 多继承支持（FR-14.6）：subClassOf 允许多条，但溯源取主父类 sourceTemplateRef。
- **风险**：M7 是最复杂里程碑（3 FR 并行 + 回推一致性），需重点评审（PRD R-19）。
- **产出**：本文档 + `详细设计-DD9-属性与关系建模与类层级回推.md`。

### DD10（M8）RDF 序列化与解析

- **范围**：FR-15（Turtle + OWL XML 序列化，方案 B 默认，注释属性驱动，单位引用）+ FR-16（解析导入 + 溯源识别 + 往返一致性）。
- **输入**：PRD 7.FR-15/FR-16、10.6、十一节场景一/二、十四节 M8、十六节 M8、附录 B/C。
- **数据**：无新建表（复用 ont_model_* 全部表）。**V15 菜单种子**（11400 段序列化菜单 + 11401~11402 权限点）。
- **后端**：`ModelSerializeController` + `SerializationService`（核心）+ `ParsingService`（核心）+ VO。
  - **SerializationService**：
    - 输入：projectId + format（TTL/OWL_XML）
    - 查项目所有类/属性/关系 → 构建 Jena `Model`
    - **方案 B 序列化**（默认）：数据属性 IRI = `{namespace_base}{classLocalName}_{propLocalName}`；每类独立属性定义
    - **注释属性驱动**：调 `/supply/v1/annotation-properties` 获取注册表 → 遍历匹配属性/类自动写入 `ont:xxx` 注解（unitRef/isIdentifier/templateRef/propertyType/cardinality/classificationCode）
    - 单位引用：`ont:unitRef rdf:resource="<QUDT IRI>"`
    - Jena `RDFDataMgr.write(model, out, Lang.TTL)` / `Lang.RDFXML`
    - Caffeine 缓存 Model（key=projectId+版本号，TTL 5min，建模操作失效）
  - **ParsingService**：
    - 输入：上传文件（multipart）+ projectId + 冲突策略
    - Jena `RDFDataMgr.loadModel()` 解析
    - 提取 owl:Class / DatatypeProperty / ObjectProperty / subClassOf
    - **溯源识别**：解析 `ont:templateRef` → 校验治理域 templateCode 存在性 → 关联或标记孤儿
    - **单位识别**：解析 `ont:unitRef` → 按 QUDT IRI 匹配 `ont_unit`
    - **注释属性识别**：按注册表校验 `ont:xxx`，注册表外忽略并告警
    - **往返一致性**（AC-16.5）：序列化→解析→再序列化，RDF 图同构比对（Jena `Model.isIsomorphicWith()`）
  - **方案 A 预留**：项目 `strategy='A'` 时返回提示"方案 A 尚未启用"（FR-15.4）。
- **前端**：`views/admin/ontology-model/serialize/index.vue`（上半区操作按钮+下半区 codemirror 预览）+ `api/ontology-model/serialize.ts` + `i18n/{zh-cn,en}.ts`。
  - codemirror 复用已有依赖（5.65.21），Turtle 语法高亮 mode。
  - 导入弹窗：文件上传 + 冲突策略 radio（覆盖/跳过/重命名）+ 导入结果报告。
- **AC**：AC-15.1~15.8 + AC-16.1~16.6。
- **关键设计点**：
  - **复用 DD6 已引入的 jena-arq 5.3.0**，零新增后端依赖（PRD 3.1）。
  - 注释属性命名空间 `ont:` 基址 `http://youming.com/ontology/annotation#`（PRD 附录 C.3）。
  - 导入文件大小限制 ≤10MB（NFR-S2）；Jena 解析异常返回友好错误（NFR-S3）。
  - 往返一致性用 Jena `Model.isIsomorphicWith()` 而非字符串比对（忽略 IRI 顺序差异，AC-16.5）。
- **产出**：本文档 + `详细设计-DD10-RDF序列化与解析.md`。

## 三、设计原则与通用约定（所有 DD 共享）

> 建模域约定在治理域约定（治理域详细设计计划第三节）基础上延伸，不重复冲突，只补充建模域特有约定。

### 3.1 后端约定（建模域延伸）

- **包结构**：在 `com.pig4cloud.pig.ontology` 下新增 `modeling` 子包：
  ```
  com.pig4cloud.pig.ontology
    ├── controller/        # 治理域（已有）
    ├── service/           # 治理域（已有）
    ├── ...
    └── modeling/          # 建模域（新增）
         ├── controller/   # ModelProjectController / ModelClassController / ...
         ├── service/      # ModelProjectService / ClassInstantiationService / SerializationService / ...
         │   └── impl/
         ├── mapper/       # ModelProjectMapper / ModelClassMapper / ...
         ├── entity/       # ModelProject / ModelClass / ...
         ├── dto/          # ClassInstantiateDTO / SerializePreviewDTO / ...
         └── vo/           # ModelClassDetailVO / SerializeResultVO / ...
  ```
- **模块**：复用 `pig-ontology-biz` 单模块（S-4，不新拆子模块，PRD 3.1 决策）。
- **Controller 路径**：类级 `@RequestMapping("/ont/model/xxx")`，对外 `/admin/ont/model/xxx`（复用 pig-gateway `Path=/admin/ont/**` 路由）。
- **鉴权**：`@HasPermission("ont_xxx_model_*")`（建模域权限标识，PRD 13.2）；写操作加 `@SysLog`。
- **治理域消费方式**：建模域 Service 通过 HTTP 调用治理域 SupplyController/SyncController（`RestTemplate` 或 `@FeignClient`，v1 用 `RestTemplate` 简化，因同模块同进程可直接 HTTP localhost）。**不直接注入治理域 Service**（保持边界，R-23），但可只读查询治理域表（如校验 templateCode 存在性）。
- **Entity 范式**：同治理域（继承 `Model<T>` + `@TableId(ASSIGN_ID)` + `@TableName` + `@TableLogic` + 审计字段 `@TableField(fill=...)`）。

### 3.2 数据库约定（建模域延伸）

- **Flyway 脚本**：建模域从 **V12** 起编号（治理域止于 V11）。放同一 `db/migration/` 目录。
  | 脚本 | DD | 内容 |
  |---|---|---|
  | V12 | DD7 | ont_model_project + ont_model_prefix 建表 + 11000/11100 段菜单种子 |
  | V13 | DD8 | ont_model_class 建表 + 11200 段菜单种子 |
  | V14 | DD9 | ont_model_datatype_property + ont_model_object_property + ont_model_subclassof 建表 + 11300 段菜单种子 |
  | V15 | DD10 | 11400 段菜单种子（无新建表） |
  | V16 | DD11 | ont_model_canvas_state 建表 + 11500 段菜单种子 |
- **表前缀**：`ont_model_`（区别治理域 `ont_`）。
- **字段约定**：同治理域（主键 bigint、布尔 char(1)、del_flag、审计字段齐全）。
- **菜单 ID 段**：建模域用 **11000–11599**（治理域用 10000–10599，不冲突）。
- **禁改已应用脚本**：V1–V11 不可修改（Flyway checksum 校验）。

### 3.3 前端约定（建模域延伸）

- **页面路径**：`web/src/views/admin/ontology-model/<feature>/index.vue`（注意是 `ontology-model`，区别治理域 `ontology`）。
  | 页面 | sys_menu.path | DD |
  |---|---|---|
  | 本体项目管理 | `/admin/ontology-model/project/index` | DD7 |
  | 本体类建模 | `/admin/ontology-model/class/index` | DD8 |
  | 本体属性建模 | `/admin/ontology-model/property/index` | DD9 |
  | 序列化与导入 | `/admin/ontology-model/serialize/index` | DD10 |
  | 可视化画布 | `/admin/ontology-model/canvas/index` | DD11 |
- **API**：`web/src/api/ontology-model/<feature>.ts`，用 `/@/utils/request`，函数名 `pageList/addObj/getObj/putObj/delObj`。
- **路由**：后端控路由（同治理域），sys_menu 种子 + `import.meta.glob` 动态装配。
- **组件复用**：splitpanes（分屏布局）、QueryTree（树组件）、codemirror（RDF 预览）、el-table/el-form（Element Plus）。
- **新增依赖**（DD11 画布）：`@antv/x6` + `@antv/x6-vue-shape` + `@antv/layout`。
- **i18n**：`views/admin/ontology-model/<feature>/i18n/{zh-cn,en}.ts`，按模块隔离（key 前缀如 `modelProject.`/`modelClass.`）。
- **权限指令**：`v-auth="'ont_xxx_model_*'"`（对齐后端权限点）。

### 3.4 横切约定（建模域延伸）

- **缓存**：
  - 序列化 Model 缓存：Caffeine（key=projectId+版本号，TTL 5min，建模写操作失效）--DD10
  - 治理域供给数据缓存：复用治理域已有 Caffeine（SupplyController 侧已缓存继承视图/单位等）--DD8/DD9 消费方无需再缓存
- **补偿任务**：镜像回推失败的 `ont_model_subclassof`（sync_status='0'），`@Scheduled` 定时重试（最多 3 次，指数退避 10s/30s/90s）--DD9
- **异常**：同治理域（`R.failed(msg)` 友好提示；Jena 解析异常捕获转中文错误）。
- **审计**：MybatisPlusMetaObjectHandler 自动填充（同治理域，无需手写）。
- **一致性**：建模域与治理域类层级一致性靠 sync_status 补偿（R-19），不走分布式事务。
