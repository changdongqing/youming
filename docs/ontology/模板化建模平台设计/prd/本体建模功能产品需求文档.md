## 一、文档说明

### 1.1 本文档定位

治理域 PRD（v1.2）已明确声明：**本治理功能是未来"本体建模功能"的前置治理底座**，先于建模功能建设。治理域负责产出治理资产（属性模板、分类模板、单位注册表、注释属性注册表、参考本体）并通过 SupplyController（`/supply/v1/`）对建模侧稳定供给；序列化/解析、建模画布、个体实例、本体类实体创建全部划归建模侧（治理 PRD 第十八节 Out of Scope）。

DD1–DD6 全部落地后，治理资产与供给管道已就绪，但**没有任何一寸代码在消费这些供给**。本 PRD 描述的就是这个消费方--**本体建模功能（ontology modeling）**本身：通过消费治理域供给的模板/单位/注册表，真正组装出 OWL 本体（类、属性、关系），并完成 RDF 序列化与解析。

### 1.2 阅读对象

| 角色 | 关注点 |
|---|---|
| 产品/架构 | 里程碑划分、与治理域边界、序列化策略、画布选型 |
| Java 后端 | 数据模型、接口契约、模板实例化、序列化引擎、类层级回推 |
| Vue 前端 | 画布交互、模板侧边栏、序列化预览、页面结构 |
| 测试 | 验收标准（AC）、DoD、序列化正确性验证 |
| 本体治理员 | 治理资产如何被建模消费、溯源字段如何回写 |

### 1.3 术语速读

| 术语 | 定义 |
|---|---|
| **建模域** | 本 PRD 描述的本体建模功能，是治理资产的消费方 |
| **治理域** | 已完成的模板化治理功能（DD1–DD6），产出治理资产 + 供给接口 |
| **本体项目** | 建模域的顶层容器，含命名空间、IRI 前缀、序列化策略配置 |
| **类实体** | 建模域创建的 `owl:Class`，有独立 IRI，区别于治理域的分类模板 |
| **模板实例化** | 从分类模板的 propertyRefs 批量生成类的属性挂载 |
| **方案 A / 方案 B** | 属性序列化的"共享单一属性 + 多 domain"与"带前缀独立副本"两种策略 |
| **templateRef** | 溯源字段，标记某属性/类源自哪个治理模板，由治理域产出供建模侧消费 |
| **画布** | 可视化建模工作区，类为节点、subClassOf/对象属性为边 |
| **AntV X6** | 蚂蚁开源图编辑引擎，本 PRD 选定的画布技术方案 |

## 二、产品背景与目标

### 2.1 背景

治理域已完成六者模板化治理（DD1–DD6），产出：
- 属性模板库（12 内置，数据属性 + 对象属性同构）
- 分类模板体系（父子继承 + 结构骨架 + GB/T 51269 编码 + 类层级镜像）
- 单位注册表（8 量纲 + 常用单位，QUDT 引用 + 换算引擎）
- 注释属性注册表（12 内置，含 unitRef/quantityKindRef 溯源注解）
- 参考本体库（QUDT/Brick/CCO 只读浏览 + 引用式导入）
- 供给接口 v1（7 端点，`/supply/v1/`，权限 `ont_supply_view`）
- 类层级同步接口（`/sync/class-hierarchy`，权限 `ont_sync_push`）

但当前 youming 平台**无法创建任何实际的 OWL 本体**--没有类实体、没有属性挂载、没有 RDF 输出。治理资产是"原料"，供给管道是"输送带"，但"工厂"（建模功能）尚未建设。本 PRD 就是建设这个工厂。

### 2.2 目标（SMART）

| 编号 | 目标 | 度量 |
|---|---|---|
| G-1 | 建模师能通过消费分类模板创建 `owl:Class` 实体并挂载属性 | 创建类 100% 可序列化为合法 OWL |
| G-2 | 能基于属性模板创建数据属性（绑单位）与对象属性（设 domain/range） | 属性含 templateRef 溯源率 ≥90%（新本体） |
| G-3 | 能将建模结果序列化为 Turtle / OWL XML 并反向解析 | 序列化-解析往返一致性 ≥99% |
| G-4 | 提供可视化建模画布，支持类节点/继承边/关联边的拖拽式编辑 | 画布操作可覆盖 100% 建模功能 |
| G-5 | 建立类层级后自动回推 `ont_class_hierarchy` 镜像 | 镜像同步成功率 ≥99% |
| G-6 | 序列化输出按注释属性注册表自动写入 `ont:xxx` 注解 | 注解写入与注册表一致率 100% |

### 2.3 业务价值

- **打通"治理→建模→输出"全链路**：治理资产不再"闲置"，真正转化为可消费的 OWL 本体
- **降低建模重复劳动**：模板实例化替代逐字段手工建属性，审计类（4 字段）一键复用
- **RDF 输出规范化**：单位走 QUDT IRI、注解走注册表、属性带溯源，输出本体可直接被外部工具消费
- **可视化建模**：画布交互降低本体建模门槛，非 RDF 专家也能操作

## 五、名词与约定

### 5.1 治理域 vs 建模域边界

| 维度 | 治理域（已完成） | 建模域（本 PRD） |
|---|---|---|
| 核心对象 | 模板（属性模板/分类模板） | 实体（owl:Class / 属性 / 关系） |
| IRI | 模板不含 IRI（templateCode 仅治理期标识） | 实体有独立 IRI（建模侧赋予） |
| 进入 RDF | 不进入（治理资产侧原型） | 进入（序列化产出 RDF） |
| 类层级 | 只读镜像（ont_class_hierarchy） + 供给建议 | **权威源**（建模侧建立 subClassOf） |
| 序列化 | 不做（只产 templateCode 判据） | **做**（方案 B 默认，方案 A 预留） |
| 个体实例 | 不做（Out of Scope） | 不做（后置 M10） |

### 5.2 关键约定

- **类实体有独立 IRI**：`owl:Class` 的 `rdf:about` = 项目命名空间 + localName，由建模侧赋予，不复用分类模板的 templateCode。
- **模板实例化复制字段值**：从分类模板实例化属性时，**复制字段值并挂 `templateRef` 溯源**（治理 PRD 5.2 约定），不引用模板本身。
- **类层级权威源在建模域**：建模侧建立 subClassOf 是唯一权威源；建立后经 SyncController 回推 `ont_class_hierarchy` 镜像（治理域只读）。
- **序列化默认方案 B**：v1 默认走方案 B（带前缀独立副本，`{entityLocalName}_{propName}`），零风险；方案 A（共享单一属性 + 多 domain）作为项目级开关预留，后续里程碑启用。
- **注释属性驱动序列化**：序列化时按注释属性注册表（`ont_annotation_property`）自动写入 `ont:xxx` 注解，不硬编码。
- **单位以 IRI 引用**：数据属性绑单位时记录 `unitRef`（QUDT IRI），序列化输出 `ont:unitRef` 注解引用外部 QUDT，不在本体重定义单位。

### 5.3 三层模型延续

```
整本体（建模域：本体项目 + 序列化输出）
  └── 分类模板（治理域：分类模板体系，结构骨架 propertyRefs）
       └── 属性模板（治理域：属性模板库，数据+对象同构）
```

建模域消费上层（分类模板）时，自动级联消费下层（属性模板）--实例化一个分类模板即批量挂载其 propertyRefs 指向的所有属性模板。

## 七、功能需求详述

### FR-10 本体项目管理与命名空间（M5）

**目标**：提供建模域的顶层容器，管理本体项目的命名空间、IRI 前缀、序列化策略。

**需求项**：

| 编号 | 需求 | 验收标准 |
|---|---|---|
| FR-10.1 | 本体项目 CRUD（名称、描述、命名空间基址、默认序列化格式） | AC-10.1：项目可创建/查询/编辑/删除；删除时校验是否有关联类实体 |
| FR-10.2 | IRI 前缀注册（项目命名空间前缀，如 `ex: http://example.com/onto/`） | AC-10.2：前缀可增删改；前缀名符合 NCName 规范；同项目前缀名唯一 |
| FR-10.3 | 序列化策略配置（默认方案 B；方案 A 开关预留，v1 禁用） | AC-10.3：项目创建时默认 `serialization_strategy='B'`；`strategy='A'` 字段存在但 v1 不支持切换（返回提示） |
| FR-10.4 | 项目状态管理（draft/active/archived） | AC-10.4：archived 项目只读，不可新建类/属性 |
| FR-10.5 | 项目列表分页查询（按名称/状态过滤） | AC-10.5：分页查询支持名称模糊搜索 + 状态过滤 |

**数据表**：`ont_model_project`（9.1）、`ont_model_prefix`（9.2）

### FR-11 类实体创建与模板实例化（M6）--核心

**目标**：创建 `owl:Class` 实体，支持基于/不基于分类模板创建，模板实例化时批量挂载属性。

**需求项**：

| 编号 | 需求 | 验收标准 |
|---|---|---|
| FR-11.1 | 类实体创建（IRI、label、labelCn、描述、所属项目） | AC-11.1：类可创建；IRI = 项目命名空间 + localName；同项目内 IRI 唯一 |
| FR-11.2 | 基于分类模板创建（选择分类模板 -> 拉取 inherited 视图 -> 实例化属性） | AC-11.2：选择模板后调 `/supply/v1/class-template/{code}/inherited`；返回的 propertyRefs 批量创建为类属性，每条挂 `templateRef` |
| FR-11.3 | 不基于模板创建（空白类，手动添加属性） | AC-11.3：空白类创建后属性列表为空；可后续手动添加 |
| FR-11.4 | 模板实例化溯源（每条实例化属性挂 `templateRef` = 属性模板 templateCode） | AC-11.4：实例化属性的 `template_ref` 字段非空，值等于源属性模板 templateCode |
| FR-11.5 | 分类模板溯源（类实体挂 `classificationCode` = 源分类模板编码） | AC-11.5：基于模板创建的类 `classification_code` 非空，值等于源分类模板 classification_code |
| FR-11.6 | 类实体 CRUD（查询/编辑/删除） | AC-11.6：编辑可修改 label/描述；删除时校验是否被其他类 subClassOf 引用、是否有属性；软删 |

### 9.1 `ont_model_project` - 本体项目

```sql
CREATE TABLE ont_model_project (
    id                      bigint       NOT NULL,
    project_code            varchar(64)  NOT NULL,        -- 项目编码（唯一）
    name                    varchar(128) NOT NULL,        -- 项目名称
    description             varchar(512),
    namespace_base          varchar(255) NOT NULL,        -- 命名空间基址，如 http://example.com/onto/
    default_format          varchar(16)  DEFAULT 'TTL',   -- 默认序列化格式：TTL / OWL_XML
    serialization_strategy  char(1)      DEFAULT 'B',     -- 序列化策略：B=方案B(默认) / A=方案A(预留,v1禁用)
    status                  varchar(16)  DEFAULT 'draft', -- draft / active / archived
    create_by               varchar(64)  DEFAULT ' ',
    create_time             timestamp    DEFAULT now(),
    update_by               varchar(64)  DEFAULT ' ',
    update_time             timestamp    DEFAULT now(),
    del_flag                char(1)      DEFAULT '0',
    CONSTRAINT pk_ont_model_project PRIMARY KEY (id),
    CONSTRAINT uk_ont_model_project_code UNIQUE (project_code)
);
COMMENT ON TABLE  ont_model_project IS '本体项目（建模域顶层容器）';

## 十一、用户故事与场景

### 11.1 场景一：从零创建一个设备本体（核心场景）

**角色**：建模师
**前置条件**：治理域已有设备分类模板树（30 设备 -> 30-01 泵 -> 30-01-01 喷淋泵）

```
1. 创建本体项目"消防设备本体"，命名空间 http://youming.com/onto/fire/
2. 注册前缀 fire: http://youming.com/onto/fire/
3. 从分类模板树选"喷淋泵(30-01-01)"，拖入画布
   -> 系统调 /supply/v1/class-template/spray-pump/inherited
   -> 返回继承视图：5 个属性（泵 4 + 喷淋泵 1）
   -> 画布生成类节点 FireSprayPump，IRI = http://youming.com/onto/fire/FireSprayPump
   -> 5 个属性自动实例化，每个挂 templateRef
4. 从属性模板库拖"price"属性到 FireSprayPump 节点
   -> 选择单位 unit:CNY（从 /supply/v1/units 选）
   -> 数据属性 price 挂 templateRef=price, unitRef=http://qudt.org/vocab/unit/CNY
5. 创建第二个类 FirePumpRoom，建立 subClassOf? 否，建立对象属性 contains
   -> 对象属性 contains(domain=FirePumpRoom, range=FireSprayPump)
   -> 系统提示是否创建反向 belongsTo，选择是
6. 点击"序列化预览"，右上角展示 Turtle:
   <owl:Class rdf:about="http://youming.com/onto/fire/FireSprayPump">
     <rdfs:label>FireSprayPump</rdfs:label>
     <ont:classificationCode>30-01-01</ont:classificationCode>
     <ont:templateRef>spray-pump</ont:templateRef>
   </owl:Class>
   <owl:DatatypeProperty rdf:about="http://youming.com/onto/fire/FireSprayPump_price">
     <rdfs:domain rdf:resource="http://youming.com/onto/fire/FireSprayPump"/>
     <rdfs:range rdf:resource="http://www.w3.org/2001/XMLSchema#decimal"/>
     <ont:templateRef>price</ont:templateRef>
     <ont:unitRef rdf:resource="http://qudt.org/vocab/unit/CNY"/>
     <ont:isIdentifier>false</ont:isIdentifier>
   </owl:DatatypeProperty>
7. 点击"导出 Turtle"，下载 fire-equipment.ttl
```

### 11.2 场景二：导入已有 OWL 本体并识别溯源

```
1. 上传一个已有的 .ttl 文件
2. 系统用 Jena 解析，提取:
   - 3 个 owl:Class（含 ont:templateRef 注解 -> 关联到治理域分类模板）
   - 12 个数据属性（含 ont:unitRef -> 关联到 ont_unit）
   - 2 个对象属性
3. 溯源识别结果:
   - 8 个属性的 templateRef 在治理域存在 -> 标记为模板派生
   - 4 个属性的 templateRef 不存在 -> 标记为孤儿，提示"是否提升为模板"
   - 3 个属性的 unitRef 匹配到 ont_unit -> 关联
4. 导入完成，画布渲染 3 个类节点 + 继承边 + 关联边
```

### 11.3 场景三：模板实例化与溯源

```
1. 建模师在画布上选中一个空白类节点
2. 右键"从模板实例化属性"
3. 弹出分类模板树（来自 /supply/v1/class-template/tree）
4. 选择"泵(30-01)"，系统调 inherited 端点
5. 返回 4 个属性（额定流量/扬程/功率/介质）
6. 确认实例化，4 个属性创建到当前类:
   - 每条属性 template_ref = 源属性模板 templateCode
   - 类 template_code = pump, classification_code = 30-01
7. 序列化输出中 4 个属性均带 <ont:templateRef>xxx</ont:templateRef>
```

### 11.4 场景四：类层级建立与镜像回推

```
1. 建模师在画布上从 FireSprayPump 拖出继承边到 Pump
2. 系统建立 subClassOf(FireSprayPump, Pump)
   - 写入 ont_model_subclassof（sync_status='0'）
3. 自动组装 ClassHierarchySyncDTO:
   - childClassIri = http://youming.com/onto/fire/FireSprayPump
   - parentClassIri = http://youming.com/onto/fire/Pump
   - sourceTemplateRef = spray-pump（从类 template_code 取）
4. 调 POST /admin/ont/sync/class-hierarchy（权限 ont_sync_push）
5. 镜像回推成功，sync_status='1'
6. 若同步失败:
   - sync_status 保持 '0'
   - 后台补偿任务重试（最多 3 次）
   - 画布上边显示"镜像待同步"警告标记
```

### 11.5 场景五：序列化策略切换（v1 预留）

```
1. 建模师在项目设置中尝试将序列化策略从 B 改为 A
2. 系统返回提示:"方案 A（共享属性+多domain）尚未启用，当前使用方案 B"
3. 字段 serialization_strategy 保持 'B'
4. v1 不支持方案 A，后续里程碑启用
```

## 十六、里程碑与交付计划

> 建模域在治理域 M0–M4 + 贯穿之后，从 M5 起编号。

```
依赖链：
M5(项目) -> M6(类实例化) -> M7(属性+关系+类层级) -> M8(序列化/解析) -> M9(画布)
                                                        ^
                                                        画布依赖 M6~M8 的全部建模能力
```

| 里程碑 | 内容 | 依赖 | 风险 | DoD |
|---|---|---|---|---|
| **M5：本体项目管理** | FR-10（项目 CRUD + 命名空间 + 前缀 + 策略配置）+ V12 建表 + V12 菜单种子 | 治理域完成 | 低 | AC-10.x |
| **M6：类实体创建与模板实例化** | FR-11（类 CRUD + 基于模板实例化 + 溯源）+ 消费 Supply API | M5 | 中 | AC-11.x |
| **M7：属性与关系建模** | FR-12（数据属性+单位）+ FR-13（对象属性+domain/range）+ FR-14（subClassOf+镜像回推） | M6 | 中 | AC-12~14.x |
| **M8：序列化与解析** | FR-15（Turtle+OWL XML 序列化，方案 B）+ FR-16（解析导入+往返一致） | M7 | 中 | AC-15~16.x |
| **M9：可视化建模画布** | FR-17（AntV X6 画布 + 模板侧边栏 + 拖拽 + 序列化预览） | M6~M8 | 高 | AC-17.x |

**建议**：
- **M5 先行**（搭项目容器），**M6 紧随**（类实例化是核心价值点，验证治理资产可消费）。
- **M7 是最复杂里程碑**（三个 FR 并行：数据属性 + 对象属性 + 类层级），需重点评审。
- **M8 依赖 M7 全部完成**（序列化需要类/属性/关系齐全）。
- **M9 放最后**（画布是增值体验，M6–M8 已能通过表单完成全部建模；画布延期不影响主链路）。
- **方案 A 序列化、个体实例（M10）不在 v1 范围**，后续独立里程碑。

## 附录 B：序列化双策略详述与迁移路径

### B.1 方案 B（v1 默认）--带前缀独立副本

```
# 数据属性：IRI = {classLocalName}_{propLocalName}
<owl:DatatypeProperty rdf:about="http://youming.com/onto/fire/FireSprayPump_price">
  <rdfs:domain rdf:resource="http://youming.com/onto/fire/FireSprayPump"/>
  <rdfs:range rdf:resource="http://www.w3.org/2001/XMLSchema#decimal"/>
  <ont:templateRef>price</ont:templateRef>
  <ont:unitRef rdf:resource="http://qudt.org/vocab/unit/CNY"/>
  <ont:isIdentifier>false</ont:isIdentifier>
</owl:DatatypeProperty>

# 对象属性：IRI = {domainLocalName}_{propLocalName}
<owl:ObjectProperty rdf:about="http://youming.com/onto/fire/FirePumpRoom_contains">
  <rdfs:domain rdf:resource="http://youming.com/onto/fire/FirePumpRoom"/>
  <rdfs:range rdf:resource="http://youming.com/onto/fire/FireSprayPump"/>
  <ont:templateRef>contains</ont:templateRef>
</owl:ObjectProperty>
```

**特点**：每类一份独立属性副本，IRI 带类前缀，向后兼容，零风险。

### B.2 方案 A（预留）--共享单一属性 + 多 domain

```
# 同 templateRef 且 range/unitRef/type 一致 -> 合并为共享属性
<owl:DatatypeProperty rdf:about="http://youming.com/onto/fire/price">
  <rdfs:domain rdf:resource="http://youming.com/onto/fire/FireSprayPump"/>
  <rdfs:domain rdf:resource="http://youming.com/onto/fire/FirePump"/>     <!-- 多 domain -->
  <rdfs:range rdf:resource="http://www.w3.org/2001/XMLSchema#decimal"/>
  <ont:templateRef>price</ont:templateRef>
  <ont:unitRef rdf:resource="http://qudt.org/vocab/unit/CNY"/>
</owl:DatatypeProperty>
```

**合并前置校验**：仅当 `range`/`unitRef`/`enumValues`/`type` 一致才合并；否则降级方案 B 并告警。

### B.3 迁移路径（承接设计稿第十一节）

```
阶段 1（v1，立即可做，零风险）：
  - 方案 B 序列化（带前缀独立副本）
  - templateRef 溯源标注
  - 注释属性驱动序列化
  - 设计期即享治理收益，RDF 输出向后兼容

阶段 2（后续里程碑，中等收益）：
  - 启用方案 A 序列化（共享属性 + 多 domain）
  - 合并前置校验（range/unitRef/type 一致性）
  - 提供"扫描同名属性 -> 推荐提升为模板"向导
  - 新本体享受 RDF 去重

不强制迁移：旧本体继续按方案 B 工作；经过治理的本体可切换方案 A 去重。
```

```

### C.3 注释属性命名空间

- 注释属性（`ont:xxx`）的命名空间基址：`http://youming.com/ontology/annotation#`
- 注释属性 localName 来自治理域 `ont_annotation_property` 注册表（12 内置项）
- 序列化时按注册表自动声明 `@prefix ont:` + 写入注解

## 附录 D：与治理域的边界对照

| 维度 | 治理域（DD1–DD6） | 建模域（本 PRD） |
|---|---|---|
| **核心对象** | 模板（属性模板/分类模板/单位/注释属性） | 实体（owl:Class/属性/关系） |
| **IRI** | 模板不含 IRI | 实体有独立 IRI |
| **进入 RDF** | 不进入 | 进入（序列化产出 RDF） |
| **类层级** | 只读镜像 + 供给建议 | 权威源（建立 subClassOf + 回推镜像） |
| **序列化** | 不做（只产判据） | 做（方案 B 默认，A 预留） |
| **解析** | 不做 | 做（Jena 解析 + 溯源识别） |
| **建模画布** | 不做 | 做（AntV X6） |
| **个体实例** | 不做（Out of Scope） | 不做（后置 M10） |
| **数据表** | ont_property_template 等 8 张（V4–V11） | ont_model_* 7 张（V12+） |
| **菜单 ID** | 10000–10599 | 11000–11599 |
| **权限标识** | ont_prop_tpl_* / ont_class_tpl_* / ont_unit_* / ont_ap_* / ont_ref_view / ont_supply_view / ont_sync_push | ont_project_* / ont_class_model_* / ont_prop_model_* / ont_serialize_* / ont_canvas_* |
| **接口前缀** | `/admin/ont/`（治理） + `/supply/v1/`（供给） + `/sync/`（同步） | `/admin/ont/model/`（建模） |
| **交互方式** | 建模域调治理域 Supply/Sync API（HTTP） | 治理域不调建模域（单向消费） |
| **代码隔离** | 治理域不引用建模域 | 建模域通过 HTTP 调 Supply/Sync API（或同模块内只读查询治理域表，但只读不写） |
