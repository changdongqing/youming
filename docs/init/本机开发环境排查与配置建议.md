## 二、项目开发环境补装与配置

### 2.1 设置 `JAVA_HOME`（必做，优先级最高）

本机已装 JDK 21 但 `JAVA_HOME` 为空，影响 Maven、VSCode Java 扩展、手动 `java -jar`。

**步骤**：
1. 定位 JDK 家目录（PowerShell）：
   ```powershell
   (Get-Command java).Source      # 这通常是 shim，需进一步找真实家目录
   # 通常在 C:\Program Files\Eclipse Adoptium\jdk-21.0.11.x
   ```
2. 设系统环境变量：`JAVA_HOME` = JDK 家目录；`%JAVA_HOME%\bin` 加入 `PATH`。
3. 重开终端验证：
   ```bash
   echo $JAVA_HOME
   "$JAVA_HOME/bin/java" -version
   ```

> Spring Boot 4.0.7 要求 Java 17+；Spring Boot 4.1 系列已建议 21。本机 21 合适，**无需降级到 17**。
> （注：`docs/start/*` 文档 2.1 仍写"JDK 17（必须）"，与最新代码现状不符，见第六节勘误。）

### 2.2 安装 Maven 3.9+（必做，仓库无 wrapper）

本仓库 `server/` 下**未携带 Maven Wrapper**（无 `mvnw`/`mvnw.cmd`/`.mvn/`），必须全局安装 Maven。

1. 下载 Apache Maven 3.9.x：https://maven.apache.org/download.cgi
2. 解压到如 `D:\dev\apache-maven-3.9.x`
3. 环境变量：`MAVEN_HOME` = 上述目录；`%MAVEN_HOME%\bin` 加入 `PATH`
4. **配阿里云镜像**（见 4.2）后验证：
   ```bash
   mvn -version
   ```

### 2.3 对接本机 PostgreSQL 容器 + 创建业务库（必做，凭证需覆盖）

本机 `devops-postgres`（PG 18.4）已在跑，但存在两个问题：
- **业务库 `mingwanwudb` 尚未创建**（容器内仅 `postgres`/`template0`/`template1`）；
- `application-dev.yml` 默认凭证是 `user_PAmcy2`/`password_bkQ4JT`（AGENTS.md 记录的 1Panel 环境），**与本机 `devops-postgres` 的 `postgres`/`postgres` 不符**——直接启动会报 `role "user_PAmcy2" does not exist`。

**操作**：

1. 创建业务空库（库结构由 Flyway 自动建，无需手工导 SQL）：
   ```bash
   docker exec devops-postgres psql -U postgres -c "CREATE DATABASE mingwanwudb;"
   ```
   > Flyway 启动时会自动执行 `server/pig-common/pig-common-data/src/main/resources/db/migration/` 下 V1~V7（V1 业务表结构 / V2 种子数据 / V3 Quartz 表 / V4~V7 本体治理模块），自动建表 + 灌种子数据。

2. 用环境变量覆盖凭证启动后端（**不改源文件**）：
   ```bash
   export PG_HOST=127.0.0.1 PG_PORT=5432 PG_DB=mingwanwudb PG_USER=postgres PG_PASSWORD=postgres
   export REDIS_HOST=127.0.0.1 REDIS_PASSWORD=redis
   ```

   或写进 `.vscode/launch.json` 的 `env` 字段（见 2.5）。

3. 操作 PG 的便捷方式（本机无 psql CLI，走 docker exec）：
   ```bash
   # 执行 SQL
   docker exec devops-postgres psql -U postgres -d mingwanwudb -c "<SQL>"
   # 导入 SQL 文件
   docker exec -i devops-postgres psql -U postgres -d mingwanwudb < some.sql
   ```

> ⚠️ 上游 pig 的 `server/db/pig.sql`、`pig_config.sql` 为 **MySQL 脚本，已弃用**（仅作迁移源参考）。mingwanwu 分支开发测试一律用 PostgreSQL，**不要导入这两个文件**。

### 2.4 Redis（已就绪，仅需对齐凭证）

`devops-redis` 已在跑（密码 `redis`）。单体版默认用 db `5`。

启动后端前用 `REDIS_HOST=127.0.0.1 REDIS_PASSWORD=redis` 覆盖默认值（默认 `redis_6QX4h2` 是 AGENTS.md 的 1Panel 凭证，本机不适用）。

### 2.5 VSCode 配置（已本地存在，需复核凭证）

本分支 commit `e6641c4` 记载：`.vscode/`（launch.json / settings.json / extensions.json）已本地配置，但**被根 `.gitignore` 忽略，不入库**。

**需复核**：`.vscode/launch.json` 中 `PigBoot (单体)` 的 `env` 是否已对齐本机 `devops-*` 容器凭证（`PG_USER=postgres` / `PG_PASSWORD=postgres` / `REDIS_PASSWORD=redis`）。若仍写的是 1Panel 凭证，启动会连不上库。

建议 `launch.json` 形如：
```json
{
  "version": "0.2.0",
  "configurations": [
    {
      "type": "java",
      "name": "PigBoot (单体)",
      "request": "launch",
      "mainClass": "com.pig4cloud.pig.PigBootApplication",
      "projectName": "pig-boot",
      "cwd": "${workspaceFolder}/server",
      "args": "--spring.profiles.active=dev",
      "vmArgs": "-Xms512m -Xmx1024m",
      "env": {
        "PG_HOST": "127.0.0.1",
        "PG_PORT": "5432",
        "PG_DB": "mingwanwudb",
        "PG_USER": "postgres",
        "PG_PASSWORD": "postgres",
        "REDIS_HOST": "127.0.0.1",
        "REDIS_PASSWORD": "redis"
      }
    }
  ]
}
```

## 四、中国大陆网络优化配置

### 4.1 npm/pnpm 镜像源（必做）

```bash
npm config set registry https://registry.npmmirror.com
pnpm config set registry https://registry.npmmirror.com
npm config get registry && pnpm config get registry   # 验证
```

### 4.2 Maven 阿里云镜像（必做，影响后端编译成败）

`~/.m2/settings.xml`（即 `C:\Users\changdq\.m2\settings.xml`）当前不存在。pig 依赖 Spring Boot 4.0.7 / Spring Cloud 2025.1.2 / Spring Cloud Alibaba 全家桶，从 Maven Central 下载在大陆极易超时。创建：
```xml
<settings xmlns="http://maven.apache.org/SETTINGS/1.2.0"
          xmlns:xsi="http://www.w3.org/2001/XMLSchema-instance"
          xsi:schemaLocation="http://maven.apache.org/SETTINGS/1.2.0
          https://maven.apache.org/xsd/settings-1.2.0.xsd">
  <mirrors>
    <mirror>
      <id>aliyun-public</id>
      <name>aliyun public</name>
      <url>https://maven.aliyun.com/repository/public</url>
      <mirrorOf>central</mirrorOf>
    </mirror>
    <mirror>
      <id>aliyun-spring</id>
      <name>aliyun spring</name>
      <url>https://maven.aliyun.com/repository/spring</url>
      <mirrorOf>spring</mirrorOf>
    </mirror>
    <mirror>
      <id>aliyun-spring-plugin</id>
      <name>aliyun spring-plugin</name>
      <url>https://maven.aliyun.com/repository/spring-plugin</url>
      <mirrorOf>spring-plugin</mirrorOf>
    </mirror>
  </mirrors>
</settings>
```

### 4.3 pip 镜像源（做文档处理脚本时装）

```bash
pip config set global.index-url https://pypi.tuna.tsinghua.edu.cn/simple
pip config set global.trusted-host pypi.tuna.tsinghua.edu.cn
```

## 六、与已有文档/AGENTS.md 的勘误（重要，动手前先理清）

切到 mingwanwu 分支后实测发现，`AGENTS.md` 与 `docs/start/*` 中记录的本机容器信息**与当前实跑容器不一致**——这是最容易导致"照文档连不上库"的坑：

### 6.1 容器名与凭证勘误（根 AGENTS.md + docs/start 单体版）

| 文档处 | 文档记录 | 本机实测 | 影响/处理 |
|--------|---------|---------|----------|
| AGENTS.md「本机开发环境」表 | PostgreSQL 容器 `1Panel-postgresql-ANBv`，用户 `user_PAmcy2`/密码 `password_bkQ4JT` | 容器 `devops-postgres`，PG 18.4，用户 `postgres`/密码 `postgres` | `application-dev.yml` 默认值按 AGENTS.md 写的是 `user_PAmcy2/...`，**本机连不上**；须用环境变量覆盖（见 2.3） |
| 同上 | Redis 容器 `1Panel-redis-2G4M`，密码 `redis_6QX4h2` | 容器 `devops-redis`，密码 `redis` | 同上，默认值对不上 |

| 同上 | Nacos 容器 `1Panel-nacos-4GLs-standalone` | 容器 `devops-nacos`（nacos/nacos-server:latest） | 名称不符；微服务版若复用需改指向 |

| docs/start 单体版 2.1 | PostgreSQL 14+（推荐 18.x） | 实测 18.4 ✅ | 版本符合，无需动 |

> **结论**：`application-dev.yml` 的默认凭证（`user_PAmcy2`/`password_bkQ4JT`/`redis_6QX4h2`）对应的是 1Panel 环境的历史快照，与本机 `devops-*` 容器不符。两种修法：
> - **A（推荐，零侵入）**：启动时用环境变量覆盖（见 2.3），不改源文件、不改 AGENTS.md；
> - **B（彻底）**：更新 `application-dev.yml` 默认值 + AGENTS.md + docs/start 凭证为本机 `devops-*` 实际值，使文档与现状一致。
