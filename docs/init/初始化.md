# 项目初始化

## 背景

你是一个git版本管理专家，现在要建一个git仓库，名称叫youming，初始化时有一部分文件是手工创建的，还有两个文件夹，分别对应两个其他git开源项目拉取过来的，我要实现所有代码文件都保存在我的这个名称为ym的git仓库中，统一执行提交、推送，但是那两个拉取来的开源项目支持从源项目拉取更新。

## 设想的整体目录

aidocs---存放ai生成的文档
docs---存放评审完成的文档
server---后端代码
web---前端代码
其他具体文件，如git配置、授权协议、readme、ai记忆文档等


## 源项目有2个

1. 后端源地址：https://github.com/pig-mesh/pig.git，拉取后在本项目中目录名称为“sever”
2. 前端前端源：https://github.com/pig-mesh/pig-ui.git，拉取后在本项目中目录名称为“web”

## 可行性方案描述举例参考教程
 Git Subtree（推荐，更符合你的“统一提交”直觉）
**适用场景**：你**经常修改**这两个开源项目里的代码，并且希望这些代码直接作为主仓库历史的一部分，无需额外推送子模块。

**核心逻辑**：将开源项目的代码完整“合并”进你的主仓库，但通过 `git subtree` 命令保持与上游的关联。

**实施步骤：**

1. **初始化主仓库**（同方案一步骤1）。

2. **拉取开源项目作为子树**（而不是复制粘贴）：
   ```bash
   # 将 libA 拉取到 ./libs/libA 目录，并合并进主仓库历史
   git subtree add --prefix=libs/libA https://github.com/libA.git main --squash
   
   # 将 libB 拉取到 ./libs/libB 目录
   git subtree add --prefix=libs/libB https://github.com/libB.git main --squash
   ```
   *（`--squash` 参数会将上游复杂的提交历史压缩成一个，保持你的主仓库历史干净）*

3. **日常统一提交（完美契合你的需求）**：
   - 你可以随意修改 `libs/libA` 下的代码。
   - 在根目录执行 `git add .` 和 `git commit`，所有改动（包括开源项目内的）都会像普通文件一样被统一提交。
   - 执行 `git push origin main`，一切都在一个仓库里。

4. **从上游拉取更新（关键）**：
   ```bash
   # 拉取 libA 上游的新代码，合并到本地子目录
   git subtree pull --prefix=libs/libA https://github.com/libA.git main --squash
   
   # 拉取 libB 上游的新代码
   git subtree pull --prefix=libs/libB https://github.com/libB.git main --squash
   ```
   *如果合并时有冲突，按正常Git冲突解决即可。*
