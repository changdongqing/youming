# 分支管理与上游同步规范

## 一、分支模型

本仓库采用三分支模型，职责分离：

| 分支 | 职责 | 是否直接跑 subtree pull |
|------|------|------------------------|
| `main` | 稳定发布主干，只接收已验证的合并 | ❌ 否 |
| `upstream-sync` | 上游同步专用，承接 `git subtree pull` 与冲突解决 | ✅ 是 |
| `youming` | 日常开发分支，承接本仓库所有二次开发改动 | ❌ 否 |

```
main            ── 稳定主干（冻结，不直接跑 subtree pull）
├─ upstream-sync ── 上游同步专用（跑 subtree pull + 解决冲突，可重置）
└─ youming       ── 日常开发分支
```

### 设计原则

- **开发隔离**：本仓库对 `server/`、`web/` 的所有二次开发改动只提交到 `youming`，不直接落 `main`。
- **冲突隔离**：上游同步的冲突解决只在 `upstream-sync` 上进行，搞砸了可 `git reset --hard main` 重来，不污染 `main` 与 `youming`。
- **单向下发**：合并方向为 `upstream-sync → main → youming`，`youming` 不反向合并回 `main`（开发成果并入主干走 PR / 评审流程，另定）。

## 二、上游同步标准流程

上游项目（pig / pig-ui）默认分支为 **`master`**（非 `main`）。

### 步骤

```bash
# 1. 切到上游同步分支，同步 main 最新状态作为基线
git checkout upstream-sync
git merge main

# 2. 拉取上游更新（--squash 压缩历史，保持主仓库历史干净）
git subtree pull --prefix=server https://github.com/pig-mesh/pig.git    master --squash
git subtree pull --prefix=web    https://github.com/pig-mesh/pig-ui.git master --squash

# 3. 如有冲突，在此分支解决后提交
#    解决失败可放弃：git reset --hard main

# 4. 验证通过后，并入稳定主干
git checkout main
git merge upstream-sync

# 5. 下发到开发分支
git checkout youming
git merge main
```

### 关键认知

- `git subtree pull` 的冲突源于「本地对子目录的改动」与「上游改动」重叠，**与合并到哪个分支无关**。
- 不能假设「main 没改动所以 subtree pull 零冲突」——`main` 上游初始快照之后会有本仓库的改动累积，`server/`/`web/` 的二次开发改动与上游新版本重叠时必然冲突。
- 正因如此，冲突解决被隔离在 `upstream-sync`，而非直接在 `main` 上进行。

## 三、日常开发流程

```bash
# 在 youming 分支开发
git checkout youming

# 修改 server/ 、web/ 或其他文件后，统一提交（根目录执行）
git add .
git commit -m "feat: ..."

# 推送
git push origin youming
```

> 所有改动（含 `server/`、`web/` 子目录内部）在根目录统一 `git add / commit / push`，与普通文件无异——这是 Git Subtree 的优势。

## 四、分支创建记录

- `main`：仓库初始主干，已推送至 `origin/main`。基线含上游初始快照 + 初始化文档。
- `youming`：从 `main`（`8c6b90fa9`）拉出，日常开发在此进行。
- `upstream-sync`：从 `main`（`8c6b90fa9`）拉出，上游同步专用，可随时重置。

## 五、注意事项

- `upstream-sync` 是临时性分支，同步完成后可保留以便下次复用，也可删除后从 `main` 重建。
- 上游更新可能覆盖本仓库对子目录的二次开发改动，`subtree pull` 前请确认 `youming` 已提交干净。
- 若 `youming` 有未合并回 `main` 的开发改动，步骤 5 的 `git merge main` 会把上游更新合入 `youming`，此时若 `youming` 的本地改动与上游冲突，需在 `youming` 上额外解决一次。
