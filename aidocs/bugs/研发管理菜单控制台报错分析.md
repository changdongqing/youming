# 研发管理模块控制台报错分析

> 分析人：高级 Java 后端 / 高级 Vue 前端
> 日期：2026-07-29
> 影响范围：菜单分组「研发管理」下全部功能（需求管理 / 开发管理 / 测试管理 / 报表统计 / 待办中心）

## 一、报错现象汇总

浏览器控制台输出可归为三类：

| # | 报错 | 类别 |
|---|------|------|
| 1 | `:8888/api/admin/rm/requirement/page` → 404 | 后端接口 404 |
| 2 | `:8888/api/admin/rm/dev-task/page` → 404 | 后端接口 404 |
| 3 | `:8888/api/admin/rm/test-case/page` → 404 | 后端接口 404 |
| 4 | `:8888/api/admin/rm/todo/my` → 404（出现两次） | 后端接口 404 |
| 5 | `:8888/api/admin/sys-file/local/2a14ae...png` → 424 Failed Dependency | 鉴权失败（令牌过期） |
| 6 | `[Vue Router warn] Record with path "/admin/rm/report/requirement-detail" is either missing a "component(s)" or "children" property.` | 前端路由缺组件 |

其中 `:8888` 是前端 Vite dev server 端口，经 `VITE_ADMIN_PROXY_PATH` 反向代理到单体后端 `localhost:9999`（pig-boot，context-path `/admin`）。

## 二、根因分析

### 根因 A（决定性）：pig-boot 单体未装载 pig-rm-biz，导致全部 `/rm/**` 接口 404

**证据链：**

1. `server/pig-boot/pom.xml` 已声明依赖 `pig-rm-biz`（第 66 行）：
   ```xml
   <dependency>
       <groupId>com.pig4cloud</groupId>
       <artifactId>pig-rm-biz</artifactId>
       <version>${project.version}</version>
   </dependency>
   ```

2. 控制器源码存在且 Mapping 正确。以 `RequirementController` 为例：
   ```java
   // package com.pig4cloud.pig.rm.controller;
   @RestController
   public class RequirementController {
       @GetMapping("/rm/requirement/page")  // + context-path /admin = /admin/rm/requirement/page
       public R<IPage<Requirement>> page(...) { ... }
   }
   ```
   `DevTaskController`(`/rm/dev-task/page`)、`TestCaseController`(`/rm/test-case/page`)、`TodoController`(`/rm/todo/my`) 同理，URL 与前端请求完全吻合。

3. `pig-rm-biz` 本身已成功编译，jar 产物存在：
   ```
   server/pig-rm/pig-rm-biz/target/pig-rm-biz.jar  （18:03 生成）
   ```

4. **但 pig-boot 的编译产物 `server/pig-boot/target/classes/` 下没有任何 `rm` 包**（`com/` 下无 `pig/rm` 目录），且 `target/` 下没有 fat jar（无 `BOOT-INF/lib`）。说明 **pig-boot 自加入 `pig-rm-biz` 依赖后未重新构建/重新启动**，当前运行中的 9999 端口进程是旧的 classpath，不包含 RM 控制器。

5. 组件扫描本应是通的：`PigBootApplication` 位于 `com.pig4cloud.pig`，`@SpringBootApplication` 默认扫描 `com.pig4cloud.pig.**`，而 RM 控制器在 `com.pig4cloud.pig.rm.controller`，属于扫描范围；RM Mapper 均标注 `@Mapper`（MyBatis-Plus 自注册），无需额外 `@MapperScan`。最近的提交 `5be3adb` 已将 `SysUserMapper` 重命名为 `RmUserQueryMapper` 解决了与 pig-upms 的 bean 名冲突。**即：一旦重新构建，组件扫描与 bean 装配没有阻塞项。**

**结论 A：** 报错 1~4 的全部 404，本质是 **pig-boot 单体未重新构建/重启**，classpath 缺失 `pig-rm-biz`，所有 `/rm/**` 路由未注册。这不是代码缺陷，是构建/部署未跟进。修复方式：重新 `mvn install` 整个 `pig-rm` 模块并重新构建启动 `pig-boot`。

### 根因 B：前端动态路由组件解析失败（报表统计菜单）

**路由机制回顾（`web/src/router/backEnd.ts`）：**

- 后端 `SysMenuServiceImpl.getNodeFunction()` 把菜单表 `path` 列作为 `path`、`component` 列作为 `componentPath` 一并下发；
- 前端 `backEndComponent()` 优先用 `componentPath` 解析组件，**`componentPath` 为 null 时回退用 `path`** 解析：
  ```js
  } else if (item.componentPath) {
      item.component = dynamicImport(dynamicViewsModules, item.componentPath);
  } else {
      item.component = dynamicImport(dynamicViewsModules, item.path);  // 回退
  }
  ```
- `dynamicImport()` 用 `import.meta.glob('../views/**/*.{vue,tsx}')` 的 key 做前缀匹配：`key.startsWith(`${component}.vue`)`。

**问题点：** `V18__rm_menu_seed.sql` 中所有二级菜单的 `component` 列均为 `NULL`，因此全部走 `path` 回退；其中：

```sql
INSERT INTO sys_menu VALUES (19400, '报表统计', NULL, '/admin/rm/report/requirement-detail', NULL, 19000, ...);
```

`path = /admin/rm/report/requirement-detail`，前端据此匹配 `views/admin/rm/report/requirement-detail.vue`。但 **`web/src/views/admin/rm/report/` 下只有 `requirement-stat.vue`，没有 `requirement-detail.vue`** → `dynamicImport` 返回 `undefined` → Vue Router 报「missing a component(s)」警告。

> 其余四个菜单（requirement/index、dev-task/index、test/case/index、todo/index）都能在 `views/admin/rm/` 下找到同名 `.vue`，故只有「报表统计」这一项触发路由警告。

**报表的设计意图（来自 `ReportController`）：**
- RPT-01 需求明细表 `/rm/report/requirement-detail`
- RPT-02 需求统计表 `/rm/report/requirement-stat`
- RPT-03 开发任务统计表 `/rm/report/dev-task-stat`

当前仅实现了 RPT-02 的视图 `requirement-stat.vue`（调用 `requirementStat` 接口）。菜单却指向 RPT-01 的 `requirement-detail`，二者不匹配。

**结论 B：** 报错 6 是菜单 `path` 与已实现视图文件名不一致。两种修复方向：
- **方向 1（推荐，最小改动）**：把菜单 19400 的 `path` 改为 `/admin/rm/report/requirement-stat`，指向已实现的 RPT-02 视图；
- 方向 2：补齐 `views/admin/rm/report/requirement-detail.vue` 视图（调用 `requirementDetail` 接口），实现 RPT-01 明细表。

本修复采用方向 1，并同步修正后续菜单种子。

### 根因 C：附件图片请求 424（令牌过期，独立于 RM 的鉴权问题）

**证据：** `ResourceAuthExceptionEntryPoint.commence()`（pig-common-security）对 `InvalidBearerTokenException` 等异常返回 `HttpStatus.FAILED_DEPENDENCY (424)`：

```java
// 针对令牌过期返回特殊的 424
if (authException instanceof InvalidBearerTokenException || ...) {
    response.setStatus(HttpStatus.FAILED_DEPENDENCY.value());
    result.setMsg(... "tokenExpired" ...);
}
```

`/admin/sys-file/local/{uuid}.png` 由 `<img>`/预览组件直接发起，未携带有效 Bearer Token（或 token 已过期），被资源服务器拒绝返回 424。

> 另：该 URL 形如 `/sys-file/local/{file}.png`，而 `SysFileController` 的本地文件端点是 `/sys-file/local/file/{fileName}`（多一级 `/file/`）。但 424 早于 404 触发（鉴权先于路由），故控制台只看到 424。这是文件预览链路的既有问题，非本次研发管理菜单报错的主因，单独记录待处理。

**结论 C：** 424 是令牌过期/图片请求未带 token 导致的鉴权失败，与 RM 模块 404 无直接因果，属附带暴露的独立问题。

## 三、修复方案

| 报错 | 根因 | 修复动作 | 归属 |
|------|------|----------|------|
| 1~4 接口 404 | pig-boot 未装载 rm-biz | 重新构建 `pig-rm` 模块并重启 `pig-boot`（构建命令见下） | 后端构建 |
| 6 路由缺组件 | 菜单 path 与视图不匹配 | 修正 `V18__rm_menu_seed.sql` 菜单 19400 的 path 为 `requirement-stat`；并补迁移脚本修正已入库数据 | 后端 SQL + 前端 |
| 5 图片 424 | 令牌过期/未带 token | 独立问题，本次记录不阻断；建议图片预览走带 token 的接口或加白名单 | 待跟进 |

### 后端构建命令
```bash
# 在 server/ 下，先装 rm 模块再重建 boot
mvn -pl pig-rm/pig-rm-biz -am install -DskipTests
mvn -pl pig-boot -am package -DskipTests
# 重启 pig-boot（9999）
```
