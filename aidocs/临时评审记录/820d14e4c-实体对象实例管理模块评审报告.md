### P1-02：后端 createInstance 事务清理反模式

**位置：** `server/.../service/impl/OntEntityInstanceServiceImpl.java:248-332`（`createInstance`）

**问题：**

方法标注 `@Transactional(rollbackFor=Exception.class)`，但执行流程是：

1. `this.save(instance)`（L272）——先插入主表（此时 iri/iriLocalName 为空）；
2. 校验 IRI 本地名格式（L279）→ 失败 `this.removeById()` + `return R.failed(...)`；
3. 校验 IRI 全局唯一（L286）→ 失败 `this.removeById()` + `return R.failed(...)`；
4. 校验本地名冲突（L292）→ 失败 `this.removeById()` + `return R.failed(...)`；
5. `this.updateById(instance)`（L304）——回填 iri/iriLocalName；
6. 校验数据值（L309）→ 失败 `throw IllegalArgumentException`；
7. 校验断言（L321）→ 失败 `throw IllegalArgumentException`。

问题：
- `@Transactional` 默认不对 `R.failed()` 正常返回回滚，所以 L280/288/298 的手动 `removeById` 是必要补丁，但脆弱（若 removeById 本身失败或中间有其他写操作则残留脏数据）；
- 同一方法内错误处理不一致：IRI 校验用 `return R.failed`（需手动清理），数据值/断言校验用 `throw`（自动回滚）；
- 先 insert 再 update 的两步写入本可避免——应先完成全部校验和 IRI 生成，再一次性 insert。

**修复方案：** 重构为先校验后写入：先生成 IRI 本地名、校验全部约束（包括数据值/断言），最后一次性 `save`。所有校验失败统一 `throw`（或保留 `return R.failed` 但在事务内由 `TransactionAspectSupport` 标记回滚）。

- 3. 功能性断言：锁对象属性行+主体实例行后检查；
- 4. 唯一数据属性：锁数据属性行后检查工程内值；
- 5. 关系创建同时涉及两个实例时，按 ID 升序 `SELECT ... FOR UPDATE`。

当前实现全部用 `selectCount` 无锁检查：
- 功能性约束（L857-864）：`relationMapper.selectCount(...)` 统计同主体+谓词断言数，无锁；
- 唯一数据属性（L688-697）：`dataValueMapper.selectCount(...)` 检查工程内值，无锁；
- 重复三元组（L847-854）：无锁；
- 主体/客体实例无 `FOR UPDATE` 锁定。

**影响：**
- 并发下功能性约束可被穿透（两个请求同时通过 `funcCount==0` 检查后各自插入），最终产生 2 条功能性断言，违反"同一主体+谓词至多一条"——且功能性跨 INSTANCE/ENTITY_TYPE 合计约束**无部分唯一索引兜底**（设计 §8.2 说明功能性依赖 Schema 条件不能用无条件唯一索引）；
- `is_unique` 数据属性并发写入可产生重复值（虽有索引兜底但会抛 DuplicateKey 而非业务错误）。

**修复方案：** 在校验前用 `SELECT ... FOR UPDATE` 锁定相关行（对象属性行、数据属性行、主体/客体实例行，按 ID 升序避免死锁）。可新增 Mapper 方法 `selectByIdForUpdate(Long id)` 或用 `@Select` 注解。

### P1-04：后端 DTO 嵌套集合缺少 @Valid

**位置：** `server/.../dto/OntEntityInstanceCreateDTO.java`，`dataValues`/`objectRelations` 字段

**问题：**

```java
private List<OntInstanceDataValueDTO> dataValues;        // 缺少 @Valid
private List<OntInstanceObjectRelationDTO> objectRelations; // 缺少 @Valid
```

Bean Validation 不会自动级联到集合元素。Controller 的 `@Valid @RequestBody OntEntityInstanceCreateDTO` 只校验根级字段，`OntInstanceDataValueDTO` 内的 `@NotNull dataPropertyId`、`@NotBlank literalValue`、`@Pattern literalType` 等**全部被静默跳过**。

客户端可提交 `dataPropertyId=null` 或 `literalValue=""`，通过 `@Valid` 后在 Service 层才被捕获（部分会 NPE 或产生不友好错误）。

**修复方案：** 两字段加 `@Valid`，import `jakarta.validation.Valid`。建议同时加 `@Size(max=...)` 限制批量大小。

## 八、结论

本模块的**数据库层（V10）和后端核心校验逻辑**质量极高，附录D的异常处理体现了对 OWL 2 语义和国标原文的深刻理解，值得肯定。但**前端仅交付了基础框架（类型/API/布局/只读展示），Schema 驱动表单和关系编辑器这两大核心交互能力虽逻辑完整却未接入视图**，导致模块在 UI 层面基本不可用于实际建模。后端联动保护改造中引入的**实体类型更新功能回归**是必须立即修复的副作用。

修复 P0 三项 + P1 四项后，本模块可达到可推送、可功能测试的状态。建议修复后重新评审前端表单/关系编辑器的端到端可用性。
